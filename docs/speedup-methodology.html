2. 가속 방법론 (영향순)

① crane-safe 디코드 엔진 가속 최대 레버 · 2~4× 단독

영향: ★★★★★난이도: 중~상리스크: 기하 정밀도

디코드는 앞단계 178s이자 cum_level·cross-bay 재디코드의 내부 엔진이다. 한 번 5~10× 빨라지면 파이프라인 전체가 연쇄 가속된다. 현재 디코드는 베이마다 블록쌍에 대해 check_entry/check_exit(shapely 기하)를 매 디코드마다 새로 호출 → per-bay ≈ O(k³) (k=베이당 블록수).

(a) 시간독립 기하 precompute. 두 블록의 crane(j≥k) 관계·충돌은 위치(x,y,orient)에만 의존하고 시간과 무관하다. 지금은 디코드 루프 안에서 매번 shapely로 재계산. 레이아웃당 쌍별 관계행렬(5 boolean: obs_entry/obs_exit/retro_entry/retro_exit/collide)을 1회 precompute하면, per-bay 스케줄링이 순수 정수 interval 로직이 되어 루프에서 shapely가 사라진다. (메모리 z1-feasibility-floor에 이미 지적된 구조 — 미구현.)

(b) 증분 재디코드. cum_level·cross-bay는 소수 베이만 건드린다. 5개 베이 전부 재디코드 말고 바뀐 베이만. _decode_cached 골격이 이미 있음 → 확장.

(c) 기하 prefilter. shapely Polygon 연산은 느리다. bbox 겹침 STRtree prefilter → bbox가 겹치는 쌍에만 shapely 호출. resolved 폴리곤 캐시.

예상: 디코드 5~10× → seeds 178s→~25s, cum_level 재디코드 동일비율. 단독 전체 2~4×.

② per-bay 서브문제 4코어 병렬화 1.5~3× · 인프라 존재

영향: ★★★★난이도: 중리스크: 오버서브스크립션

cum_level·bbox_pack은 베이별로 독립 CP-SAT인데 순차 실행. 평가서버 4코어 → 5베이를 4코어에 fan-out하면 그 단계가 ~4×. run_parallel_cumlevel 인프라가 이미 있으나 폐기 상태 → ①의 빠른 디코드와 함께 부활.

주의: 베이별 CP-SAT를 1-thread로 두고 4베이 병렬(=4코어)해야 함. 현재처럼 베이별 4-thread CP-SAT를 또 병렬하면 16-way 오버서브스크립션 → 역효과.

예상: cum_level 70~188s→~25~50s, bbox 80s→~25s.

③ CP-SAT 조기종료 + 타이트 캡 1.3~2× · 저위험

영향: ★★★★난이도: 하~중리스크: 과조기종료시 품질↓

현재 per-bay CP-SAT는 부여된 시간 캡까지 돈다. (a) OPTIMAL 증명 즉시 종료(CP-SAT status), (b) 개선정체 N초면 중단(stop_after_no_improvement), (c) 현재 레이아웃으로 강한 warm-start → 빠른 수렴, (d) 더 많은 변수 고정(이미 풀린 베이는 동결). tardiness=0은 Z1의 전역최소라 도달 즉시 그 베이 종료.

예상: CP-SAT 단계들 30~50% 절감 (대부분 일찍 수렴).

④ 수렴 기반 조기종료 (단계 레벨) 1.5~3× on cum_level

영향: ★★★★난이도: 중리스크: 수렴추적 정확도

측정: cum_level은 초반에 대부분의 일을 한다 (prob_14: Z1 5222→17). 후반은 한계효용 급감. 개선율(ΔZ1/Δt)이 임계 아래로 떨어지면 다음 단계로. + 이미 구현한 OGC_EXIT_ON_Z1_ZERO(Z1=0 도달 즉시 남은 레버 스킵·반환) — 평가서버 timeout=−1 위험도 동시 감소.

예상: cum_level 188s→~60s (작업의 80%가 앞 1/3에서 발생).

⑤ 실행분산 제거 (결정화) 실효속도 · 신뢰성

영향: ★★★난이도: 중리스크: 결정모드는 더 느릴 수도

모든 CP-SAT가 num_search_workers=4 → 멀티스레드 비결정성. 같은 prob_20이 실행마다 {2,8,11,17,20,320,530}로 진동. 결과: (1) 제출이 도박, (2) 조기종료 신뢰 불가. 대안: CP-SAT random_seed 고정 + 결정모드, 또는 독립basin 포트폴리오 keep-best(이미 일부 존재). 분산이 줄면 "운 나쁜 긴 런"이 사라져 실효 속도·안정성↑.

⑦ 구현 레벨 (Python 핫루프) 10~30%

영향: ★★난이도: 중

디코드/체크가 순수 Python. (a) numpy 벡터화(bbox 겹침·면적), (b) _results_from_solution 라운드트립(솔루션 dict↔내부구조 왕복) 제거, (c) 폴리곤·면적 캐시(블록당 1회), (d) 불필요한 재채점 제거.

4. 권장 실행 순서

  1. ①(a) 시간독립 기하 precompute부터. 단일 최대 레버이고, ②④의 효과까지 키운다. 먼저 디코드를 격리 벤치(인스턴스 1개, 기하 정밀도를 공식 check_feasibility로 대조)해 5~10× 확인 후 통합.
  2. ②(per-bay 병렬)를 빠른 디코드 위에 부활 — run_parallel_cumlevel을 1-thread CP-SAT로.
  3. ③④(조기종료) — 저위험. OGC_EXIT_ON_Z1_ZERO는 구현됨, 수렴캡 추가.
  4. ⑥(배분)은 ① 이후 재측정 (스위트 스팟이 이동하므로).
  5. ⑤(결정화)는 마지막 — 정확한 벤치를 위한 기반(분산 제거가 측정 신뢰도도 올림).

전 과정 게이트(check_feasibility + strict-improve) 유지 → 가속이 정답을 바꾸지 못함(−1·회귀 불가). 각 변경은 격리 A/B + solo 측정(멀티런 평균, 분산 때문).
