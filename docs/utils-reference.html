G 용어 사전 (Glossary) — 도메인을 모르는 사람을 위한 기초 개념

utils.py 에 등장하는 도메인 용어를 조선소·물류 맥락을 모르는 사람도 이해할 수 있게 풀이한다. 코드 식별자(이탤릭체)와 한글 명칭을 함께 표기한다.

베이(창고 구역) 2개와 블록(조선 부품) 배치 개념도. 크레인은 수직으로만 이동한다.
Bay
베이 / 보관 구역
조선소 야드 안의 직사각형 보관 공간. 블록을 일시적으로 쌓아두는 "주차 구역"과 같다. width × height 그리드 유닛 크기를 가진다.
Block
블록 / 조선 부품
조립이 필요한 선박 구성 요소 하나. 각 블록은 release(투입 가능 시각), processing_time(최소 체류 시간), due_date(납기)를 가진다.
Layer
층 / 레이어
블록을 2D 평면(x-y 바닥면)으로 자른 단면 폴리곤. Layer 0이 가장 아래, 인덱스가 클수록 위쪽. 크레인 경로 검사에서 층별로 충돌을 확인한다.
Anchor / Anchoring
앵커링 / 기준점 정규화
폴리곤의 최솟값 꼭짓점이 원점(0,0)이 되도록 좌표를 평행이동하는 작업. "블록의 기준점을 바닥 왼쪽 모서리로 고정"하는 것과 같다.
Orientation / orient_idx
방향 / 방향 인덱스
블록을 90°·180° 등으로 회전·반전한 형상 변형 하나. block_data["shape"] 리스트의 인덱스로 선택한다. 같은 블록도 여러 방향을 가질 수 있다.
Footprint
풋프린트 / 바닥면적
블록이 베이 바닥면에서 차지하는 2D 영역. 각 레이어의 폴리곤 합집합이 전체 풋프린트를 형성한다.
ENTRY / EXIT time
진입 시각 / 퇴출 시각
크레인이 블록을 베이에 내려놓는(ENTRY) 시각과 들어올리는(EXIT) 시각. 정수형 문자열로 솔루션 dict에 키로 사용된다.
AABB (Bounding Box)
축 정렬 바운딩 박스
폴리곤을 감싸는 가장 작은 직사각형(min_x, min_y, max_x, max_y). 정확한 다각형 교차 계산 전에 빠른 겹침 사전 필터로 쓴다.
Crane Vertical Access (j≥k)
크레인 수직접근 규칙
수직 크레인이 블록을 내릴 때 새 블록의 레이어 k가 기존 블록의 레이어 j(j≥k) 높이를 통과한다는 물리적 사실. 이 규칙을 위반하면 즉시 infeasible, 점수 −1.
Sweep Collision
스윕(경로) 충돌
크레인이 블록을 이동하는 도중에 다른 블록과 닿는 충돌. j>k 인 경우. 최종 위치에서는 문제없어도 경로 중간에 막힐 수 있다.
release_time / processing_time / due_date
출고 가능 시각 / 최소 체류 시간 / 납기
entry_time ≥ release_time, exit_time - entry_time ≥ processing_time, 납기 초과 시 tardiness(지연) 발생 → Z1 증가.
Tardiness (Z1)
지연량 / 납기 초과
max(0, exit_time − due_date). 납기 전 퇴출이면 0, 넘어가면 초과한 시간만큼 페널티. 전체 블록의 합이 목적함수 Z1.

_resolve_layers internal
raw_layers 를 순수 Python list-of-lists 로 복사해 반환. 인스턴스 데이터 변조 방지용 얕은 복사.

이 함수가 푸는 문제: 인스턴스 JSON에서 읽어온 레이어 데이터는 파이썬 내부적으로 동일 객체를 가리킬 수 있다. 솔버가 레이어 좌표를 제자리에서 수정하면 원본 인스턴스가 오염돼 이후 검사가 틀린 결과를 낸다. 이 함수는 항상 새 리스트를 만들어 반환해 그 문제를 차단한다.

raw_layerslist각 원소가 폴리곤 꼭짓점 리스트 [[x,y], ...]인 레이어 목록
반환값

Note
빈 레이어(if layer가 False인 항목)는 필터링된다. 인터페이스 호환성 유지용 경량 래퍼.

raw = [[[0,0],[4,0],[4,3],[0,3]], [], [[1,1],[3,1],[3,2]]]

# len(result) == 2  (원본 3개 → 2개)
_anchor_verts internal
단일 꼭짓점 목록의 바운딩 박스 최솟값이 (0, 0)이 되도록 평행이동.

이 함수가 푸는 문제: 블록 형상 데이터는 임의 좌표에서 정의돼 있을 수 있다. AABB 추정이나 그리드 배치 계산을 하려면 폴리곤을 원점 기준으로 정규화해야 한다. 이 함수는 단일 레이어 하나를 "왼쪽 아래 모서리 = (0,0)"이 되도록 이동시켜 준다.

def _anchor_verts(verts: list) -> list
파라미터타입설명
vertslist[[x, y], ...] 형태의 꼭짓점 목록
반환값
list — 평행이동된 꼭짓점 목록
_anchor_verts: 폴리곤 전체를 (min_x, min_y)만큼 빼서 왼쪽 아래가 원점이 되도록 이동
계산 예시
verts = [[120, 110], [170, 110], [170, 60], [140, 40], [120, 60]]
# min_x=120, min_y=40
result = _anchor_verts(verts)
# result = [[0, 70], [50, 70], [50, 20], [20, 0], [0, 20]]
# 모든 x에서 120을 빼고, 모든 y에서 40을 뺌
주의 — 다중 레이어에는 사용 금지
여러 레이어가 서로 정렬된 상태를 유지해야 할 때는 이 함수 대신 _anchor_layers를 써야 한다. 레이어별로 개별 앵커링하면 오프셋이 달라져 크레인 경로 기하가 깨진다.
_anchor_layers internal
모든 레이어의 합집합 바운딩 박스 기준으로 전체를 동일 오프셋으로 평행이동. 레이어 간 상대 위치를 유지.

이 함수가 푸는 문제: 블록은 여러 층(레이어)으로 구성된 3D 형상이다. 모든 레이어를 함께 정규화할 때 각 레이어를 따로 앵커링하면 레이어마다 다른 오프셋이 적용돼 물리적으로 어긋난 형상이 된다. 이 함수는 전체 레이어의 꼭짓점을 합산해 하나의 최솟값(min_x, min_y)을 구하고, 그 오프셋을 모든 레이어에 동일하게 빼주어 3D 형상의 상대 구조를 그대로 보존한다.

def _anchor_layers(layers: list) -> list
파라미터타입설명
layerslist[list]레이어 목록. 각 레이어는 꼭짓점 리스트
반환값
list[list] — 새 레이어 목록 (원본 불변)
계산 예시 — 왜 개별 앵커링이 틀리는가
layers = [
    [[10, 20], [30, 20], [30, 40], [10, 40]],  # Layer 0: min_x=10, min_y=20
    [[15, 20], [25, 20], [25, 35], [15, 35]],  # Layer 1: min_x=15, min_y=20
]

# _anchor_layers 사용 → 전체 min_x=10, min_y=20 (동일 오프셋)

# Layer 0: [[0,0],[20,0],[20,20],[0,20]]
# Layer 1: [[5,0],[15,0],[15,15],[5,15]]  ← 상대 위치 보존됨 (x+5 차이 유지)

# _anchor_verts 를 각각 쓰면? (잘못된 방식)
# Layer 0: [[0,0],[20,0],[20,20],[0,20]]   (min_x=10빼면 OK)
# Layer 1: [[0,0],[10,0],[10,15],[0,15]]   (min_x=15빼면 → Layer 1이 Layer 0 대비 x+5 어긋남 사라짐!)
사용 시점
여러 레이어가 물리적으로 쌓인 3D 블록 형상을 정규화할 때. 동일 오프셋 보장이 크레인 j≥k 규칙의 전제 조건.

_bounding_box internal

_bb_overlap internal
두 AABB가 엄밀하게(strictly) 겹치는지 판단. 모서리·꼭짓점만 공유하는 경우는 False.

이 함수가 푸는 문제: check_collisions / check_entry / check_exit 모두 블록 쌍에 대해 AABB를 먼저 비교한다. 이 함수가 False를 반환하면 Shapely intersection을 전혀 호출하지 않아도 된다. 대부분의 블록 쌍은 여기서 걸려 O(1)에 skip된다.

def _bb_overlap( a: tuple[float,float,float,float], b: tuple[float,float,float,float] ) -> bool
파라미터타입설명
atuple(min_x, min_y, max_x, max_y) — 첫 번째 바운딩 박스
btuple(min_x, min_y, max_x, max_y) — 두 번째 바운딩 박스
반환값
bool — 내부 넓이가 겹치면 True
판별식
a[0] < b[2] and b[0] < a[2] and a[1] < b[3] and b[1] < a[3] — 4개 strict inequality 모두 참일 때만 겹침.
_bb_overlap: 두 박스의 min/max 좌표만으로 겹침을 O(1) 판단. 겹치면 Shapely 정밀 검사 진행.
계산 예시
a = (30, 30, 130, 110)
b = (80, 60, 180, 140)
_bb_overlap(a, b)
# 30 < 180 and 80 < 130 and 30 < 140 and 60 < 110  →  True

c = (270, 40, 360, 110)
d = (400, 40, 490, 110)
_bb_overlap(c, d)
# 270 < 490 and 400 < 360?  →  400 < 360 = False  →  False
2 데이터 모델 (dataclass)
Bay
단일 베이의 직사각형 치수를 담는 dataclass. 좌표계 원점은 좌하단 모서리. x는 수평(0…width), y는 수직(0…height).

이 클래스가 푸는 문제: 블록이 베이 경계를 벗어나는지 판단하는 기준 객체. check_entry / check_feasibility 가 경계 검사에 이 객체를 사용한다. width·height 이 0 이하면 생성 시 ValueError.

구현 세부
실제 폴리곤이 아닌 bounding_rect() 를 기준으로 검사한다. 볼록하지 않은 형상이더라도 AABB가 베이를 벗어나지 않으면 True 를 반환한다. 검사 조건: 0 ≤ min_x && max_x ≤ width && 0 ≤ min_y && max_y ≤ height
Block
베이 내 특정 위치·방향으로 배치된 단일 블록. 생성 시 월드 좌표 레이어 캐시를 미리 계산한다.

이 클래스가 푸는 문제: 솔버는 같은 블록에 대해 check_entry / check_exit를 수백~수천 번 호출한다. 매번 "로컬 좌표 → 베이 좌표" 변환을 계산하면 느리다. Block 객체는 생성 시 한 번만 레이어를 베이 좌표로 변환해 _layers_cache에 저장한다. 이후 layers_at_pos()는 O(1) 조회만 하면 된다. 위치나 방향이 바뀌면 반드시 새 Block 객체를 만들어야 한다.

@dataclass class Block: block_id: int # instance["blocks"] 인덱스 block_data: dict # instance["blocks"][i] 전체 dict x: int = 0 # 베이 좌표 x (정수 그리드) y: int = 0 # 베이 좌표 y (정수 그리드) orient_idx: int = 0 # shape[] 인덱스 (0-기반)
중요 — 좌표는 정수
평가 서버는 x, y를 int(round(...)) 로 변환한다. 솔버가 부동소수점 위치를 반환하더라도 검사기는 정수 좌표로 반올림해 처리하므로, 솔버 내부에서도 정수 좌표를 사용하는 것이 안전하다.

함정 — 정수 좌표 강제
check_feasibility는 솔루션 dict의 x, y를 int(round(...))로 변환해 Block을 생성한다. 솔버가 부동소수점 좌표를 반환하면 반올림 후 위치가 미묘하게 달라져 경계·충돌 검사 결과가 바뀔 수 있다. 솔버 내부에서부터 정수 좌표를 쓰는 것이 안전하다.

EntryObstruction.is_sweep property
크레인 이동 경로(스윕) 충돌이면 True, 최종 안착 위치 충돌이면 False.
bool — exist_layer > new_layer (즉 j > k) 이면 True

이 클래스가 푸는 문제: 크레인이 블록을 내리거나 올릴 때 왜 방해가 생기는지, 정확히 어느 레이어(k)와 어느 기존 블록 레이어(j)가 부딪히는지를 기록한다. 솔버는 이 정보를 보고 "어떤 블록을 먼저 꺼내야 삽입이 가능해지는지" 추론할 수 있다.

크레인 수직 이동 규칙: j≥k인 모든 (k,j) 쌍을 검사한다. j==k는 안착 위치 충돌(is_sweep=False), j>k는 경로 중 충돌(is_sweep=True), j<k는 항상 안전.
크레인 j≥k 규칙 (핵심) — 왜 어렵고 왜 -1을 유발하는가

크레인이 블록을 수직으로 내릴 때, 새 블록의 레이어 k는 기존 블록의 레이어 j (j ≥ k) 높이를 통과한다. 최종 위치에서 겹침이 없어도, 내려오는 경로 중간에 기존 블록의 상위 레이어(j>k)와 겹치면 infeasible이다. 즉 "자리가 비어 있더라도 크레인 경로를 막는 블록을 먼저 꺼내야" 삽입이 가능하다. 이 제약을 위반하면 check_feasibility Stage 2 또는 Stage 5가 실패 → 점수 −1.

  • j == k: 최종 안착 위치에서의 충돌 (같은 높이) — is_sweep = False
  • j > k: 하강 경로 스윕 충돌 (내려오는 도중 지나가는 높이) — is_sweep = True
  • j < k: 충돌 없음 — 기존 레이어 j가 새 레이어 k보다 낮아 내려오는 동안 닿지 않음
상승(EXIT)에도 동일 규칙이 대칭 적용된다.
self-reference sentinel — 베이 경계 위반 구별법
existing_block.block_id == new_block.block_id인 EntryObstruction은 다른 블록과의 충돌이 아니라 베이 경계 초과를 나타낸다. check_entry가 경계 위반 시 이 패턴으로 반환하므로, 호출자는 이 조건으로 "경계 문제"와 "블록간 충돌"을 구분해 처리할 수 있다.
3 충돌·진입·퇴출 검사
check_collisions
공존하는 모든 블록 쌍에 대해 동일 레이어의 공간 겹침을 검사. AABB 선행 필터로 Shapely 호출을 최소화.

이 함수가 푸는 문제: 같은 시간에 같은 베이에 있는 두 블록이 물리적으로 겹치는지 확인한다. 조선소 야드에서 두 부품이 동시에 같은 자리를 차지하면 물리적으로 불가능하다. check_feasibility Stage 4에서 시간 구간이 겹치는 블록 쌍에만 이 함수를 호출한다.

check_entry
크레인이 new_block을 베이에 내릴(ENTRY) 때 장애물 여부를 검사. j≥k 하강 경로 규칙 적용.

이 함수가 푸는 문제: 블록을 특정 위치에 놓고 싶어도, 크레인이 위에서 수직으로 내려오는 과정에서 이미 있는 블록의 상위 레이어를 통과해야 할 수 있다. "자리는 비어 있지만 경로가 막혀 내릴 수 없다"는 상황을 정확히 잡아낸다.

check_entry: 크레인이 새 블록을 내리는 수직 경로 전체에서 기존 블록 레이어(j≥k)와의 겹침을 검사한다.
def check_entry( bay: Bay, blocks: list[Block], new_block: Block, fast: bool = False ) -> list[EntryObstruction]
파라미터타입설명
bayBay경계 검사용 베이
blockslist[Block]삽입 시점에 이미 베이에 있는 블록들
new_blockBlock삽입하려는 블록. x, y, orient_idx 가 목표 위치로 설정되어 있어야 함
fastboolTrue이면 첫 번째 장애물 발견 즉시 반환 (존재 여부만 필요할 때)

list[EntryObstruction] — 장애물 없으면 []
베이 경계 위반 sentinel

  1. 베이 경계: new_block의 AABB가 베이 밖으로 나가지 않아야 함

솔버 사용 가이드
솔버가 새 배치 후보를 평가할 때 fast=True 옵션으로 feasibility 만 확인하고, 세부 진단이 필요할 때만 fast=False (기본)로 전체 목록을 수집한다.
check_exit
크레인이 target_block을 베이에서 들어올릴(EXIT) 때 장애물 여부를 검사. j≥k 상승 경로 규칙 적용. check_entry와 기하 동일.

이 함수가 푸는 문제: 블록을 꺼내려 할 때 위에 다른 블록이 얹혀 있거나 옆 블록의 상위 레이어가 경로를 막으면 크레인이 블록을 들어올릴 수 없다. "꺼내고 싶은데 경로가 막혀 나올 수 없다"는 상황을 잡는다. 기하 논리는 check_entry와 동일하며, blocks에 target_block 자신이 포함돼도 내부에서 자동으로 제외한다.

ENTRY op 키: type, block_id, bay_id, x, y, orient_idx
EXIT op 키: type, block_id, bay_id
시간 키는 정수형 문자열 (예: "100")

이 함수가 푸는 문제: 솔버가 만들어낸 솔루션 dict가 실제로 물리적으로 가능한지, 그리고 점수(목적함수 Z1+Z2+Z3)가 얼마인지를 한 번에 확인한다. 평가 서버가 이 함수 그대로를 사용하므로, 로컬에서 이 함수가 feasible=True를 반환해야 제출 점수가 나온다. feasible=False → 해당 인스턴스 점수 −1.

평가 서버 정본 — infeasible = 점수 −1
이 검사기는 평가 서버에서 그대로 실행된다. feasible=False이면 그 인스턴스 점수는 즉시 −1. 전체 R팀 중 평균 R/2 순위 손실과 같은 효과. 단 하나의 인스턴스도 infeasible을 내선 안 된다. Stage 1 위반(타이밍 오류, 중복 연산)도 동일하게 −1 처리된다.
5단계 검사 흐름 (단계별 상세)
단계별 조기 종료
첫 번째로 위반이 발생하는 단계에서 즉시 반환한다. 이후 단계는 평가되지 않는다. 반환된 stage 번호가 곧 가장 앞선 위반 단계이다.
1
할당 유효성 (Assignment Validity)
모든 블록이 ENTRY 1회 + EXIT 1회씩 정확히 등장해야 한다.
  • 중복 ENTRY 또는 중복 EXIT → 즉시 위반
  • 누락된 block_id → 위반
  • bay_id ∈ [0, n_bays), orient_idx ∈ [0, len(shape)) 범위 검사
  • entry_time ≥ release_time (1e-6 부동소수점 허용오차)
  • exit_time - entry_time ≥ processing_time (1e-6 허용오차)
Stage 1 상세
검사 입력
solution["operations"] dict 전체
실패 조건
block_id 중복 ENTRY/EXIT, 누락 block_id, bay_id 범위 초과, orient_idx 범위 초과, entry_time < release_time, exit_time−entry_time < processing_time
실패 반환
{"feasible": False, "stage": 1, "violations": ["Stage1: block X ..."], "objective": None, ...}
함정
시간 키는 정수형 문자열이어야 한다. int(_t_str)으로 변환 실패하면 Stage 1 위반 처리됨
2
크레인 진입 가능성 (Crane Entry Feasibility)
각 블록 ENTRY 시각 ai에 check_entry 호출.
co-present 조건: a_k ≤ ai < e_k (기존 블록의 퇴장 시각이 ai와 같으면 이미 나간 것 → 포함 안 함).
위반 메시지 예: Stage2: t=100: block 3 entry obstructed by block 7 (new_layer=0, exist_layer=1, kind=sweep, area=12.50)
Stage 2 상세
검사 입력
각 블록의 entry_time 시점 co-present 집합 (스냅숏)
co-present 조건
other["entry_time"] <= ai < other["exit_time"] — 퇴장 시각이 정확히 같으면 이미 나간 것
실패 조건
check_entry()가 빈 리스트가 아닌 것을 반환. 경계 초과(self-ref sentinel) 포함
함정
베이 경계 초과도 Stage 2 위반. existing_block.block_id == new_block.block_id이면 경계 초과 메시지 출력
3
크레인 퇴출 가능성 (Crane Exit Feasibility)
각 블록 EXIT 시각 ei에 check_exit 호출.
co-present 조건: a_k < ei < e_k (양쪽 strict; entry_time == ei인 블록은 아직 미도착).
target_block 자신은 항상 blocks에 포함되어야 하며, check_exit 내부에서 자동 제외된다.
Stage 3 상세
검사 입력
각 블록의 exit_time 시점 co-present 집합 + target 자신
co-present 조건
other["entry_time"] < ei < other["exit_time"] — 양쪽 모두 strict
Stage 2와 차이
Stage 2: entry_time <= ai (왼쪽 닫힘). Stage 3: entry_time < ei (양쪽 열림). 같은 시각에 동시 입출이면 Stage 3 에서 상대방이 co-present로 간주되지 않을 수 있음
4
공간 충돌 & 베이 경계 (Spatial Collision & Boundary)
4-a. bay.contains_block으로 모든 블록의 AABB 경계 검사.
4-b. 동일 베이에서 시간 구간이 겹치는([a_p,e_p) ∩ [a_q,e_q) ≠ ∅) 블록 쌍에 check_collisions 호출.
시간이 겹치지 않는 쌍은 Shapely 검사 자체를 생략한다.
Stage 4 상세
4-a 입력
각 Block의 bounding_rect() → Bay.contains_block()
4-b 시간 겹침
a_p < e_q and a_q < e_p (반개구간 모델). 겹치는 쌍만 Shapely 정밀 검사
함정
Stage 2/3를 통과했더라도 두 블록이 동시에 존재하면서 실제로 겹치면 Stage 4에서 잡힘. Stage 2/3는 크레인 경로 검사, Stage 4는 정적 공간 겹침 검사
5
순차 연산 가능성 (Sequential Operation Feasibility)
연산을 시간순 재현(replay). 베이별 bay_present 집합을 유지하며:
  1. 같은 시각에 EXIT가 ENTRY 뒤에 오면 위반 (EXIT → ENTRY 순서 강제)
  2. EXIT: 블록이 bay_present에 있어야 하고, check_exit 통과해야 함
  3. ENTRY: check_entry 통과해야 함; 성공 시 bay_present에 추가
Stage 2/3보다 동시 시각 내 순서 위반을 더 엄격하게 잡는다.
Stage 5 상세
동작 원리
operations dict를 시간순(int(t_str) 기준)으로 정렬해 replay. bay_present[bay_id] 집합으로 현재 베이 상태 추적
같은 시각 순서
EXIT 먼저, 그다음 ENTRY. 리스트에서 EXIT 뒤에 ENTRY가 먼저 나오면 위반. 솔루션 생성 시 같은 시각 ops를 EXIT→ENTRY 순으로 정렬해야 함
Stage 2/3와 차이
Stage 2/3는 "스냅숏" 방식(각 블록의 시각에 co-present 계산). Stage 5는 "순차 재현" 방식(EXIT 후 ENTRY, 순서 엄격). Stage 2/3 통과 후 Stage 5 실패 가능
함정
EXIT가 성공해야 bay_present에서 제거된다. EXIT 실패 시 bay_present는 그대로 — 이후 ENTRY가 막혀 연쇄 실패 가능
목적함수 계산 (5단계 모두 통과 시)
가중치 기본값
prob_info["weights"]가 없으면 w1 = w2 = w3 = 1.0 을 사용한다. 실제 대회 인스턴스는 가중치가 다를 수 있으므로 항상 인스턴스 dict를 확인할 것.
구성요소공식설명
obj1 (tardiness) Σ max(0, exit_time - due_date) 전체 지연 합계. due_date 는 block_data["due_date"]. 납기 전 퇴출이면 0 기여
obj2 (load balance) math.floor(max|u_j1·load_j1 - u_j2·load_j2|) 정규화 작업부하 불균형. u_j = avg_area / (W_j * H_j)
1개 베이면 0.0. math.floor 적용됨에 주의
obj3 (preference) Σ (S_i_max - S_i_bay) 선호도 편차 합계. S_i_max = max(bay_preferences). 가장 선호하는 베이에 배정하면 0 기여
objective w1·obj1 + w2·obj2 + w3·obj3 총 목적함수 값 (낮을수록 좋음)
obj1 = Σ_i max(0, exit_time_i - due_date_i) # 전체 지연 u_j = avg_bay_area / (W_j * H_j) # 베이 j 정규화 계수 obj2 = math.floor( max |u_j1 * load_j1 - u_j2 * load_j2| # 모든 베이 쌍 (j1≠j2) ) # n_bays==1 이면 0.0 obj3 = Σ_i (max_j bay_preferences_i[j] - bay_preferences_i[bay_id_i]) objective = w1*obj1 + w2*obj2 + w3*obj3
obj2 주의 — math.floor 적용
obj2에는 math.floor가 적용된다. 불균형이 3.9이면 obj2=3, 4.0이면 4. 솔버가 직접 불균형을 계산할 때 floor 없이 비교하면 미묘하게 다른 결론이 날 수 있다. 또한 workload는 block_data["workload"] 필드이며, 면적과는 다른 개념이다.
반환 dict 구조
키타입설명
feasiblebool5단계 모두 통과하면 True
stageint실패 단계 (1~5). 전체 통과 시 5 반환
violationslist[str]위반 설명 문자열 목록. 통과 시 []
objectivefloat | None총 목적함수 값. 불가능하면 None
obj1float | None지연(tardiness) 성분
obj2float | None작업부하 불균형 성분 (math.floor 적용됨)
obj3float | None베이 선호도 편차 성분

반환 dict 예시 — Feasible (실현가능)

{ "feasible": true, "stage": 5, "violations": [], "objective": 1247.5, "obj1": 820.0, // 전체 지연 합계 (Z1) "obj2": 312.0, // math.floor 적용된 불균형 (Z2) "obj3": 115.5 // 선호도 편차 합계 (Z3) }

반환 dict 예시 — Infeasible (Stage 2 실패)

{ "feasible": false, "stage": 2, "violations": [ "Stage2: t=100: block 3 entry obstructed by block 7 (new_layer=0, exist_layer=1, kind=sweep, area=12.500)" ], "objective": null, "obj1": null, "obj2": null, "obj3": null }
점수 모델과의 연결
평가 서버는 feasible=False이면 score = -1을 부여한다. 한 인스턴스의 -1은 평균 R/2점 손실과 동일한 효과. Stage 1 위반(중복 연산, 타이밍 오류)도 infeasible = -1 처리된다. 솔버 개발 시 Stage 1 → 2 → 3 순서로 먼저 안정화하는 것이 유리하다.
Stage 2 vs Stage 5 차이
Stage 2/3는 각 블록 기준으로 co-present 집합을 스냅숏 계산한다. Stage 5는 시간순 재현으로 동일 시각 내 ENTRY/EXIT 순서 위반을 추가로 잡는다. Stage 2/3를 통과해도 Stage 5에서 실패할 수 있다. (솔루션 생성 시 EXIT→ENTRY 순서 보장 필요)
솔버 개발 우선순위 가이드
  1. Stage 1부터 안정화 — 모든 블록 ENTRY+EXIT 쌍, 타이밍 제약(release/processing) 먼저
  2. Stage 2/3 — check_entry/check_exit 통과. 크레인 j≥k 규칙이 핵심
  3. Stage 5 — 같은 시각 ops를 EXIT→ENTRY 순으로 정렬
  4. Stage 4 — 공간 충돌. Stage 2/3가 통과했다면 보통 통과됨
  5. feasible 확정 후 obj1(tardiness), obj3(preference) 최적화
