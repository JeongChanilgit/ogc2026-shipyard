1. 문제와 목적함수

각 블록에 대해 ① 베이 j · ② 위치 (x,y) · ③ 방향 o · ④ ENTRY 시각 · ⑤ EXIT 시각을 동시에 결정한다. 목적은 가중합 min w1·Z1 + w2·Z2 + w3·Z3 의 최소화이며, 본 작업은 Z1(총 지연, tardiness) 에 집중했다.

Z1 = Σ max(0, EXIT − due). 핵심 제약은 크레인 수직 접근(j≥k): 두 블록의 footprint 가 겹치면 충돌(clear-above) — 즉 footprint 가 겹치는 블록은 같은 시각에 공존할 수 없다.

결정적 사실(측정): 20개 인스턴스 전부 Σ max(0, release+processing−due)=0 — 단 한 블록도 본질적으로 지연되지 않는다. 따라서 관측되는 모든 Z1 은 크레인 직렬화 + 2D 패킹 단편화로 유발된 것이고, Z1<20 은 원리상 모든 인스턴스에서 달성 가능하다. 이 통찰이 전략의 토대가 됐다.

2. 알고리즘 파이프라인

모든 단계는 공식 체커 게이트를 통과해야 채택된다 → 최종해는 절대 floor 보다 나빠지지 않는다(objective-safe). 인스턴스별 분기는 0개이며, alpha/order 등은 런타임 best-of(게이트가 인스턴스마다 최적 선택)라 미지의 인스턴스에 그대로 일반화된다.

A
베이스라인 (Greedy)
EDD 순서 + Best-Fit 배치 + 크레인-안전 디코드(완전 retroactive 검사)로 보장된 feasible floor 를 만든다. 이후 모든 개선은 이 위에서만 진행 — 절대 −1(실패)이 나올 수 없다.
B
탐색 (Parallel Multistart + ALNS)
4코어 병렬 multistart + ALNS(destroy/repair, SA accept-worse)로 베이 배정을 탐색한다. 한 move 가 건드린 베이만 재디코드. 좋은 배정(시작점)을 제공.
C1
cum_level — 수요 평탄화 재디코드
베이마다 cumulative CP-SAT(footprint 면적을 자원으로)로 지연-최소 ENTRY 타깃을 구해, effective release = max(release, target) 로 재디코드한다. 여유(slack)를 써서 release 시점에 몰리는 수요를 시간축으로 분산. multi-alpha(90/85/80) × multi-order best-of.
C2
cpsat_timing — 최적 크레인 타이밍
고정 레이아웃에서 베이별 최적 crane-feasible ENTRY/EXIT 를 CP-SAT 로 푼다(exit=entry+P 가 WLOG-최적, crane precedence 는 time-independent 5불리언). x/y/orient/bay 불변 → Z2/Z3 불변, Z1만↓.
C3
bbox_pack — 결합 2D 패킹 솔버 핵심 돌파
베이마다 2D CP-SAT: 각 블록의 (x,y)+ENTRY 를 골라 시간이 겹치면 footprint 가 disjoint 가 되게 한다(=충돌·크레인 동시제거). 공간과 due-date 여유를 동시에 최적화 — greedy 가 단편화하던 걸 정확히 푼다. bbox-보수적(bbox-disjoint⟹polygon-disjoint)이라 공식 체커 통과 보장. 측정: prob_15 Z1 149→2 (3.7s).
C4
crossbay_relocate (bbox-aware) — 과부하 베이 해소 핵심 돌파
과부하 베이의 tardy 블록을 덜 붐비는 베이로 이동하되, 각 이동을 bbox_pack 으로 평가한다 — 옮긴 블록이 빈 베이에서 on-time 으로 착지하는지 정확히 본다(greedy 평가는 이를 tardy 로 오판해 거부했음). 출발 베이는 블록 제거만(재디코드 불필요) → 빠름. 측정: prob_20 65→12.
C5
bbox_pack2 — 이동 후 재패킹
cross-bay 가 과부하 베이를 비운 뒤, 2차 bbox_pack 으로 균형 잡힌 배정을 다시 최적 패킹. 둘이 함께라야 154% 과부하 베이(prob_20 bay1)가 풀린다.
C6
cheaper steps — 값싼 정리
exit_pull(EXIT 당기기) · reschedule · shift · tardy_redecode · single_move. 남은 자투리 개선을 빠르게 긁어모은다.
D
게이트 (공식 체커)
모든 후보는 check_feasibility 를 통과하고 objective 가 엄밀히 개선될 때만 채택된다. 어떤 레버도 최종해를 악화시킬 수 없음(objective-safe).

3. 4단계 돌파 (진단 주도)

5. 시간 분석 — 읽는 법

cum_level 이 시간의 다수를 차지

후처리 예산의 대부분을 cum_level 이 쓴다(예: prob_9 196s, prob_17 193s, prob_13 188s). multi-alpha × multi-order best-of 가 베이마다 여러 번 재디코드하기 때문 — 가장 비싼 대신 3→14 의 토대.

bbox_pack 은 하드 인스턴스에 집중

tardy 베이가 많은 인스턴스에서 크게 쓰임(prob_13 80s, prob_11 54s, prob_9 26s). 쉬운(Z1=0) 인스턴스는 tardy 베이가 없어 거의 0초(no-op).

cross-bay 는 작지만 결정적

대부분 0~5초지만 prob_20 에서 14.9초 — 154% 과부하 bay1 을 비워 231→9~14 로 끌어내린 마지막 열쇠. cpsat_timing 은 어디서나 1초 미만(매우 빠름).

큰 인스턴스 = 시간 의존

prob_14/20(250·300블록)은 full budget(≈296s)을 다 쓴다. 120초로 줄이면 이 둘만 >20 — eval 은 큰 인스턴스에 더 주므로(수분~30분) 안전. 18/20 은 120초 내 crack.
