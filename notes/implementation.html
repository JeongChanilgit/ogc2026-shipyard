한 줄 요약

Layer 1(배정)이 Z2·Z3를 closed-form으로 확정하고, Layer 2(베이별 디코더)가 베이스라인의 검증된 크레인 프리미티브를 재사용해 Z1+feasibility만 푼다. 그 사이를 배정-레벨 hill-climb이 봉합한다 — 픽셀이 아니라 어느 블록을 어느 베이에 수준에서만 탐색하므로 한 수가 닿은 2개 베이만 재디코드하면 된다.

예시 인스턴스에서 베이스라인 1,055.73 → 1,022.70 (feasible, Z1=0). 스모크 3/3 통과.

│                       ③ 최선호-베이 배정(w3 지배 대비).  각 seed를 디코드해 best 선택.

핵심 설계 결정 — "베이스라인 위에 얹는다". 새 패킹 엔진을 처음부터 다시 짜지 않았다. 베이스라인의 검증된 크레인 프리미티브 (_candidate_positions, _find_earliest_slot, _empty_bay_entry)를 그대로 재사용해 베이별 디코더를 만들고, 베이스라인이 못 하던 배정 재고려를 그 위에 올렸다. 그래서 최악의 경우라도 결과는 베이스라인과 동일 — 절대 후퇴 없음.

Z1만 기하/시각 결합

feasibility = 베이별 독립
Stage 2–5 모두 베이 단위 검사, cross-bay 결합 0. → 베이 = 독립 단일-크레인 셀. 독립 디코드·캐시·(미래)병렬 정당화. utils.py:1168/1208/1235/1289
그래서 한 수가 싸다. 블록 하나를 bay j→k로 옮기면 — Z2/Z3는 부하·선호만 더하고 빼면 끝(closed-form), 재디코드가 필요한 기하는 j와 k 두 베이뿐. 나머지 베이는 손대지 않는다. 이것이 "수천 번 픽셀 repair"가 아닌 "수천 번 조합 이동"의 정체.

06

−1 회피 체크리스트

점수 모델: infeasible/timeout/crash = −1 (평균 R/2 손실). feasible = R−nb. 동점=만점.

  • 3중 바닥. trivial(빈-창 force-place, 구조적 feasible) → baseline(검증됨) → search. 셋 중 통과+최소값.
  • never-worse-than-baseline. baseline 후보를 항상 평가에 포함 → 탐색이 실패해도 결과는 ≥ baseline 품질.
  • 타임가드 0.85. timelimit×0.85에 탐색 중단 → 남은 15%로 조립 + O(n²) check_feasibility 여유. 벽시계 초과 = 서버 타임아웃 = −1 이라 보수적.
  • 전면 try/except. CP-SAT·디코더·탐색 각각 격리. 어디서 터져도 이미 확보한 바닥을 반환.
  • defer-not-fail. 겹치는 슬롯이 없으면 ENTRY를 빈-창으로 미뤄서라도 feasible (Z1 커도 −1보다 낫다).
  • 반환 전 게이트. 공식 check_feasibility로 최종 확인한 해만 내보냄.
  • 네트워크 0 · 상용솔버 0. firejail 무인터넷에서 안전(외부 호출 0). 상용 솔버(Gurobi/Xpress)는 서버에 제공되지만 의식적으로 안 씀 — 라이선스/네트워크 변수 제거. OR-Tools(CP-SAT)만 옵션 사용, 없거나 실패해도 휴리스틱으로 진행.
07

다음 단계 (v2 후보)

우선순위 순 — 모두 "더 빠르게/더 깊게", feasibility 위협 없음.

  • swap + 다중-블록 destroy/repair 이동 추가 — 2-베이 이상에서 hill-climb 탈출력 강화 (진짜 ALNS).
  • 명시적 no-good cut 루프 — Layer 2가 "이 블록셋은 이 베이에 동시 수용 불가" 인증서를 내면 CP-SAT에 cut 주입·재해결.
  • suffix-OR 비트마스크 크레인 커널(NumPy) — 대형 인스턴스 디코드 throughput. 현재 Shapely 기반 검사가 병목이면 교체.
  • 4코어 병렬 디코드 — 베이 독립성을 multiprocessing으로 실현 (피클링 안전 확인 후).
  • 베이별 Z1 정밀화 — 블록 수 적은 베이는 단일머신 tardiness를 CP-SAT로 거의 최적.
  • 레짐 라우팅 명시화 — w1:w2:w3·밀도·n 읽고 탐색 예산/모드 분기.
