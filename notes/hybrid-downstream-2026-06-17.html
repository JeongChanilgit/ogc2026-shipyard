린 레거시 "뒤" — 하이브리드 다운스트림 분해

OGC2026 · algorithm(prob_info, timelimit) 엔트리 (myalgorithm.py:7575-7835) · 2026-06-17 · code-analyzer 정밀분석
한 줄 요약: 레거시(린이든 풀이든)는 후보 하나일 뿐. 그 뒤 algorithm()은 순수 additive best-of 오케스트레이터 — box·gassign·perbay 후보를 얹고 전부 공식 채점기 obj로 비교해 strict-better일 때만 교체. 수학적으로 regression-free + never−1(레거시가 항상 살아남음).

★ 결정적 발견 — 예산은 사전 고정 슬라이스다

제가 이전에 "린 레거시가 48s에 끝나면 남는 ~82s가 box/gassign로 흘러간다"고 했는데 — 순차 경로에선 그런 산식이 없습니다.

  • box·gassign 예산은 timelimit에서 미리 떼어둔 고정 슬라이스(reserve, _gassign_budget). 레거시가 빨리 끝나도 안 커진다.
  • 남는 wall(leftover)을 먹는 건 perbay 하나뿐(작은 polish, −4.6%급).
  • 즉 린 레거시로 floor를 적출해도 그 시간은 box/gassign 품질로 전환되지 않는다 — perbay로만 가거나 낭비.

함의: 린의 freed time을 쓰려면 둘 중 하나 — (A) 동적 예산 재배분(레거시 조기 종료 → box/gassign 슬라이스 확대, 미구현 아키텍처 레버) 또는 (B) 병렬(코어 분할로 FALSIFIED). 그래서 린-as-legacy의 가치는 "속도 전환"이 아니라 그 자체가 z3-탁월 후보라는 점에 한정된다.

3. ★ best-of 선택 — 전부 진짜 obj, regression-free

② box candidate CP-SAT 기본 ON (T≥100)

역할: box-decomp 전결정 CP-SAT 해. 패킹-heavy 주력 승자. 모듈: boxsolver.algorithm :7748. 실행 전 OGC_BOXDECOMP=1, OGC_FEASSPILL=0 세팅.

② gassign candidate CP-SATLBBD T≥200에서만

역할: z1-aware 배정 마스터 + per-bay 디코드 + no-good 컷(depgroup 기본 ON). 모듈: gassign.algorithm :7767. 운영 TL=120에선 비활성.

③ perbay candidate CP-SAT 기본 ON

역할: best 후보 채택 후 per-bay placement polish(joint). 모듈: perbay.improve :7801. 예산 = T − elapsed − min(8,0.06T) = 순수 leftover wall(≥4s). 개선 없으면 동일 객체 반환→스킵. additive·deadline-bound·strict-improve → −1 위험 0.

5. 병렬 블록 :7710-7737 OGC_PARALLEL_CANDS 기본 OFF · FALSIFIED

  • 게이트: OGC_PARALLEL_CANDS ∧ reserve≥20. 후보 ["box"](+gassign on이면 추가).
  • par_budget = T − elapsed − pb_keep − par_overhead (pb_keep=min(22,0.08T), par_overhead=min(12,0.05T)+6) → box·gassign이 leftover wall 전체를 동시에 받음(병렬).
  • 워커: parcand.run_parallel_candidates(..., OGC_PARALLEL_WORKERS=2) — spawn 프로세스, 각 CP-SAT 2워커(4코어 비-oversub). par obj도 워커 내부 check_feasibility 진짜 obj.
  • 성공 시 _parallel_done=True → 순차 box·gassign 스킵. 실패/timeout/크래시 → [] 반환 → legacy 유지(never−1).
FALSIFIED (2026-06-17): 대표 4문제 재측정 결과 banked best-of 대비 3/4 퇴화(prob_38 +29M, prob_39 +5.6M, prob_27 +3.5M; prob_29만 −1.35M). 원인 = 병렬이 코어를 나눠 box·gassign 각자 2워커로 굶음. → KILL. 고정 풀-코어 standalone best-of(290M)가 더 낫다.

6. 계측 · return :7812-7835

계측(OGC_STAGE_TIMING ON): _stage_timer(후보별 wall) + _stage_obj(채택 순간 before/after/delta) → stderr [HYBRID_TIMING]/[HYBRID_OBJ] JSON flush. 레거시 내부는 별도 [STAGE_TIMING]로 flush.

return :7835: return sol — 최신 incumbent. 명시적 마지막 가드는 없으나 모든 교체가 feasible-gated라 항상 feasible. (진단 경로 OGC_BOX_ONLY는 별도 early-return.)

7. 이 분해가 주는 함의

  1. best-of는 안전판이다 — 공식 채점기 obj 기반 strict-better라 어떤 후보를 추가해도 regression 0, never−1. 새 후보/레버를 마음껏 additive로 붙일 수 있다.
  2. 운영 TL=120 현실: gassign OFF → 실제 제출은 legacy+box+perbay. gassign/depgroup/z3-spill 컷은 T≥200 (set2 서버 TL)에서만 의미. set1(T=120)에선 legacy+box가 전부.
  3. "floor 적출 → box에 시간" 은 거짓(고정 슬라이스). 린의 freed time은 perbay로만 흐름. 린-as-legacy의 진짜 가치 = z3-탁월 후보 자체(best-of로 흡수), 속도 전환 아님.
  4. 벤더스 컷 환류 레버는 여전히 유효 — 그건 다운스트림(예산)이 아니라 후보 내부(③→① 루프) 문제라, 예산 구조와 무관하게 후보 품질을 올림.
