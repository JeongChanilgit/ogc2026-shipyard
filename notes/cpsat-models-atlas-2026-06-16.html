▸한눈에 — CP-SAT 5계열 스펙트럼

CP-SAT가 tractable한 이유는 단 하나 — 정확한 2D 기하 non-overlap을 결정 변수로 두지 않을 때다. ①은 기하가 아예 없고, ②는 기하를 상수로 빼냈고, ③은 기하를 면적으로 완화했다. ④·⑤는 위치를 변수로 넣어 정확 non-overlap을 강제하는 순간 — 그래서 멤버 캡·npairs 캡·게이트로 묶여 있고, 작은 베이에서만 켜진다.

▸먼저 알 것 — 모든 모델이 쓰는 제약 idiom 5종

14개 모델은 사실 아래 5개의 제약 패턴을 조합한 것이다. 이걸 알면 각 모델이 한눈에 읽힌다.

idiom 1 · 배정 유일성 (Σ=1)

# 블록 b는 정확히 1개 베이에
model.Add(sum(x[b, j] for j in feasible_bays[b]) == 1)

idiom 2 · min–max 불균형 (z2)

# 베이별 가중 부하의 최대-최소 = workload imbalance
model.AddMaxEquality(hi, wl);  model.AddMinEquality(lo, wl)
model.Add(z2 == hi - lo)

idiom 3 · half-reified disjunction (분리 OR)

# "이 조건 OR 저 조건" — 충돌 회피의 핵심. 시간·공간 모두 이 형태
model.Add(ax <= be).OnlyEnforceIf(l1)    # a가 b보다 먼저 끝나거나
model.Add(bx <= ae).OnlyEnforceIf(l2)    # b가 a보다 먼저 끝나거나
model.AddBoolOr([l1, l2])                # 둘 중 하나는 참이어야

idiom 4 · cumulative (면적-용량 완화)

# 같은 시각에 베이 안 블록 면적 합 ≤ 베이 면적. 정확 위치는 안 봄(완화)
model.AddCumulative(intervals, demands, capacity)
# interval = [entry, entry+P], demand = bbox 면적, capacity = W·H·alpha

idiom 5 · tardiness + warm-start hint

model.Add(td[b] >= entry[b] + P[b] - D[b])   # td≥0 도메인이라 max(0,·)
model.AddHint(entry[b], current_entry[b])     # 현재 해를 시드로 (feasible)
model.Minimize(sum(td))

공통 솔버 설정: num_search_workers=4(메인 모델)~1(packing), max_time_in_seconds=베이별 예산 분배, OGC_DEV_DET(기본 OFF→비결정성), 항상 공식 checker consider() 게이트 통과해야 채택.

①배정 (Assignment) — 기하 없는 0-1, CP-SAT의 안방

블록을 어느 베이에 넣을지만 정한다. 위치·시간·충돌을 전혀 모델링하지 않아 순수 0-1 ILP다. 가장 가볍고 항상 잘 풀린다. 단, z1(tardiness)을 모름 → "realize barrier"의 근원: 낮은 z3 배정이 z1=0으로 실현되지 않는 이유.

②타이밍 오라클 — 고정 layout 위 1D disjunctive (주력)

③Cumulative 완화 — 면적을 용량으로, 정확 위치는 포기

정확한 2D non-overlap을 풀면 폭발하므로, "같은 시각 블록 면적 합 ≤ 베이 면적"이라는 완화(relaxation)로 바꾼다. AddCumulative는 CP-SAT가 강하게 전파하는 전역 제약이라 tractable. 출력은 위치가 아니라 entry 시각 타깃이며, 이후 그리디가 그 타깃에 맞춰 재디코드한다. 이 계열이 가장 많다(6개).

▸운영 활성 정리 & 주의

✅ 운영 경로에서 실제로 도는 CP-SAT
① 배정(_cpsat_assignment, seed) · ② 타이밍 오라클(주력, z1을 가장 크게 깎음) · ③ cumulative entry-target(OGC_CUMLEVEL 기본 ON) · ④ _bbox_pack_bay(OGC_BBOX_PACK 기본 ON) · ④ box-decomp(OGC_HYBRID로 best-of 합류, set2 픽스 후 TL≥100에서 ON).
⚠️ dormant / 옵션 / 우회로 (운영에서 안 돌거나 조건부)
  • 배정 모델의 area-cap·count-cap: 라이브 호출에서 인자 None → 비활성 myalgorithm.py:5750,7088
  • _temporal_reassign_redecode_verified(⑤): 호출처·게이트 미발견 → dormant 가능
  • pack_bay_cp(⑤ exact box packer): CLAUDE.md 반증 레버. uconstruct cppack 모드에서만 호출, HYBRID default 경로 활성 여부 미확인
  • OGC_TIMING_DECOMP·OGC_BD_Z1ZERO·OGC_CUMLEVEL_PARALLEL·OGC_GUROBI_TIMING·OGC_CPSAT_FIRST: 전부 기본 OFF
🔥 큰 그림 (이 아틀라스의 결론)
14개 모델이지만 정작 obj를 크게 줄이는 건 ②(타이밍)와 ③(cumulative 완화) — 둘 다 정확한 2D 위치를 안 푼다. 위치를 변수로 넣는 ④·⑤는 멤버 캡·npairs 캡·dormant로 묶여 작은 베이에서만 마진 이득(box-decomp가 prob_3/4/18). 즉 "CP-SAT가 강하다"는 인상은 정확히 기하를 변수에서 빼낸 모델들이 만든 것이고, 패킹 밀도 갭(80%→95%)을 메우려면 CP-SAT를 더 넣는 게 아니라 전용 2D nesting이 필요하다(직전 설명서 §7).
