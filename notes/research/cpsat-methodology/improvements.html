우리 솔버에 적용할 CP-SAT 개선 제안

현재 솔버(src/myalgorithm.py 하이브리드 + 실험용 cp-sat/ LBBD)의 CP-SAT 사용을 5개 분석 에이전트로 감사하고, 12-페이지 방법론 리서치와 교차 대조해 도출한 구체 제안. 모든 제안은 실제 코드 위치(file:line)·근거 페이지·never−1 안전성을 명시한다.

먼저, 정직한 판정 (헛다리 방지)

감사 결과 현재 타이밍 오라클의 목적함수 인코딩과 가중치 스케일링은 이미 교과서적이다(tardiness를 t >= end−due, t>=0 하한 부등식으로, master는 grader 일치 정수 스케일). 즉 "CP-SAT 모델링을 고쳐 set1 <1,000,000을 뚫는다"는 길은 없다. 캘리브레이션상 <1M의 바인딩 제약은 per-bay 패킹 밀도이고, 그 밀도 레버는 속도에 묶여 있다(dense placer는 ~2배 느려 T120/4코어에서 net-negative). 따라서 아래 CP-SAT 제안의 진짜 가치는 두 가지다:

  • 속도를 벌어준다 — 더 강한 propagator·조기중단·결정성으로 같은 z1을 더 적은 시간에 → 남는 예산을 dense packer/LNS에 → 밀도(z3) 소폭 개선.
  • −1을 막는다 — set2 제출 안전. 각 −1 회피 ≈ +R/2 = 단일 최대 점수 레버. ALL40 제출 전 최우선.

밀도 천장 자체를 올리는 건 CP-SAT 튜닝이 아니라 직교 방법론(semi-discrete BLF·ROMA, 맨 아래 §방법론)이다 — 재구현 과제이므로 명확히 구분해 둔다.

A. CP-SAT 모델링 강화 (propagator를 제대로 쓰자)

P1

A1 · 타이밍 오라클: 수동 BoolOr 충돌 disjunction → AddNoOverlap

현재 myalgorithm.py:2830–2874 — 블록당 entry 정수변수 1개(e[b]), exit=e[b]+P. 충돌·진입·퇴출을 쌍마다 half-reified AddBoolOr로 인코딩(O(n²) bool var). NewIntervalVar/AddNoOverlap 미사용.
근거 03 스케줄링 11 성능 — AddNoOverlap은 전용 disjunctive propagator(Theta-tree/edge-finding)를 써서, 동일 모델을 일반 선형 disjunction보다 훨씬 강하게 가지친다. big-M은 LP 완화가 약하다(안티패턴).
제안 충돌쌍의 시간 비겹침(ax<=be OR bx<=ae = 정확히 1-D disjunctive)을 베이별 AddNoOverlap으로 대체. 크레인 entry/exit 비대칭 금지는 NoOverlap으로 안 잡히므로 그 부분만 기존 BoolOr 유지(하이브리드).
# before: pairwise time disjoint (collision)
m.AddBoolOr([a_before_b, b_before_a])  # O(n^2) literals
# after: one interval per block, one disjunctive propagator per bay
iv = {b: m.NewIntervalVar(e[b], P[b], e[b]+P[b], f"iv_{b}") for b in colliding}
m.AddNoOverlap([iv[b] for b in colliding])   # Theta-tree edge-finding
효과 혼잡 베이(prob_14/20)에서 동일 z1을 더 빨리 → 예산 절약(속도 리프레임 정조준). 위험 중간 — 크레인 비대칭 제약과의 정합 검증 필요. 안전 OGC_ORACLE_NOOVERLAP 게이트 + full-set A/B, 채택은 총 obj 무회귀 시에만.
P2

A2 · box-decomp 패킹: 6-way big-M → AddNoOverlap2D

현재 boxsolver.py:545–556 (_pack_bay_boxdecomp, production) — 블록쌍마다 6개 BoolVar(좌/우/상/하 + 시간전/후) + AddBoolOr. footprint를 ≤K(=2) rect로 분해(:472)하면서도 AddNoOverlap2D는 안 씀.
근거 04 패킹 08 유효부등식 — K-rect 분해는 정확히 2D interval 쌍으로 표현 가능하고, AddNoOverlap2D는 전용 2D propagator로 훨씬 강하게 prune. orient는 이미 그리디 L0에서 고정(:519)되어 있어 joint 폭발 위험 없음.
x_iv = m.NewIntervalVar(tx[b], w[b], tx[b]+w[b], ...)   # per rect
y_iv = m.NewIntervalVar(ty[b], h[b], ty[b]+h[b], ...)
m.AddNoOverlap2D(x_ivs, y_ivs)   # replaces n^2 big-M space-disjunctions
# 시간축 분리(공존)는 기존 time-before/after BoolOr 유지 → 공간은 NoOverlap2D
효과 같은 예산에서 더 조밀/빠른 패킹(box가 이기는 prob_3/4/18 강화 가능). 위험 중간 — 공간/시간 disjunction 분리 재구성 필요. 안전 OGC_BD_NOOVERLAP2D 게이트, best-of로 감싸 회귀 0.
P1

A3 · area-cumulative redundant 제약을 모든 패킹 모델로 확대

현재 boxsolver.py:533–540 — box-decomp에만 면적 누적 하한(AddCumulative, OGC_BD_CUMUL 기본 ON)이 있다. _pack_bay_cpsat·baypack_cp.pack_bay_cp에는 없음.
근거 08 유효부등식 — "동시 공존 블록 면적합 ≤ 베이 면적"은 redundant지만 energetic propagator가 일찍 가지친다(LP 완화 강화). 거의 공짜.
제안 동일한 area-cumulative 하한 블록을 _pack_bay_cpsat과 timing 오라클(공존 면적 기반 z1 floor 추정)에도 추가. 헬퍼로 추출해 1곳에서 관리.
효과 가지치기 → 속도. 위험 낮음(redundant라 정확성 영향 없음). 안전 ✓.
P2

A4 · 동일 형상·동일 마감 블록 대칭 깨기 (lex 순서)

현재 패킹·타이밍 모델 어디에도 대칭 깨기 없음(감사: symmetry/AddDecisionStrategy grep no-match). 동일 dims·동일 due 블록이 서로 자리를 바꾸는 대칭이 탐색을 폭발.
근거 08 대칭 — 동일 객체에 위치/순서 lex 제약을 부과하면 disjunction의 절반을 제거. CP-SAT symmetry_level도 켜져 있는지 확인.
# identical (w,h,due) blocks i,j with i<j: fix an order to kill the swap symmetry
m.Add(tx[i]*BIG + ty[i] <= tx[j]*BIG + ty[j])   # lex on position
# entry-time tie: m.Add(e[i] <= e[j]) for identical-due identical-shape pairs
효과 대형 베이(prob_29 116블록류)에서 큼. 위험 중간 — 진짜 동일 블록에만(아니면 최적해 배제). 수동 SBP와 symmetry_level=2 충돌 주의(둘 중 하나). 안전 동일성 판정 엄격 + full-set A/B.

P0

B4 · algorithm() 말단에 serial-floor 최종 안전바닥

현재 myalgorithm.py:7575 algorithm()은 모든 후보를 try/except+공식 checker로 감싸 견고하지만, "legacy가 항상 feasible을 반환한다"는 가정에 의존한다. legacy가 set2에서 타임아웃/infeasible이면 → −1 직행. cp-sat/solver.py:72–99의 serial_floor(항상 feasible)는 src/ 경로엔 미적용.
근거 11 성능 (never−1) + 캘리브레이션: 각 −1 ≈ −R/2 = 단일 최대 점수 레버. set2는 경쟁자도 z1>0 → −1 회피가 set2의 핵심.
제안 cp-sat/solver.py의 serial_floor(선호 베이 BL 배치 + 베이 내 EDD 직렬화, 크레인 제약 자동 만족)를 src/로 포팅해 algorithm() 반환 직전 무조건 한 번 더 안전망으로 둔다: 현재 best가 비검증/None이면 serial-floor로 대체.
sol = best_candidate  # from best-of chain
if sol is None or not _verify(sol):
    sol = serial_floor(prob_info)   # always feasible, EDD per bay
return sol
효과 ALL40 제출에서 −1 구조적 차단. 위험 낮음(순수 추가). 안전 ✓ 강화 — 이게 핵심 목적.
P0

B1 · max_deterministic_time 보조 캡 + seed 정책 통일

현재 제출 경로 타이밍 오라클은 random_seed 미고정(_dev_det 기본 OFF, :208–211) + wall-clock max_time_in_seconds만 사용 → 4-worker race로 ±13~20% 변동(prob_20 변동·±130K 노이즈의 직접 원인). seed가 코드마다 제각각(1/12345/20260611/20260616).
근거 06 파라미터 — 재현성은 random_seed + max_deterministic_time(wall이 아닌 결정적 시간 단위)로 얻는다. 멀티워커는 seed만으론 완전 결정 안 되지만, deterministic-time 캡은 타임아웃을 재현 가능하게 만들어 set2 −1 race를 줄인다.
제안 (1) 모든 call-site에서 random_seed 고정(공유 헬퍼). (2) 제출 후보의 최종 solve에 max_deterministic_time을 보조 캡으로 추가(wall 캡은 유지). 처리량을 위해 num_workers=4는 유지하되, 변동 기반 잘못된 채택을 막는 건 기존 within-run diag 규칙으로.
효과 타임아웃 재현성↑ → set2 −1 위험↓, run-to-run 노이즈↓. 위험 낮음. 안전 ✓.
P0

B2 · per-bay 시간예산을 난이도 비례로

현재 myalgorithm.py:2665 — per_bay = total_budget / len(work) 균등분할. 큰 component를 가진 어려운 베이가 작은 베이와 같은 시간 → 어려운 베이 timeout(z1 잔존), 쉬운 베이 시간 낭비. 난이도 비례인 decomp 경로(:2817)는 기본 OFF.
근거 09 분해 06 파라미터 — 예산은 서브문제 난이도(블록 수/충돌쌍 수)에 비례 배분이 정석.
weight[bay] = n_blocks[bay] + alpha * n_collision_pairs[bay]
per_bay[bay] = total_budget * weight[bay] / sum(weight)   # 하한/상한 클램프
효과 같은 총예산에서 어려운 베이 z1↓(set1 prob_14/20, set2 혼잡). 위험 낮음. 안전 ✓ — 총예산 불변, deadline 가드 유지.

B3 · 공유 CP-SAT 파라미터 헬퍼 + box workers 1→4

현재 num_workers가 call-site마다 1/2/4 제각각, log_search_progress는 코드 전체에 0곳. 특히 boxsolver.py:390 OGC_BD_WORKERS 기본 1 — box가 순차 best-of에서 단독으로 36~80s를 쓰는데 4코어 중 1코어만 사용(underutilize).

제안 configure_solver(solver, *, wall, det=None, workers=4, seed=FIXED) 헬퍼 1개로 통일. box는 순차 슬라이스에서 단독이므로 workers=4로(병렬 parcand 경로일 때만 2로 축소). log_search_progress는 진단 env에서만 ON.

C. 웜스타트 · 조기중단 · 잠든 LNS 깨우기

P1

C3 · z1=0 도달 즉시 조기중단 (헬퍼가 이미 있는데 미연결)

현재 타이밍 오라클은 z1=0(베이 floor에서 globally optimal)을 찾고도 OPTIMAL 증명에 슬라이스를 다 쓸 수 있다. myalgorithm.py:680에 _zero_obj_stopper 콜백 헬퍼가 이미 존재하지만 이 오라클엔 미연결(다른 함수만 사용).
근거 07 콜백 — CpSolverSolutionCallback로 목적값 0(또는 known-LB) 도달 시 StopSearch(). 증명에 쓰던 시간을 회수.
제안 per-bay solve에 solver.Solve(m, _zero_obj_stopper(lb=bay_tardiness_lb))로 콜백 연결. LB는 이미 _bay_tardiness_lb로 계산 중.
효과 회수한 예산을 어려운 베이/dense packer/LNS에 재투입(속도 리프레임 직격). 위험 낮음(이미 검증된 헬퍼). 안전 ✓.

C2 · 죽은 lns.py(time-shift destroy)를 best-of 체인에 게이트 배선

현재 src/lns.py(45KB)는 완전 dead code — myalgorithm.py에서 import조차 안 됨(grep 0건). 내부에 ALNS 룰렛 + 4 이웃, 특히 #3 TIME-SHIFT removal(tardy 블록 + 그 desired-earlier 윈도우 점유 블록 동시 제거 = 그리디가 못하는 backtracking)이 구현돼 있다.
근거 09 LNS + 메모리: time-shift destroy는 "그리디가 못하는 backtracking = 거의 유일한 z1 레버"로 평가됨. assignment/위치 고정 → Z2/Z3 불변, Z1만 스코프.
제안 perbay와 동일한 best-of 컨트랙트로 OGC_LNS 게이트 하에 체인(myalgorithm.py:7785 부근)에 배선. 혼잡 베이(prob_14/20)에 한정, 시간 남을 때만. CP-SAT 오라클을 LNS의 재최적화 엔진으로 재사용.
효과 혼잡 베이 z1 추가 감소(CP-SAT 로컬 옵티멈 탈출). 위험 중간(dead code 검증 필요). 안전 ✓ 게이트 + best-of + checker.
P2

C1 · LNS 반복 간 hint 이월 (현재는 단발 시드뿐)

현재 myalgorithm.py:2882–2883 — 각 오라클 호출은 그 베이의 현재 entry만 AddHint. 호출부(uconstruct/rebuild/z3race)는 deadline만 바꿔 재호출 → 반복 간 누적 웜스타트 없음.
근거 07 힌트·증분 — CP-SAT는 진정한 증분 풀이 미지원 → 직전 채택 해를 다음 subproblem hint로 이월하는 것이 유일한 실질 웜스타트. LNS 루프에서 첫 feasible 도달 단축.
제안 C2의 LNS 루프와 함께, 직전 라운드 accepted 해를 다음 라운드 모든 자유변수의 hint로 전달.
효과 반복 수렴 가속(속도). 위험 중간(C2 의존). 안전 ✓.

D. LBBD 컷 강화 (cp-sat/ 실험 솔버를 진지하게 키울 경우)

전제

cp-sat/ 폴더는 전결정 CP-SAT LBBD 솔버로, 현재 src/ 하이브리드에 미달(대형은 패킹밀도벽으로 Z1 지배). 아래는 "이 솔버를 경쟁력 있게 키운다"는 결정을 했을 때의 로드맵 — 감사상 컷이 결정적으로 약하다(가장 큰 레버).

P2

D1 · (선결 버그) INFEASIBLE을 timeout과 분리

현재 bay_pack_cp.py:201–202 — OPTIMAL/FEASIBLE 외 모든 status를 "timeout"으로 뭉갬(INFEASIBLE조차). 그래서 진짜 "공간/크레인상 못 들어감"은 컷을 못 만들고(solver.py:174–176), master가 같은 배정을 무한 재선택할 수 있다.
근거 10 LBBD — subproblem의 INFEASIBLE이 곧 cut 생성 신호. 이걸 잃으면 LBBD가 학습을 못 한다.
제안 status에 INFEASIBLE을 추가 분기해 no-good/cardinality cut으로 연결. 효과 컷 생성 정상화(선결). 위험 낮음. 안전 ✓(serial_floor 바닥).
P2

D2 · no-good을 MIS로 축소 (최대 레버)

현재 solver.py:170 — no-good이 베이에 배정된 블록 전체 집합 S를 그대로 배제(master_cp.py:112–115). 가장 느슨한 컷 — "이 정확한 조합"만 막아 거의 학습이 안 됨.
근거 10 LBBD — subproblem을 assumption 기반으로 재구성하고 sufficient_assumptions_for_infeasibility()로 minimal infeasible subset만 추출하면, 한 컷이 지수적으로 많은 배정조합을 한꺼번에 배제(Codato–Fischetti combinatorial Benders).
present = {b: m.NewBoolVar(f"in_{b}") for b in ids}   # assumption literal per block
... constraints OnlyEnforceIf(present[b]) ...
if status == INFEASIBLE:
    core = solver.sufficient_assumptions_for_infeasibility()   # MIS
    nogoods.append((j, frozenset(blk_of[l] for l in core)))    # tiny S
효과 LBBD 수렴 급가속. 위험 높음(subproblem 재구성). 안전 ✓.
P2

D3 · optimality cut(비용 하한) 추가 + cardinality RHS 타이트화

현재 Z1 피드백이 cardinality cut(time-overlap clique, kmax=clique−1로 매번 1씩만, solver.py:179–182)뿐. clique는 현재 타이밍의 산물이지 공간 capacity 증명이 아니고, master의 relaxed Z1과 true Z1의 비용 갭을 직접 막는 Benders optimality cut이 없다.
근거 10 LBBD — Hooker 배정+스케줄링 LBBD의 핵심은 feasibility no-good + optimality cut의 결합. 베이 area/crane-layer 기반으로 진짜 공존 상한을 계산해 RHS를 타이트하게.
효과 master가 같은 over-pack을 비용상 재선택하는 걸 차단. 위험 높음. 안전 ✓.

밀도 천장은 CP-SAT 밖에 있다 — 직교 방법론

위 CP-SAT 제안은 속도·안전을 벌어주지만, <1M이 요구하는 패킹 밀도 천장은 못 올린다. 그 레버는 재구현 과제다(리서치 backed, CP-SAT 무관):

  • Semi-discrete BLF (Chehrazad 2021): NFP 없이 선분 스윕, 기존 대비 ~100배↓ ms. z축 선분 마스크로 크레인 j≥k 인코딩 가능 → "dense를 BL 속도로"(속도 벽 정조준).
  • ROMA raster penetration map (Sato 2019): 정수격자 네이티브, O(1) 오버랩 조회, numpy로 우리 래스터 핫루프 직접 가속.
  • departure-time 그룹 배정: src/gassign.py에 이미 빌드됨(base-first race, never−1) — 동시 공존 수를 줄여 필요 밀도 자체를 낮춤. full ALL40 hybrid A/B로 실현 delta 정량화가 다음 단계.
  • GLS "충돌 허용→반복 해소" 패턴(sparrow/spyrrow) 차용.
