CP-SAT Methodology · 02

모델링 기본기
변수 · 제약 · Reification · Channeling

CpModel/CpSolver API 흐름부터 변수 선언, 선형 제약, Boolean 로직, 그리고 CP-SAT에서 가장 강력하고 동시에 가장 오해가 많은 기능인 Reification(OnlyEnforceIf)과 Channeling 관용구까지. OGC 2026 조선소 배정 모델에 직결되는 패턴을 중심으로 정리한다.

OGC 2026 관련성

블록 b가 베이 j에 배정됨 ↔ BoolVar assigned[b][j]를 채널링하는 패턴, 크레인 수직접근 제약(레이어 j ≥ k)을 AddImplication으로 인코딩하는 방법, 그리고 entry/exit 시각 결정에 OnlyEnforceIf를 적용하는 방법이 이 페이지의 핵심이다. 현재 src/의 _cpsat_bay_timing_verified와 src/baypack_cp/에서 실제로 사용 중인 모든 모델링 관용구의 이론 배경이 여기 있다.

1. CpModel / CpSolver API 흐름

CP-SAT의 Python 인터페이스는 두 클래스 중심이다: CpModel(변수 생성 + 제약 추가 + 목적함수 설정)과 CpSolver(탐색 파라미터 + 실행). 모든 변수와 제약은 모델 객체에 귀속되며, 변수 자체는 선언일 뿐 값이 아니다 — 값은 solver.Value()로 꺼낸다. 

# 기본 흐름 (새 snake_case API, or-tools 9.6+)
from ortools.sat.python import cp_model

model = cp_model.CpModel()

# 1) 변수 선언
x = model.new_int_var(0, 100, "x")
y = model.new_int_var(0, 100, "y")
b = model.new_bool_var("b")

# 2) 제약 추가
model.add(x + 2 * y <= 100)
model.add(x + y >= 10).only_enforce_if(b)

# 3) 목적함수
model.maximize(3 * x + 5 * y)

# 4) 탐색
solver = cp_model.CpSolver()
solver.parameters.max_time_in_seconds = 30.0
status = solver.solve(model)

# 5) 결과 조회
if status in (cp_model.OPTIMAL, cp_model.FEASIBLE):
    print(f"x={solver.value(x)}, y={solver.value(y)}, b={solver.value(b)}")
    print(f"obj={solver.objective_value}")
API 호환성

or-tools 9.x 부터 snake_case 메서드(new_int_var, add_bool_or, only_enforce_if)가 공식이다. 구 PascalCase (NewIntVar, AddBoolOr, OnlyEnforceIf)도 alias로 남아 있지만 새 코드에서는 snake_case 사용을 권장한다. 이 문서는 두 표기법 모두 예시한다.

2. 변수 선언

2.1 NewIntVar — 연속 정수 도메인

# new_int_var(lb, ub, name) → IntVar
x = model.new_int_var(0, 10, "x")       # 0 ≤ x ≤ 10
z = model.new_int_var(-100, 100, "z")   # 음수 허용

# 구 API (PascalCase)
x_old = model.NewIntVar(0, 10, "x_old")

2.2 NewBoolVar — 불리언 (0/1)

b = model.new_bool_var("b")   # 도메인 {0, 1}

# 부정(Negation): 새 변수를 만들지 않는다, 뷰(view)를 반환한다
not_b  = ~b          # 새 문법
not_b2 = b.Not()     # 구 문법 (동일 객체)

# BoolVar는 IntVar의 서브타입 — 산술식에 그대로 쓸 수 있다
model.add(sum(bool_vars) <= 3)
model.maximize(sum(bool_vars))

2.3 NewConstant — 상수

c = model.new_constant(42)   # domain = {42}, 제약 식에 쓸 수 있는 IntVar

2.4 NewIntVarFromDomain — 비연속(Sparse) 도메인

도메인이 연속적이지 않을 때 Domain을 사용한다. 내부적으로 CP-SAT는 도메인을 정렬된 구간(interval) 목록으로 관리한다. 

from ortools.sat.python import cp_model

# (a) 이산값 집합
d1 = cp_model.Domain.from_values([2, 5, 8, 10, 20, 50])
x  = model.new_int_var_from_domain(d1, "x")
# x ∈ {2, 5, 8, 10, 20, 50}

# (b) 구간 목록
d2 = cp_model.Domain.from_intervals([[1, 3], [7, 9], [15, 20]])
y  = model.new_int_var_from_domain(d2, "y")
# y ∈ [1,3] ∪ [7,9] ∪ [15,20]

# (c) 합집합 연산
d3 = d1.union_with(d2)

# (d) AddLinearExpressionInDomain — 식을 특정 도메인에 제한
model.add_linear_expression_in_domain(3 * x + 2 * y, d1)
# 3x + 2y ∈ {2, 5, 8, 10, 20, 50}

# 구 API
d_old = cp_model.Domain.FromValues([1, 3, 5])
x_old = model.NewIntVarFromDomain(d_old, "x_old")
도메인 변수 활용 시점

방향(orientation)이 0° / 90° / 180° / 270° 만 가능한 변수, 또는 입항 시각이 사전 정의된 슬롯 집합에서만 선택 가능한 경우 등에 유용하다. CP-SAT는 Order Encoding을 통해 도메인을 내부적으로 Boolean 변수 집합으로 표현하므로, 도메인이 작을수록 변수 수가 줄어 효율이 높아진다.

3. 선형 제약

3.1 model.Add(...) — 기본 비교

# 지원되는 연산자: ==, !=, <=, >=, <, >
model.add(x + y <= 100)
model.add(x == y + 5)
model.add(2 * x - 3 * y >= -50)
model.add(x != y)     # disequality: 내부적으로 BoolVar 도입

# 대용량 합산 — sum()보다 LinearExpr.sum()이 빠르다
from ortools.sat.python.cp_model import LinearExpr
model.add(LinearExpr.sum(xs) >= 1)
model.minimize(LinearExpr.weighted_sum(xs, weights))

3.2 AddLinearConstraint — lb ≤ expr ≤ ub 형식

# add_linear_constraint(expr, lb, ub)
model.add_linear_constraint(10 * x + 15 * y, lb=-100, ub=10)
# -100 ≤ 10x + 15y ≤ 10

3.3 AllDifferent

vars_ = [model.new_int_var(0, n - 1, f"v{i}") for i in range(n)]
model.add_all_different(vars_)

# 오프셋 변형 — 라틴 방진 등에 유용
model.add_all_different([v + i for i, v in enumerate(vars_)])

4. Boolean 로직 제약

메서드 의미 동등 선형식
add_bool_or([b1, b2, b3]) b1 ∨ b2 ∨ b3 b1+b2+b3 ≥ 1
add_at_least_one([...]) 동일 (별칭) —
add_bool_and([b1, ~b2, b3]) b1 ∧ ¬b2 ∧ b3 b1=1, b2=0, b3=1
add_at_most_one([b1, b2, b3]) ∑ ≤ 1 b1+b2+b3 ≤ 1
add_exactly_one([b1, b2, b3]) ∑ = 1 b1+b2+b3 = 1
add_implication(a, b) a → b b ≥ a
add_bool_xor([b1, b2, b3]) 홀수 개 true b1+b2+b3 ≡ 1 (mod 2) 
b1 = model.new_bool_var("b1")
b2 = model.new_bool_var("b2")
b3 = model.new_bool_var("b3")

# OR: 적어도 하나는 true
model.add_bool_or([b1, b2, b3])

# AND with negation: b1=T, b2=F, b3=F
model.add_bool_and([b1, ~b2, ~b3])

# 배타적 선택 (정확히 하나)
model.add_exactly_one([b1, b2, b3])

# 함의: b1이 true이면 b2도 true
model.add_implication(b1, b2)
# 동등 선형식: model.add(b2 >= b1)

# 복합: (b1 AND b2) → b3   ≡   ¬b1 ∨ ¬b2 ∨ b3
model.add_bool_or([~b1, ~b2, b3])
OGC 2026 — 베이 배정 ExactlyOne
# 블록 b는 정확히 하나의 베이에 배정
assign = {(blk, bay): model.new_bool_var(f"a_{blk}_{bay}")
          for blk in blocks for bay in bays}

for blk in blocks:
    model.add_exactly_one([assign[blk, bay] for bay in bays])

# 크레인 j≥k 수직접근 제약: 레이어 j에 블록이 있으면 k<j 레이어도 없어야 함
# "present[b][j]=True → present[b][k]=False" (k < j)
for blk in blocks:
    for j in range(num_layers):
        for k in range(j):           # k < j
            model.add_implication(present[blk][j], ~present[blk][k])

5. Reification — OnlyEnforceIf

Reification은 제약의 참/거짓 여부를 Boolean 변수에 연결하는 기법이다. CP-SAT는 full reification을 직접 지원하지 않고, half-reification(단방향)인 only_enforce_if를 제공한다.

5.1 Half-Reification: OnlyEnforceIf 의미

model.add(C).only_enforce_if(b)의 정확한 의미는:

b = 1 이면 제약 C가 반드시 성립한다.
b = 0 이면 제약 C는 무시된다 — C가 성립해도 되고, 성립하지 않아도 된다. 
# Half-reification: b=1 → x >= 5  (b=0 이면 x는 아무 값도 OK)
model.add(x >= 5).only_enforce_if(b)

# 부정 조건: ~b = 1 (즉 b=0) 이면 x < 5
model.add(x < 5).only_enforce_if(~b)

# 복수 조건 (AND): b1 AND b2 둘 다 true일 때만 제약 강제
model.add(x + y == 10).only_enforce_if([b1, b2])
함정 #1: OnlyEnforceIf는 단방향이다

model.add(x >= 5).only_enforce_if(b) 만 추가하면
"b=1 → x≥5"는 강제되지만,
"x≥5 → b=1"은 강제되지 않는다.

즉, 솔버는 x=7, b=0 을 선택할 수 있다. b가 "x≥5인지 여부"를 정확히 반영해야 한다면 반드시 양방향을 모두 걸어야 한다 (아래 §5.2 참고).

5.2 Full Reification (양방향 채널링): b ⟺ (x ≥ v)

# b == (x >= 5) 를 완전히 인코딩하려면 양방향이 필요하다
b = model.new_bool_var("b_x_ge_5")

model.add(x >= 5).only_enforce_if(b)       # b=1 → x≥5
model.add(x <  5).only_enforce_if(~b)      # b=0 → x<5  (역방향)
# 이제 b=1 ↔ x≥5 가 완전히 인코딩됨

# 마찬가지로 b == (x == v)
v = 7
b_eq = model.new_bool_var("b_x_eq_7")

model.add(x == v).only_enforce_if(b_eq)    # b=1 → x=7
model.add(x != v).only_enforce_if(~b_eq)   # b=0 → x≠7
# 주의: model.add(x != v)는 내부적으로 보조 BoolVar를 생성한다
함정 #2: 등호 제약에 OnlyEnforceIf 직접 사용 시 주의

model.add(x == v).only_enforce_if(b)는 동작하지만, CP-SAT 내부에서 x == v는 두 부등식(x≤v, x≥v)으로 분해된다. 역방향(b=0 → x≠v)을 추가하지 않으면 솔버가 b=0이더라도 x=v를 선택할 수 있다. 반드시 model.add(x != v).only_enforce_if(~b)를 쌍으로 추가하라.

5.3 AddBoolAnd + OnlyEnforceIf 조합 (Conditional AND)

# b=1일 때만 b1=T, b2=T, b3=F 를 강제
model.add_bool_and([b1, b2, ~b3]).only_enforce_if(b)

# 반대: b=0일 때는 위 AND를 강제하지 않음 (half-reification)
# 역방향이 필요하면: b=0 → NOT(b1 AND b2 AND ~b3) = ~b1 OR ~b2 OR b3
model.add_bool_or([~b1, ~b2, b3]).only_enforce_if(~b)

6. Channeling 관용구

Channeling은 정수 변수 값과 Boolean 변수 사이의 연결을 만드는 것이다 — 예: "변수 x가 베이 j에 배정됨 ↔ assign[x][j]=1". 대부분 양방향 half-reification 2줄의 조합으로 구현한다.

6.1 기본 if-then 인코딩

# if b then y = 10 - x, else y = 0
b = model.new_bool_var("branch")

model.add(y == 10 - x).only_enforce_if(b)
model.add(y == 0).only_enforce_if(~b)

# b의 값을 제약이나 목적함수에서 직접 사용할 수 있다
model.maximize(b * profit + other_term)   # BoolVar × 상수 = OK

6.2 b ⟺ (x ∈ 집합) — 집합 소속 채널링

# 'b = (x is in preferred_bays)' 인코딩
preferred_bays = [2, 3, 5]
bay_var = model.new_int_var(0, num_bays - 1, "bay")
b_pref  = model.new_bool_var("in_preferred")

# 도메인 기반 채널링
d_pref = cp_model.Domain.from_values(preferred_bays)
d_not  = d_pref.complement()

model.add_linear_expression_in_domain(bay_var, d_pref).only_enforce_if(b_pref)
model.add_linear_expression_in_domain(bay_var, d_not).only_enforce_if(~b_pref)

6.3 Boolean → Integer 인덱스 채널링 (Array Element)

# 베이 배정 bool → 정수 인덱스로 채널링 (AddElement)
# assign[b][j] : 블록 b가 베이 j에 배정됨
bay_idx = model.new_int_var(0, num_bays - 1, f"bay_idx_{blk}")

# 방법 1: AddExactlyOne + 선형식
model.add_exactly_one([assign[blk][j] for j in range(num_bays)])
model.add(bay_idx == sum(j * assign[blk][j] for j in range(num_bays)))

# 방법 2: AddElement (조회 테이블)
# target = array[index]  →  bay_weight = bay_weights[bay_idx]
bay_weight_var = model.new_int_var(0, max_weight, f"bw_{blk}")
model.add_element(bay_weights, bay_idx, bay_weight_var)
# bay_weights는 정수 리스트 또는 IntVar 리스트

6.4 Implication 체인 — 크레인 j ≥ k 규칙

# 크레인은 수직접근: 레이어 j에 블록이 있으면 j보다 위 레이어(k < j)가 비어야 함
# (조선소 '위에서 꺼내야 함' 규칙)

occupied = [[model.new_bool_var(f"occ_{blk}_{lay}")
             for lay in range(num_layers)]
            for blk in range(num_blocks)]

for blk in range(num_blocks):
    for j in range(num_layers):
        for k in range(j):            # k < j : k가 j보다 위(크레인 먼저 통과)
            # occupied[blk][j]=T → occupied[blk][k]=F
            model.add_implication(occupied[blk][j], ~occupied[blk][k])

# 동등 선형식 (AddImplication보다 느릴 수 있음)
# model.add(occupied[blk][k] + occupied[blk][j] <= 1)
OGC 2026 — 배정 ↔ 정수 타이밍 채널링
# 블록 b를 베이 j에 배정할 때, 그 베이의 처리 파라미터를 entry/exit 타이밍에 반영
# "assign[b][j]=1 이면 entry[b] >= ready_time[b][j]"

entry = {b: model.new_int_var(0, horizon, f"entry_{b}") for b in blocks}
exit_ = {b: model.new_int_var(0, horizon, f"exit_{b}")  for b in blocks}

for b in blocks:
    for j in bays:
        # 배정됐을 때만 ready_time 제약 활성화
        model.add(entry[b] >= ready_time[b][j]).only_enforce_if(assign[b][j])
        # 배정됐을 때만 처리시간 하한 활성화
        model.add(exit_[b] - entry[b] >= process_time[b][j]).only_enforce_if(assign[b][j])

# 역방향(b가 j에 배정되지 않으면 해당 타이밍 제약 없음)은 별도 필요 없음:
# 배정 변수가 ExactlyOne으로 묶여 있으면 다른 베이 제약이 자동으로 비활성화된다.

7. Boolean vs Integer 모델링 선택 기준

상황 권장 이유
이진 의사결정 (포함/미포함, 배정/비배정) NewBoolVar 도메인={0,1} 최소, 전파 효율 최대
연속 정수 범위 (시각, 위치) NewIntVar Order Encoding으로 내부 분기
비연속 값 집합 (방향: 0/90/180/270) NewIntVarFromDomain(FromValues(...)) 도메인 크기를 직접 제한
배타적 선택 중 정수 인덱스도 필요 BoolVar 배열 + ExactlyOne + Element Channeling으로 인덱스 추출
조건부 제약 (경우에 따라 다른 제약) BoolVar + OnlyEnforceIf (양방향) Full reification 구현
대칭 그룹 (순열, 컬러링) Integer + AddAllDifferent 대칭 파괴 직접 표현 쉬움
Boolean 표현의 전파 우위

CP-SAT 내부에서 정수 변수는 Order Encoding(오더 인코딩)을 통해 Boolean 변수의 집합으로 표현된다. BoolVar를 직접 사용하면 그 인코딩 계층이 없어져 전파가 빠르다. 특히 AddAtMostOne과 AddExactlyOne은 CP-SAT가 특수 전파 알고리즘을 적용하므로, sum(bools) == 1 선형 제약보다 훨씬 강한 추론이 가능하다.

8. 완전한 채널링 예제 — 빈 패킹 (Bin Packing)

빈 패킹은 배정 변수(Bool)↔하중(Int)을 채널링하는 전형적인 예시다.

from ortools.sat.python import cp_model

model     = cp_model.CpModel()
num_items = 5
num_bins  = 3
capacity  = 10
weights   = [3, 5, 2, 4, 6]

# item i가 bin j에 배정됨
assign = {(i, j): model.new_bool_var(f"a_{i}_{j}")
          for i in range(num_items) for j in range(num_bins)}

# 각 아이템은 정확히 하나의 빈에
for i in range(num_items):
    model.add_exactly_one([assign[i, j] for j in range(num_bins)])

# 각 빈의 하중 = Σ weights[i] * assign[i, j]
load = [model.new_int_var(0, capacity, f"load_{j}") for j in range(num_bins)]
for j in range(num_bins):
    model.add(load[j] == sum(weights[i] * assign[i, j] for i in range(num_items)))
    model.add(load[j] <= capacity)

# 빈 사용 여부 채널링: used[j] ↔ (load[j] > 0)
used = [model.new_bool_var(f"used_{j}") for j in range(num_bins)]
for j in range(num_bins):
    model.add(load[j] >= 1).only_enforce_if(used[j])       # used→load>0
    model.add(load[j] == 0).only_enforce_if(~used[j])      # ~used→load=0

model.minimize(sum(used))   # 사용 빈 최소화

solver = cp_model.CpSolver()
status = solver.solve(model)
if status in (cp_model.OPTIMAL, cp_model.FEASIBLE):
    for j in range(num_bins):
        if solver.value(used[j]):
            items = [i for i in range(num_items) if solver.value(assign[i, j])]
            print(f"Bin {j}: items={items}, load={solver.value(load[j])}")

9. 흔한 함정 모음

함정 #1: OnlyEnforceIf 단방향 — 역방향 누락

model.add(x >= 5).only_enforce_if(b)만 있으면 솔버가 x=7, b=0을 선택할 수 있다. "b가 조건을 표현"하려면 반드시 model.add(x < 5).only_enforce_if(~b)를 추가해야 한다.

함정 #2: AddBoolAnd + OnlyEnforceIf 역방향

model.add_bool_and([b1, b2]).only_enforce_if(b)는 "b=1 → b1=T AND b2=T" 만 강제한다. "b=0일 때 b1 OR b2 중 하나가 false" 를 원한다면 model.add_bool_or([~b1, ~b2]).only_enforce_if(~b)를 추가해야 한다. 이를 누락하면 솔버가 b=0 이면서 b1=b2=1인 해를 반환할 수 있다.

함정 #3: BoolVar.Not()은 새 변수가 아니라 뷰

b.Not() 또는 ~b는 새 BoolVar가 아니라 동일 변수의 보수 뷰다. 따라서 model.add(x >= 5).only_enforce_if(b.Not())는 완전히 유효하고 효율적이다. 이를 nb = model.new_bool_var(...); model.add_implication(nb, b.Not()); ...로 불필요하게 확장하면 변수 수가 늘어난다.

함정 #4: 제약 없는 BoolVar가 자유롭게 배회

Channeling용 BoolVar를 선언만 하고 목적함수에도 제약에도 연결하지 않으면, 솔버가 원하는 대로 값을 정한다 — 대개 0. 모든 보조 BoolVar는 목적함수의 최소화/최대화 또는 제약을 통해 "압력"을 받아야 의미 있는 채널링이 된다.

함정 #5: OnlyEnforceIf 는 모든 제약 유형에 지원되지 않는다

only_enforce_if는 선형 제약과 일부 Boolean 제약에만 지원된다. AddAllDifferent, AddNoOverlap 같은 글로벌 제약에는 적용할 수 없다. 해당 제약을 조건부로 만들려면 보조 변수나 빅-M 인코딩 없이 분리된 모델 경로를 설계해야 한다.

함정 #6: sum()과 LinearExpr.sum() 성능 차이

Python 내장 sum()으로 수백~수천 개의 CP-SAT 변수를 더하면 매 단계마다 LinearExpr 중간 객체가 생성되어 매우 느려진다. cp_model.LinearExpr.sum(var_list) 또는 LinearExpr.weighted_sum(vars, coefs)를 사용하라.
