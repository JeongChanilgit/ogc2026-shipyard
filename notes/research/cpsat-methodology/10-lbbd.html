Logic-Based Benders Decomposition
LBBD · Branch-and-Check · CP-SAT를 서브문제 오라클로

배정(master) ↔ 스케줄링·패킹(subproblem)을 분리하고, subproblem의 feasibility/optimality 판정을 CP-SAT 오라클로 위임하는 아키텍처. Hooker & Ottosson(2003)이 정립한 이론부터, no-good cut / Benders cut 생성, branch-and-check 전략, 그리고 Python 의사코드까지 — OGC 2026 master_cp ↔ bay_pack_cp 구조에 1:1 대응하는 수준으로 정밀하게 정리한다.

OGC 2026 관련성 (cp-sat/ 폴더 구조)

cp-sat/ 폴더의 솔버가 정확히 LBBD 구조다. master_cp.py = 베이 배정(assign[b][j])과 완화 스케줄·z2/z3을 CP-SAT로 풀고, bay_pack_cp.py = 고정된 배정 하에 per-bay 패킹·타이밍 feasibility를 CP-SAT로 검증(oraclee). 서브문제가 infeasible이면 master에 no-good cut (해당 배정 조합을 금지하는 AddBoolOr 제약)을 추가하고 master를 재풀이한다. serial_floor는 "항상 feasible한 안전바닥"으로서 LBBD 루프 전에 실행 가능한 초기해를 보장 — 이것이 없으면 LBBD 첫 iteration이 -1로 시작할 위험이 있다.

이 아키텍처가 정확히 Hooker(2007)의 planning+scheduling LBBD (master=배정, subproblem=스케줄링 CP, Benders cut=배정 제약)의 직접 구현이다. Hooker는 MIP 대비 수십~수천 배 속도 향상을 보고했다.

1. 왜 LBBD인가 — 고전 Benders와의 차이

고전 Benders 분해(Benders, 1962)는 혼합 정수 프로그램에서 연속 변수를 subproblem으로 내보내고 LP 쌍대(dual)로 cut을 생성한다. LP duality에 의존하기 때문에 subproblem이 반드시 LP이어야 한다.

Logic-Based Benders Decomposition(LBBD)(Hooker & Ottosson, 2003)은 이 제한을 완전히 제거한다. LP dual 대신 inference dual — 즉 "subproblem이 왜 infeasible/suboptimal한지를 논리적 추론으로 master에 돌려주는" 방식 — 을 사용한다. subproblem은 임의의 구조(CP, MIP, 휴리스틱 ...)여도 된다. 이것이 CP-SAT를 오라클로 쓸 수 있는 이론적 근거다.

항목 고전 Benders Logic-Based Benders (LBBD)
subproblem 형태 반드시 LP (연속) 임의 (CP, MIP, 시뮬레이션 ...)
cut 근거 LP 쌍대 (Farkas / dual ray) 논리 추론 (inference dual)
cut 강도 LP 쌍대가 tight ⇒ 강하다 no-good(약) → lifted(강): 설계에 따라 다름
수렴 보장 weak조건 하 보장 weak조건 하 보장 (유한번 반복)
실용적 우위 영역 연속 혼합 LP 구조 배정+스케줄링, 패킹+타이밍 등 2단계 CP 문제

2. LBBD 핵심 구조 — master · subproblem · cut

2.1 분해 원리

문제 변수를 두 그룹으로 분리한다: x(master가 결정, 주로 배정/할당 정수 변수)와 y(subproblem이 결정, 주로 타이밍/위치/순서). 목적은 min f(x) + g(x, y) 형태. 

# LBBD 분해 개요
# -------------------------------------------
# Master problem:  min  f(x) + η
#                  s.t. x ∈ X (배정 도메인)
#                       η ≥ benders_lower_bound(x)  [optimality cuts]
#                       (x, y) 배제 조합 금지        [feasibility cuts]
#
# Subproblem:      min  g(x̄, y)
#                  s.t. y ∈ Y(x̄)  (x̄ = master 해, 고정)
#   → FEASIBLE  : optimality cut (η 하한 강화)
#   → INFEASIBLE: feasibility cut (해당 x̄ 금지)

2.2 LBBD 기본 알고리즘 (Outer-Approximation 루프)

from ortools.sat.python import cp_model

def lbbd_solve(blocks, bays, timelimit):
    """
    LBBD outer-approximation loop.
    master  : bay 배정 (CP-SAT)
    subproblem: per-bay 패킹/타이밍 feasibility (CP-SAT oracle)
    """
    UB = float('inf')       # 현재 최선 feasible 목적값
    best_solution = None
    iteration = 0
    deadline = time.time() + timelimit

    # ---- Master 모델 (배정) 초기 구성 ----
    master = cp_model.CpModel()
    assign = {}
    for b in blocks:
        for j in bays:
            assign[b, j] = master.new_bool_var(f"assign_{b}_{j}")
    # 각 블록은 정확히 1 베이
    for b in blocks:
        master.add_exactly_one([assign[b, j] for j in bays])
    # η: subproblem 비용 하한 (optimality cut 수신용)
    eta = master.new_int_var(0, 10_000_000, "eta")
    master.minimize(linear_master_cost(assign, blocks, bays) + eta)

    master_solver = cp_model.CpSolver()

    while time.time() < deadline:
        iteration += 1
        # ---- 1) Master 풀기 ----
        master_solver.parameters.max_time_in_seconds = deadline - time.time()
        status = master_solver.solve(master)
        if status not in (cp_model.OPTIMAL, cp_model.FEASIBLE):
            break   # 더 이상 새로운 x̄ 없음 → 종료

        LB = master_solver.objective_value
        if LB >= UB - 1e-6:
            break   # 갭이 닫혔다 → 최적

        # ---- 2) 배정 읽기 ----
        x_bar = {(b, j): master_solver.boolean_value(assign[b, j])
                 for b in blocks for j in bays}
        bay_assignment = {b: j for b in blocks
                          for j in bays if x_bar[b, j]}

        # ---- 3) Subproblem 오라클 (CP-SAT) ----
        sub_status, sub_cost, proof = solve_subproblem(
            bay_assignment, blocks, bays, deadline - time.time()
        )

        if sub_status == "INFEASIBLE":
            # --- Feasibility No-Good Cut 추가 ---
            # 이 배정 조합은 infeasible → 적어도 1개 assign은 반전시켜야
            nogood_lits = []
            for b in blocks:
                j = bay_assignment[b]
                nogood_lits.append(assign[b, j].negated())
            master.add_bool_or(nogood_lits)
            # (lifted cut이 있다면 proof를 이용해 부분집합으로 강화)
            if proof:
                _add_lifted_nogood(master, assign, blocks, proof)

        else:  # FEASIBLE
            # --- Optimality Cut 추가 ---
            # η ≥ sub_cost 를 이 배정(x̄)에서 enforce
            _add_optimality_cut(master, eta, assign, bay_assignment,
                                blocks, sub_cost)
            # UB 갱신
            total = master_solver.objective_value - \
                    master_solver.value(eta) + sub_cost
            if total < UB:
                UB = total
                best_solution = (bay_assignment, sub_cost)

    return best_solution, UB

3. Cut 종류 — 공식과 강화

3.1 Feasibility No-Good Cut (기본)

서브문제가 infeasible일 때 가장 단순한 cut: 현재 배정 x̄를 그대로 다시 선택하는 것을 금지. x̄에 해당하는 boolean 변수들 중 적어도 하나는 반전되어야 한다는 조건이다. 

# 기본 no-good cut:
# NOT (assign[b1,j1]=1 AND assign[b2,j2]=1 AND ...)
# ↔  (assign[b1,j1]=0) OR (assign[b2,j2]=0) OR ...
#
# OR-Tools CP-SAT에서:
lits_negated = [assign[b, bay_assignment[b]].negated() for b in blocks]
master.add_bool_or(lits_negated)

# 수학적으로: Σ_{b} assign[b, j_b] ≤ |blocks| - 1
# (동치이지만 AddBoolOr가 CP-SAT 내부에서 더 효율적)
함정: 약한 no-good cut만 쓰면 수렴이 느리다

기본 no-good cut은 오직 해당 배정만 제거한다. 블록이 N개이면 최악의 경우 2^N번 반복이 필요할 수 있다. infeasibility의 근본 원인(어떤 블록들의 어떤 조합이 충돌하는가)을 파악해 minimal infeasible subset으로 cut을 강화해야 수렴이 빠르다.

3.2 Lifted / Strengthened No-Good Cut

서브문제가 infeasible일 때, infeasibility의 원인이 되는 블록 부분집합(minimal infeasible subset, MIS)을 찾아서 그 부분집합만으로 cut을 구성한다. MIS가 {b1, b2, b3}이면 이 세 블록의 현재 베이 배정을 동시에 유지하는 것은 불가능하다는 강한 cut이 된다. 

def _add_lifted_nogood(master, assign, blocks, proof):
    """
    proof = 서브문제가 반환한 infeasibility 원인 블록 집합.
    예: 베이 j의 capacity overflow를 일으킨 블록 집합.
    기본 no-good보다 강한 cut — 더 많은 배정 조합을 동시에 차단.
    """
    conflict_blocks = proof['conflict_blocks']  # e.g. [b2, b5, b11]
    conflict_bay    = proof['conflict_bay']      # e.g. j=3

    # 이 블록들이 모두 같은 베이에 들어가는 것을 금지
    lits = [assign[b, conflict_bay].negated() for b in conflict_blocks]
    master.add_bool_or(lits)
    # 원래 no-good보다 훨씬 강함:
    # conflict_blocks의 어떤 부분집합도 이 베이에 동시 배정 불가


# 크레인 j≥k 충돌 예시:
def crane_conflict_cut(master, assign, b_high, b_low, j):
    """
    블록 b_high가 레이어 k에, b_low가 레이어 j(j < k)에 있으면
    크레인이 b_high를 진입/퇴출하는 동안 b_low가 경로를 막는다.
    → b_high를 베이 j에 배정하는 것과 b_low를 같은 베이에
      동시 배정하는 것을 금지.
    """
    master.add_bool_or([
        assign[b_high, j].negated(),
        assign[b_low, j].negated()
    ])

3.3 Optimality Cut

서브문제가 feasible이고 비용 v*를 반환할 때, "이 배정에서 서브문제 비용은 적어도 v*"라는 하한을 master의 eta에 부과한다. 

def _add_optimality_cut(master, eta, assign, bay_assignment, blocks, sub_cost):
    """
    현재 배정 x̄에서 서브문제 최적값이 sub_cost임을 master에 알린다.

    가장 단순한 형태: 현재 배정일 때만 유효한 조건부 하한.
      (assign 전부 현재값 유지) → η ≥ sub_cost

    Big-M 방식:
      η ≥ sub_cost - M * (1 - ∑ [assign == x̄])

    CP-SAT에서는 BoolVar로 조건부 제약을 표현:
    """
    # "현재 배정과 동일" 여부를 나타내는 Bool
    same_assign_lits = [assign[b, bay_assignment[b]] for b in blocks]
    # 모두 동일할 때만 enforce (OnlyEnforceIf 조합)
    # CP-SAT에서는 reification + linear 조합으로:
    all_same = master.new_bool_var(f"all_same_{id(sub_cost)}")
    master.add_bool_and(same_assign_lits).only_enforce_if(all_same)
    master.add_bool_or([l.negated() for l in same_assign_lits] + [all_same])
    master.add(eta >= int(sub_cost)).only_enforce_if(all_same)

    # 더 단순한 대안: LP Benders cut 스타일
    # η ≥ sub_cost - M*(|blocks| - Σ assign[b,j_b])
    M = int(sub_cost) + 1
    assigned_sum = sum(assign[b, bay_assignment[b]] for b in blocks)
    master.add(eta * 1 >= int(sub_cost) - M * (len(blocks) - assigned_sum))

4. Branch-and-Check — LBBD의 고속 변형

Outer-approximation은 master를 매 iteration마다 처음부터 재풀이한다. Branch-and-Check(Thorsteinsson, 2001; Hooker, 2000)는 이보다 훨씬 효율적이다: master의 branch-and-bound 트리를 한 번만 실행하면서, 정수 해가 발견될 때마다 서브문제를 호출해 cut을 생성하고 그 자리에서 트리에 추가한다. 재탐색(backtrack) 비용이 크게 줄어든다.

Branch-and-Check의 핵심 관찰 (Hooker, 2000)

"master 문제를 단 한 번만 풀면 된다 — 모든 정수 후보 해마다 서브문제 cut을 즉시 주입하면." 이것이 lazy constraint callback 기반 구현의 이론적 근거다.

CP-SAT는 현재 solve 중 외부 cut 주입 콜백(lazy constraint callback)을 직접 지원하지 않는다. 그러나 실제로는 두 가지 방식으로 branch-and-check에 근접하거나 대체할 수 있다:

방식설명CP-SAT 적합성
Outer loop (기본) master solve → sub check → cut 추가 → master 재solve 반복 완전 지원. 이 문서의 메인 패턴.
SolutionCallback 기반 master solve 중 중간 해마다 sub 호출, 실패 시 StopSearch()+cut 추가 후 재solve 부분 지원. on_solution_callback 내에서 서브문제 호출 가능하나 cut 주입은 재solve 필요.
Assumptions 기반 AddAssumptions로 배정 고정 → sub solve → infeasible 시 SufficientAssumptionsForInfeasibility()로 MIS 추출 강력. MIS 기반 lifted cut 생성에 최적.

4.1 Assumptions로 MIS(Minimal Infeasible Subset) 추출

CP-SAT의 AddAssumptions + SufficientAssumptionsForInfeasibility()는 LBBD lifted cut 생성에 강력한 도구다. 서브문제에 배정을 assumption으로 고정하면, infeasible일 때 어떤 assumption의 부분집합이 충돌 원인인지를 반환한다. 

def solve_subproblem_with_mis(bay_assignment, blocks, bays, timelimit):
    """
    CP-SAT Assumptions로 서브문제 풀기 + MIS 추출.
    반환: (status, cost, mis_assignments)
      status: "FEASIBLE" | "INFEASIBLE"
      mis_assignments: infeasible이면 충돌 원인 (b, j) 쌍 집합
    """
    sub = cp_model.CpModel()

    # 베이별 타이밍/패킹 변수
    entry = {b: sub.new_int_var(0, T_MAX, f"entry_{b}") for b in blocks}
    exit_ = {b: sub.new_int_var(0, T_MAX, f"exit_{b}") for b in blocks}

    # assumption 변수: assign[b][j]를 boolean으로 인코딩
    a_vars = {}
    for b in blocks:
        j = bay_assignment[b]
        a_vars[b] = sub.new_bool_var(f"a_{b}_{j}")

    # 배정에 따른 제약: a_vars[b]=True 가정 → 해당 베이 제약 활성화
    for b in blocks:
        j = bay_assignment[b]
        # entry ≥ release[b], exit - entry ≥ process[b]
        sub.add(entry[b] >= RELEASE[b]).only_enforce_if(a_vars[b])
        sub.add(exit_[b] - entry[b] >= PROCESS[b]).only_enforce_if(a_vars[b])
        # 크레인 접근 제약: j ≥ k 규칙 (같은 베이 내 레이어)
        for b2 in blocks:
            if b2 != b and bay_assignment[b2] == j:
                layer_b  = LAYER[b]
                layer_b2 = LAYER[b2]
                if layer_b > layer_b2:   # b가 위에 있어야 먼저 빠져야
                    sub.add(exit_[b] <= entry[b2]).only_enforce_if(
                        sub.new_bool_var(f"crane_{b}_{b2}")
                    )

    # Assumptions: 모든 a_vars를 True로 가정
    assumptions = list(a_vars.values())
    sub.add_assumptions(assumptions)
    sub.minimize(sum(max(0, exit_[b] - DUE[b]) for b in blocks))

    solver = cp_model.CpSolver()
    solver.parameters.max_time_in_seconds = timelimit
    status = solver.solve(sub)

    if status == cp_model.INFEASIBLE:
        # MIS: 충돌 원인 assumption만 추출
        mis_indices = solver.sufficient_assumptions_for_infeasibility()
        mis_bvars   = [assumptions[i] for i in mis_indices]
        mis_blocks  = [b for b, av in a_vars.items() if av in mis_bvars]
        return "INFEASIBLE", None, {
            'conflict_blocks': mis_blocks,
            'conflict_bay': bay_assignment[mis_blocks[0]]
        }
    elif status in (cp_model.OPTIMAL, cp_model.FEASIBLE):
        cost = solver.objective_value
        return "FEASIBLE", cost, None
    else:
        # UNKNOWN/timeout: 보수적으로 feasible로 취급 (안전바닥 fallback)
        return "UNKNOWN", None, None

5. 완성된 LBBD 루프 — serial_floor 안전바닥 포함

import time
from ortools.sat.python import cp_model

def full_lbbd(prob_info: dict, timelimit: float) -> dict:
    """
    OGC 2026 스타일 LBBD:
      - serial_floor: 항상 feasible한 탐욕적 초기해 (안전바닥)
      - master_cp: 베이 배정 + relaxed 스케줄 (CP-SAT)
      - bay_pack_cp: per-bay 패킹·타이밍 검증 (CP-SAT oracle)
      - no-good / lifted / optimality cut 루프
    """
    blocks = prob_info['blocks']
    bays   = prob_info['bays']
    deadline = time.time() + timelimit

    # ① 안전바닥: 항상 feasible한 greedy 초기해
    best_sol = serial_floor(prob_info)         # never returns None
    best_obj = evaluate(best_sol, prob_info)
    print(f"[LBBD] serial_floor UB = {best_obj:,.0f}")

    # ② Master CP-SAT 모델 초기화
    master, assign, eta = build_master(blocks, bays)
    master_solver = cp_model.CpSolver()

    cut_count = 0
    for it in range(1, 500):
        remaining = deadline - time.time()
        if remaining < 2:
            break

        # ③ Master 풀기
        master_solver.parameters.max_time_in_seconds = min(remaining * 0.4, 60)
        m_status = master_solver.solve(master)
        if m_status not in (cp_model.OPTIMAL, cp_model.FEASIBLE):
            break

        LB = master_solver.objective_value
        if LB >= best_obj - 0.5:
            print(f"[LBBD] iter {it}: gap closed (LB={LB:.0f}, UB={best_obj:.0f})")
            break

        # ④ 배정 추출
        bay_asgn = {b: j for b in blocks for j in bays
                    if master_solver.boolean_value(assign[b, j])}

        # ⑤ Subproblem oracle
        sub_status, sub_cost, proof = solve_subproblem_with_mis(
            bay_asgn, blocks, bays,
            timelimit=min(remaining * 0.5, 120)
        )

        if sub_status == "INFEASIBLE":
            # 기본 no-good cut
            lits = [assign[b, bay_asgn[b]].negated() for b in blocks]
            master.add_bool_or(lits)
            # lifted cut (MIS 기반)
            if proof:
                cb = proof['conflict_blocks']
                cj = proof['conflict_bay']
                master.add_bool_or([assign[b, cj].negated() for b in cb])
            cut_count += 1
            print(f"[LBBD] iter {it}: INFEASIBLE → cut #{cut_count} added")

        elif sub_status == "FEASIBLE":
            # Optimality cut
            _add_optimality_cut(master, eta, assign, bay_asgn, blocks, sub_cost)
            # UB 갱신
            m_cost = (master_solver.objective_value
                      - master_solver.value(eta))
            total  = m_cost + sub_cost
            if total < best_obj:
                best_obj = total
                best_sol = reconstruct_solution(bay_asgn, prob_info)
                print(f"[LBBD] iter {it}: UB ↓ {best_obj:,.0f} (sub={sub_cost:.0f})")
            cut_count += 1

        else:  # UNKNOWN: sub timed out
            # 안전 처리: no-good만 추가하고 계속
            lits = [assign[b, bay_asgn[b]].negated() for b in blocks]
            master.add_bool_or(lits)

    print(f"[LBBD] done: {it} iter, {cut_count} cuts, UB={best_obj:,.0f}")
    return best_sol
serial_floor 안전바닥이 LBBD에서 결정적인 이유

LBBD는 master가 infeasible이 되면 루프가 끝난다. 그런데 master가 제공하는 배정이 아직 한 번도 feasible을 달성하지 못한 채 UB=∞이면, 서버 타임아웃이 올 때 반환할 해가 없어 -1이 된다. serial_floor는 루프 진입 전에 항상 feasible한 해를 확보해두는 안전장치다. LBBD 루프 전체가 timeout되어도 best_sol에 초기 탐욕해가 남아 있어 -1 회피가 보장된다.

6. 수렴 · 종료 조건

LBBD는 다음 세 조건 중 하나에서 종료된다:

  1. 최적성 gap 닫힘: LB(master) ≥ UB - ε → 현재 best_sol이 최적
  2. Master infeasible: 더 이상 새로운 배정이 없음 → 현재 best_sol이 최적
  3. 시간 초과: 가장 최근 feasible best_sol 반환 (UB 기준)
유한 수렴 보장 (Hooker & Ottosson, 2003)

배정 공간 X가 유한하고 매 iteration마다 최소 1개의 배정이 cut으로 제거된다면, LBBD는 유한 번의 반복 이후 반드시 종료된다. 기본 no-good cut은 매 iteration에서 정확히 1개 배정을 제거하므로 이 조건을 충족한다. lifted cut은 한 번에 여러 배정을 제거해 수렴이 더 빠르다.

6.1 수렴 가속 기법

기법설명효과
Lifted no-good (MIS) infeasibility 최소 원인 집합만으로 cut 구성 iteration 수 대폭 감소
Pareto-optimal cut Magnanti-Wong: core point를 이용해 가장 강한 optimality cut 선택 LB 빠르게 상승

7. CP-SAT를 Subproblem 오라클로 설계하는 방법

7.1 오라클 인터페이스

서브문제 오라클은 세 가지 답 중 하나를 반환해야 한다: FEASIBLE(비용 포함), INFEASIBLE(증명 포함), UNKNOWN(timeout). UNKNOWN을 최소화하기 위해 시간 예산 관리가 중요하다. 

# CP-SAT 서브문제 오라클 골격
def oracle(fixed_assignment: dict, timelimit: float):
    model = cp_model.CpModel()

    # 고정된 배정에 따라 per-bay 변수 생성
    ...

    # CP-SAT 검증 파라미터
    solver = cp_model.CpSolver()
    solver.parameters.max_time_in_seconds = timelimit
    solver.parameters.num_search_workers  = 4   # 병렬화
    solver.parameters.cp_model_presolve   = True
    # feasibility 우선 탐색: 최적화보다 빠르게 feasibility 확인
    solver.parameters.optimize_with_core  = True

    status = solver.solve(model)

    if status == cp_model.INFEASIBLE:
        mis = solver.sufficient_assumptions_for_infeasibility()
        return {"status": "INFEASIBLE", "mis": mis}
    elif status in (cp_model.OPTIMAL, cp_model.FEASIBLE):
        return {"status": "FEASIBLE",
                "cost":   solver.objective_value,
                "values": {v: solver.value(v) for v in ...}}
    else:
        return {"status": "UNKNOWN"}

7.2 Feasibility oracle vs Optimization oracle

서브문제를 feasibility 체크만 할 것인지, 최적화도 할 것인지에 따라 cut의 종류와 수렴 속도가 달라진다.

모드cut 종류UB 개선속도
Feasibility only no-good/lifted cut만 없음 (별도 해 평가 필요) 빠름
Optimization feasibility + optimality cut 직접 UB 개선 느리지만 수렴 빠름
혼합 (권장) feasibility 체크 후 feasible이면 최적화 UB 개선 균형

8. OGC 2026 master_cp ↔ bay_pack_cp 상세 매핑

OGC 2026 cp-sat/ 폴더 구조와 LBBD 이론의 1:1 대응
LBBD 이론 요소OGC 2026 구현파일
Master problem 베이 배정 assign[b][j] + 완화 스케줄 + z2/z3 목적 cp-sat/master_cp.py
Subproblem oracle per-bay 패킹(후보 set-packing) + 타이밍(NoOverlap + 크레인 j≥k) cp-sat/bay_pack_cp.py
No-good cut infeasible bay의 블록 배정 조합 금지 → AddBoolOr master_cp.py 루프
Lifted cut 크레인 충돌 쌍(b_high, b_low) 직접 cut bay_pack_cp.py proof 반환
Optimality cut eta ≥ z1_sub (per-bay tardiness 하한) master_cp.py 루프
Serial floor (안전바닥) greedy EDD 배정 → 항상 feasible한 초기해 cp-sat/solver.py
Branch-and-check outer loop (master solve → sub check → cut → repeat) cp-sat/solver.py main loop

크레인 j≥k 제약이 이 아키텍처에서 가장 강한 no-good cut 소스다. 레이어 위치상 위에 있는 블록이 아래 블록보다 먼저 퇴출되어야 하는 제약은 per-bay 패킹·타이밍 feasibility에서 직접 위반을 탐지할 수 있고, 위반 쌍 (b_high, b_low, bay) 를 proof로 반환해 master에 강한 lifted cut을 추가한다.

흔한 함정

함정 1: 약한 no-good cut만 → 지수 반복

기본 no-good cut은 매 iteration에서 배정 조합 1개만 제거한다. 블록 N개이면 최악 2^N iteration. 해결: subproblem에서 infeasibility proof(MIS)를 반드시 추출하고 lifted cut을 사용. CP-SAT의 sufficient_assumptions_for_infeasibility()가 MIS를 반환한다.

함정 2: Master와 Subproblem의 목적함수 불일치

Master가 z1+z2+z3을 최소화하는데 subproblem이 z1만 보고 비용을 반환하면, optimality cut(η ≥ sub_cost)이 master의 목적과 맞지 않아 UB가 잘못된다. 해결: eta가 subproblem이 반환하는 것과 정확히 같은 비용 구성을 측정하도록 설계.

함정 3: 안전바닥 없이 LBBD 시작 → timeout시 -1

LBBD 루프가 시작 전 feasible 해를 확보하지 않으면, 서버 TL 안에 루프가 convergence하지 않을 경우 반환할 해가 없어 -1을 리턴하게 된다. 해결: 루프 전에 serial_floor(EDD greedy) 같은 "항상 feasible" 탐욕해를 실행. 이것이 best_sol의 초기값이자 최악의 경우 반환값이 된다.

함정 4: CP-SAT에 solve 중 외부 cut 주입 시도

Gurobi/CPLEX는 lazy constraint callback으로 solve 중에 cut을 추가할 수 있다. CP-SAT는 이를 지원하지 않는다. 해결: outer loop 방식 (master를 재solve) 사용. 또는 SolutionCallback.stop_search()로 중단 후 cut 추가 → 재solve 패턴. 성능 차이는 대부분 무시 가능하다 (CP-SAT의 presolve/clause learning이 보완).

함정 5: Subproblem timeout을 FEASIBLE로 오해

CP-SAT가 UNKNOWN(timeout)을 반환했을 때 feasible로 취급하면, 실제로 infeasible한 배정에 optimality cut을 추가해 UB가 잘못된다. 해결: UNKNOWN은 별도 처리 — no-good cut만 추가하고 다음 iteration으로. 또는 timeout 발생 시 서브문제 시간 예산을 늘리는 adaptive 전략.

함정 6: 무한루프 — cut이 추가되지 않는 iteration

subproblem이 UNKNOWN을 반환하면서 no-good cut도 추가되지 않으면 master가 같은 해를 반복한다. 해결: UNKNOWN일 때도 반드시 현재 배정에 대한 no-good cut은 추가. iteration 카운터와 cut 카운터를 별도로 추적해 "cut 추가 없이 k회 반복" 시 강제 종료.

베스트프랙티스 요약
  • 항상 serial_floor로 안전바닥을 확보한 뒤 LBBD 루프 진입
  • subproblem에서 MIS(minimal infeasible subset) 추출 → lifted cut 사용
  • 매 iteration에서 UB bound를 master에 전달 (eta ≤ UB) → master 탐색 가속
  • subproblem 시간 예산은 전체 TL의 40~60%로 dynamic하게 배분
  • cut 수가 수백 개를 넘으면 master solve 시간이 증가 → 오래된/약한 cut pruning 고려
  • convergence 판정: LB ≥ UB - ε, 또는 master가 INFEASIBLE 반환
