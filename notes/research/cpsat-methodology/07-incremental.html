add_hint로 탐색을 안내하고, AddAssumption으로 불가능 핵심을 추출하며, CpSolverSolutionCallback으로 중간해를 수집하거나 조기 중단한다. CP-SAT는 진정한 증분 풀이를 지원하지 않으므로, 직전 해를 hint로 이월하는 패턴이 실질적인 웜스타트다.

OGC 2026 관련성

베이 타이밍 oracle(_cpsat_bay_timing_verified)은 LNS 반복마다 직전 해를 hint로 이월해 수렴을 가속할 수 있다. CP-SAT best-of 후보(legacy ∥ box)를 try/except로 감싸는 구조에서 CpSolverSolutionCallback의 plateau 감지 → stop_search()로 예산을 아끼고, AddAssumption으로 force_after 같은 시간창 what-if를 빠르게 탐색할 수 있다. "hint가 LNS 반복 간 이어진다"는 것이 핵심 — 모델을 매 반복 재구축하더라도 직전 솔루션을 힌트로 주입하면 첫 번째 feasible 해 도달 시간이 크게 단축된다.

1. 솔루션 힌트 (Solution Hints)

힌트는 소프트 제안이다. CP-SAT는 힌트된 값으로 탐색을 시작하지만, 힌트가 충족 불가능해도 오류를 내지 않고 점진적으로 기본 탐색으로 전환한다. SAT 문헌의 "phase saving"을 정수변수까지 확장한 개념이다.

1.1 기본 사용법

from ortools.sat.python import cp_model

model = cp_model.CpModel()
x = model.new_int_var(0, 10, 'x')
y = model.new_int_var(0, 10, 'y')
z = model.new_int_var(0, 10, 'z')

model.add(x != y)
model.maximize(x + 2 * y + 3 * z)

# 힌트 추가 (부분 힌트 OK — z는 생략해도 됨)
model.add_hint(x, 1)
model.add_hint(y, 2)

solver = cp_model.CpSolver()
status = solver.solve(model)

print(solver.value(x), solver.value(y), solver.value(z))
Tip — 부분 힌트

모든 변수에 힌트를 줄 필요 없다. 결정이 어려운 핵심 변수(예: 베이 배정 변수)에만 힌트를 주면 나머지는 solver가 자유롭게 탐색한다. 불완전한 힌트도 "repair" 진입점으로 활용된다.

1.2 내부 동작

CpModelProto의 solution_hint 필드(PartialVariableAssignment)에 변수 인덱스와 힌트 값이 병렬 벡터로 저장된다. 솔버는 힌트된 변수에 대해 해당 값으로 먼저 분기(branch)를 시도하고, 제약 위반이 없으면 그 방향으로 탐색을 진행한다.

1.3 관련 파라미터

파라미터기본값설명

Pitfall — add_hint는 누적된다

add_hint는 append 방식이다. 반복 루프에서 같은 변수에 힌트를 다시 주려면 모델을 재구축(새 CpModel())하거나, model.clear_hints() (proto 직접 조작: model.proto.solution_hint.Clear())를 호출해야 한다. 누적된 힌트가 서로 모순이면 solver는 그 힌트를 무시하고 진행한다.

2. 증분 풀이 · 반복 웜스타트

CP-SAT는 진정한 증분 풀이(incremental solve)를 지원하지 않는다. 매 solver.solve() 호출은 새로운 검색을 시작하며, 내부 상태(학습된 절 등)는 유지되지 않는다. 실질적인 웜스타트 방법은 직전 해를 hint로 이월하는 패턴이다.

2.1 직전 해를 hint로 이월 (기본 패턴)

from ortools.sat.python import cp_model

def solve_with_warmstart(vars_list, constraints_fn, obj_fn, n_iters=5):
    """매 반복 모델 재구축 + 직전 해를 hint로 이월."""
    best_solution = None

    for i in range(n_iters):
        model = cp_model.CpModel()
        vars_map = {name: model.new_int_var(lb, ub, name)
                    for name, lb, ub in vars_list}

        constraints_fn(model, vars_map)       # 제약 재등록
        model.minimize(obj_fn(vars_map))      # 목적함수

        # ★ 직전 해를 hint로 주입
        if best_solution is not None:
            for name, val in best_solution.items():
                model.add_hint(vars_map[name], val)

        solver = cp_model.CpSolver()
        solver.parameters.max_time_in_seconds = 30.0
        status = solver.solve(model)

        if status in (cp_model.OPTIMAL, cp_model.FEASIBLE):
            best_solution = {name: solver.value(v)
                             for name, v in vars_map.items()}
            print(f"iter {i}: obj={solver.objective_value():.1f}")

    return best_solution

2.3 변수 고정으로 부분 모델 고정 (LNS 수동 구현)

import random

def manual_lns(all_vars, initial_solution, model_builder,
               destroy_frac=0.3, n_iters=20, time_per_iter=15.0):
    """수동 LNS: 일부 변수 고정 + 나머지를 hint로 안내."""
    current = dict(initial_solution)

    for it in range(n_iters):
        model = cp_model.CpModel()
        vars_map = model_builder(model)

        # destroy: 랜덤 변수 집합만 자유롭게 탐색
        free_vars = set(random.sample(list(all_vars),
                                      k=max(1, int(len(all_vars) * destroy_frac))))

        for name in all_vars:
            v = vars_map[name]
            if name not in free_vars:
                # repair: 고정 변수는 도메인을 단일값으로 좁혀 fix
                model.add(v == current[name])
            else:
                # hint: 자유 변수도 직전 값으로 안내
                model.add_hint(v, current[name])

        solver = cp_model.CpSolver()
        solver.parameters.max_time_in_seconds = time_per_iter
        status = solver.solve(model)

        if status in (cp_model.OPTIMAL, cp_model.FEASIBLE):
            new_obj = solver.objective_value()
            if new_obj < compute_obj(current):   # minimize 가정
                current = {name: solver.value(v)
                           for name, v in vars_map.items()}
                print(f"LNS iter {it}: improved → {new_obj:.1f}")

    return current
Tip — fix vs hint 선택 기준

fix(도메인을 단일값으로 좁히기): 변수를 절대 바꾸지 않을 때.
hint: 변경은 허용하지만 직전 값 근처에서 시작하게 할 때.
LNS "repair" 단계는 fix + hint를 혼합해 "free 변수만 최적화" 하는 게 핵심이다.

3. Assumptions — 불가능 핵심 추출

add_assumption(lit) / add_assumptions(lits)는 Boolean 리터럴을 가정으로 등록한다. 모델이 INFEASIBLE이 되면 solver.sufficient_assumptions_for_infeasibility()가 충돌에 기여한 최소 가정 집합(UNSAT 코어)을 반환한다. 각 제약에 Boolean indicator를 달아 "이 제약이 켜진 상태"를 가정으로 등록하는 패턴이 일반적이다.

3.1 UNSAT 코어 추출 예제

from ortools.sat.python import cp_model

model = cp_model.CpModel()
x = model.new_int_var(0, 100, 'x')
y = model.new_int_var(0, 100, 'y')
z = model.new_int_var(0, 100, 'z')

# 각 제약에 Boolean indicator 부착
ind1 = model.new_bool_var('c1: x+y<=4')
model.add(x + y <= 4).only_enforce_if(ind1)

ind2 = model.new_bool_var('c2: x+z<=2')
model.add(x + z <= 2).only_enforce_if(ind2)

ind3 = model.new_bool_var('c3: z>=4')
model.add(z >= 4).only_enforce_if(ind3)

# 세 제약을 동시에 "켜진" 상태로 가정 → 동시 만족 불가
model.add_assumptions([ind1, ind2, ind3])

solver = cp_model.CpSolver()
status = solver.solve(model)

if status == cp_model.INFEASIBLE:
    print("충돌 가정 (UNSAT 코어):")
    for idx in solver.sufficient_assumptions_for_infeasibility():
        print(f"  [{idx}] {model.proto.variables[idx].name}")
Tip — what-if 빠른 탐색

가정은 매 풀이 전에 갱신할 수 있다. 제약 집합을 바꾸지 않고 model.clear_assumptions() 후 새 가정만 교체하면 모델 재구축 없이 다양한 시나리오를 빠르게 테스트할 수 있다. 단, CP-SAT는 매번 전체 재풀이를 한다 — "진짜" 가정 기반 증분은 없다.

Pitfall — 가정의 한계

sufficient_assumptions_for_infeasibility()는 충분 집합이지 최소 UNSAT 코어를 보장하지 않는다. 실제 충돌보다 큰 집합을 반환할 수 있다. 또한 모델이 FEASIBLE로 반환된 경우에는 이 메서드를 호출해도 의미 있는 결과를 얻지 못한다.

4. CpSolverSolutionCallback — 중간해 수집 · 조기 중단

CpSolverSolutionCallback을 상속해 on_solution_callback()을 구현하면 solver가 새 해를 찾을 때마다 호출된다. 이 안에서 변수 값 읽기, 로그 기록, 조기 중단이 가능하다.

4.1 핵심 API

메서드반환 타입설명
on_solution_callback()—새 해 발견 시 호출. 반드시 override.
objective_value()float현재 최선 해의 목적함수 값.
best_objective_bound()float최적 하한(최소화) 또는 상한(최대화).

boolean_value(lit)bool현재 해에서 Boolean 리터럴의 값.
stop_search()—탐색 종료 신호. 비블로킹.

4.2 중간해 수집 콜백

class SolutionCollector(cp_model.CpSolverSolutionCallback):
    """발견된 모든 해를 수집하고 진행상황을 출력한다."""

    def __init__(self, variables):
        super().__init__()
        self._vars = variables
        self.solutions = []       # [(obj, {var: val})]
        self._best = float('inf')

    def on_solution_callback(self):
        obj = self.objective_value()
        sol = {v.name: self.value(v) for v in self._vars}
        self.solutions.append((obj, sol))
        if obj < self._best:
            self._best = obj
            bound = self.best_objective_bound()
            gap = abs(obj - bound) / (abs(obj) + 1e-9)
            print(f"  ★ new best: obj={obj:.1f}  bound={bound:.1f}"
                  f"  gap={gap:.2%}  branches={self.num_branches()}")


model = cp_model.CpModel()
x = model.new_int_var(0, 20, 'x')
y = model.new_int_var(0, 20, 'y')
model.add(x + y <= 15)
model.minimize(x * 2 + y)

solver = cp_model.CpSolver()
solver.parameters.max_time_in_seconds = 30.0
cb = SolutionCollector([x, y])
status = solver.solve(model, cb)

print(f"총 {len(cb.solutions)}개 해 발견, 최선: {cb._best}")

4.3 개선 정체 시 조기 중단 (Timer 기반)

from threading import Timer

class EarlyStopOnStagnation(cp_model.CpSolverSolutionCallback):
    """마지막 개선 후 stagnation_sec 초 이상 정체하면 중단."""

    def __init__(self, stagnation_sec: float = 10.0):
        super().__init__()
        self.stagnation_sec = stagnation_sec
        self._best = float('inf')
        self._timer = None
        self._arm_timer()

    def on_solution_callback(self):
        obj = self.objective_value()
        if obj < self._best - 1e-6:  # 진짜 개선이면 타이머 리셋
            self._best = obj
            self._arm_timer()

    def _arm_timer(self):
        if self._timer:
            self._timer.cancel()
        self._timer = Timer(self.stagnation_sec, self._trigger_stop)
        self._timer.daemon = True
        self._timer.start()

    def _trigger_stop(self):
        print(f"[조기중단] {self.stagnation_sec}s 동안 개선 없음 → stop_search()")
        self.stop_search()

    def cancel(self):
        if self._timer:
            self._timer.cancel()


solver = cp_model.CpSolver()
solver.parameters.max_time_in_seconds = 300.0
cb = EarlyStopOnStagnation(stagnation_sec=15.0)
status = solver.solve(model, cb)
cb.cancel()   # 풀이 완료 후 타이머 정리

4.4 Gap 임계값 조기 중단

class GapStopCallback(cp_model.CpSolverSolutionCallback):
    """obj-bound 갭이 목표 이하가 되면 즉시 중단."""

    def __init__(self, target_gap: float = 0.01):
        super().__init__()
        self.target_gap = target_gap  # 1% gap

    def on_solution_callback(self):
        obj = self.objective_value()
        bound = self.best_objective_bound()
        if obj == 0:
            return
        gap = abs(obj - bound) / abs(obj)
        if gap <= self.target_gap:
            print(f"Gap {gap:.4%} ≤ {self.target_gap:.4%} → 조기중단")
            self.stop_search()


cb = GapStopCallback(target_gap=0.005)  # 0.5%
solver.solve(model, cb)
Pitfall — 콜백 안에서 무거운 작업 금지

on_solution_callback()은 solver 스레드에서 직접 호출된다. I/O, 무거운 계산, Python GIL을 오래 잡는 작업을 넣으면 solver 성능이 심각하게 저하된다. 해야 한다면 결과를 큐에 넣고 메인 스레드에서 처리하거나, 조건 체크와 stop_search()만 두어야 한다.

        model.add_max_equality(t, [exit_[b] - D[b], 0])
        tardiness.append(t)
    model.minimize(sum(tardiness))

    # ★ 직전 해를 hint로 이월
    if prev_solution:
        for b in bay_blocks:
            if b in prev_solution:
                model.add_hint(entry[b], prev_solution[b]['entry'])
                model.add_hint(exit_[b],  prev_solution[b]['exit'])

    solver = cp_model.CpSolver()
    solver.parameters.max_time_in_seconds = timelimit
    solver.parameters.num_workers = 4
    status = solver.solve(model)

    if status in (cp_model.OPTIMAL, cp_model.FEASIBLE):
        return {b: {'entry': solver.value(entry[b]),
                    'exit':  solver.value(exit_[b])}
                for b in bay_blocks}
    return None  # None 반환 시 best-of에서 안전하게 무시

6.2 best-of 후보 병렬 실행 + plateau 조기 중단

class BudgetAwareCallback(cp_model.CpSolverSolutionCallback):
    """
    best-of(legacy ∥ box) 구조에서 시간 예산 내 plateau 감지.
    개선이 min_improvement 미만이면 stagnation_sec 후 중단.
    """
    def __init__(self, time_budget: float, min_improvement: float = 0.02,
                 stagnation_sec: float = 8.0):
        super().__init__()
        self._budget = time_budget
        self._min_imp = min_improvement
        self._stagnation = stagnation_sec
        self._best = float('inf')
        self._timer = None

    def on_solution_callback(self):
        obj = self.objective_value()
        rel_imp = (self._best - obj) / (abs(self._best) + 1e-9)
        if rel_imp >= self._min_imp:
            self._best = obj
            self._arm_timer()   # 의미있는 개선 → 타이머 리셋

    def _arm_timer(self):
        if self._timer:
            self._timer.cancel()
        self._timer = Timer(self._stagnation, self.stop_search)
        self._timer.daemon = True
        self._timer.start()

    def cancel(self):
        if self._timer:
            self._timer.cancel()

흔한 함정 요약

1. hint 누적 — add_hint는 append

동일 변수에 여러 번 add_hint를 호출하면 proto에 중복 엔트리가 쌓인다. 반복 루프에서는 매 반복 모델을 재구축하거나 del model.proto.solution_hint.vars[:] 등으로 직접 초기화해야 한다.

2. 모순된 hint — 무시되거나 성능 저하

힌트된 값이 기존 제약과 충돌하면 solver는 조용히 힌트를 버리고 진행한다. debug_crash_on_bad_hint = True로 개발 중에만 체크하라. 힌트가 전혀 도움이 안 되거나 오히려 느려지는 경우가 생길 수 있다.

3. presolve가 hint를 깬다

presolve 단계에서 변수 도메인이 축소되면 원래 feasible했던 hint가 INFEASIBLE이 될 수 있다. repair_hint = True를 켜거나, debug_crash_if_presolve_breaks_hint = True로 진단하라.

4. 증분 풀이 없음 — 매번 전체 재풀이

CP-SAT는 Clause Learning을 반드시 초기화하고 새로 시작한다. "이전 풀이 결과를 이어받아 계속 풀기"는 불가능하다. hint 이월만이 유일한 웜스타트 수단이며, 이전 해가 새 제약을 위반하더라도 repair 진입점으로 활용될 수 있다.

5. 콜백 안에서 무거운 작업 — solver 성능 파괴

on_solution_callback은 solver 내부 스레드에서 호출된다. 파일 I/O, 대규모 계산, 외부 API 호출을 넣으면 solver가 블로킹된다. 결과는 queue.Queue에 넣고 별도 스레드에서 처리하라.

6. sufficient_assumptions_for_infeasibility — 최소 코어 아님

반환값은 "충분한" 가정 집합이지, 이론적 최소 UNSAT 코어가 아니다. 실제 충돌보다 큰 집합을 반환할 수 있으며, 더 작은 코어를 원한다면 반환된 집합을 다시 탐색해야 한다.

7. fix_variables_to_their_hinted_value — 전역 적용

이 파라미터를 켜면 힌트된 모든 변수가 고정된다. LNS에서 "일부 변수만 고정"하려면 파라미터 대신 model.add(v == hint_val) 제약으로 개별 제어하라.
