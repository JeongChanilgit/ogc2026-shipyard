패킹 밀도를 높이는 방법 — 대규모 리서치

OGC 2026 · 조선소 블록 패킹 · 2026-06-17 · web-researcher 7개 병렬(논문·깃허브·SOTA) → 우리 솔버의 "속도-제약 밀도 벽"에 연결한 종합

한 화면 결론 (TL;DR)

우리의 추월 레버는 이미 확정돼 있다 — per-bay 패킹 효율 ~80%→~95%. 진짜 벽은 밀도 자체가 아니라 속도: 우리의 dense packer(LCA)는 ~2배 느려 T120/4-core에서 밀도 이득 < 연산비용이라 net-negative였다. 이번 리서치는 그 벽을 정면으로 겨냥한 두 갈래 + 한 우회로를 찾았다.

  • 갈래 1 — 더 빠른 dense packer 기법: Semi-discrete BLF(Chehrazad 2021, NFP 없이 선분-스윕, 기존 대비 ~100배↓ ms 단위) + ROMA raster penetration map(Sato 2019, 정수격자 네이티브, O(1) 오버랩 조회). 둘 다 우리 래스터를 대체/가속해 "dense를 BL 속도로" 만드는 직접 후보. (우리가 찾던 net-positive 조건)
  • 갈래 2 — 밀도 벽을 우회: 문제의 진짜 클래스는 Block Relocation + Temporal Bin Packing. 밀도를 더 짜내지 말고 필요한 밀도 자체를 줄인다 — departure-time 그룹 배정 + 클리크-면적 사전필터 + blocking-pair 페널티. O(n) 싸고, crane-feasibility를 밀도 희생 없이 높임.
  • SOTA 도구: sparrow + jagua-rs(2025 오픈소스 SOTA, "충돌 허용→GLS로 반복 해소" 패턴)가 진짜 알고리즘 레버. Python wheel spyrrow 존재(MIT, 오프라인 벤더 가능)지만 strip-packing·Rust·20분 기준·crane 미지원 → 바이너리보다 GLS 패턴 차용이 현실적.
  • 막다른 길(확정): 학습 기반(RL/Transformer/diffusion) 패킹은 전부 GPU 종속 또는 ~37s+ CPU 추론 → CPU-only/오프라인/120s에 전원 부적합. "학습된 순서를 단순 규칙으로 증류" 도 논문들이 직접 불가라고 결론. 고전 휴리스틱이 이 제약에서 지배.

§0 우리의 벽 — 왜 "밀도"가 아니라 "속도"인가

2026-06-16 캠페인(약 17 가설 검증)에서 엄밀하게 확인된 것:

  • 밀도 레버는 PROVEN: fastfloor의 _ft_search_pos_lca(Largest-Contact-Area dense placer)를 배선하니 prob_22가 comp를 이기고, prob_29는 z1·z3 둘 다 comp 추월. 즉 더 조밀하게 깔면 손실→승리로 뒤집힌다.
  • 그런데 T120/4-core에서 net-negative: LCA는 ~2배 느려 floor race에서 예산을 먹고 postprocess를 굶긴다. best-of(banked, LCA)=328.4M은 2회 full-run이 필요해 120초에 불가. (근거: notes/research/z1z3-lowering-2026-06-16.md "BUDGET WALL")
  • 줄일 수 없는 비용 = crane-feasibility 래스터 체크: 다층 블록 + j≥k 수직접근 규칙 때문에 표준 nesting 도구의 "footprint 비충돌=feasible" 가정이 틀린다. per-bay 충돌 체크가 irreducible.
그래서 이번 리서치의 질문은 둘이다: ① dense packing을 BL 속도로 할 수 있는 기법이 있는가? ② 애초에 필요한 밀도를 줄이는 직교 레버가 있는가? — 둘 다 "예"로 답이 나왔다.

§2 갈래 1 — "dense를 BL 속도로": 빠른 후보생성·충돌검출

우리 벽의 직접 해답. 핵심은 per-candidate 충돌 비용을 ms 이하로 떨궈 dense packer를 net-positive로 만드는 것.

★ Semi-discrete BLF — Chehrazad, Roose, Wauters 2021 (EJOR / arXiv:2103.08739)

폴리곤과 베이를 모두 등간격 수직 선분 집합으로 반이산화하고, 충돌=선분 오버랩 테스트로 환원. NFP를 명시적으로 계산하지 않고 BL 정착점을 스윕라인으로 찾는다. 저자 주장: 기하 기반 NFP-BLF 대비 ~2 order of magnitude(≈100배) 빠름, 회전 포함 ms 단위. 2025년 같은 그룹이 3D deepest-LBF로 확장(z방향 선분) — 이 z축 마스킹이 우리 crane "접근 가능한 열" 검사와 구조적으로 동형이라 가장 자연스러운 통합 후보.

우리 적용: fastfloor의 래스터 충돌을 선분-표현으로 교체하면 해상도 독립 + 정확 + 빠름. crane 규칙은 "내 위층 블록 선분이 내 하강열에 있으면 금지"로 z선분 오버랩에 직접 인코딩. 공개 Python 구현은 없음 → 재구현(알고리즘 단순). 단독 밀도 수치는 논문 미공개(메타휴리스틱 빌딩블록으로 위치).

★ ROMA — Raster Penetration Map (Sato et al. 2019/2020, EJOR)

각 폴리곤에 사전계산된 래스터 침투맵을 두면 임의 위치의 오버랩 값을 O(1) 조회. 정수격자 네이티브라 우리 환경에 직결. 15개 벤치 중 9개에서 기존 최선 동등·개선. crane 금지열을 맵 마스크로 더하면 됨.

우리 적용: 우리는 이미 래스터를 쓴다 → 침투맵 사전계산으로 "후보 위치마다 풀스캔" 비용을 O(1)로. ±r 정수 이동 후보를 O(1)로 평가해 dense 배치/컴팩션의 핫루프를 직접 가속. 속도 벽을 정조준.

NFP 전처리 캐시 + 레퍼런스 점 쿼리

회전이 0/90/180/270 4가지뿐이고 유니크 형상 수가 제한적이면, 형상 쌍별 NFP를 1회 전처리 캐시 → 이후 배치 쿼리 = O(n) 점-폴리곤 내부판정. 래스터 풀스캔 대비 수십~수백배. Python에선 pyclipr(ClipperLib2)/pyclipper Minkowski가 가장 빠름. 주의: 비볼록 NFP 생성 robustness 이슈(libnfporb는 2023 아카이브, CGAL reduced-convolution이 실측 빠름).

jagua-rs CDE — Gardeyn 2025 (INFORMS JoC / arXiv:2508.08341)

기하 계산을 최적화에서 분리한 오픈소스 충돌 엔진(Rust). 삼각법 + poles-of-inaccessibility(내접원 중심) + piers + quadtree로 대부분 충돌을 싼 폴-검사로 조기기각, "수백만 쿼리/s". Python 바인딩 없음 → subprocess/FFI 필요 + 오프라인 빌드 부담. → 바이너리 통합보다 "fail-fast surrogate(pole) 먼저, 정밀검사 나중" 설계 패턴을 우리 체커에 차용하는 게 실용적.

§4 구성적 배치·스코어링 — BL을 넘는 후보 생성

per-candidate 비용이 비싸니 "적지만 좋은 후보"가 핵심.

  • BLF (Burke 2006) — NFP+IFP orbital slide, 후보=NFP 정점. 정확하지만 비볼록 NFP 비쌈/robustness 이슈.
  • Extreme-Point (Crainic 2008) — 배치 후 코너 투영으로 소수의 의미있는 극점만 후보화 → 비싼 crane체크를 적은 후보에만 돌릴 수 있어 우리에 유리.
  • LCA / BCA 접촉면적 스코어 (Shang&Gu 2017; Koh 08; Zheng 11) — 후보 중 기존블록·벽과 접촉길이 최대 선택. 조선소 맥락서 BLF 대비 ~30% makespan↓. 우리는 이미 _ft_search_pos_lca로 부분 구현(밀도 PROVEN).
  • Diagonal-fill / 다중앵커 BLF (Kwon&Lee 2015, 조선소) — BL앵커 + TR앵커 동시평가로 대각 충진. 후보 2배지만 밀도↑.
  • MergeDJD (2026) — 기하 보완적 블록쌍을 사전 병합해 더 규칙적 형상으로 → 빈패킹 평균 <2s. 아이디어 차용 가능.
권고 조합: Semi-discrete 후보생성 + 접촉길이(BCA) 스코어 = NFP 없이 "slide-to-contact" 후보를 자동 생성하고, crane체크를 최소 후보에만. 우리가 이미 가진 LCA의 밀도 이득을 빠른 표현 위에서 재현하는 길.

§5 갈래 2 — crane·시간축 우회로: 필요한 밀도 자체를 줄인다 ★

가장 새롭고 실행적인 발견. 우리 문제의 진짜 클래스는 순수 nesting이 아니라 Block Relocation Problem(BRP) + Temporal Bin Packing. 모든 분석이 한 통찰로 수렴: blocking은 시간 현상 — 시간창이 겹치지 않는 두 블록은 서로 어떻게 쌓아도 무방하고, 동시 공존하면서 레이어 순서가 틀린 쌍만 진짜 제약이다. 이걸 쓰면 밀도를 더 안 짜내고도 z1을 줄인다.

① Departure-time 그룹 배정

Borgman 2010 (OR Spectrum); Kim&Hong 2006 BRP

새 블록을 베이에 넣을 때, 그 베이 기존 블록들의 EXIT 시각이 새 블록 EXIT에 가까운 베이를 선호. "같이 나가는 블록끼리" 모으면 j≥k 위반 확률이 구조적으로 낮아짐. 실험상 reshuffle 30~50%↓. O(1) 정렬/버킷.

⚠ 우리 H18(temporal pre-staggering)은 low-slack서 falsified였음 — 단 그건 진입시각 분산이고, 이건 같은 베이를 공유할 블록 선택(배정)이라 다른 레버. 재시도 가치 있음.

② 클리크-면적 사전필터

Temporal Bin Packing 클리크 하한 (Dell'Amico 19; Martinovic 23)

인터벌 그래프의 최대 클리크(동시 공존 집합)를 sweep으로 구해, 그 시간슬라이스 합산 footprint가 베이 면적을 넘으면 어떤 패커도 실현 불가 → 배정 단계서 O(n)으로 조기 차단. 탐색공간 축소 + 무의미한 dense-pack 시도 방지.

③ Blocking-pair 페널티 스코어

LIFO 컨테이너 적재 + 항공기 hangar MILP (arXiv:2508.02640)

블록 A를 (x,y)에 놓을 때, "A와 동시 존재 + A보다 높은 레이어 + A의 하강열 위" 기존블록 수를 세어 페널티(ENAR식). =0 위치 우선 → dense BL 유지하면서 j≥k 위반 최소화. hangar의 blocks_AB → 시간 분리 Big-M 패턴의 soft 버전.

④ well-placed 불변식

BRP 하한 (Tanaka 16; Azab&Morita 22 BRPAS)

위에 더 늦게 나가는 블록이 없으면 "well-placed". badly-placed 블록 수 = 재배치 하한. 배치 우선순위로: 더 늦게-나가는 블록을 더 일찍-나가는 블록 위/하강열에 두지 않기. BRPAS는 시간창 조정으로 blocking 관계 자체를 줄임 = 우리 ENTRY/EXIT 결정과 동형.

왜 매력적인가: 이 4개는 전부 O(n) 안팎으로 싸다 — §0의 속도 벽을 안 건드린다. 그리고 우리 진단(prob_29: 116블록 중 89개 delayed=공간부족)을 "동시 공존 수를 배정·시간으로 줄여 공간부족 자체를 완화"로 직접 공격. 밀도 벽을 우회하는 유일한 길.

① 이 89~92%는 단층·무제약 strip 기준. 우리 다층+crane j≥k는 배치자유도가 훨씬 낮아 동일 밀도 달성 불가 — "경쟁자 ~95%"는 우리 추정이며 crane 하에선 천장이 더 낮다.
② sparrow 기준 런타임 = 20분/3스레드. 우리 120s/4-core에서 실용 도달 밀도는 추정 ~85~88%(직접 측정 필요). 저자들 스스로 "지난 10년 진전 ~2~5%p"라고 명시 = 밀도는 짜기 어렵다.

§8 학습 기반 = 부적합 (확정된 negative result)

대규모 조사했지만 우리 제약(GPU 없음·인터넷 차단·120s·이형 다층)에서 전부 탈락. 시간 절약을 위해 명시 기록:

  • GFPack++ (ICCV 2025) — diffusion gradient field, Puzzle 95.1%. 학습 4×RTX4090·50h, 추론 GPU 필수. 부적합
  • PCT (ICLR 2022) — Transformer+DRL, 3D 직육면체 전용. 이형 없음, GPU. 부적합
  • Learning-based 2D Irregular (arXiv:2309.10329) — CPU 실행되나 추론 37.76s/인스턴스(예산 31%), UV 패치 전용. 부적합
  • 증류(학습된 순서→단순 규칙)? — 저자들이 직접 "area-descending 같은 근시안 규칙으로 줄일 수 없다(정책이 H스텝 미래를 본다)"고 명시. 신경 NFP(NFP-UNet)도 후보마다 CNN forward라 수천 후보에 불가.
결론: 이 환경에서는 고전 휴리스틱(BLF+NFP/래스터+국소탐색)이 지배. 학습 기반은 막다른 길이며 재시도 가치 없음. (단 이미 우리가 쓰는 "Z3-aware 배정=선호 높은 블록 먼저"는 문헌이 지지하는 경험칙과 일치.)

§9 우리 솔버를 위한 우선순위 권고 ★

§0의 벽(속도-제약 밀도, never-−1, 120s/4-core, 가역 게이트)에 맞춰 ROI·리스크 순.

1crane·시간축 우회로 먼저 (§5) — 가장 싸고 벽을 안 건드림

departure-time 그룹 배정(①) + 클리크-면적 사전필터(②) + blocking-pair 페널티(③)를 배정/디코드에 추가형으로. 전부 O(n)이라 속도 벽 무관, obj-gated + best-of로 never-−1. 우리 진단(공간부족으로 89개 delayed)을 "동시 공존 수 감소"로 직접 공격. ⚠ H18 falsification과의 차이(진입분산 vs 배정선택)를 per-bay A/B로 먼저 확인.

2crane-aware 반복 jostle 개선 패스 (§3) — 가장 쉬운 밀도 이득

기존 _fixed_time_decode(crane 이미 처리) 위에 "제거→BLF 재삽입→obj개선시 채택" 루프 15~30줄. additive·anytime·never-infeasible. 120s 내 수백 반복. banked 보존하며 게이트 ON.

3표현 교체로 속도 벽 돌파 (§2) — 중기, 진짜 unlock

per-bay 충돌을 ROMA 침투맵(O(1) 조회) 또는 semi-discrete 선분표현으로 교체 → 우리가 PROVEN한 LCA 밀도를 BL 속도로 재현(net-positive 조건 달성). crane은 z선분/맵 마스크로 인코딩. 이게 되면 LCA_RACE가 default ON 가능.

4spyrrow 어댑터 PoC (§7) — 탐색적, 리스크 큼

오프라인 wheel로 strip-pack 호출 → 위치 받아 외부 crane체크. 단 strip→bin 어댑터 품질 미검·20분→120s early-exit·평가서버 설치 불확실. 먼저 GLS "충돌 허용→반복 해소" 패턴을 우리 코드로 포팅하는 게 안전.

하지 말 것: 학습 기반(§8) 전부 · libnfporb(아카이브) · SVGnest/Deepnest(서버불가) · Imamichi/Gomes 풀 NLP/LP(120s 예산 초과 위험, 무거움).

§10 주의·미해결

  • 벤치 밀도 ≠ 우리 밀도: 89~92%는 단층·무제약. crane j≥k 하에선 천장이 더 낮음. "95% 경쟁자"는 추정. 우리 인스턴스(정수좌표·육중한 근사직사각형)에서 실측 필요.
  • semi-discrete 단독 밀도 수치 미공개(논문이 빌딩블록으로만 제시). 속도 주장(~100배)은 명확, 밀도는 메타휴리스틱과 결합 전제.
  • departure-grouping vs H18 falsification: 반드시 per-bay로 "배정선택 레버"가 "진입분산 레버"와 다르게 효과 있는지 먼저 검증 후 채택.
  • spyrrow/jagua-rs 오프라인·OS: 평가서버(Linux 추정) wheel/바이너리 가용성, 15MB zip, 20분→120s 수렴곡선 모두 미측정.
  • NFP robustness: 비볼록 NFP 생성은 Python서 불안정 빈번. 블록이 단순 형상이면 pyclipr Minkowski로 대체.
  • 측정/채택 규칙(불변): 검증은 full set(set1 또는 ALL40), 판정은 개별 z 아닌 총 obj, never-−1, 게이트 default-OFF로 banked(328.7M) 보존.
