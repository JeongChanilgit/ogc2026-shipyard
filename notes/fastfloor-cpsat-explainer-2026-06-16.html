Fast-Floor Decode와 CP-SAT

🎯 핵심
이 솔버의 풀이 파이프라인은 양 끝단(베이 배정·타이밍)이 이미 CP-SAT이고, 가운데의 위치 배치(x, y, 방향)만 그리디 Bottom-Left다. 목적함수를 크게 줄이는 그 CP-SAT(타이밍 오라클)가 잘 푸는 이유는 정확히 공간을 안 풀기 때문이다 — 배치를 고정해 문제를 1차원으로 환원한 덕분이다. 그래서 "decode(공간)에 CP-SAT를 넣자"는 시도는 이미 boxsolver.py(box-decomp)로 구현되어 있고, 그게 바로 "터진다"고 알려진 모듈이다.

아래는 (1) 현재 decode 로직 → (2) CP-SAT 개념 → (3) 이 솔버의 CP-SAT 3종 → (4) 왜 타이밍 CP-SAT는 강력한가 → (5) 왜 같은 도구를 공간에 쓰면 무너지는가 → (6) 그래서 다음 레버는 무엇인가, 순서로 설명한다.

2Fast-Floor Decode 상세 — 그리디 Bottom-Left의 해부

함수 _fixed_time_decode(fastfloor.py:556-643)는 이름 그대로 "시간을 고정(fixed-time)하고 위치만 decode"한다. 베이 하나를 받아 그 안의 블록들을 한 개씩 BL로 떨어뜨린다.

2.1 입력·출력

항목내용
입력bay(베이 기하), ids(이 베이에 배정된 블록 목록 — 배정은 ①에서 이미 끝남), blocks_data, deadline, order_key
시간 처리블록마다 aB, eB = R, R+P — ENTRY=release, EXIT=ENTRY+process로 완전히 고정 fastfloor.py:598
출력블록별 {block_id, bay_id, x, y, orient_idx, entry_time, exit_time} + ft_stats(placed_at_R / delayed / forced / grid_hits / tardiness) :638-640
이 한 줄이 모든 것을 정한다
aB, eB = R, R + P   # 시간 완전 고정 → 남은 자유도는 (x, y, 방향)뿐
시간이 상수가 되면서, decode는 순수 2D 배치 문제로 축소된다. (이 사실이 §6에서 결정적으로 다시 등장한다.)

2.2 블록당 3단계 배치 — at-R → delayed → forced

각 블록은 순서대로(2.3의 정렬 순) 다음을 시도한다 fastfloor.py:594-628:

단계시도tardiness위치
① at-RENTRY=R(가장 이른 시각)으로 빈 자리 탐색0:601-606
② delayed실패 시, 이미 놓인 블록들의 EXIT 시각을 오름차순으로 훑으며 ENTRY를 미뤄 자리 확보발생:607-618
③ forced그래도 실패 시, 모든 기존 EXIT 이후로 밀어 상호작용 0인 빈 윈도를 만들고 아무 BL 자리큼:619-628

즉 tardiness(z1)는 "자리가 없어서 시간을 미룬" 결과로 발생한다. 공간이 빽빽할수록 ②·③로 떨어지고 z1이 커진다 — 이것이 패킹 밀도와 z1을 잇는 고리다.

2.3 배치 순서 — 어떤 블록부터 떨어뜨리나

순서는 _ft_order fastfloor.py:538-553로 결정. 기본 F0 = release 오름차순, footprint 면적 내림차순(큰 것 먼저). F1/F2/F3는 due·area 변형이며, 여러 순서를 best-of로 경쟁시킨다.

2.4 후보 위치 생성 — NFP가 아니라 BL-abut + raster

핵심 함수 _ft_search_pos fastfloor.py:231-366. 두 패스로 후보 좌표를 만든다:

Pass 1 · BL abut 코너
  • x-앵커 = 좌/우 벽 + 각 기존 블록의 좌/우 모서리 ±1 :274-283
  • y-앵커 = 바닥 + x가 겹치는 기존 블록들의 top ±1 :288-297
  • → "벽이나 다른 블록에 딱 붙는" 후보만 생성 (NFP 없이 코너 휴리스틱)
Pass 2 · 정수격자 raster
  • Pass 1 전부 실패 시 발동 (grid=True)
  • dy, dx 전 범위를 stride 1(넓은 베이는 2)로 전수 스캔 :330-343
  • → 느리지만 빈틈을 빠짐없이 검사하는 안전망

후보 랭킹은 (Y, X, 방향) 사전식 정렬 — 가장 낮고(아래) 가장 왼쪽 자리를 채택. 이것이 "Bottom-Left"의 정의다 fastfloor.py:302:

cands.sort(key=lambda c:(c[0], c[1], c[2]))   # (Y, X, orient) — 낮고 왼쪽 우선

방향(orientation)은 별도 단계가 아니라 후보 생성에 통합된다 — 모든 회전을 후보로 펼친 뒤 위 정렬의 3번째 키로 동시에 고른다 :267, :301-302.

2.5 충돌·크레인 검사 — _ft_pair_ok

후보를 채택하기 전, 기존에 놓인 블록들과 충돌하지 않는지 _ft_pair_ok fastfloor.py:157-200로 검사한다. 래스터 셀 교집합으로 5개 금지 조건(forbidden predicate)을 확인:

  • 동일층 충돌(cond 5, collide :196-199) — 두 블록이 같은 시간에 같은 자리
  • 크레인 수직접근 j≥k(obstruct :162, :186-195) — 위에서 내려오는 크레인 경로가 막히면 금지. 정의: obstruct(M,S) = ∃ k<n(M), j∈[k,n(S)) : cells_M[k] ∩ cells_S[j] ≠ ∅

bbox로 1차 prefilter 후 :314-318, 채택 직전 _verify가 float-world 래스터로 재검증 + bay.contains_block(베이 경계)까지 확인 :246-264.

2.6 베이 병렬 + best-of race

베이는 ①에서 이미 독립적으로 배정됐으므로 베이끼리 상호작용이 없다. 따라서 _decode_bays_parallel fastfloor.py:1029가 베이를 4-worker로 병렬 decode한다. 각 베이 안에서는 여러 order_key·시도를 _decode_attempts가 경쟁시켜 best를 채택 :670-673.

✅ 2장 정리
Fast-floor decode = ① 시간 고정 → ② 블록을 면적 큰 순으로 → ③ BL-abut/raster 후보 중 가장 낮고 왼쪽 자리에 → ④ 충돌·크레인 통과하면 놓고, 안 되면 시간을 미룸(tardiness). 베이별 병렬·온라인 그리디. 빠르고 항상 feasible하지만, 한 번 놓으면 안 옮기는(append-only) 탓에 밀도가 ~80%에서 막힌다.

3CP-SAT란 무엇인가 — 그리디와 무엇이 다른가

CP-SAT는 Google OR-Tools의 제약 프로그래밍 + SAT 솔버다. "변수·제약·목적함수"를 선언하면, 솔버가 모든 가능성을 탐색해 (예산 내에서) 증명된 최적해 또는 그에 근접한 해를 찾아준다. 그리디와의 결정적 차이는 되돌아갈 수 있다(backtracking)는 것이다.

그리디 (현재 decode)
  • 블록을 하나씩 보고 그 순간 최선의 자리에 확정
  • 한 번 놓으면 다시 안 옮김 (append-only)
  • 빠름. 항상 답이 나옴. 하지만 지역 최적에 갇힘
  • "지금 좋아 보이는 자리"가 나중에 다른 블록의 자리를 망쳐도 모름
CP-SAT
  • 모든 블록의 결정을 동시에 변수로 두고 탐색
  • 제약 전파(propagation)로 불가능한 조합을 가지치기
  • 막다른 길이면 되돌아가 다른 조합 시도
  • 예산 내 전역 최적 또는 최적성 증명 가능. 단 변수가 많으면 폭발

3.1 CP-SAT 모델의 3요소

① 결정 변수 (decision variables)
솔버가 값을 정해야 하는 미지수. 정수 변수(예: entry_time), 불리언 변수(예: "블록 b를 베이 j에 = 0/1") 등.
② 제약 (constraints)
변수들이 지켜야 할 규칙. 선형 부등식, "둘 중 하나"(disjunction), reified("이 조건이 참이면 저 제약 적용") 등.
③ 목적함수 (objective)
Minimize(...) / Maximize(...). 우리 문제에선 tardiness 합, 부하 불균형, 선호 페널티 등.

3.2 왜 "잘 푼다"고 느껴지나 — 그리고 무엇이 비용인가

CP-SAT가 강력한 이유는 제약 전파다. 한 변수 값을 시도하면 그것이 강제하는 다른 변수 값들이 도미노처럼 확정되고, 모순이 나면 즉시 그 가지 전체를 버린다. 잘 구조화된 문제(변수 수가 적고 제약이 강한 propagation을 만드는)에서는 거대한 탐색 공간이 순식간에 줄어든다.

⚠️ 단, 공짜가 아니다
탐색 공간은 변수 수와 제약의 결합 방식에 지수적으로 민감하다. 변수가 많아지거나, 제약이 서로 곱해지면(예: "쌍마다 disjunction") 같은 CP-SAT도 예산 안에 못 푼다. 이것이 §5(성공)와 §6(실패)를 가르는 단 하나의 축이다.

5왜 타이밍 CP-SAT(B)는 강력한가 — decoupling의 마법

사용자가 "CP-SAT가 obj를 크게 줄인다"고 본 그 컴포넌트가 바로 이 타이밍 오라클이다. 잘 푸는 비결은 세 가지 구조적 환원이며, docstring myalgorithm.py:2625-2633에 명시돼 있다.

① 모든 기하 검사가 시간과 무관 → 충돌 boolean이 상수가 된다

layout(위치·방향)이 고정이므로, "블록 A와 B가 충돌하나? 크레인이 막나?"는 entry 시각이 뭐든 답이 똑같다. 그래서 쌍당 5개 충돌 boolean을 Shapely로 딱 한 번 계산하고 :2838-2842, 모델에는 정수 부등식만 남긴다.

② exit = entry + P가 WLOG 최적 → 블록당 변수 1개

블록은 들어오면 P만큼 머무르고 나가는 게 항상 최선이므로, exit를 따로 변수로 둘 필요가 없다. 블록당 미지수는 entry 하나뿐.

③ 남는 건 단일머신 tardiness → CP-SAT의 홈그라운드

정수 entry에 대한 interval disjunction = 전형적 단일머신 스케줄링. 게다가 OGC_TIMING_DECOMP :2697,:2785-2827가 상호작용 그래프의 connected component로 더 쪼개 서브문제를 작게 만든다 → 베이별 최적까지.

# 타이밍 오라클의 핵심: 충돌은 상수, entry만 변수
for (a, b) in interacting_pairs:          # 고정 layout에서 미리 추린 쌍만
    l1, l2 = precomputed_collision_bools(a, b)   # ← 상수 (위치 고정이라)
    model.Add(...).OnlyEnforceIf(l).AddBoolOr([l1, l2])  # entry 시각으로만 충돌 회피
model.Minimize(sum(tardiness))
✅ 5장 정리
타이밍 오라클은 2D-어려운 공간을 고정하고, 1D-쉬운 시간만 푼다. CP-SAT가 빛나는 건 정확히 이 환원 덕분 — 공간을 안 건드렸기 때문이다. 이 사실을 기억한 채 §6으로.

6비대칭 — 왜 decode에 CP-SAT를 넣으면 무너지나

사용자의 질문 "fast-floor decode에 CP-SAT를 넣을 수 있나?"의 정직한 답: 그 시도는 이미 존재한다(boxsolver.py box-decomp), 그리고 그게 바로 터지는 모듈이다. 왜인지가 이 문서의 클라이맥스다.

6.1 위치를 변수로 만드는 순간, 상수가 결정 변수로 변질된다

§5에서 타이밍이 깨끗했던 단 하나의 이유는 충돌 boolean이 상수였기 때문이다. 그런데 위치 tx, ty를 변수로 풀면, "A와 B가 분리됐나?"가 더 이상 상수가 아니라 tx, ty의 함수인 결정 변수가 된다 boxsolver.py:376-379, 552-555:

# box-decomp: 분리 여부 자체가 변수에 묶인 결정
model.Add(tx[a] - tx[c] <= floor(minx_c - maxx_a)).OnlyEnforceIf(sep_x)
model.AddBoolOr([sep_x, sep_y, sep_time])   # 쌍마다 이런 disjunction

그 결과 disjunctive 분기가 위치 자유도와 곱해진다. 타이밍에선 entry 하나당 분기였는데, 여기선 (tx, ty, ev) × 쌍마다 분리 boolean이 결합돼 탐색 공간이 폭발한다.

6.2 이형 폴리곤 non-overlap은 더 비싸다

블록이 사각형이 아니라 이형 폴리곤이라, 정확히 풀려면 footprint를 K개 rectangle로 분해하고 rect-쌍마다 분리 제약을 걸어야 한다. 쌍당 제약이 |rects[a]| × |rects[c]|로 늘어 전체는 O(n² · K²). 코드는 이 폭발을 미리 알고, 모델을 짓기도 전에 거절한다 boxsolver.py:507-512, 472-473:

npairs = sum(len(rects[a]) * len(rects[c]) for a, c in pairs)
if npairs > 90000:        # OGC_BOXDECOMP_CAP — 모델조차 안 짓고 포기
    return L0                  # 그리디 layout으로 fallback
# docstring: "K=2는 single-bbox를 이기지만 K=3은 9× 모델, CP-SAT가 예산 내 못 푼다"

6.3 크레인 j≥k를 정확히 넣으면 더 나빠진다

그래서 box-decomp는 크레인을 직접 모델링하지 않고 "co-present면 footprint를 완전히 분리"라는 보수적 invariant로 우회한다 boxsolver.py:304-308, 459-462. 이건 안전하지만 과도하게 보수적 — 같은 시간에 있으면 공간을 완전히 떼어놓으라는 강제라, 경쟁자(~95%)의 밀집 패킹을 못 만든다.

🔥 비대칭의 핵심 (한 문장)
타이밍 오라클은 2D-어려운 공간을 고정하고 1D-쉬운 시간을 푼다. decode에 CP-SAT를 넣는 건 그 정반대 — entry=R로 시간을 고정하고 공간을 푼다. 그런데 entry=R이면 모든 블록이 같은 시간대(co-present)라 시간 분리 탈출구마저 없는 순수 2D 이형 nesting이 된다(box-decomp보다 더 어려움). 쉬운 쪽을 풀어서 이득을 봤는데, 어려운 쪽을 풀려 하니 그 이득이 사라지는 것이다.
실측 위치
box-decomp는 HYBRID(src/myalgorithm.py)에 best-of 후보로 이미 들어 있다. 작은 베이 prob_3/4/18 정도에서만 legacy 그리디를 이기고, congested·대형 베이는 그리디 BL이 이긴다. full set1 = 1,312,961 (old 1.39M에서 box가 −73K 기여). 즉 "decode에 CP-SAT"는 미답의 영역이 아니라, 이미 한계가 측정된 레버다.

7그래서 진짜 레버는 — 그리고 CP-SAT를 굳이 쓴다면

우리 그리디 BL도 box-decomp도 per-bay 패킹효율 ~80%에 막혀 있고 경쟁자는 ~95%다. 이 갭은 풀 CP-SAT가 아니라 전용 2D nesting(NFP / semi-discrete BLF / compaction)의 영역이다. CP-SAT를 그래도 공간에 쓰고 싶다면, §5에서 통한 트릭 — "한 차원을 상수로 만들기" — 을 공간에 복제해야 한다.

A. semi-discrete shelf + 1D CP-SAT

y를 레벨(shelf)로 이산화 → 레벨 내 x-배치만 CP-SAT 1D. y를 고정하면 타이밍처럼 한 축이 상수가 되어 폭발 회피. 리서치 노트의 semi-discrete BLF가 바로 이것. 가장 유망하고 구조적으로 새로움.

B. CP-SAT compaction LNS

그리디 BL layout을 그대로 두고, 소수의 movable 블록만 CP-SAT로 압축/재배치해 공간 회수. 이웃 고정 → 모델 작음. 밀도 회수 이득은 A보다 작을 수 있음.

⚠️ 반증된 레버 — 다시 시도 금지
메모리·CLAUDE.md상 "exact box packer"(=box-decomp 풀 버전) · "finer-raster" · "LCA/contact-area 배치"는 이미 반증됐다. A/B는 구조가 다르지만(한 축 고정 / 부분 LNS), 채택 판정은 반드시 full set1(또는 ALL40)의 총 obj 기준이어야 한다 — 개별 z나 단일 캡처 랭킹으로 판단 금지(사용자 측정 규칙).
