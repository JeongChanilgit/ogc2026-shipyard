P

비정형 2D 패킹 / 네스팅

Irregular Strip Packing · Nesting — 비-볼록 폴리곤을 정수 좌표·이산 방향으로 베이에 채우기

핵심 알고리즘

No-Fit-Polygon (NFP) / Inner-Fit-Polygon (IFP)
두 폴리곤이 닿지만 안 겹치는 상대 위치 영역을 사전계산 → 겹침 검사를 점-내부 판정으로 환원. IFP는 베이 경계 안에 넣을 수 있는 영역.
이산 방향 집합이 고정이라 (피스쌍 × 방향) NFP를 한 번 precompute해 캐싱 가능 → 최대 속도 레버. Toledo의 discrete/raster NFP는 정수 좌표에 천연 적합.
Bottom-Left-Fill (BLF) 디코더
피스를 하나씩 "가장 아래 → 그다음 왼쪽" 가능 지점에 배치 (Burke et al. 2006). 순서+방향 시퀀스가 주어지면 결정론적·저렴.
메타휴리스틱의 내부 루프로 이상적 — 메타휴리스틱은 (순서, 방향)만 탐색하고 기하 배치는 BLF가 맡는다.
순서·방향 메타휴리스틱 (GA / SA / Tabu / GRASP)
피스 시퀀스 + 방향을 SA/GA/tabu로 탐색, 디코더는 BLF. Burke의 BLF + tabu/hill-climbing이 정석 조합.
솔버 불필요·CPU/시간 예산에 맞춰 튜닝 자유.
Separation / Compaction (jostling)
겹친 상태에서 시작해 평행이동으로 밀어내 분리·압축. sparrow의 "exploration → compression"이 현재 SOTA.
Raster / Grid 비트마스크 배치
베이를 정수 그리드로 이산화, 충돌 비트마스크로 패킹.
정수 좌표 + 이산 방향엔 이게 가장 단순·빠름. NFP 부동소수점 robustness 버그를 회피, NumPy로 벡터화.

솔버 없는 파이썬 구현 권고
  1. 이산 NFP/IFP를 한 번만 precompute — 고정 방향 집합 + 정수 그리드라 유한·캐싱 가능. 단일 최대 속도 레버.
  2. 정수 raster/비트마스크 충돌을 NumPy로 — NFP 부동소수점 고통 회피.

  5. 먼저 읽기: Bennell & Oliveira, "The geometry of nesting problems: A tutorial" (EJOR 2008) — raster·삼각법·NFP·phi-function 한 번에 비교.
S

조선소 블록 공간 스케줄링

Spatial Scheduling Problem (SSP) / Block Stockyard — 이 대회와 가장 가까운 실제 연구 분야 (한국 OR/IE 학계·조선사 다수 논문)

🎯
우리 문제는 곧 "공간 스케줄링 문제 / 블록 적치장 배치 문제"다 — 2D 패킹(네스팅) + 납기 기반 스케줄링의 결합. 현대중공업·삼성중공업·대우조선·한화오션 + SNU/KAIST가 30년 가까이 다뤄온 문제다. 바퀴를 다시 발명할 필요 없다.

핵심 논문 (알고리즘 중심)

Park, Lee, Park & Kim (1996) — 공간 블록 스케줄링 기초 논문
분해(decomposition) + 부분 열거 스케줄링 + 휴리스틱 공간 할당 탐색. 공간·일정 동시 처리. Computers & Industrial Engineering 30(3).
Koh, Park, Choi 등 — GA 동적 블록 배치
블록 배치 시퀀스를 GA로 인코딩 → 2D 배치로 디코드. "시퀀스 GA + greedy 배치 디코더"의 전형.
Liu, Chua 등 (2015) — 대형 조립 블록 공간 스케줄링
2단계 휴리스틱: 디스패칭 우선순위 규칙 + diagonal-fill (BLF 변형) 공간 할당.
(2021) 비정형 블록 공간 스케줄링
GA + SA 하이브리드, 정점배치 + bottom-left moving 규칙으로 비정형 폴리곤 디코드.
Roh / Cho 등 (2017) — 빈 공간·미배치 블록 고려
명시적 free-space 관리 + 아직 안 들어가는 블록의 지연(deferral) 처리 → 우리의 −1 회피와 직결.
Cheon, Woo 등 (2020) — DRL로 재배치 최소화
미래 relocation(간섭 블록) 최소화하도록 배치를 학습. 단, 평가서버 GPU 없음 → 추론만 CPU 가능 여부 검토.
Xie 등 (2025) — 적치장 레이아웃 적응 동적 스케줄링
이진탐색트리 free-space 레이아웃 + DRL. 실데이터에서 간섭 이동 ~56% 감소.
(2023) 블록 배정 matheuristic / (2024) rolling-horizon 스케줄러
배정 레이어에 MIP+휴리스틱 결합 / situ-aware 롤링호라이즌 — 시간축 분할 패턴.

공간+시간 결합의 반복 패턴

시퀀스 + greedy 디코더
메타휴리스틱은 블록 순서만 탐색, 결정론적 배치기(BLF·diagonal-fill·NFP)가 기하 실현. 이 분리가 솔버 없는 레버.
시간축 BLF / 롤링호라이즌
ENTRY/EXIT를 이벤트 시각(다른 블록의 EXIT)에 스냅, 호라이즌 전진, 활성 집합만 재패킹.
Free-space 리스트 — defer-not-fail
빈 사각형 추적, 못 넣는 블록은 실패 대신 ENTRY 지연. infeasible을 절대 안 만든다 (Roh 2017).
시간-공간 분해
베이 배정 고정 → 베이별 2D패킹 + 1D tardiness 독립; 혹은 일정 고정 → 패킹. 반복.
이전될 아이디어
  1. EDD/우선순위 디스패치 + 활성 시간창 한정 BLF — 베이스라인의 EDD+best-fit을 BLF/diagonal-fill로 업그레이드 (Liu 2015).
  2. 시퀀스 기반 메타휴리스틱 + 기하 결정론 디코더 — GA/SA를 블록순서·베이선택에만 씌우고 배치는 빠른 결정론 배치기. 견고·솔버 불필요.
  3. 크레인 접근 = 역시간/LIFO 배치 — 컨테이너 relocation 로직 차용: 블록의 EXIT가 "위에 있는" 공존 블록 이동을 요구하지 않도록 retrieval 순서로 배치.
  4. defer-not-fail: 못 넣으면 ENTRY를 미뤄서라도 항상 feasible → −1 페널티 직접 방어.
  5. 3-항 목적함수의 시간-공간 분해: 베이배정(Z2 불균형·Z3 선호 견인) 고정 → 베이별 2D패킹+tardiness(Z1) → 재배정 반복으로 부하 균형.
⚠️
주의: 공개된 OGC 2024/2025 솔루션 레포는 못 찾음. OGC 2024는 번들배송 라우팅 문제(다른 도메인)라 writeup 전이 안 됨. → 직접 만든 베이스라인 + 위 SSP 논문이 최선의 출발점.
E

Tardiness 스케줄링 · 메타휴리스틱 엔진

디스패칭 규칙 cheat-sheet + 실제 탐색 엔진 (ALNS) + 무료·오프라인 도구

납기 디스패칭 규칙 — cheat-sheet

규칙우선순위언제 이기나
EDD최소 dj작업 길이 비슷·tardiness가 순서지배일 때. max-tardiness 최적, 총-tardiness엔 약함.
WSPT/SPT최소 pj (또는 pj/wj)과부하·혼잡 시(대부분 지연 → flow 최소화).
MDD최소 min(dj, t+pj)slack>0이면 EDD처럼, 이미 늦으면 SPT처럼. 단순·견고. 총-tardiness 강한 기본값 → bulletproof 폴백.
ATC(wj/pj)·exp(−max(dj−pj−t,0)/(k·p̄))일반 단일머신 가중 총-tardiness의 최강 규칙. WSPT↔EDD 보간. k≈1.5~4.5(slack 빡빡)·0.5~2(여유).
ATCS ★ATC + setup항 + 릴리즈 할인 exp(−max(rj−t,0)/(k₃·p̄))릴리즈 시각이 있을 때(우리 ENTRY≥R!) — 본 문제에 직접 매칭. Lee, Bhaskaran & Pinedo 1997.
실전 결론: ATCS를 주 constructive 휴리스틱으로(릴리즈+선호 가중 처리), MDD는 항상-feasible 폴백으로. k는 인스턴스 통계로 간단 grid 튜닝.

메타휴리스틱 프레임워크 — ALNS가 정답

왜 ALNS (Adaptive Large Neighborhood Search)인가
결합형 패킹+스케줄링은 ruin-and-recreate가 맞다 — destroy/repair가 ENTRY/EXIT/베이/위치를 자연스럽게 함께 재결정.
정석 레퍼런스: Shaw 1998 (LNS) · Schrimpf 2000 (ruin-recreate) · Ropke & Pisinger 2006 (ALNS, 적응 연산자 가중치 + SA식 수용).
연산자 설계
이웃: 인접쌍/블록 swap, insertion(작업→새 위치), time-shift. destroy: random, worst-tardiness removal, related/shaw-removal(같은 베이·겹치는 시간창).
SA / GRASP / Tabu — 언제
SA = ALNS 내부 수용 기준으로. GRASP = 무작위 greedy 다중 재시작(4코어 병렬에 자명). Tabu = 강하나 feasible 유지 어려움.
"항상 incumbent 보유" 요구엔 constructive-greedy + ALNS(SA 수용)가 실용 승자.

견고성 체크리스트 (timeout=−1 방지) — 점수 모델상 "가끔 천재적"보다 "항상 feasible"이 이긴다.
  1. feasible incumbent를 먼저 구성(EDD/ATCS+best-fit)하고 저장 후 개선 루프 진입.
  2. 하드 타임 가드: timelimit 읽어 90~95%에서 중단, 직렬화 여유 남김. time.monotonic()을 매 반복 체크.

  4. 개선 루프 전체를 try/except로 감싸 예외 시 저장 incumbent 반환 — 절대 crash 금지.
  5. 큰 인스턴스는 이웃·repair 노력 축소(graceful degradation). 빈/불법해보다 평범한 feasible.
  6. 고정 RNG seed + 반환 전 공식 check_feasibility 검증.
  7. 4코어 활용: 독립 무작위 재시작(GRASP) 또는 병렬 ALNS 체인, best-feasible만 채택.
대회 우승 패턴 (ROADEF/EURO 등, 상용 MIP 없이)

최근 ROADEF 챌린지 우승자들(2020 Buljubašić&Vasquez, 2022 Fontan&Libralesso)은 ILS / ALNS + 문제특화 destroy-repair + 빠른 local-search + penalty-relaxation을 썼고 상용 MIP를 쓰지 않았다. → 우리 전략과 정확히 일치.

C

크레인 수직접근 제약

"위에 뭔가 쌓여 있으면 못 든다" (l2 ≥ l1 규칙) — 이 문제의 진짜 난점. 컨테이너 재배치 문제와 구조 동형.

유사 문제 + 핵심 레퍼런스

Block/Container Relocation Problem (BRP/CRP) — 가장 가까운 동형
"위에 쌓이면 못 꺼낸다" ≡ "타깃 위 블로킹 컨테이너를 relocate해야 한다". 기초 서베이 Lehnfeld & Knust 2014(EJOR). Beam search + dominance 하한 da Silva 2022 (arXiv:2206.12303).
Pre-marshalling — 우리의 ENTRY 순서결정과 직결
미래 retrieval을 막지 않게 미리 재정렬. Tanaka(2018) iterative-deepening B&B, Tierney(2019) 대형 B&B.
3D bin packing + LIFO/접근성 (차량 적재)
배송 순서대로 relocation 없이 꺼낼 수 있어야. Gzara 2020(pallet loading, reachability), Pollaris 2021(multi-drop LIFO = 수직 클리어런스). 우리 EXIT 순서 = multi-drop LIFO.
Blocking / no-wait job-shop
ENTRY/EXIT 크레인 이벤트 순서결정 = alternative graph 상의 blocking 제약 시퀀싱 (Mascis & Pacciarelli 2002).

수직접근 feasibility 검사 — 효율 자료구조 (핵심). 모노토니시티(l2 ≥ l1만 문제) 활용:
  1. 레이어별 점유 비트마스크: (베이, 레벨)마다 정수 그리드 boolean raster. 겹침 = bitwise-AND, 존재 = (A & B).any() — NumPy uint64로 O(cells/64).
  2. "상위합집합" suffix-OR 마스크 (핵심): 각 레벨 L에 U[L] = (레벨 ≥ L의 모든 in-bay 레이어 footprint OR). 블록 i의 l₁ 추출 가능성 = i footprint AND U[l₁] (자기 기여 제외). all-pairs 대신 레이어당 AND 1회.
  3. 증분 유지: ENTRY/EXIT는 한 블록의 K 레이어만 건드림 → suffix-OR을 해당 블록 top 이하 레벨만 재계산.
  4. raster AND 전에 bbox / cell-list 사전필터.
솔버 없는 처리 아이디어
  1. EXIT를 CRP retrieval처럼 — (x,y,o,ENTRY,EXIT) 후보를 "미래 공존 블록 중 상위 footprint가 겹치는 수(=blocker)"로 채점, blocker=0 우선. BRP look-ahead 하한의 직접 포팅.
  2. Pre-marshalling식 ENTRY 순서: 키 큰(레이어 多)·EXIT 늦은 블록을 footprint-disjoint 영역에 → suffix-OR 마스크 sparse 유지.
  3. Bounded beam search(이벤트 순서) — alternative graph 노드=부분 ENTRY/EXIT 순서, (tardiness + 위반수) 상위 beam만 확장, suffix-OR로 prune. arXiv:2206.12303 직접 적용.
  4. LIFO 시간창 → precedence: A footprint가 B 레벨 위에 있으면 ENTRY(A)·EXIT(A)를 B 기준 선후관계로 → 기하 제약을 위상정렬 가능한 일정 precedence로 변환.
  5. 레벨별 skyline 배치: 기존 footprint 위로 상위 마스크를 가장 적게 올리는 곳에 신규 블록 → 추출 경로를 구성적으로 확보.
