§2 핵심 설계 — Fixed-Time Decode (발상의 역전)
기존 파이프라인

"배치하고 → 가능한 시간을 찾는다"

크레인 직렬화가 사후에 발견되고, 수리(Phase 2)가 실행 시간의 51%를 소비. z1≈0까지 평균 ~131초.

FastFloor

"시간을 먼저 고정하고 → 위치만 찾는다"

entry=R, exit=R+P → z1=0 by construction. 위치탐색만 남아 20초 내 풀이.

왜 빠른가: 크레인 검사는 이동 순간에만 필요. 시간이 고정되면 쌍별 시간관계가 상수가 되어, 시간이 안 겹치는 쌍은 기하 제약이 아예 없음 (같은 자리 재사용 가능). 베이는 시간상 75~94% 비어 있으므로 실제 제약 쌍은 소수.
설계 역전의 근거 — 결정적 실패: fast path 플래그 실험(v2a)에서 "예산 부족으로 빈 시간창에 강제 직렬 배치된 꼬리"가 영리한 조밀 패킹보다 z1이 좋았음 (역사적 s703 회귀 재확인).
파이프라인 — 6단계
①
z2+z3 정확 배정 (CP-SAT, 기하 없음)
~0.1s. 베이별 부하·선호도만 고려. 위치·크레인 제약 없이 최적 배정.
②
베이별 entry-target (cumulative 완화) + 과적 spill
각 블록의 목표 시작 시각 계산. 베이 용량 초과 시 타 베이로 spill.
③
Fixed-time 디코드 (베이 4코어 병렬)
abut 후보 → 전체 그리드 스캔 폴백 → 지연 폴백 → 빈-창 강제. 보수적 per-layer raster 술어 5종, 채택 시 직접 rasterize 재검증.
④
크로스베이 fixed-time 재배치
잔여 tardy 블록을 타 베이 기존 레이아웃에 R시각 그대로 삽입. 순이득 게이트: −w1·Δz1 + w3·Δz3 < 0 조건 충족 시에만 채택.
⑤
CP-SAT 재타이밍 (레이아웃 고정 최적)
위치는 고정, 타이밍만 재최적화. v3에서 "현 레이아웃 타이밍 이미 최적" 증명 → 잔여 레버=위치/배정 확인.
⑥
공식 check_feasibility 게이트 + best-of 경쟁
기존 _decode_bay best-of 시도들과 베이별 best-of 경쟁 (안전망).
§3 실험 궤적 (v1 → v4)

§5 유의 (정직하게)
이것은 "초기해(floor)"다. obj 비교에서 경쟁자 최종해를 이기는 게 목적이 아님. 남은 ~90% 시간이 z3 본 게임(Front B 등)에 들어가는 것이 새 아키텍처의 골자.

z3 비용

xbay 재배치가 선호를 z1과 교환함. 예: prob_12 z3 859→2,450. 단 z1=0 유지 하에 Front B relocate가 회수 가능한 영역.

런 간 변동

prob_13 스모크 4 vs full-20 52 — 병렬 디코드 타이밍 비결정성. 단일 캡처 신뢰 금지 (프로젝트 룰). 채택 판정은 paired full-20 필요.

로컬 환경 낙관 가능성

워커·CP-SAT 전부 4 고정 (평가서버 4코어 미러)이나 로컬 20코어라 경합 없음. 벽시계 ~10~20% 낙관 가능.
