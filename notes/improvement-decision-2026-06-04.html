한 줄 결론

34편 리서치가 가장 강력히 권고한 L1(full combinatorial Benders)을 우리는 1순위로 두지 않는다. 그 핵심 이득은 이미 존재하는 M4 cut 기계장치로 값싸게 취하고, 즉효성 있는 dispatch/tie-break 개선을 먼저 실행한다.

리서치가 가장 강력히 수렴한 권고(L1 = full combinatorial Benders로 CP-SAT를 감싸기)는 우리 코드베이스에는 1순위가 아니다. 우리는 L1의 정신(infeasible 그룹핑을 다시 못 고르게 하는 no-good cut)만 이미 존재하는 M4 cut 기계장치로 값싸게 취하고, 즉효성 있는 dispatch/tie-break 개선을 먼저 한다. 모든 변경은 floor+gate 안에서 −1 불가능.

KEY REVERSAL — 왜 리서치 1순위(L1 full)를 1순위로 안 하나

이 섹션이 이 문서에서 가장 중요하다. 코드 정찰(code-analyzer)이 드러낸 3가지 사실로 L1 full 형태를 명시적으로 보류한다.

코드 증거 3가지

1
_cpsat_assignment는 build-once-solve-once 구조다. myalgorithm.py:686-763
CpModel / CpSolver / x 리터럴이 전부 함수 로컬 변수로 선언되어 있으며, 함수 반환 후 즉시 파괴된다. AddBoolOr no-good cut을 붙일 표면도, 증분 재해결(incremental re-solve)도 없다. Benders master로 사용하려면 solver 인스턴스를 stateful 객체로 전면 재작성해야 한다.
2
현재 master는 assignment 전용이고 timing/Z1 항이 없다. myalgorithm.py:723 (목적식 c2·z2 + c3·pref)
목적식에 ENTRY/EXIT 정수변수가 없고 Z1(tardiness) 항도 없다. Benders timing-master로 기능하려면 entry/exit 정수변수와 timing relaxation을 새로 도입해야 한다. 이는 CP-SAT 모델의 major rewrite에 해당한다.
3
ROI가 낮다 — assignment는 이미 gap=0이다.
milestone-status.md 진단: CP-SAT가 21개 인스턴스 중 19개에서 배정 수준 최적을 증명(gap=0.0). 이는 곧 현재의 timing-free master가 이미 gap 0이라는 뜻이다. Benders master를 재작성해도 나머지 2개 + congested 케이스에서만 도움이 된다. high-effort, low-headroom.
결론: full Benders는 KILL (이 코드, 이 헤드룸에서). 대신 그 정신을 P1으로 값싸게 실현한다: _find_slot_crane_safe의 rejection booleans에 이미 계산되어 있는 충돌 블록 데이터를 cut_store / op_cut_destroy에 minimal no-good cut으로 공급. CP-SAT 재작성 없이 "infeasible 그룹핑 재채택 금지"를 달성한다.

P별 상세 카드

Tier 1 (P1~P3) + Tier 2 (P4~P5) 각각에 대해 무엇/왜/어떻게/근거 논문을 기술한다.

P1
크레인 conflict-set → no-good cut
기존 M4 기계장치에 공급
MODERATE L1 · L5의 buildable 형태 −1 SAFE TIER 1
무엇

_find_slot_crane_safe(:298)가 실패 시 반환하는 (None, None)을 넘어서, 실패를 유발한 충돌 블록 집합을 tight하게 추출하여 기존 cut_store / op_cut_destroy(:855-1067, M4)에 minimal no-good cut으로 공급한다.

왜

_decode_bay는 현재 coarse forced_ids만 기록(:392-396)한다. 그런데 어느 블록이 거부를 유발했는지의 데이터는 rejection booleans (obs_new_entry / retro_entry / collide, :258-269)에 이미 계산되어 있고 단지 버려지고 있다. 이 데이터를 tight한 conflicting block id 집합으로 뽑아 기존 M4에 공급하면, CP-SAT 재작성 없이 "infeasible 그룹핑 재채택 금지"를 달성할 수 있다. 이것이 L1 Benders의 정신을 값싸게 구현하는 방법이다.

어떻게

1. _find_slot_crane_safe가 실패할 때 충돌에 직접 관여한 블록 id 집합 S를 반환값에 추가 (또는 side-effect로 전달).
2. _decode_bay가 이 집합을 받아 cut_store에 minimal no-good cut으로 등록.
3. M4 op_cut_destroy가 기존 메커니즘대로 이를 적용해 해당 그룹핑 재채택을 차단.
4. feature-flag OGC_CONFLICT_CUT(신규)로 격리.

근거 논문
Mao et al. 2024 — Combinatorial Benders for Single Machine Scheduling + 2D Packing (EJOR) Verstichel et al. 2015 — Combinatorial Benders for Lock Scheduling (COR) Hooker 2007 — Planning and Scheduling by Logic-Based Benders (OR) Avgerinos et al. 2025 — One Benders Cut to Rule All Schedules in the Neighbourhood (EJOR)

※ 위 논문들은 full master 재작성의 근거가 아니라 cut 설계의 영감으로 인용. 우리는 이 논문들의 no-good cut 구조만 차용하고, Benders master 재작성은 KEY REVERSAL에서 명시적으로 보류.

P2
gate/banking 버그 근원 수정:
크레인-violation tie-breaker
EASY L5 −1 SAFE TIER 1
무엇

동점 목적값(quick_obj) 이동에서 크레인-violation이 적은 레이아웃을 선호하는 tie-breaker를 삽입한다(:1143-1149 근방). 서치가 feasibility 쪽으로 표류하도록 유도하여 OGC_PROTECT_SEED banking(:2166) 의존을 구조적으로 줄인다.

왜

알려진 버그(:2140-2155): 서치가 같은 quick_obj지만 크레인 infeasible한 레이아웃으로 변형 → gate 기각 → floor 추락. 현재는 OGC_PROTECT_SEED로 방어적 banking만 하고 있다. 그러나 banking은 근본 원인이 아닌 증상 억제다. 서치 자체가 feasibility-preserving 방향으로 이동하도록 tie-breaking 우선순위를 부여해야 banking 의존을 낮출 수 있다.

※ 서치는 이미 TRUE decoded objective를 최적화한다(_obj_of_results :816/:1143). "서치가 proxy를 쓴다"는 통념은 틀렸고, 문제는 gate/banking 층에 있다.

어떻게

1. 이동 수락 기준에서 delta == 0 (동점)인 경우, 해당 후보의 크레인-violation 카운트를 secondary key로 비교.
2. violation이 적은 쪽을 선택하도록 수락 함수에 1줄 조건 추가.
3. violation 카운트는 _decode_bay가 이미 rejection booleans에서 계산 가능.

근거 논문
Schäfer et al. 2022 — Bounded Beam Search for BRP: violation lower bound as tie-breaker Feillet et al. 2019 — Local-Search for Unrestricted BRP: feasibility-preserving state space
P3
ATCR 시드 순서를
_orderings의 3번째 후보로 추가
EASY L5 −1 SAFE TIER 1
무엇

_orderings(:414-420)에 ATCR(Apparent Tardiness Cost with Release dates) 우선순위 지수 정렬을 3번째 후보 시드 순서로 추가한다. weighted tardiness + release date 인스턴스에서 EDD보다 우월한 dispatch 규칙으로, w1-congested 케이스에서 floor 품질을 높인다.

왜

현재 _orderings는 EDD와 balanced를 포함하지만, w1-지배 + congested 인스턴스에서 단순 EDD가 타이밍/릴리즈 날짜 상호작용을 놓친다. ATCR 지수(w_j · exp(-max(0, d_j-p_j-r_j-t_now) / (k·avg_p)))는 릴리즈 날짜와 지연 비용을 동시에 반영해 더 나은 시드를 만들어 준다. deterministic, gate-protected, −1 위험 0.

어떻게

1. _orderings 목록에 ATCR 정렬 람다 1줄 추가.
2. k(lookahead factor)는 인스턴스 밀도 기반 기본값 설정 (초기 k≈1.5 탐색).
3. feature-flag 불필요(기존 orderings 패턴과 동일 구조).

근거 논문
Modified ATCR rule (2025, COR:107097) — fixed/variable cost tardiness, release dates Jouglet & Savourey 2011 — Dominance rules for parallel machine weighted tardiness with release dates
P4
소형 베이 한정 per-bay joint
(x,y,ENTRY,EXIT) 정밀화
HIGH effort L3 −1 SAFE TIER 2 DEFER
무엇

CP-SAT 배정 후 잔여 시간 예산에서, 블록 수 ≤30인 소형 베이에 한해 연속시간 MILP (Pazhooh 2025 참고)를 베이별로 실행해 (x,y,ENTRY,EXIT) 공동 최적화. L3의 값싼 슬라이스.

왜 DEFER인가

우리 dense 인스턴스는 베이당 40~60 블록이므로 "≤30 소형"이 드물다. 적용 범위가 제한적이어서 score-flow 개선은 있지만 −1 회피에는 기여하지 않는다. full NFP 연속 MILP는 우리 밀도에서 intractable이라 제외(KILL-D). Tier 1이 착지하고 시간 예산이 남을 경우에만 시도.

KILL 목록 — 명시적 보류 및 사유

결정 문서의 중요한 역할은 "하지 않는 것"을 명문화하는 것이다. 아래 각 항목은 리서치에서 강력히 권고되었으나 우리 코드/헤드룸/목표에 맞지 않아 명시적으로 제외한다.

KILL-A: Full combinatorial Benders master (L1 문헌 원형)

high-effort 재작성 + assignment 이미 19/21 gap=0 → 나머지 2개 + congested 케이스에서만 도움. CP-SAT가 build-once-solve-once(myalgorithm.py:686-763)라 AddBoolOr no-good cut 표면 없음. 목적식에 Z1 항 없어 timing-master가 되려면 major rewrite 필요. 정신만 P1으로 값싸게 취한다.

KILL-B: Tchebycheff MOEA / MO-ALNS/D (L4 원형)

인스턴스별 (w1,w2,w3)가 이미 주어져 있다 — Pareto front를 찾을 필요가 없다. 주어진 가중치로 단일 스칼라화 목적을 최적화하면 된다. Tchebycheff는 가중치를 모를 때(또는 의사결정자가 사후에 선택할 때) 유용하다. 우리 설정에는 해당하지 않는다.

KILL-C: Skyline/jostle 재패킹 + packing-height-as-Z1 (L2 원형)

서치는 이미 TRUE decoded objective를 사용한다(_obj_of_results :816/:1143). packing height와 우리 tardiness Z1 사이의 상관이 약하다(직렬화가 더 나을 때가 있음 — decode-acceleration 실험에서 확인). 유용한 부분(true objective 사용)은 이미 구현되어 있다.

KILL-D: Full NFP 연속 MILP per bay (L3 원형)

우리 dense 인스턴스는 베이당 블록 수가 40~60개에 달한다. NFP-CM-VS(Lastra-Díaz 2024)는 최대 27조각까지 1시간 내 최적을 증명하므로, 40~60 블록에서는 시간 예산 내 수렴이 사실상 불가능하다. ≤30 소형 베이 한정의 DEFER 버전(P4)은 조건부 검토.

KILL-E: 0-개선 ALNS 4코어 fan-out (OGC_PARALLEL_MS 기본 ON 형태)

모든 트레이스에서 op_improves = [0,0,0]. ALNS가 개선을 못 찾는 것은 assignment 수준에서 이미 최적이기 때문이다 — 같은 0-개선 ALNS를 4개 돌리면 4배의 CPU 낭비만 발생한다. P5(진짜 다양화)와 구분해 이 형태는 기 결정 KILL 유지.

가드레일 — 모든 변경 공통

아래 4가지 원칙은 P1~P5 모든 변경에 적용되며, 어느 하나라도 위반하면 변경을 차단한다.

  • feature-flag + kill-switch. 모든 새 기능은 기존 OGC_* 환경변수 패턴으로 격리한다. P1 → OGC_CONFLICT_CUT(신규), P2 → tie-break 인라인 조건(flag 불필요), P3 → orderings 목록 추가(flag 불필요), P4/P5 → 각 신규 flag. kill-switch 비활성화 시 현재 동작과 bit-identical.
  • floor+gate 보존 → 새 서치는 candidates.append(...)로만 추가. 어떤 변경도 기존 floor 승격 경로(:2256-2317)와 gate 검증 구조를 건드리지 않는다. 새 서치 결과는 항상 후보 풀에 추가만 하고, gate가 최종 선택 — 이 구조가 −1을 구조적으로 불가능하게 만든다.
  • 회귀 검증: example 1022.70 bit-identical + gen 17개 + dense stress + 0 timeout. P1~P5 각 단계마다 독립 회귀를 돌린다. example은 증명된 전역 최적(1022.70)이므로 소수점까지 bit-identical을 요구한다. gen 17개 전부 feasible, timeout 0, 기존 개선 수치 유지.
  • 코딩 직전 /confidence-gate → 구현 후 /validate + verifier → 머지 전 /parallel-review. 5점 준비도 체크(중복 구현 없음·아키텍처 적합·문서 근거·작동 레퍼런스·명확성) <70%면 멈추고 재검토. 구현 후 lint→unit→integration 실제 명령으로 실행(mock 금지). verifier가 증거(테스트 통과·요구사항 충족·미검증 가정·증거)로 done 확정.
