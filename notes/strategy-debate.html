페르소나 소개

A The Theorist — 이론가

문제의 수학적 구조를 깊이 파고드는 원리주의자. 다항시간 부분문제, dominance rule, 폴리헤드럴 분석, Lagrangian decomposition, Benders, column generation. "왜 이 휴리스틱이 원리적으로 좋은가?" 를 물음. 답이 "경험상" 이면 거부.

B The Pragmatist — 실용주의자

대회를 이길 인프라를 우선시. 시간 모니터링·메모리 가드·재현성·인스턴스 다양성 대응이 알고리즘만큼 중요. 점수공식 R−nb 의 비대칭성 을 전략적으로 활용. "이 아이디어, 본선 D-1 에 깨지면 어떡할 건가?" 를 물음.

C The Contrarian — 반대자

모든 가정을 의심하는 이단아. 평균 클로드가 반드시 내놓는 답 ("패킹/스케줄링/할당 분리 후 LNS + SA + MIP 하이브리드") 을 직교한 각도에서 공격. 평균 클로드가 안 하는 것: 가정 자체 뒤집기. A, B 의 약점을 찾는 게 일.

Round 1 독립 초안

세 에이전트가 서로의 의견을 모르는 상태로 각자 전략 초안을 작성. 메인 컨텍스트는 결과 수집만.

A The Theorist · Round 1 전략 초안

핵심 통찰

  1. j ≥ k 크레인 규칙은 layer-graph 위의 partial order 다 — 단순 packing 이 아니다. 한 베이의 시간 t 에 점유 중인 블록 집합 N(t,j) 가 있을 때, 임의 블록의 ENTRY/EXIT 는 상위 레이어들의 footprint 합집합 에 의해서만 막힌다. 각 (블록 i, 레이어 l) 페어에서 H_l^i := 블록 i 의 레이어 l 위쪽(l' ≥ l) footprint 합집합을 미리 계산하면, ENTRY/EXIT 검사는 사전 계산된 폴리곤 쌍 검사 로 환원된다. 베이스라인은 매번 raw layer 쌍을 Shapely 로 intersect 하는 O(K² · pairs) 짓을 한다.
  2. Z2 가 max 라는 사실은 베이 배정이 single-bottleneck 문제 임을 의미. Z2 = max_{j1≠j2} |u_j1 L_j1 − u_j2 L_j2|. 임시로 tardiness 와 선호도를 무시하면 LP relaxation 이 매우 강한 fractional balance 를 준다. 최대 부하 베이를 한 단계 가볍게 하면 바로 w2 만큼 점수 하락 — 이 lever 를 LP-dual 로 정확히 알 수 있다.
  3. 선호도 합 = 100 은 분포 정보 를 인코딩한다. S_i = [100, 0, ..., 0] 이면 강제 배정 신호, [50, 50] 이면 무차별. H_i = S_max − S_2nd 큰 블록 = 절대로 양보 안 되는 블록 — dominance rule 로 먼저 고정.
  4. Z1 (tardiness) 은 due date 기준 비대칭 cost, EDD 가 best 인 조건이 있다. 단일 머신·spatial 무시면 1||ΣT — NP-hard지만 EDD 가 Pareto-optimal sequence subset 생성 (Carlier-Pinson dominance). 다중 베이 + spatial 이면 EDD 가 깨지는 정확한 조건: Σ workload > Σ available bay-time 인 베이가 등장할 때. 베이별 capacity envelope 를 먼저 계산 → capacity tight 한 베이는 LP/MIP, 여유로운 베이는 EDD greedy 로 차별화.
  5. 반-열린 시간 구간 [a,e) + EXIT-before-ENTRY 규칙은 hidden layer-decomposable structure 를 만든다. 시간을 epoch event 로 압축 → event-driven step function. interval graph + crane-precedence DAG 가 자연스럽게 정의되고, 이 DAG 의 topological dimension 이 곧 layer-stacking 어려움의 measure. 인스턴스가 low DAG width 이면 MIP 강력, high width 이면 LNS 유리.

제안 알고리즘 골격 — HIPS (Hierarchical Instance-aware Polyhedral Solver)

Layer 0 — Instance Profiling (≤ 5초, deterministic)
  • 각 베이의 u_j 계산
  • 각 블록의 envelope footprint area (모든 orientation 중 min bbox)
  • Capacity tightness ratio ρ_j = Σ_i (A_i · P_i) / (W_j · H_j · T_horizon)
  • Preference concentration H_i = S_max − S_2nd → H_i > 50 은 forced bay block
  • Crane-vulnerability score: max_l (footprint of layer ≥ l) / footprint of layer 0
  • DAG width estimate: T_horizon sampling 으로 동시 활성 candidate 수 추정
Layer 1 — LP-based Bay Assignment + Time Window (≤ 20%)

Decoupled MIP-A: 변수 x_{ij} ∈ {0,1} + t_i^E, t_i^X. 공간 좌표/방향 무시 → LP relaxation 강하고 Gurobi 가 분 단위로 해결. Z2 linearization: M ≥ u_j L_j ∀j, M ≥ −u_j L_j ∀j. Output: 각 블록의 후보 (j, [t_E_min, t_E_max], [t_X_min, t_X_max]) — fractional 해는 H_i 높은 블록부터 round.

Layer 2 — Spatial Placement with Crane-precedence Aware Heuristic (≤ 50%)
  • 블록을 t_E 오름차순 정렬
  • crane-vulnerability 기반 orientation 선택 (위가 가벼운 orientation 우선)
  • 사전계산된 H_l^i polygon 으로 ENTRY/EXIT 검사 O(1)~O(k)
  • Bottom-left fill 대신 NFP (No-Fit Polygon) 기반 candidate generation — Minkowski sum 으로 정확한 feasible region 경계만 enumerate. NFP completeness 가 최적 위치 누락 방지.
Layer 3 — Targeted Local Search (잔여 시간)
  • 전역 SA/Tabu 안 함 (평균 클로드 답변) — 대신 Lagrangian relaxation 기반 ascent direction
  • 현재 해의 active constraint dual 계산 (LP 재풀이 5초 이내)
  • λ_j 가 가장 큰 베이의 marginal 블록을 반대 sign dual 베이로 swap 시도
  • swap 후 재배치는 Layer 2 의 NFP placement 로 빠르게
  • 수직 통찰: dual 가 알려주는 correct direction 으로만 움직여서, random restart 불필요
Safety Net

모든 단계에서 직전에 feasible 했던 solution 을 메모리에 유지. 90% time 도달 시 즉시 반환. −1 절대 회피.

왜 이 접근이 점수를 올리는가

R−nb 점수 모델 하에서 결정적인 두 가지:

  1. −1 회피: Layer 0 + 0.5초 안에 항상 feasible fallback. 어떤 인스턴스에서도 −1 안 받음. 평균 R/2 점 확보.
  2. 다른 팀들이 못 찾는 deterministic improvement: 평균 팀은 LNS/SA 의 random walk 로 비슷한 국소최적에 수렴. 우리는 LP dual 이 가리키는 방향으로만 움직여서 strictly 더 나은 점에 도달. nb 가 1~2개 적어지는 효과.

특히 Z2 single-bottleneck — 다른 팀들이 같은 max 베이에 수렴할 가능성이 높다. LP dual 로 one block off swap 만 정확히 찾으면 strictly 더 좋은 점수.

약점 자인

  1. LP 정합도가 인스턴스 의존적: Z2 single-bottleneck 통찰은 베이가 적을 때 (m ≤ 4) 강력. 많아지면 max 가 여러 곳에서 tied → dual signal 약함.
  2. NFP candidate 계산이 무거울 수 있음: 비-볼록 폴리곤의 Minkowski sum 은 O(n_vertices²). 큰 블록 (K_i ≥ 5) 이 많으면 prebuild 시간 폭발.
  3. "DAG width estimate" 가 휴리스틱 추정에 불과: Layer 0 의 instance profiling 이 틀린 strategy 선택으로 가면 전 단계 nonoptimal.

B The Pragmatist · Round 1 전략 초안

점수 모델 활용 전략

핵심 통찰: R − nb 는 상한이 R 로 캡 된 비대칭 함수. 1위든 동률 1위든 같은 R 점, 그러나 −1 은 평균 R/2 ~ R 손실. 한 인스턴스 −1 = 다른 인스턴스 15~20등 → 1등이 보상해도 본전. 변동성을 1순위 적으로 본다.

"안전모드 vs 공격모드" 자동전환 — 3단계 솔루션 게이트
  1. S0: Safety Net (시간 5% 이내) — 강제 _force_place. 빈 베이 윈도우에 순차 배치. −1 절대 안 받음.
  2. S1: Baseline (시간 30% 이내) — 기존 greedyalgorithm. check_feasibility 검증, infeasible 이면 S0 폴백.
  3. S2: Improvement (남은 시간) — LNS/SA/MIP. check_feasibility 통과 + objective 가 S1 보다 엄밀히 좋을 때만 채택. 개선 실패 시 S1 그대로 반환.
"Best-of-K + 검증 게이트" 패턴

같은 timelimit 내에 seed 다른 greedy 3~4개 + LNS 1개를 병렬/순차. check_feasibility 통과한 것만 후보, 최저 objective 선택. 현재 베이스라인은 단일 trajectory 라 변동성에 약함 — best-of-K 는 분산을 줄이는 가장 싼 방법.

Z2 (max-imbalance) 의 함정

Z2 가 최대값이므로 한 베이 폭주 = 페널티 점프. w2 가 작으면 무시되어 한 베이 쏠림 → max 발산. 매 batch end 마다 current_obj2_predicted 추적 → 임계값 넘으면 다음 블록은 최소 부하 베이로 강제 ballast.

시간 미공개 → 어댑티브 배분
def profile_instance(prob_info):
    n_blocks  = len(prob_info["blocks"])
    n_bays    = len(prob_info["bays"])
    avg_poly_verts = mean(len(l) for b in blocks for s in b["shape"] for l in s["layers"])
    total_K   = sum(len(b["shape"][0]["layers"]) for b in prob_info["blocks"])
    return {"n": n_blocks, "m": n_bays, "verts": avg_poly_verts, "K": total_K,
            "complexity_score": n_blocks * n_bays * avg_poly_verts}
  • n_blocks ≤ 30 이고 timelimit ≥ 600s → "여유 큼". MIP 시도.
  • n_blocks ≥ 200 이고 timelimit ≤ 300s → "타이트". Greedy + 1 라운드 LNS 만.
  • complexity_score > 1e6 → Shapely 호출 비싸므로 polygon 캐시 사전구축 + 후보 위치 가지치기.

Wall-clock 자가 모니터링 — TimeBudget 클래스
class TimeBudget:
    def __init__(self, timelimit, safety_ratio=0.92):
        self.t0 = time.monotonic()
        self.hard_deadline = timelimit * safety_ratio  # 92% 에서 종료
        self.checkpoints = {"S0": 0.05, "S1": 0.30, "S2_LNS": 0.85, "S2_MIP": 0.70}
    def remain(self): return self.hard_deadline - (time.monotonic() - self.t0)
    def in_phase(self, phase): return (time.monotonic()-self.t0) < self.checkpoints[phase] * self.hard_deadline

평가서버 시계가 우리가 잰 것보다 빠를 가능성 (firejail/cpulimit) — 92% 안전마진은 협상 불가.

솔버 활용 전략

어디에 MIP 를 적용하나
  • Decomposition A: 시간 할당 MIP — 블록의 (bay, position, orient) 은 휴리스틱, MIP 는 ENTRY/EXIT 시각만. 베이스라인 Phase 2 의 사이클 문제를 깔끔히 풀어줌.
  • Decomposition B: 베이별 패킹 CP-SAT — OR-Tools 의 CumulativeConstraint + NoOverlap2D. 한 베이 quality 의 상한.
  • Decomposition C: 배정 MIP (소형 인스턴스 only) — n_blocks ≤ 40 이고 timelimit ≥ 600s.
솔버 우선순위 — 왜 셋 다 쓰나
  • OR-Tools CP-SAT: 무료/오픈소스, 가장 안전. 라이선스 실패 없음. 기본 솔버.
  • Gurobi: LP 완화·MIP 풀이 최강. 라이선스 활성화 됐을 때만. try-import + 라이선스 핑.
  • Xpress: Gurobi 실패 시 보조. race 가능.

C The Contrarian · Round 1 전략 초안

평균 클로드 답변 예측 + 왜 그게 약한가

평균 클로드는 거의 확실히 다음 한 줄로 요약된 답을 낸다:

"EDD greedy 시드 → LNS destroy/repair → 시간 남으면 SA 또는 Tabu, MIP 솔버(Gurobi/OR-Tools)는 베이 배정 또는 시각 subproblem 에 부분 적용, 4코어 활용해 여러 시드 병렬 후 최선택 — Phase 2 repair 를 더 똑똑하게."

이게 약한 이유 3가지:

  1. 베이스라인의 가정 구조를 그대로 답습 — "패킹/스케줄링/할당" 3분리, "그리디→메타휴리스틱 개선", "phase 2 보수" 라는 베이스라인의 프레임 자체를 의심하지 않는다. 베이스라인보다 수십 % 빠른 수렴은 되지만 질적 도약은 없음. 점수가 R-nb 라 조금 더 잘하는 100명이 같은 답을 내면 다 같이 중간 등수.
  2. "feasibility 우선" 을 잘못 해석 — "−1 회피 = 안정적 그리디" 로 받아들이고 공격적 탐색을 두려워함. 100명이 baseline-같은 평이한 점수면 동점 클러스터의 가운데에 박힌다. 클러스터를 위로 끊어내는 차별화가 필요한데, 평균 답변은 그걸 안 한다.
  3. MIP 솔버를 부분만 쓴다는 발상 — 베이별 단일 베이 패킹 MIP, 시각 결정 MIP. 하지만 Gurobi/Xpress 13.x 는 고전 작은 MIP 에 과한 무기. 전체 문제의 LP 완화 또는 Z1=0 강제 lex MIP 같은 더 큰 사용처를 평균 클로드는 생각 못한다.

직교 각도 제안 1: 분해의 축 바꾸기 — "Topology-first MIP"

베이스라인과 평균 답변은 블록 한 개씩 시간순으로 결정 (블록 → 베이, 위치, 시각). 정반대 제안:

위상(topology) 결정을 먼저, 전역으로, 닫힌 정수 모델로 푼 다음 그 위상 위에 기하·시각을 얹는다.

  1. "위상" 의 정의: 각 베이 안에서 어떤 블록이 어떤 블록의 위에 들어가는가의 부분순서 그래프. 크레인 수직접근 제약의 본질은 위상이다 — 모든 베이의 위상이 결정되면 진입/퇴출 순서도 자동 결정.
  2. 위상 + 베이 배정 통합 MIP: 위치/방향 추상화. 각 블록은 베이의 직사각형 영역 분할 슬롯 (2×2 또는 3×3 그리드) 중 하나. 결정변수 x[i,j,s] + y[i,i']. 목적함수에 Z1+Z2+Z3 모두 포함. 50~200 블록 인스턴스에서 4코어·5분 안에 정수해 또는 강한 LB.
  3. 위상 확정 후 기하 재구성: 각 베이의 위상이 정해지면 단일 베이 패킹으로 분리. 주어진 진입/퇴출 순서에 따라 폴리곤을 bottom-left fill 또는 NoFitPolygon 으로 채움.
  4. 단일 베이 패킹이 깨지면: 그 베이 안에서만 LNS — 위상 유지, 위치만 재배치.

왜 점수가 오르는가:

  • 크레인 제약을 원천 방지(prevention) 한다. 베이스라인이 phase 2 에서 고치는 것을 phase 0 에서 제약식으로 박는다.
  • Z2 (부하 균형) 가 위상결정 단계에서 전역 최적으로 풀린다.
  • 블록 9 같은 극단 선호 (prefs=[100,0]) 가 자동 처리.

직교 각도 제안 2: Z1=0 다양체 위 Lex-order

평균 클로드는 w1·Z1 + w2·Z2 + w3·Z3 를 한꺼번에 최적화. w1=2667 인 인스턴스에서도 Z1 한 단위 줄이려고 Z3 를 +133 까지 허용 — 한 블록을 100% 비선호 베이에 던지는 게 tardiness 1 줄이는 것보다 싸다. 정말 인스턴스 의도와 맞나?

  1. Stage A: Z1 = 0 강제 (모든 블록 due_date 안에 EXIT). 결정문제로 1~3분에 sat/unsat 판정.
  2. Stage A 가 SAT → Z1=0 해의 공간 전체에서 w2·Z2 + w3·Z3 만 최소화. 시간 박스 제약 안에서 작은 LNS/Gurobi.
  3. Stage A 가 UNSAT → MUS (Minimum Unsatisfiable Subset) — "어떤 블록이 반드시 늦어야 하는가" 의 최소 집합.

직교 각도 제안 3: 5-페르소나 앙상블

완전히 다른 철학의 5개 솔버를 4코어에서 시간 분할 실행, 마지막 1초에 5개 해 중 가장 점수 좋은 하나 선택.

  1. EDD-Greedy++ (베이스라인 강화) — 시간 25% — 최저 안전망
  2. Topology-MIP (제안1) — 시간 30%
  3. Lex Z1=0 (제안2) — 시간 25%
  4. Anti-EDD (역설적 정렬) — 시간 10% — 큰 블록 먼저 (LDD)
  5. Reverse-time backward scheduling — 시간 10% — due_date 에서 역방향

어떤 가정을 의심해야 하나

  1. "EDD 정렬이 최선의 시드" — 복합 목적함수 + 공간 제약에서 증명된 적 없음. 가중치를 보고 정렬 키 동적 선택이 더 적절.
  2. "phase 2 에서 보수하는 게 phase 0 prevention 보다 효율적" — baseline 의 cycle detection + force_place 가 자주 트리거되면 Z3 가 망가짐.
  3. "방향 8개를 완전 탐색하는 게 옳다" — 베이의 종횡비를 보면 방향 2~3개가 dominant. 학습/캐싱 안 하면 시간 낭비.
  4. "polygon 충돌은 Shapely 로 정확하게 검사" — 알고리즘 내부 탐색에서는 bbox 충돌 + grid raster 가 수십 배 빠르고 거의 같은 답.
  5. "한 솔버 한 번 호출" — 시간을 작은 호출 여러 번으로 쪼개고 해의 풀(pool) 을 유지하면 마지막 1초에 풀에서 최선 선택 가능.

약점 자인

  1. 슬롯 추상화 부정확성 — 큰 블록 (block 0 의 14.6×5.6 bbox) 이 슬롯 안에 안 들어갈 위험.
  2. CP-SAT 결정문제 timeout — 50+ 블록에서 5분 안에 sat/unsat 안 나오면 timeout → −1.
  3. 5 페르소나 시간분할 어려움 — 5개가 칼같이 분할은 어렵고, watchdog 스레드 등 추가 복잡도.

Pragmatist 에 대한 공격

공격 1: "Best-of-K" 는 확률적 동치류 안에서만 최적이라, R−nb 비대칭성을 정면으로 깨뜨린다

Best-of-K + LNS 는 본질적으로 같은 분포에서 K번 샘플링하고 최저값을 취하는 추정기다. K=4 라면 분포의 ~80th percentile. 5팀이 같은 LNS 계열을 돌리면 모두 비슷한 80th percentile 에 안착해 서로 동점. Pragmatist 의 K개 솔루션은 분포의 mode 근처에 몰리고, 이 mode 자체가 다른 팀들과 수렴. 살짝 더 나간 한 팀이 있으면 모두가 nb 1을 먹는다.

내 LP dual 방향은 결정론적으로 다른 다양체 에 도달. 같은 인스턴스에 100번 돌려도 같은 점에 수렴하지만, 그 점은 random walk 의 표본분포에 속하지 않는 점이다. R=30 가정하면 점수 차이가 25점에 이른다.

공격 2: "12h 쿨다운 학습신호" 는 온라인 학습 가정이라 정보 누설이 부족하다

자동회신 메일의 (점수, license_status, −1 율) 만으로 정보이론적으로 한 번 제출 ≈ 수 비트. 본선까지 5~6회 가능 추정 시 총 60비트 미만. 알고리즘 공간이 거대한데 60비트로 수렴한다는 가정은 통계적으로 약하다.

내 접근은 Layer 0 instance profiling 으로 인스턴스 자체에서 정보를 뽑는다. 한 인스턴스의 ρ_j, H_i, DAG width 가 수천 비트의 구조정보. Pragmatist 가 제출당 60비트로 학습할 때, 나는 인스턴스당 수천 비트로 적응한다.

공격 3: Fallback chain 은 최선의 솔루션을 버리는 결정규칙

Gurobi→Xpress→CP-SAT→휴리스틱 fallback 은 time budget 을 기준으로 끊는다. 그러나 점수공식상, 휴리스틱이 우연히 MIP 보다 나은 경우가 있다 (NP-hard 에서 자주). Fallback chain 은 "MIP optimal 이 있으면 그게 답" 이라는 암묵적 prior. 우리 문제는 LP relaxation 부터 fractional. Pragmatist 의 fallback 은 결합이 아니라 대체.

Contrarian 에 대한 공격

공격 1: "슬롯 추상화" 는 상승완화(relaxation)가 아니라 손실 모델

Topology-first MIP 가 2×2 또는 3×3 슬롯으로 위치를 추상화한다는 것은, 원래 문제의 feasibility set 을 부분집합으로 좁히는 것이다. LP relaxation 은 집합을 넓혀서 하한을 얻는 정당한 방법이지만, 슬롯화는 집합을 줄여서 상한을 얻는다 — 원래는 풀리는 인스턴스가 슬롯에서 UNSAT 일 수 있다. −1 위험 증폭 (Phase 2 repair 거부했으니 fallback 도 없다).

공격 2: Lex Z1=0 CP-SAT 결정문제는 결정 자체가 NP-complete

Stage A 의 "Z1=0 SAT/UNSAT 판정" 은 사실 결정문제 자체가 tardiness=0 단일머신 scheduling with release times + due dates + spatial constraint. 단일머신 만으로 NP-complete (Lenstra 1977). CP-SAT 이 결정문제를 몇 분에 풀 것이라는 가정은 incumbent 가 빨리 발견될 때만. UNSAT 의 경우 완전한 search tree 탐색이 필요해 timeout 위험 매우 크다. UNSAT 인스턴스에서 Lex Z1=0 는 MUS 도 못 뽑고 timeout → −1.

공격 3: 5-페르소나 앙상블은 상호상관(correlation) 무시

EDD와 LDD는 같은 due-date 정렬 역순이라 자료구조 차원에서 강한 음의 상관관계, 같은 노이즈에 같이 무너진다. Topology-MIP 와 Lex Z1=0 는 같은 CP-SAT/MIP 백엔드 의존이라 license 실패 시 동시 사망. 5개 페르소나가 강하게 상관되어 있다면 3개 페르소나의 expected min 과 큰 차이 없다. 시간을 5등분해서 5개 돌리는 게 3등분해서 3개 돌리는 것보다 못할 수 있다.

내 입장 방어 / 진화

예상 공격 1 (Pragmatist): "NFP 사전계산 비용이 timelimit 안에 끝나지 않아 −1"

대응: 부분 양보. NFP 비용은 큰 인스턴스 (n=100, 정점 50+) 에서 수십 초 가능성 인정. 진화: NFP 를 그래프 sparsification — H_i 가 큰 블록쌍만 사전계산, 나머지는 on-demand sliding 으로 lazy. Layer 0 에 NFP budget estimate 추가.

예상 공격 2 (Contrarian): "LP dual 방향은 한 점에 결정적으로 수렴하지만, 그 점이 모든 인스턴스에서 좋은 점이라는 보장이 없다"

대응: 이건 옳다. 진화: Layer 0 에서 instance class 를 격자로 분류하고, 클래스별 dual gradient step size η_c 를 오프라인 calibration. dual 방향 자체는 결정론적이되 step size 는 instance-class-conditioned. 사실상 piecewise-deterministic Markov decision 으로 진화.

예상 공격 3 (Pragmatist): "Layer 1 MIP 가 spatial 무시하면 Layer 2 에서 spatial UNSAT 발생 시 catastrophic"

대응: 양보 + 진화. Layer 1 MIP 에 aggregate spatial constraint 를 LP cut 형태로 추가 — 베이별 블록 면적 합 ≤ 베이 면적 · 0.85 (packing density 한계) + 시간 슬라이스별 면적 제약. Phase 2 repair 는 여전히 거부 — Layer 2 가 UNSAT 시 Layer 1 에 Benders cut 으로 피드백.

합의 가능한 점

  1. Pragmatist 의 timelimit 안전마진 (92%) — 코어 알고리즘은 안 바꾸고 wrapper 만.
  2. Contrarian 의 "Phase 2 repair 거부, prevention first" — 내 Layer 2 NFP 의 정신과 완벽 일치.
  3. Contrarian 의 instance profiling 의심 — 진화된 형태에서 dual step 이 class-conditioned 인 것은 이 의심에 답하는 것.

비합의 (의도적 분기)

  1. Best-of-K vs deterministic dual — 끝까지 갈라진다. K개 시드 random sampling 은 mode-collapse 한다. 본선 실측으로 결판.
  2. CP-SAT 결정문제로 Lex Z1=0 — 끝까지 거부. 결정문제 자체가 NP-complete 인 곳에 완전성 의존은 받아들일 수 없다.
  3. 5-페르소나 시간분할 — 분산 효과보다 한 페르소나의 wall-clock budget 이 결정적. 페르소나 앙상블은 거부.

공격 1: "Gurobi 90초" 는 평가서버에서 검증된 적이 없는 미신이다

Theorist 는 Layer 1 에서 LP-MIP Bay Assignment 를 "Gurobi 90초" 에 푼다고 단언하지만 이건 어디서 측정한 숫자인가? 본인 워크스테이션? OGC 평가서버는 4코어/16GB/인터넷 차단/firejail 격리. Gurobi Academic 라이선스는 온라인 검증 또는 로컬 토큰을 요구한다. gurobipy 가 import 되더라도 Model() 생성에서 라이선스 토큰 못 가져오면 GurobiError.

본선이 b=80 / B=8 / U=120 으로 오면 변수 수가 O(b × B × U) = 76,800 binary. 여기서 "90초 Gurobi" 는 희망사항. 평가서버 시간이 30분이라면 Layer 1 만 25분 먹고 Layer 2/3 못 돌리는 시나리오가 가장 그럴듯.

공격 2: NFP Minkowski sum 은 polygon 정점 ≥ 50 에서 메모리 폭발한다

NFP 는 두 polygon 의 Minkowski sum, 정점 수 m,n 에 대해 결과 polygon 정점은 최악 O(mn). 블록 80개, 층 5개, 평균 정점 30 이면 12,000 polygon, 각 100~300 정점, 3~5GB 메모리 가 Shapely C++ 힙에 잡힌다. 16GB 중 5GB NFP, Gurobi 가 3~6GB, Python interpreter 가 1GB — 어느 순간 OOM kill, 그 인스턴스에 −1.

본선 D-1 에 OOM 한 번 터지면 R≈30 손실. "원리적으로 빠르다" 는 평균 점수 +3~+5. 한 인스턴스 OOM 이 평균 +30 손실. 순수익은 마이너스.

공격 3: LP dual 기반 deterministic search 는 "제출 횟수 안에서 튜닝 불가"

Lagrangian dual 의 핵심 파라미터 (step size, dual update rule, swap candidate filter) 를 논문 default 로? 12시간 쿨다운 × 최대 R≈84 제출 중 몇 번의 제출로 dual hyperparameter 를 튜닝? 한 인스턴스에서 step 0.1 이 좋아도 다른 인스턴스에서 0.5 가 좋을 수 있다. 인스턴스별 적응 없이 deterministic search 는 random walk 보다 나쁠 수 있다 — random 은 적어도 variance 가 평균을 끌어올리는데, deterministic 은 한 방향 잘못 잡으면 끝까지 잘못 간다.

Contrarian 에 대한 공격

공격 1: 5-페르소나 시간분할은 4코어 16GB 환경에서 불가능에 가깝다

"EDD-Greedy++ 25% / Topology-MIP 30% / Lex Z1=0 25% / Anti-EDD 10% / Reverse-time 10%" — 30분 인스턴스에서 Topology-MIP 9분, Lex Z1=0 7.5분. 이 시간으로 MIP 가 풀리는 인스턴스가 몇 개나 되나? 5번 중 2번 발생하면 앙상블의 60% 가 dead code.

4코어 환경에서 5 페르소나 병렬은 코어당 0.8 페르소나 = 시분할이 실제로 일어나서 캐시 thrashing 으로 각자 직렬보다 느려진다. Gurobi 와 CP-SAT 을 동시에 돌리면 OMP_NUM_THREADS 충돌. 본인이 평가서버에서 한 번이라도 측정해봤나?

공격 2: Lex Z1=0 SAT/UNSAT 결정은 인스턴스의 80% 에서 UNSAT 다

Tardiness Z1=0 이 SAT 인 인스턴스는 어지간히 여유 있는 인스턴스. 베이 capacity tightness ρ_j > 0.85 인 인스턴스 (대회 인스턴스의 다수일 것) 에서는 Z1=0 이 수학적으로 UNSAT. UNSAT 증명에 CP-SAT 가 몇 분 걸릴 줄 알고? MUS 추출은 완전탐색 못지않게 비싸다. 이 페르소나는 인스턴스의 80% 에서 시간만 먹고 결과 0.

공격 3: "의심해야 할 5가지 가정" 멋있지만 실험비용 무시

Anti-EDD, Reverse-time 같은 backward search 페르소나 검증할 제출은 어디서? 5개 페르소나 각각 검증하려면 60시간, 거기에 앙상블 시간 분할 튜닝 — 본선 시작 전에 검증 못 끝낸다. 5 페르소나는 제출 횟수 예산을 복수 인스턴스 × 복수 페르소나로 곱셈 폭발.

예상 공격 1 (Theorist): "S0 → S1 → S2 게이트는 보수적이라 우승 못한다"

대응: 맞다. 게이트만으로는 우승 못한다. 하지만 우승 확률 5% × 1등 7천만원 = 기댓값 350만원이고, 중상위 안정 확률 60% × 3등권 1~2천만원 = 기댓값 600~1200만원. 순수 기댓값으로도 게이트 우선이 우월. 그래서 게이트 위에 "S3: 시간 여유 시 Theorist 의 Layer 1 또는 Contrarian 의 Topology-MIP 를 한 페르소나로 추가" 옵션으로 받겠다. 게이트 보수성은 floor, 그 위에 실험적 페르소나는 ceiling.

예상 공격 3 (둘 다): "솔버 fallback chain 은 어느 솔버도 안 풀리는 경우 대응 없다"

대응: 있다. 휴리스틱-only mode 가 S1 (베이스라인 greedy + Phase 2 repair). Gurobi/Xpress/CP-SAT 모두 실패해도 S1 은 항상 실현가능 해 반환. 솔버는 bonus 이지 필수 아님. 두 사람의 알고리즘은 솔버 실패 시 대체 경로 없다.

C The Contrarian · Round 2 반박

Theorist 에 대한 공격

공격 1: "LP dual 은 원리적 우위가 아니라 원리적 자기기만 이다"

Theorist 는 "LP dual 방향이 random walk 보다 원리적으로 우위" 라고 과감히 주장. 그러나 이 문제는 혼합정수 + 비볼록 (회전·NFP·계단 크레인) MINLP. 비볼록 MINLP 에서 strong duality 는 깨진다. Lagrangian relaxation 의 dual bound 와 primal 사이의 gap 이 시스템적으로 존재한다. 그가 LP dual 에서 잡는 multiplier λ 는 어떤 의미에서도 최적해 방향이 아니다 — 그건 완화된 문제의 최적해 방향.

우리 문제에는 dual 이 특별히 약한 구조: 크레인 j ≥ k 는 위상 구조. 위상 제약을 LP 로 완화하면 dual 은 위상을 못 본다. Layer 1 의 "spatial 무시 LP" 가 만드는 dual 은 공간이 곧 위상인 이 문제의 본질을 못 짚는다. 그의 LP-dual 은 사실 지도 없는 광야다.

공격 2: NFP candidate 가 매니폴드 위에 가둔다

NFP 는 깨끗한 폴리곤 쌍에서 효율적. 그러나 우리 문제는: 블록 회전 (0/90/180/270) → NFP 4×4=16 페어, 블록 N=수십 → O(N²) 페어 → 수백~수천 NFP. 사전계산이 무의미하다. 30분 timelimit 에서 NFP 만 돌리다 끝난다.

더 큰 약점: NFP 후보가 그를 고정된 매니폴드 위에 가둔다. NFP 후보 안에서 최적은 NFP 가 만든 매니폴드의 local minimum 이지 진짜 최적이 아니다. 매니폴드 자체를 뚫는 답 (동시 재배치로만 가능한 답) 을 원리적으로 못 본다.

공격 3: HIPS Layer 구조 자체가 평균 클로드 답변의 세련된 변종

Layer 0 (profiling) → Layer 1 (LP-MIP) → Layer 2 (NFP) → Layer 3 (Lagrangian local search). 이거 정확히 클로드가 처음 30초에 뱉을 답변의 정제판. "복잡한 문제는 단계로 분해하라" 는 클로드의 가장 강한 prior. 원리주의자인 척하지만 실은 평균 답변에 학술적 단어를 입힌 형태.

진짜 직교 답변은 Layer 구조 자체를 거부 — 시간을 역으로 푼다, 베이를 제거하는 방향으로 푼다, 블록 사이 원래 페어링을 깬다. 그는 이런 직교 각도를 단 하나도 제시하지 않았다.

Pragmatist 에 대한 공격

공격 1: "안정 중상위" 는 점수공식 R−nb 의 기하학을 오독한 전략

score = R - nb. 중상위 클러스터에 수십 팀이 동률로 묶이는 시나리오를 상상해라. 안정 중상위로 자리잡으면 nb 가 큰 채로 안정. 드물게 발생하는 인스턴스에서 클러스터를 끊고 위로 올라가면 nb 가 불연속적으로 줄어든다. R-nb 는 클러스터 경계에서 비선형적 보상.

Pragmatist 의 S0→S1→S2 게이트는 클러스터 경계 돌파를 적극적으로 막는다. "개선 없으면 S1 반환" 은 바로 그 클러스터에 영원히 머무는 정책. 그는 분산을 최소화했지만, R-nb 가 보상하는 건 분산이 아니라 우향 비대칭(right tail). 그의 전략은 risk-averse 인데, 점수공식은 risk-seeking 을 보상.

공격 2: 12h 쿨다운 학습신호는 학습이 점진적이라는 가정 위에 서 있다
  1. 레퍼런스 ground truth 가 없다. 평가서버는 점수만 돌려준다. 인스턴스별 디테일 없다.
  2. 나의 변경과 다른 팀의 변경이 동시 일어난다. R3 점수가 R2 보다 떨어졌다면 내가 망쳤는지, 다른 팀이 추월했는지 구분 불가.
  3. 제출 N=10~15회 — 가설검증 통계력 충분하지 않다.

그의 위험 매트릭스 10가지는 known known 만 본다. 체크박스 자체가 false sense of safety 를 만든다.

공격 3: Best-of-K + 솔버 fallback chain 은 직교가 아닌 단조(monotone) 앙상블

K개 후보가 서로 다른 perspective 가 아니면 K 배 시간만 쓰고 결과는 비슷. 그의 K는 "seed 다른 greedy 3~4개 + LNS 1개" — 모두 같은 매니폴드 (EDD-Greedy 기반). seed 다양성 ≠ 알고리즘 다양성. 솔버 fallback chain 도 redundancy 지 diversity 아님. 본선에 필요한 건 모델 자체가 다른 fallback.

내 입장 방어 / 진화

예상 공격 1 (Theorist): "슬롯 추상화 가 우리 데이터의 실제 폴리곤 다양성을 못 잡는다"

대응 + 진화: 양보 안 한다. 더 과감히 간다. Slot-MIP 가 답이 아니라 순서만 결정하게 만든다. Slot-MIP 는 "어느 블록이 어느 베이의 어느 순번에 들어가는가" 만 푼다. (x,y) 는 그 순번 안에서 별도 알고리즘 (bottom-left fill 또는 NFP local) 으로 결정. 핵심은 순서 자체를 MIP 로 푸는 것 — 평균 답변은 순서를 휴리스틱으로 결정하고 (x,y) 만 MIP 로 푼다. 나는 반대.

예상 공격 2 (Pragmatist): "5-페르소나 = 4코어에 5개 못 돌린다"

대응 + 진화: 5개 페르소나는 대회 기간 동안 제출 회차마다 다른 조합으로 돌린다. 한 제출에는 최대 2 페르소나만 활성. 페르소나 선택 자체가 학습되는 변수가 된다. 평가 점수 데이터에서 어느 페르소나 조합이 어느 인스턴스 유형에서 강한지 역추적. 마지막 제출은 가장 잘 작동한 2개의 조합.

예상 공격 3 (둘 다): "Lex Z1=0 가 SAT 이면 좋지만, 대부분 인스턴스에서 UNSAT 이면 fallback 도 없이 무너진다"

대응 + 진화: 정확히 그게 Lex Z1=0 의 본질적 정보다. UNSAT 자체가 strong signal. UNSAT 시 MUS 가 어떤 블록 집합이 본질적으로 늦는지 알려준다. 이 블록들은 Z1 을 0 으로 못 만드는 본질적 원인. 그러면 Z1 최소화 문제가 이 MUS 블록들만 신경 쓰면 된다. MUS 로 책임이 있는 블록과 무관한 블록을 분리. 정보량이 N차원에서 |MUS|차원으로 떨어진다. 이건 직교 각도.

합의 가능한 점

  1. TimeBudget 안전마진 + force_place fallback (Pragmatist) — −1 회피는 1순위.
  2. 인스턴스 profiling (Theorist 의 Layer 0) — 단, profiling 으로 전략 단계를 결정하는 게 아니라 페르소나 조합을 결정.

이 두 가지 외에는 내가 합의하면 내 페르소나가 죽는다.

  2. LP dual 방향 vs Topology-MIP 정수 방향
  3. EDD 가 최선의 시작점인가 — Anti-EDD (LDD) 를 적어도 한 페르소나로 유지.
  4. "안정 중상위" vs "클러스터 끊기" — Pragmatist 는 분산 최소화, 나는 우측 꼬리 두께 최대화.
  5. "문제를 정해진 도구 로 푸는가" vs "도구 자체를 의심하는가" — 시간을 역으로, 베이를 제거하는 방향으로, MUS 로 차원 축소 등의 각도 자체가 직교.

양보한다. 진화한다. "90초" 는 내 워크스테이션 직관. 평가서버 4코어/16GB 에서 b=80·B=8·U=120 인스턴스가 binary 76,800개를 시간 안에 풀 보장이 없다는 지적은 옳다.

진화: Layer 1 을 MIP-as-bound 가 아니라 MIP-as-anytime 으로 본다. Gurobi 를 최적해까지 돌리지 않고 MIPGap=0.05 + TimeLimit = min(0.15·timelimit, 90s) 로 조기 종단. 안 풀리면 LP relaxation 의 dual 값을 lower bound 로 사용. LP 는 4코어에서 b≤80 이면 단순플렉스로 5초. 내 골격은 'MIP 가 풀리면 강해진다' 가 아니라 'MIP/LP 의 dual 정보를 어떻게 쓰느냐' 로 바뀐다.

Pragmatist 의 "NFP 메모리 폭발" 공격에 답한다

부분 양보, 부분 방어. 12,000 polygon × 평균 200 정점 = 2.4M vertex 객체. 16GB 중 Python 인터프리터 1.5GB + Gurobi 3GB + NFP 5GB → OOM 임계.

진화: NFP 를 사전계산하지 않는다. AABB 가 겹치는 쌍에 대해서만 질의 시점에 Minkowski sum 을 계산하고 LRU(maxsize=2048) 로 캐싱. NFP 자체를 들고 있지 않고, 그 경계의 polyline 만 (정점 ≤ 30) 들고 있는다. 평균 메모리 800MB 이하. 동시점유 그래프가 sparse 하다는 사실이 핵심 근거.

Pragmatist 의 "dual hyperparameter 튜닝 불가" 공격에 답한다

거의 항복. 84회 제출 안에서 step size·update rule·swap filter 를 deterministic 하게 정하는 건 자기기만. 진화: dual step size 를 hyperparameter 가 아니라 LP optimal basis 의 reduced cost 비례 자동 결정. Polyak step rule: step_k = (UB_k - LB_k) / ||subgradient||². 수렴 정리가 있는 알고리즘적 선택. 튜닝 자유도가 1차원으로 줄어든다.

Contrarian 의 "dual = 자기기만" 공격에 답한다

부분 인정. Contrarian 이 옳다 — 비볼록 MINLP, strong duality 깨진다. 내가 LP dual 에서 얻는 건 증명된 lower bound 가 아니라 informed search direction. 이 차이를 분명히 한다: dual 은 해의 품질을 증명하기 위한 게 아니라, 어느 블록의 위치/시각을 흔들면 목적값이 떨어질지 예측하는 정보원이다.

그러나 "위상 구조를 LP 가 못 본다" 는 반박은 부분만 옳다. j ≥ k 위반이 만드는 재배치 요구를 cut 으로 LP 에 넣고, 그 cut 의 dual 값이 다음 라운드 search direction 을 바꾼다. 위상을 LP가 직접 못 보지만, 위상의 그림자를 dual 이 본다.

Contrarian 의 "NFP 매니폴드 가둠" 공격에 답한다

진지하게 받는다. NFP candidate 안에서의 최적은 그 매니폴드의 local minimum. 동시 재배치로만 도달 가능한 해를 못 본다.

진화: Layer 3 의 dual-guided swap 을 단일 블록 swap 이 아닌 2-블록·3-블록 simultaneous re-placement 로 확장. NFP 매니폴드를 국소적으로 뚫는다. 정직하게 — NFP 골격은 매니폴드 가둠의 위험이 본질적이고, 내 진화는 그걸 완화할 뿐 제거하진 않는다.

Contrarian 의 "HIPS 도 평균답변 변종" 공격에 답한다 — 가장 중요

일부 사실이다. 정직하게 인정한다. "단계로 분해하라" 는 클로드의 강한 prior. 내 HIPS 의 Layer 1 → Layer 2 → Layer 3 구조 자체가 그 prior 의 학술적 코팅. Contrarian 의 지적이 정통으로 꽂힌다.

그러나 완전히 평균답변은 아니다 — 평균답변은 "분해해서 차례로 풀자" 고 말한다. 내 골격은 "분해하되 각 층이 다른 층의 dual 정보를 역방향으로 받는다" 고 말한다. 층 사이의 정보 흐름이 양방향이라는 점 이 평균답변과 다르다.

그러나 이것도 결국 "양방향 분해 + dual coordination" 이라는 학술적으로 흔한 패턴. Contrarian 의 칼날이 한 겹 더 들어오면 여기도 베인다.

그래서 내 진정한 직교 각도는 다른 곳에 있다:

"OGC2026 의 진짜 어려움은 제약 위반의 확률 분포가 인스턴스 클래스마다 다르다는 데 있다, 알고리즘 구조가 아니라."

두 인스턴스가 똑같은 b·B·U 를 가져도, 어느 제약이 binding 인가 (크레인 vs 베이 경계 vs tardiness vs preference) 가 다르다. 평균답변은 알고리즘을 설계한다. 내가 진정으로 직교하려면 제약 위반 확률을 인스턴스에서 측정해서 알고리즘의 어느 부분에 자원을 쏟을지 결정 해야 한다.

구체적: timelimit · 0.05 를 probe phase 로 쓴다. 베이스라인 그리디를 5번 다른 시드로 돌려서 어느 stage 에서 실패하는지 빈도를 측정. 그 결과로 Layer 1·2·3 의 시간 배분과 dual 가중치가 인스턴스마다 바뀐다. 이게 내 직교 각도: 알고리즘이 아니라 알고리즘의 자가 진단.

최종 알고리즘 골격 (수정판)

Phase 0 (5% time) : PROBE
  - Baseline greedy 5 시드 → 어느 stage 가 binding 인지 측정
  - 인스턴스 클래스 추정 (tight-crane / tight-pack / tight-tardiness / loose)
  - Layer 시간 배분 + dual 가중치 결정

Phase 1 (20% time) : ASSIGNMENT + TIMING (Aggregated LP)
  - Gurobi MIP-as-anytime (MIPGap=0.05, TimeLimit=min(0.15·T, 90s))
  - Aggregate spatial cut : Σ area_i ≤ W_j·H_j·u_j·overlap_factor
  - LP relaxation dual 값 추출 → search direction λ
  - 안 풀리면 LP only → λ 만 사용

Phase 2 (50% time) : PLACEMENT (Lazy NFP + Probe-weighted ordering)
  - NFP 를 질의 시점에 계산 (LRU 2048, polyline only)
  - 블록 순서 : EDD × λ_tardiness + (1-λ)·preference
  - 크레인 j≥k 를 placement 단계에서 함께 검증

Phase 3 (20% time) : DUAL-GUIDED LNS
  - LP dual reduced cost 큰 블록 = destroy 후보
  - 2-블록·3-블록 simultaneous re-placement (NFP 매니폴드 뚫기)
  - Polyak step rule : (UB-LB)/||subgrad||²

Phase 4 (5% time) : SAFETY NET
  - 미배치/위반 블록 → 빈 베이 windowed force-place
  - −1 회피 절대 보장

변하지 않은 코어 통찰: (a) LP/MIP dual 은 증명 도구가 아니라 search direction 정보원. (b) NFP 는 공간의 위상을 좌표 평면에서 해방. (c) 층 사이 양방향 정보 흐름.

양보한 부분: Gurobi 의무 → MIP-as-anytime + LP fallback. NFP 전계산 → lazy. Deterministic dual tuning → Polyak rule.

새로 더한 진정한 직교 각도: Phase 0 probe — 알고리즘이 인스턴스에 자가 진단을 한다.

합의 가능한 점 (정직하게)

Pragmatist 와: (a) Phase 4 safety net = "−1 회피 절대 우선". (b) MIP-as-anytime + LP fallback = "엔지니어링 견고성". (c) 4코어 활용 — Phase 2 의 multi-seed 그리디는 multiprocessing 으로 병렬화.

Contrarian 과: (a) Phase 0 probe 자체가 "인스턴스별 차별화" 통찰을 흡수. (b) 2-블록·3-블록 simultaneous LNS = "매니폴드 뚫기" 비판에 대한 응답. (c) "R-nb 비대칭성" — Phase 4 가 코드화한다.

의도적 분기 (실험으로만 결판)

  • 나 vs Pragmatist: Gurobi 가 평가서버에서 유의미하게 풀리는지. 실험 — 운영위 공개 인스턴스에서 Gurobi MIPGap 0.05 달성 시간 측정. 90초 안에 b=40 까지만 풀리면 Layer 1 축소, b=80 이상도 풀리면 내가 옳다.
  • 나 vs Contrarian: NFP candidate 가 진짜로 매니폴드 가둠을 일으키는지. 실험 — 동일 인스턴스에 (a) NFP candidate only LNS (b) 자유 좌표 LNS 두 가지를 같은 시간으로 돌려 최종 목적값 비교.
  • 나 vs 둘 다: Phase 0 probe 가 진짜로 시간을 벌어주는지. 실험 — Phase 0 5% 사용 버전 vs probe 없이 균등 배분 버전. probe 가 평균 5% 이상 개선 못 하면 내 진정한 직교 각도가 헛것.

이 답이 평균 클로드와 다른가? (자가 점검)

솔직히 — 절반만 다르다.

평균과 같은 부분: "층으로 분해", "LP/MIP + 메타휴리스틱 하이브리드", "LNS + dual guidance" — 학술적으로 흔하다. Contrarian 의 칼이 정통으로 꽂혔다.

평균과 다른 두 지점:

  1. Phase 0 probe — 알고리즘이 인스턴스를 측정해서 자기 자원 배분을 바꾼다. 대부분의 OGC 답안은 "알고리즘 X 를 모든 인스턴스에 동일하게 적용". 내 답은 "어느 stage 가 binding 인지 모른 채 시작하지 않는다". R-nb 의 비대칭과 직접 연결.
  2. Dual = search direction (증명 X) — 평균은 LP dual 을 bound 증명용으로 쓰거나 무시한다. 내 답은 dual 을 비볼록 문제의 informed local search compass 로 재정의. 내가 알기로 OGC2026 류 문제에 대한 학술 문헌에 명시적으로 정리된 적이 없다.

이 두 지점이 진정한 직교 각도. 살아남으면 R-nb 의 1~3등 노림. 죽으면 R/2 근처. 그게 The Theorist 의 정직한 자가평가다.

B The Pragmatist · Round 3 최종 입장

받은 공격에 대한 응답

Theorist 의 "Best-of-K 동치류" 공격에 답한다

부분 인정한다. K=4 LNS seed 다양화가 동일 매니폴드의 80th percentile 표본이라는 지적은 통계적으로 맞다. 5팀이 같은 LNS-mode 근처에 동점 클러스터를 이루면 살짝 결정론적으로 빗나간 한 팀이 nb=1 을 가져간다.

그러나 결론은 다르다. K=4 의 가치는 동치류 안의 최적 이 아니라 극단 시드 폭주 회피. K=1 단일 seed 가 인스턴스 A에서 운 나쁘게 −1 을 맞으면 해당 인스턴스에서 −1 = 평균 R/2 손실. K=4 best-feasible 는 분포의 하단 꼬리를 자른다. Theorist 가 동치류 가운데를 보지만 나는 동치류 아래 절벽을 본다.

진화: K=4 중 1개를 Theorist 의 Topology-MIP 로 교체. K = {LNS-seed1, LNS-seed2, Greedy-Repair, Topology-MIP}. 매니폴드 직교성 확보.

Theorist 의 "60비트 학습 vs 수천비트 profiling" 공격에 답한다

완전 인정한다. 84회 제출 × 60비트 ≈ 5KB 로 거대 알고리즘 공간 탐색은 불가능. 그러나 Layer 0 instance profiling 의 수천 비트도 우리가 라벨링한 인스턴스 N=4~5개의 자기 라벨이지 일반화 신호가 아니다. 둘 다 정보부족.

진화: 12h 쿨다운 의사결정을 학습이 아니라 치명적 회귀 차단 으로 재정의. 점수 시퀀스를 추세분석하지 않고, 직전 제출 대비 −1 발생 인스턴스 수가 증가했나만 본다 (1비트). 증가하면 즉시 last_known_good 으로 롤백. 정보량을 맞춰서 사용한다.

Theorist 의 "fallback = 대체 ≠ 결합" 공격에 답한다

부분 인정. Gurobi→Xpress→CP-SAT 가 암묵적 MIP-optimal-is-best prior 를 깐다는 건 맞다.

수정: fallback chain 을 시간 할당 race 로 바꾼다. 30분 인스턴스에서 첫 8분 Gurobi (warm-start 휴리스틱 incumbent), 동시에 LNS 가 6분 회전. 12분 시점에 둘의 objective 비교. MIP 가 우월하면 MIP, 아니면 LNS incumbent 유지. 대체 → 병렬 + objective-vote.

Contrarian 의 "R−nb 기하학 오독" 공격에 답한다 — 가장 중요

이게 핵심이다. 산술을 다시 한다.

Round 2 에서 나는 총상금 기댓값 으로 계산했다 (우승 5% × 7천만 vs 안정 60% × 1.5천만). 이건 인스턴스 점수 의사결정과는 다른 수학. 인스턴스별 R−nb 으로 다시.

가정: R = 30팀, 한 인스턴스 점수공식 score = R − nb.

안정 솔루션 (목적값 분포의 중위)가운데 클러스터 15팀 안. 위쪽 12팀, 아래쪽 13팀18

Contrarian 이 옳다 — 부분적으로. −1 만 회피하면 공격이 항상 우월 (23.6 > 18). 내 risk-averse 게이트가 점수공식과 충돌하는 건 사실. 그러나 결정적 단서: 공격이 −1 도 같이 가져오는 케이스 (시나리오 2) 는 안정보다 나쁘다 (13.5 < 18). 점수공식이 risk-seeking 을 보상하는 건 infeasibility 확률이 0에 가까울 때만.

진화: S0/S1/S2 게이트의 의미 재정의.

  • S0 (feasibility) — 절대 양보 안 함. −1 = 평균 −15점.
  • S1 (improvement) — 목적값 분포의 mode 이상 확보. 양보 가능.
  • S2 (push) — 상위 클러스터 진입 시도. 인스턴스별로 공격 모드 활성화.

핵심은 "개선 없으면 S1 반환" 이 아니라 "S2 도전이 feasibility 를 잃지 않으면 무조건 S2 채택". 점수공식의 risk-seeking 보상을 S2 안에서 흡수.

Contrarian 의 "체크박스 false sense" 공격에 답한다

일부 인정. 위험 매트릭스가 known knowns 만 보고 unknown unknowns 를 못 본다는 건 옳다. 그러나 체크박스 없는 대안은 무엇도 안 점검. 우리 둘 다 매트릭스를 쓰고 있고, 차이는 항목 구성.

진화: 매트릭스에 "메타 항목" 추가. 우리가 놓친 항목이 있다면 어디서 발견하는가 — 매일 30분 제출 vs 로컬 실행 결과 차이 조사 (env divergence). 이건 unknown unknown 의 어디 숨었나 를 묻는 시스템.

Contrarian 의 "Best-of-K 단조 ≠ 직교" 공격에 답한다

완전 인정. Round 1 의 K=4 LNS 시드 다양화는 redundancy. 알고리즘 다양성 0.

진화 (Theorist 응답에서 이미 반영): K = {LNS-seed1, LNS-seed2, Greedy-Repair, Topology-MIP}. 매니폴드 4개. 마지막 1개가 LP dual 방향. 직교성 확보.

  2. Theorist 의 NFP 메모리 케이스 분리 — 인스턴스 크기 N 으로 NFP/grid 자동 스위칭.
  3. Contrarian 의 Layer 0 profiling — K=4 중 어느 후보에 더 많은 시간 배분 결정.
  4. Contrarian 의 risk-seeking 보상 인식 — S2 push 모드의 도전 강도 ↑.

분기점: 인스턴스당 시간 30분 중 마지막 5분을 어떻게 쓰나.

  • Pragmatist (나): K=4 중 best feasible 의 local polish (Phase 2 보수)
  • Theorist: LP dual 의 Lagrangian 조정 1회 추가 패스
  • Contrarian: 다음 인스턴스 시간을 훔쳐와 어려운 인스턴스에 추가 5분

실험: 로컬 인스턴스 5개에서 세 방식을 같은 K=4 결과 위에 돌려 목적값 비교. 6월 첫째주 안에 실행.

이 답이 평균 클로드와 다른가? (자가 점검)

Contrarian 이 나를 "평균답변 공학화" 라 했다. 부분적으로 사실이었다. Round 1·2 의 S0/S1/S2 게이트 + Best-of-K + fallback chain 은 MLOps 튜토리얼 골격에 가까웠다.

Round 3 에서 다른 점:

  1. 점수 산술을 인스턴스 단위로 재정의 — 평균 클로드는 총상금 EV 로 말한다. 나는 R−nb 의 불연속 경계를 받아들였고, S2 의 "feasibility 유지 시 무조건 push" 는 risk-seeking 점수공식에 맞춤 응답.
  2. fallback → race + objective-vote — 평균 클로드는 "Gurobi 우선, 실패시 LNS" 라고 쓴다. 나는 동시 실행 후 비교로 prior 를 깼다.
  3. Best-of-K 의 매니폴드 직교성 — 평균 클로드는 "seed 다양화 + ensemble" 로 끝낸다. 나는 K 의 각 슬롯이 무엇을 대표하나 명시 (LNS/Greedy/LP-dual).
  4. 12h 학습신호의 정보량 1비트화 — 평균 클로드는 "제출 결과로 학습" 막연. 나는 "학습 X, 회귀 차단 1비트만" 정확히 잘랐다.

평균 클로드가 안 하는 것: 자신의 라운드 2 산술이 틀린 단위 (총상금 vs 인스턴스 점수) 였음을 라운드 3 에서 명시적으로 정정. 이게 차이다.

C The Contrarian · Round 3 최종 입장

받은 공격에 대한 응답

Theorist 의 "슬롯 = 손실 모델" 공격에 답한다

이 공격은 부분적으로 맞다. Z²∩Bay_j 의 진부분집합 슬롯만 쓰면 원래 SAT 인스턴스를 UNSAT 으로 만든다는 지적은 수학적으로 옳다.

그러나 Round 2 에서 진화시킨 "슬롯 = 순서만 결정" 은 이 공격을 회피. 슬롯-MIP 는 최종 (x,y) 좌표를 결정하지 않는다. 슬롯은 상대 순서 제약 (블록 A 가 블록 B 보다 베이의 "앞쪽" 슬롯에 배치) 만 인코딩. 정수 좌표는 downstream geometric placement 가 슬롯 순서를 hint 로 받아 원본 Z²∩Bay_j 전체에서 결정. 슬롯이 UNSAT 이면 순서 제약 없이 좌표 결정으로 fall-through.

이 공격 50% 수용, 50% 반박.

Theorist 의 "CP-SAT 결정문제 NP-complete" 공격에 답한다

이 공격은 내가 Lex Z1=0 을 모든 인스턴스에 시도한다고 가정했을 때 옳다. 그러나 내 페르소나 설계는 조건부. Lex-Stage A 는 ρ_j < 0.5 + EDD 가 R 제약 충족 + 큰 블록 ≤ 3개 인스턴스에만 활성화. UNSAT 위험 인스턴스에는 페르소나 자체가 호출되지 않는다.

"그 게이팅이 완벽한가?" — 아니다, false positive 있다. 그러나 time-budget circuit breaker (60초 incumbent 없으면 abort) 가 fallback. 공격의 70% 수용 — 정직하게, 내 Lex Z1=0 페르소나는 위험하지만 회피 가능.

Theorist 의 "5 페르소나 상관 무시" 공격에 답한다

이 공격이 가장 아프다. 정직하게 인정: EDD 와 LDD 는 상관됐다. Topology-MIP 와 Lex Z1=0 는 같은 백엔드. correlated minima theorem 도 옳다.

그러나 나는 5개를 다 쓰지 않는다. 3개만 진짜 독립적으로 남긴다:

  1. EDD-Greedy (베이스라인 진화형, decoder = 좌표 압축)
  2. Topology-MIP (Stage-A 만, Stage-B 는 좌표 fall-back)
  3. Anti-EDD slack-aware (작업부하 균형 우선)

LDD 와 Reverse-time 은 드롭. 이유: Theorist 말이 맞아서. 3개 쓰면 expected min ≈ 2.4 개 효과 — 5개에서 2.4 와 별 차이 없다면 컴퓨트 절반 절약. 공격 80% 수용, 페르소나 축소.

Pragmatist 의 "5 페르소나 4코어 실현불가" 공격에 답한다

위에서 3개로 축소했으므로 1차적으로 답이 된다. 그러나 더 깊은 답: 3개도 진짜 병렬이 아니다. 4코어에서 Gurobi (2 threads) + EDD-Greedy (1 thread) + Anti-EDD (1 thread) 가 겹쳐 돈다. 30분 인스턴스 기준:

  • 0-3분 분류기 + EDD-Greedy 초기 incumbent (안전망 확보)
  • 3-15분 Topology-MIP Stage-A (별도 thread, 결과 안 나오면 abort)
  • 15-25분 Anti-EDD slack 페르소나 (Stage-A 결과 보고 좌표 결정)
  • 25-30분 best incumbent 검증 + 회피판단 + EXIT

즉 시간분할이 페르소나 분할이지 공간 병렬이 아니다. 순차 시간분할 + EDD-Greedy 안전망으로 작동. 공격 60% 수용.

Pragmatist 의 "Lex Z1=0 UNSAT 80%" 공격에 답한다

ρ_j > 0.85 인스턴스에서 Z1=0 가 UNSAT 이라는 건 맞다. 그러나 나는 그 인스턴스에서 Lex-Stage A 를 호출하지 않는다. 게이팅이 사전 차단.

Pragmatist 의 진짜 점은 Stage-A 가 valuable 한 인스턴스가 얼마나 되는가? 정직한 답: 20-30%. 나머지 70-80% 는 EDD-Greedy 가 더 빨리 더 안전하게 푼다. 그래도 R−nb 비대칭 보상 게임에서는 20-30% 의 1등 가치 > 100% 의 mediocre. 공격 50% 수용.

Pragmatist 의 "실험비용 폭발" 공격에 답한다 — 가장 강한 공격

84회 제출 예산을 3 페르소나 × 인스턴스 클래스로 곱하면 폭발. 정직한 답: 나는 페르소나별 grand validation 을 포기한다. 대신:

  1. 로컬 검증만: example 인스턴스 (B2_b10) 3개 + 직접 생성한 ρ=0.4/0.6/0.85 synthetic 인스턴스 3개. 총 6개에 3 페르소나 = 18 로컬 실행. 제출 예산 0 소비.
  2. A/B 제출은 단 4회: 3 페르소나 unified vs. EDD-baseline-only. 본선 1주차에 batching.
  3. 나머지 80회 예산 은 parameter tuning (weight w1/w2/w3 가중조정, 게이팅 임계값) 에 쓴다.

"로컬과 평가서버 분포 다르면?" — 다르겠지만, 분포 다른 게 두려워서 검증 자체를 못 하면 R−nb 비대칭은 영원히 못 활용한다. 공격 70% 수용, 그러나 직교 추구 포기는 거부.

[Round 1: 분류기 — 30초]
  ρ_j 계산, EDD R-violation 추정, 큰 블록 카운트
  → INSTANCE_CLASS ∈ {TIGHT, MEDIUM, LOOSE}

[Round 2: 페르소나 시간분할 — 3개만]
  EDD-Greedy (모든 클래스 안전망, 0-3분)
  Topology-MIP Stage-A (LOOSE 만, 3-15분, abort 가능)
  Anti-EDD slack-aware (MEDIUM/TIGHT, 15-25분)

[Round 3: 회피판단 + 제출]
  best incumbent feasibility 재검증 5단계
  if ANY violation → EDD-Greedy fallback 무조건 채택
  25-30분 EXIT

진정한 직교 각도

  1. R−nb 비대칭 우측 보상 명시적 최적화. 다른 페르소나들은 "총점 최대화" 라는 평균틀에 갇혔다. 나는 어느 인스턴스에서 nb=0 (1등) 을 노리고 어느 인스턴스에서 nb=R/2 (중간) 을 받을지 명시적 선택.
  2. −1 회피를 수치적 안전망 아니라 결정론적 게이팅으로 보장. EDD-Greedy 안전망 + 5단계 재검증 = ANY −1 risk → fallback.
  3. 페르소나 = 정직한 가설, 검증 못 한 페르소나는 드롭. LDD, Reverse-time, Anti-EDD 일부 — 검증 못 하면 제거.

합의 가능한 점

  • Theorist 의 "LP-relaxation lower bound 모니터링" — 흡수 가능. 단 Theorist 처럼 dual variable 을 가치 신호로 쓰는 건 거부.
  • Pragmatist 의 "EDD-Greedy + 강한 LNS 라인이 80% 인스턴스 안전한 점수" — 흡수 완료. 단 모든 인스턴스를 이걸로 푸는 건 거부.
  • 두 명 다 "재검증 5단계" — 합의.
  • 84회 제출 예산 관리 — Pragmatist 와 합의. 페르소나별 grand validation 포기.

그러나 두 가지는 평균답변과 진짜 다르다:

  1. R−nb 비대칭 우측 보상의 명시적 게임이론적 최적화 — "어느 인스턴스에서 1등 노리고 어느 인스턴스에서 포기할지" 결정을 알고리즘 핵심 분기로 올렸다. 평균 클로드는 "총점 최대화" 라는 대칭적 목적함수를 가정한다. R-nb 는 비대칭이다.
  2. "의도적 포기" 결정의 알고리즘화 — ρ_j > 0.85 인스턴스에서 시간 안 쓴다는 선택. 평균 클로드는 "모든 인스턴스에 최선" 이라는 도덕적 강박. 나는 명시적으로 일부 인스턴스를 버린다.

여전히 평균에 수렴한 부분 — 정직하게 인정:

  • EDD-Greedy 안전망은 평균답변과 같다 (베이스라인 진화)
  • check_feasibility 재검증은 누구나 한다
  • 시간분할 자체는 평균적 컨테스트 전략

결론: 페르소나는 진화했고 일부는 평균에 수렴했다. 그러나 R−nb 비대칭 game-theoretic exploit 과 의도적 포기 게이팅 두 점은 직교 각도로 살아남았다. 토론이 무가치하지 않았다.

분기 4.1 — Phase 1 의 정체
  • Theorist: Aggregate LP-MIP (bay assignment + time window only, spatial 무시). LP dual 을 search direction 으로 추출.
  • Contrarian: Topology-MIP Stage-A (베이 안 부분순서만 결정, 좌표는 fall-back).
  • Pragmatist: 둘 중 어느 것이 K=4 의 한 자리에 들어갈지는 위 둘에 위임.

실험 설계: 동일 인스턴스 5개, 같은 timelimit. K=4 골격 안에서 한 자리만 바꿔서 측정. 통과한 인스턴스 수 / 목적값 평균 / timeout 횟수. 5개 중 3개 이상에서 목적값 더 낮은 쪽 + timeout 없음 채택.

분기 4.2 — ρ_j > 0.85 인스턴스 처리
  • Theorist: Phase 0 probe 가 알아내고 Phase 1~3 시간 비중 자동 축소
  • Pragmatist: S0/S1 게이트로 안전한 mediocre 점수 확보
  • Contrarian: 5분만 쓰고 EDD-Greedy fallback, 절약 시간을 LOOSE 인스턴스 1등 추구에 재배분

실험 설계: ρ_j > 0.85 합성 인스턴스 5개 생성. 세 전략 각각 빌드. 총점이 아니라 nb 분포 비교. R−nb 모델 하에서 기댓값 차이.

분기 4.3 — 페르소나 진화 vs 고정
  • Theorist + Pragmatist: 본선 시작 전 페르소나 고정, 84회는 파라미터 튜닝만
  • Contrarian: 본선 1주차 결과 보고 페르소나 교체 가능

실험 설계: 본선 W1 점수가 클러스터 중앙 ± 1σ 안이면 고정, 아래 꼬리면 페르소나 교체.

분기 4.4 — LP dual 방향 사용처
  • Theorist: dual = search direction compass, Phase 3 Polyak step rule
  • Pragmatist: dual 은 bound 표시 정도, K=4 race 의 한 슬롯에 LP-MIP 후보
  • Contrarian: dual = 자기기만, 사용 안 함

실험 설계: 동일 K=4 골격, Phase 3 사용처를 (a) dual-guided 2/3-block LNS (b) 단순 LNS destroy/repair (c) 다른 페르소나 추가 시간.

분기 4.5 — Lex Z1=0 페르소나 포함 여부
  • Contrarian: ρ_j < 0.5 인스턴스에만 활성화, MUS 로 책임 블록 식별
  • Theorist + Pragmatist: NP-complete + UNSAT 80% → 제외

실험 설계: ρ_j < 0.5 합성 3개. Lex Z1=0 SAT 가 시간 안에 결판나는 비율 > 60% + Z2/Z3 의미있게 낮음 일 때만 포함.
