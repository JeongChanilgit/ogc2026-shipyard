perbay — per-bay 공간+시간 JOINT 재배치 폴리시

OGC 2026 · src/perbay.py (612줄) 상세 해설 · 2026-06-19 · 현 프로덕션의 마지막 폴리시 단계 (OGC_PERBAY 기본 ON)

perbay는 완성된 해(best-of winner)를 받아, tardy한 베이를 하나씩 CP-SAT로 다시 풀어 각 블록의 위치 (x,y)·방향·진입시각을 동시에(joint) 재배치한다. 목표는 그 베이의 지각합(Z1)을 줄이는 것뿐. 공간 베이 배정은 안 바꾸므로 Z2(부하불균형)·Z3(선호)는 수학적으로 불변 — 오직 Z1만 움직인다. 워밍스타트 + 엄격개선 게이트라 최악의 경우 입력 해를 그대로 반환(절대 나빠지지 않음).

0. 파이프라인 어디에 있나

set2(T≥200) 경로: gassign-first가 배정(B1)→위치배치(B2)→타이밍(B3)으로 해를 만들고, box가 별도 후보를 내서 best-of. 그 승자 위에 perbay가 마지막으로 한 번 더 베이별 폴리시를 건다.

perbay는 "leftover wall"(gassign+box가 쓰고 남은 시간)에서 돈다. 시간이 없으면 그냥 건너뛴다(입력 해 유지).

1. 핵심 아이디어 — 왜 "joint"인가 (B3와의 차이)

B3(_cpsat_bay_timing_verified)는 위치를 고정하고 진입시각만 다시 푼다. 그래서 두 블록이 공간에서 겹치면 "한쪽을 시간적으로 미루는" 길밖에 없다 → 지각 발생. perbay는 위치·방향까지 같이 움직여서, 충돌하는 블록을 공간적으로 옆으로 밀어 동시에 공존시킬 수 있다 → 미루지 않아도 됨 → 지각↓.

B3 (시간만) — 위치 고정

perbay (공간+시간) — 위치도 이동

즉 perbay의 추가 레버 = "미룰래(time) vs 옆으로 비킬래(space)"를 CP-SAT가 같이 고른다. 크레인/충돌 제약으로 묶여 지각하던 베이가 공간 재배치로 풀릴 수 있다.

2. improve() — 오케스트레이션 (베이별 루프 + 게이트)

입력: prob_info, 현재 해 sol, 시간예산 time_budget. 출력: 개선된 해 또는 입력 해 그대로.

1해 파싱 → 베이별 레코드 {j: {block: rec}} 로 정리. rec = 위치·방향·진입/퇴출.
2work 베이 선별: 각 베이의 현재 지각 cur_tard = Σ max(0, exit − due) 계산. 필터 cur_tard = 0 인 베이는 제외 — 지각이 0이면 재배치로 더 못 줄임.
3payoff 정렬: cur_tard 큰 베이부터(내림차순). 한정된 예산을 지각 큰 베이에 먼저 투입.
4크기 필터 −1/속도 보호: 블록 수 n > maxn(기본 100) 베이는 skip — 쌍별 disjunction이 O(n²)라 너무 큰 베이는 CP-SAT가 못 푼다.
5베이별 예산 배분: per_bay = (남은시간) / (남은 work 베이 수), 상한 bay_cap(기본 20s). per_bay < 0.5s 거나 데드라인 < 1s 면 skip.
6베이 풀기: _solve_bay(...) 호출(아래 §3). 개선된 레이아웃을 반환하면 그 베이만 교체(변경된 베이만 deep-copy).
7채택 게이트 never-worse: 하나라도 개선됐으면 새 해 반환, 아니면 입력 해 그대로. 모든 단계 try/except — 절대 예외 전파 안 함.
바깥(myalgorithm)에도 한 겹 더: perbay 결과는 공식 check_feasibility 통과 + 총 obj 엄격 개선일 때만 채택된다. 즉 이중 게이트(perbay 내부 베이별 + 바깥 전체 obj).

3. _solve_bay() — 한 베이의 JOINT CP-SAT 모델 (핵심)

한 베이의 블록들에 대해 (x, y, 방향, 진입시각)을 동시에 정해 그 베이의 지각합을 최소화한다.

3.1 결정 변수 (블록 b마다)

변수의미비고
oi[b]방향 (0..O−1)IntVar
Wv[b], Hv[b]선택된 방향의 폭·높이AddElement(oi, w_list, Wv) — 방향에 따라 폭/높이가 따라옴(채널링)
xl[b], yl[b]bbox 좌·하단 좌표위치. anchor = bbox − offset 으로 환산
entry[b]진입시각 (R..Hmax)퇴출 = entry + P (WLOG 최적)
tard[b]지각 = max(0, entry+P−D)목적함수 항

3.2 제약 ① 베이 경계 + 보수적 정수 bbox 공간

xl + Wv ≤ W, yl + Hv ≤ H. 핵심 안전장치(BUG-1): 채커는 float 폴리곤으로 검사하므로, 정수 bbox가 그 float 폴리곤을 보수적으로 포함해야 한다 → _orient_geom이 min-offset은 floor, 최대범위는 ceil로 둘러싼다. 그래서 정수 non-overlap ⟹ float non-overlap, 정수 in-bounds ⟹ float in-bounds.

3.3 제약 ② 쌍별 분리 — 6개 disjunct 중 하나 공간시간

모든 블록쌍 (a,b)에 대해 AddBoolOr([sx_ab, sx_ba, sy_ab, sy_ba, st_ab, st_ba]) — 아래 6가지 중 최소 하나가 성립해야 한다. 이게 안전 모델: 두 공존 블록의 bbox가 (x,y)에서 안 겹치면 어느 층에서도 충돌·크레인 방해가 불가능하다. 따라서 "모든 순간 공간 분리" 또는 "시간 분리(한쪽이 끝난 뒤 다른쪽 시작)" 면 항상 feasible.

공간 분리 (①~④) — 동시 공존, 지각 안 늘림 시간 분리 (⑤⑥) — 순차, 지각 늘 수 있음

3.4 제약 ③ 크레인 (T6) — 기본 OFF

OGC_PERBAY_CRANE 기본 OFF. 켜면 "안전한 다층 LIFO 공존"(작은 블록이 큰 블록 발자국 안에 층층이 nest)을 추가 disjunct로 허용하려 했으나, nest 여부가 방향·오프셋(=결정변수)에 의존해 precompute가 불가능 → 보수적 분리 모델만 쓴다(항상 feasible 유지). 그래서 perbay는 "공간을 떼거나 시간을 미루거나"만 하고, 크레인 적재 공존은 안 쓴다(약간 보수적, 대신 안전).

3.5 목적 · 워밍스타트 · 채택 게이트

목적함수

Minimize Σ tard[b] — 이 베이의 총 지각만. (Z2/Z3는 배정 고정이라 손댈 수 없음.)

워밍스타트 never-worse 핵심

AddHint로 현재 레이아웃(방향·위치·진입)을 즉시 feasible 인컴번트로 준다 → CP-SAT는 폴리시만 하지, 현재보다 나쁜 해를 보고하지 않는다.

솔버

max_time = per_bayworkers 4seed 12345 (결정적)

채택 게이트
  • status가 OPTIMAL/FEASIBLE 아니면 → None
  • new_tard ≥ cur_bay_tard (엄격 개선 아니면) → None (기각)
  • 개선됐을 때만 (anchor_x = xl − offx, …) 환산해 새 베이 레코드 반환

4. 안전성 요약 (왜 절대 −1/회귀가 없나)

속성보장 방법
예외 안 터짐모든 경로 try/except → 최악의 경우 입력 해 그대로 반환
시간 초과 안 함time.monotonic() 데드라인 + 베이별 예산 상한 + 큰 베이 skip(maxn)
해가 나빠지지 않음워밍스타트(현재 해가 인컴번트) + 베이별 엄격개선 게이트 + 바깥 obj 게이트
실현가능 유지보수적 정수 bbox + 6-disjunct 분리(공간 또는 시간) → 반환 레이아웃은 항상 feasible, 바깥에서 공식 채커 재확인
Z2/Z3 불변베이 배정 고정 — 블록이 베이를 안 떠나므로 부하·선호 항 변화 없음

6. 측정된 성격 (per-bay 연구 LEDGER 요약)

  • per-bay Z1 감소폭은 베이 의존적: −1% ~ −19%. 회복 여지가 있는 베이(예: prob_39 b0, 80블록 −17%)에선 크고, 이미 포화된 베이(prob_26/27)에선 ~−1%.
  • 정렬(order)이 거의 공짜 레버: COVERT 정렬이 EDD를 큰 폭으로 이김. CP-SAT 4워커 비결정성으로 run-to-run 변동 ±15~35 존재(평균내면 실재 이득).
  • 큰 베이(≥~100블록)는 쌍별 모델이 커져 CP-SAT가 좋은 해를 못 찾음 → maxn으로 skip(그래서 큰 set2 베이엔 효과 제한적).
  • 2026-06-19: perbay를 windowed relayout으로 대체(C)하면 작은 혼잡 베이에서 더 나빠짐 → perbay가 더 강한 폴리시임이 확인됨(relayout이 −2.6M post-hoc로 이긴 건 perbay 위에 추가했을 때뿐).
