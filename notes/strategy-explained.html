원칙 01 · −1 절대 회피
서커스 그물 — 어떤 일이 있어도 떨어져 죽지 않는다
🎪
비유

공중곡예사가 묘기를 부리든 떨어지든, 아래에는 항상 그물이 있다. 그물 없는 묘기는 *멋있어 보여도* 한 번 실패하면 끝이다.

원칙 02 · 인스턴스 프로파일링
의사의 진찰 — 5초 안에 환자 상태를 판단한다
🩺
비유

응급실 의사는 환자가 들어오자마자 5초 안에 청진기·체온·혈압 만 보고 "이건 응급실? 일반외래? 중환자실?" 을 결정한다. 정밀 검사는 그 뒤에 시작한다.

우리도 마찬가지. "이 인스턴스는 어느 제약이 가장 빡빡한가" 를 5초 안에 진단해서 그 다음 25분의 자원 배분을 결정한다.

진단 결과 = 4가지 분기
🔴 TIGHT
ρ_j 최대 > 0.85 — 공간이 너무 빡빡. 의도적 포기 검토.
🟢 LOOSE
ρ_j 최대 < 0.5 — 여유 있음. MIP 적극 시도.
🟠 TARDINESS-DOM
w1 · Z1 추정값이 압도. EDD 강화.
🟣 PREFERENCE-DOM
H_i > 50 블록 다수. 강한 선호 블록 변수 고정.
측정하는 5가지 지표
  • ρ_j — 베이별 시공간 빡빡함: Σ(A_i · P_i) / (W_j · H_j · T)
  • H_i = S_max − S_2nd — 블록당 preference concentration
  • DAG width — 시간축 sampling 으로 동시 활성 블록 수 분포
  • w1/w2/w3 비율 — Z1/Z2/Z3 중 dominant 식별
  • 블록 크기 + polygon 정점 분포 → NFP/grid 자동 스위칭 임계
왜 *수천 비트* 인가

Theorist 의 통찰: 제출 1회로 받는 정보는 점수·license·-1 여부 ≈ 60비트. 반면 인스턴스 자체에서 뽑는 통계는 인스턴스당 수천 비트 — 학습 신호 풍부.

원칙 03 · 매니폴드 직교 K=3 race
세 명의 요리사 — 같은 손님을 위해 다른 요리법으로 동시에
👨‍🍳👩‍🍳🧑‍🍳
비유

같은 식재료, 같은 시간. 세 요리사가 완전히 다른 요리법 으로 동시 시작. 일식·이탈리안·중식. 시간 끝나면 가장 맛있는 것 만 서빙.

Theorist 의 통찰: "같은 요리법으로 시드만 다른 세 그릇"은 무의미. seed 다양화 ≠ 알고리즘 다양성. 다른 매니폴드 위에 있어야 진짜 다양성.

3 매니폴드 라인업
  • EDD-Greedy++ — 베이스라인 진화. 안전망 역할 (모든 클래스에서 활성).
  • MIP/LP 기반 — Theorist Aggregate LP-MIP 또는 Contrarian Topology-MIP. LOOSE 인스턴스에서 강력.
  • Anti-EDD slack-aware — 워크로드 균형 우선. Z2 dominant 인스턴스 대비.
왜 직교성이 점수공식에 유리

R−nb 모델에서 5팀이 같은 LNS mode 에 수렴하면 모두 동점. 살짝 결정론적으로 빗나간 한 팀이 nb=1 가져감.
다른 매니폴드 위에 있으면 random walk 의 표본분포에 안 속한 점에 도달 — 그 인스턴스에서 우리만 그 점.

원칙 04 · NFP candidate 는 lazy + LRU
호텔 객실 청소 — 손님이 *오면* 그제야 청소한다
🏨
비유

500개 객실을 미리 전부 청소해두면 인력·시간·물자 모두 낭비. 실제 손님이 묵을 객실은 30개뿐.

NFP (No-Fit Polygon) 도 마찬가지. 80블록 × 5층 × 정점 30 = 12,000 polygon 을 미리 만들면 3~5GB. 16GB 환경에서 OOM kill → −1. 실제 충돌 검사할 쌍에만 그때그때 계산하고, 자주 쓰는 것만 LRU 캐시.

메모리 비교
구현 디테일
  • AABB (axis-aligned bbox) 가 겹치는 쌍에 대해서만 질의 시점에 Minkowski sum 계산
  • LRU(maxsize=2048) 로 자주 쓰는 NFP 만 캐싱
  • NFP 자체가 아니라 경계 polyline 만 저장 (정점 ≤ 30)
  • 평균 메모리 < 1GB — 동시점유 그래프가 sparse 한 점 활용
원칙 05 · 솔버 race + objective-vote
F1 그랑프리 — 두 머신을 동시에 트랙에 보내고 빠른 쪽을 채택
🏎️
비유

F1 팀이 두 머신을 같은 트랙에 동시에 보낸다. 먼저 끝나는 쪽이 우승. 한 쪽이 고장나도 다른 쪽이 들어온다.

평균 답변은 "Gurobi 먼저 시도, 실패하면 LNS" — 직렬 fallback. 우리는 Gurobi 와 LNS 를 동시에 출발시키고 12분 시점에 objective 비교. "MIP optimal 이 답" 이라는 암묵적 prior 를 깬다.

직렬 fallback vs race
구현 디테일
  • Gurobi 는 warm-start 로 휴리스틱 incumbent 를 받아 시작
  • 동시에 LNS destroy/repair 가 별도 worker 에서 회전
  • 8~12분 시점에 두 worker 의 best incumbent objective 비교
  • 좋은 쪽 채택, 진 쪽 worker 는 중단
  • R1 sanity 제출 때 license_status 로그 박아 Gurobi 가용성 검증
원칙 06 · 84회 제출 = 회귀 차단 (학습 X)
사진관 백업 룰 — 어제 잘 나온 사진을 항상 들고 다닌다
📸
비유

결혼식 사진관: 매일 새 카메라 세팅으로 더 좋은 사진을 시도. 하지만 어제 잘 나온 사진 은 항상 백업. 오늘 새 세팅이 망하면 1초 안에 어제 사진을 인화.

평균 답변: "제출 결과로 학습해서 알고리즘 개선". Theorist 통찰: 제출 1회 = 60비트 정보, 84회 곱해도 5KB. 알고리즘 공간이 거대해서 학습은 불가능. 대신 회귀 차단 1비트 만 정확히 본다.

원칙 07 · 본선 D-1 방어
비행기 점검 — 이륙 직전 체크리스트와 비상 백업
✈️
비유

여객기가 이륙하기 전, 조종사는 매번 체크리스트를 외운다. 기온·연료·엔진·랜딩기어·비상통신. 동시에 비상시 사용할 백업 시스템도 항상 작동 대기.

본선 D-1 에 새 빌드가 깨지면 7천만 원이 날아간다. 매 제출에 진단 로그 박고, last_known_good zip 을 항상 들고, 무거운 import 는 try/except 로 격리.

방어 매트릭스 — 깨질 수 있는 시나리오

  • 짧은 timelimit (30s) → safety net 3초 안에 완료 보장
  • Polygon 정점 50+ → AABB 사전필터 + intersection 캐시
  • w 극단 비율 → 베이 ballast 강제 로직 사전 준비

  • Gurobi 라이선스 종료 → 솔버 race 의 다른 쪽 (LNS) 으로 자동 폴백
왜 이 7개가 *점수공식* 에 정합하는가

R−nb 라는 비대칭 게임

점수공식 score = R − nb (R = 참가팀, nb = 엄밀히 더 잘한 팀 수). Pragmatist 가 Round 3 에서 산술 오류를 정정한 결정적 발견.

R=30 가정 — 한 인스턴스의 기댓값

18

우리가 노리는 영역

결정적 통찰: −1 만 회피하면 공격이 항상 우월. 하지만 infeasibility 가 같이 따라오면 안정보다 나쁘다. 그래서 7개 원칙 중 원칙 01 (안전망) 이 모든 것의 floor 고, 원칙 02~05 (진단·K=3·NFP·솔버 race) 가 ceiling 을 끌어올린다. 원칙 06~07 은 그 사이를 본선까지 유지.
