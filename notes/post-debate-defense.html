합의안 재검증 토론 · 2 라운드

Defender vs Aggressor vs Minimalist

이전 3-에이전트 토론 (Theorist/Pragmatist/Contrarian) 의 결과 도출된 합의안에 대해, 옹호자 1명 + 서로 다른 두 입장의 비판자 2명 이 다시 검증. 셋 다 최선의 항변 → 합의안은 살아남았는가?

세 입장 한눈에

셋이 *각자* 어떻게 점수공식을 해석했는가

셋 다 같은 점수공식 R − nb 를 봤다. 그러나 *어떻게 살아남을지* 의 결론이 완전히 갈렸다.

🛡️
Defender (옹호자)
합의안을 옹호
"합의안은 3 라운드 토론을 거친 *균형점*. Phase 4 safety floor + Phase 1·3 ceiling 추구. 6개 직교 각도가 *동시* 작동. 분해 불가."
"두 비판자가 정반대 방향인 게 *역으로* 합의안의 위치를 증명한다."
⚔️
Aggressor (과격파)
"더 과격해야 우승"
"합의안은 *평균 클로드의 학구적 정제판*. R−nb 우측 비대칭 보상을 손에 쥐고도 R/2 안주. *우측 꼬리* 를 자발적으로 닫는 설계."
"30명 중 1등 시도자가 *명시적으로 0명* 이면 시도하는 자가 자동 1등."
🪶
Minimalist (회의주의자)
"6주에 못 만든다"
"베이스라인 962줄 + 17줄 stub 에 6 모듈 + 3 도구는 공학적 비현실. Risk-adjusted EV 가 답 — Lean Baseline + simple LNS + safety net."
"*복잡함은 야망의 증거가 아니라 시간 부족의 증거가 된다*."
Round 1 · 각자 입장 표명

서로 모르는 상태에서 각자 출발

세 에이전트가 *서로의 의견을 모르는 상태에서* 합의안에 대한 입장 표명. 각자 자기 페르소나에 맞게 최선의 항변.

🛡️ Defender R1 옹호

  • 6 직교 각도 동시 작동 — Phase 0 probe / dual compass / 매니폴드 K=3 / race + vote / 1비트 회귀 / R-nb 비대칭
  • Phase 간 정보 의존성 — Phase 0 → 시간배분, Phase 1 → dual λ, Phase 1/2 → 롤백 기준점
  • 예상 공격 선제 답변 — Phase 3 실패 시 단순 LNS 다운그레이드 가능
  • 약점 자인: 분기 실험 미완료 / dual 보장 약함 / profiling 정확도 보장 약함

⚔️ Aggressor R1 5 비판

  • K=3 직교성은 수사 — EDD/LP-MIP/Anti-EDD 다 학술 도구
  • Dual-guided LNS 절반 차별화 — Polyak 비볼록 자기기만
  • R-nb 와 반대로 설계 — Phase 4 너무 크고 MIPGap 너무 안전
  • 4분기는 시간배분만 — 클래스마다 *완전 다른 알고리즘* 필요
  • 조선업 도메인 지식 0줄 — LG CNS = 한국 조선소 컨설팅
  • 대안: ASYM-RAID — 7 클래스 + Forest-ALNS + 도메인 인터뷰

🪶 Minimalist R1 6 비판

  • 9개 작업 ÷ 60일 = 6.7일 — 디버그 시간 무시
  • 멀티 워커 평가서버 위험 — fork/spawn, Shapely pickle, Gurobi 라이선스
  • Aggregate LP-MIP 가장 위험 — 라이선스 + 모델 정확도 + 큰 인스턴스
  • Dual-LNS 5개 기능 통합 — 어느 부분 깨졌나 디버그 불가
  • K=3 시간분할 + OOM — 4코어/16GB 한계
  • 대안: Lean Baseline — 작업 3개, 14일, 분산 작음
Round 2 · 결정적 충돌

EV 산수가 *세 가지로 갈렸다*

셋이 *같은 점수공식* 을 본 결과 *서로 다른 산수* 를 제시. 어느 산수가 옳은가?

R=30·15 인스턴스 가정 — 인스턴스 점수 합산

Defender 의 통찰: OGC 2026 의 점수는 상금 분배가 아니라 *인스턴스별 R−nb 합산*. Minimalist 의 EV 산수는 단위가 틀렸다.

완성 확률을 가중하면?

Minimalist 의 진짜 무기는 완성 확률 을 EV 에 곱하는 것. 어느 가정이 옳은가?

시나리오 1 — Defender 의 산수 (완성 60%/부분 30%/실패 10%)

합의안 EV = 0.6 × 354 + 0.3 × 315 + 0.1 × (−15) = 305.4 점
Lean EV   = 0.9 × 270 + 0.1 × 260                = 269.0 점
→ 합의안 13% 우월

시나리오 2 — Aggressor 의 정정 (Safety Net 회귀 차단 = 부분 작동 30%, 완전 실패 0%)

합의안 EV = 0.7 × 354 + 0.3 × 270 (baseline fallback) = 328 점
Lean EV   = 270 점
→ 합의안 21% 우월

시나리오 3 — Minimalist 의 정정 (작업 시점 EV, 분산까지)

합의안 EV 1200만원 (분산 큼: 왼쪽 꼬리 300만)
Lean EV   1234만원 (분산 작음)
ASYM-RAID 945만원 (Aggressor 의 대안)
→ Sharpe ratio 관점에서 Lean 우월
핵심 통찰: 세 산수의 차이는 *완성 확률* 의 가정에 있다. 합의안 §5 A2 (safety net 자동 회귀 차단) 가 *진짜* 작동하면 Defender·Aggressor 의 산수가 옳다. *작동 안 하면* Minimalist 의 산수가 옳다. 이건 실험으로만 결판날 문제.
Round 2 · Aggressor vs Minimalist 직격

"ASYM-RAID 가 사실은 11개 알고리즘이다"

Minimalist 가 Aggressor 의 "5 → 3 축소" 라는 *수사* 를 분해. ASYM-RAID 가 실제로는 *합의안보다 더 복잡* 함을 폭로.

Aggressor 의 ASYM-RAID 진화판 (R2)

  • 분기 A — Exact-First (작은 n) — MIP, MIPGap=0.05 공격적
  • 분기 B — Domain-Heuristic (중간 n) — 조선업 가중 EDD + 도메인 인터뷰
  • 분기 C — Matroid-Destroy ALNS (큰 n) — 시공간 매니폴드 destroy

표면적으로 3 분기. 그러나 Minimalist 가 풀어보면:

SA·Tabu·MIP·도메인 greedy·Topology-MIP·Lawler·Hungarian·workload-balance + K=3 race(3)
= 11개의 독립 구현체

Minimalist 의 결론: "ASYM-RAID 는 '5 → 3 축소' 라는 *수사* 로 *실제는 합의안보다 복잡* 한 시스템".

Aggressor 의 반박

Aggressor 는 *Minimalist 의 EV 산수* 를 가차없이 짚었다. 특히:

  • 산수 오류 1: "우승 5% × 7천만 = 350만 vs 중상위 60% × 1.5천만 = 900만" 은 상금 분배 가정. OGC 2026 점수는 인스턴스 합산.
  • 산수 오류 2: "완전 실패 10%" 는 합의안 §5 A2 (safety net 회귀 차단) 무시 — 실제로는 0% 에 근접.
  • 산수 오류 3: "우승 0%" 는 자기 충족 예언 — 시도조차 안 하면 0이 보장된다.
Aggressor 의 메타-비판: "Defender 와 Minimalist 모두 *우리는 평균 클로드를 못 이긴다* 는 가정. Defender 는 평균의 *학구적 정제판*, Minimalist 는 평균의 *축소판*. 진짜 우승 시도가 없다."
Round 2 · Defender 의 진화

합의안의 R2 양보 — 3가지 변경

Defender 는 두 비판자의 *진짜로 옳은 부분* 을 받아 합의안을 진화시켰다. 틀은 유지, 세부는 조정.

🛡️ 합의안 R2 진화판

  1. Phase 4 시간 3분 → 90초, 절약된 90초를 Phase 3 의 *risk-seeking branch* 에 배정. MIPGap 0.05 → 0.15 공격적, 단 *더 좋으면 채택, 아니면 기존 incumbent 유지* (downside 0). → Aggressor §3 비판 부분 인정 (R-nb 비대칭 적극 활용)
  2. Dual-LNS 를 2단계 incremental 통합 — 2주차에 reactive ALNS only 검증, 4주차에 LP-dual guidance 추가. 통합 실패 시 1단계만 유지. → Minimalist §4 비판 부분 인정 (5개 기능 동시 위험)
  3. Phase 0 에 인스턴스 데이터 프로파일링 — 블록 크기·deadline 밀도·베이 가중치 분산을 데이터에서 추출해 파라미터 적응. 도메인 *추측* 대신 *데이터 기반*. → Aggressor §5 + Minimalist 의 "측정 없는 가설 금지" 원칙

Defender 의 핵심 무기: "Aggressor 와 Minimalist 가 *동시에 옳을 수 없다*". Aggressor 는 "더 복잡하게 (7 알고리즘)", Minimalist 는 "더 단순하게 (3 작업)". 두 입장 사이의 절충점이 합의안 — 한쪽이 옳다면 다른 쪽이 틀린다.

결론 · 토론의 수렴

셋이 동시에 satisfy 되는 단계적 구현

세 입장이 *반대 방향* 으로 보이지만, *단계적 구현 전략* 으로 모두 수용 가능. 이게 토론의 진짜 결론.

핵심 통찰

Minimalist 의 진화판 (작업 4개) ≈ 합의안 §5 A1~A4. 즉 합의안의 *부분 폐기 fallback 라인* 과 Lean Baseline 이 같은 것. 둘은 대립이 아니라 같은 베이스 위에 다른 ceiling.

그러므로: 먼저 Lean Baseline 을 *반드시* 만들고, 그 위에 합의안 모듈을 *증분 추가*. 깨지면 Lean 으로 자동 폴백. Aggressor 의 도메인 인터뷰는 *zero-risk* — Week 1 에 시도.

셋의 기여가 단계별로 어떻게 흡수되는가

🪶 Minimalist 의 흡수

  • Week 1~2: Lean Baseline 이 *베이스* 가 됨 (안전 제출 라인)
  • 전체: 매 증분 모듈 추가 시 *깨지면 Lean 으로 자동 폴백* 보장
  • EV 산수 정정: Sharpe ratio 관점에서 분산 관리
  • 핵심 통찰: "먼저 산수부터 하자"

🛡️ Defender 의 흡수

  • Week 3~4: 합의안 모듈 (profiler, K=3 race, Dual-LNS) 증분
  • R2 진화 3가지: Phase 4 축소·Dual 2단계·데이터 프로파일링
  • Phase 간 정보 의존성: 모듈 간 인터페이스 명세
  • 핵심 통찰: "두 비판자가 동시에 옳을 수 없다"

⚔️ Aggressor 의 흡수

  • Week 1: 조선업 인터뷰 (zero-risk, 1시간) — 도메인 가중치 5개 확보 시도
  • Week 6: Phase 3 의 risk-seeking branch (MIPGap=0.15)
  • 실패 시 fallback: 도메인 가중치 = 1.0 균등 (Lean 동등)
  • 핵심 통찰: "R-nb 우측 비대칭 보상에 명시적 베팅"
자가검열

셋의 정직한 자가 평가

세 명 모두 "이 답이 평균 클로드와 얼마나 다른가" 자가검열. 누구도 완벽한 차별화를 주장하지 않았다.

🛡️ Defender
"골격은 여전히 학구적 (ALNS+MIP+race+safety). EV 산수 정정 과 risk-seeking branch 는 평균이 안 하는 디테일. 그러나 차별화의 결정적 1% 는 R3 에서 더 들어가야 함."
⚔️ Aggressor
"클로드 100명 중 5~10명 도달 가능. 0.1% 천재 답안은 아님. 도메인 인터뷰 + R-nb 우측 꼬리 명시는 *진정한 차별점*. 그러나 ALNS·MIP·race 골격 자체는 흔함."
🪶 Minimalist
"Lean Baseline 자체는 평균과 비슷. 차별화는 답이 아니라 EV 가 답. 평균 클로드는 7천만 우승에 끌려 환영을 EV 전부로 착각. Risk-adjusted EV 가 진짜 차별화."
즉시 실행할 액션

토론의 결과 → 실행 계획

세 입장이 *모두* 동의할 5가지 즉시 실행 항목.

5 액션 — 우선순위 순

A1. Lean Baseline 먼저 짜기 (Week 1~2, 10일) [Minimalist 채택]

baseline_greedy + simple LNS + safety net + Phase 0 mini-profiling (1지표). src/myalgorithm.py 가 *반드시 작동하는* 안전 라인 확보. R0~R2 안전 제출 가능. 합의안 §5 A1~A4 와 사실상 동일.

A2. 조선업 인터뷰 시도 (Week 1, 1시간) [Aggressor 의 zero-risk 제안]

한국 거주 + 조선업 종사자 25만명. 지인 1명 30분 인터뷰로 *알고리즘에 박을 변수 우선순위 top-3* 확보 시도. 실패 시 fallback: 가중치 = 1.0 균등. 다운사이드 0, 업사이드 차별화.

A3. 합의안 모듈 증분 추가 (Week 3~5) [Defender 의 ceiling]

Profiler · Aggregate LP-MIP · K=3 race · reactive ALNS · LP-dual guidance 순차 증분. 매 모듈 추가 시 로컬 6 인스턴스 검증 통과해야 zip 생성 (Minimalist 의 위험 매트릭스). 모듈 실패 시 Lean 으로 자동 폴백.

A4. 분기 실험 §4.1·4.2·4.4 (Week 5) [합의안 §4]

Phase 1 의 정체 (Aggregate LP vs Topology-MIP) / ρ>0.85 처리 (의도적 포기?) / Phase 3 dual 사용처. 세 입장의 진짜 결판은 이 실험에 의존. 로컬에서만 결판, 제출 예산 소비 X.

A5. Phase 3 risk-seeking branch (Week 6) [Aggressor R2 진화]

Defender 의 R2 진화 ①. MIPGap 0.05 → 0.15 공격적, 단 *더 좋으면 채택* (downside 0). R-nb 우측 비대칭 보상에 *명시적* 베팅. 본선 캘리브레이션 시 적용.

단 하나 결판 안 난 것: 합의안 §5 A2 (safety net 회귀 차단) 가 *진짜* 모든 부분 실패에서 작동하는가? Defender 와 Aggressor 는 *작동한다고 가정* (그래서 합의안 EV 가 더 큼). Minimalist 는 *작동 안 할 위험* (그래서 분산 큼). 이건 Week 2 검증으로 결판. 만약 작동하면 합의안 채택, 작동 안 하면 Lean 유지.
