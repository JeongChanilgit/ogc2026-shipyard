1. 결론 요약

OGC 2026 문제는 “불규칙 패킹 문제에 스케줄링을 붙인 것”이 아니다. 더 정확히는 event-driven dynamic nesting with vertical-access constraints다. 즉 시간 이벤트가 바뀔 때마다 베이 내부의 2.5D 형상이 달라지고, 그 순간 크레인이 위에서 내려올 수 있어야 한다.

핵심 명제: 전체 문제를 하나의 거대한 MIP/CP로 밀어 넣는 전략은 대회 시간 제한과 불규칙 폴리곤 기하 때문에 무너질 가능성이 높다. 우승권 접근은 항상 feasible한 디코더를 바닥에 깔고, 그 위에서 베이 배정, 순서, 위치, 시간의 일부만 고정한 작은 부분문제를 ALNS, CP-SAT, MIP, 다중 시드 포트폴리오로 계속 개선하는 형태가 가장 그럴듯하다.

1순위: -1 회피

점수식이 feasible/timeout/crash를 -1로 떨어뜨리므로, 미검증 공격적 해보다 보수적 feasible incumbent가 더 중요하다.

2순위: 크레인-aware 패킹

동일층 충돌보다 어려운 것은 ENTRY/EXIT 순간의 위쪽 레이어 투영 충돌이다. 배치 점수에 “나중에 뺄 수 있는가”를 넣어야 한다.

3순위: 목적함수 분해

Z2/Z3는 베이 배정에서 크게 결정되고, Z1은 시간/공간 디코더에서 결정된다. 이 분해를 이용해야 탐색이 빨라진다.

5. 심도 깊은 통합 인사이트

세 묶음의 자료를 OGC 문제에 맞춰 합치면 다음 결론이 나온다.

Insight A: “패킹”이 아니라 “출구가 있는 동적 패킹”이다

일반 nesting은 모든 부품이 끝까지 남는 정적 문제다. OGC는 블록이 들어오고 나가며, EXIT 순간에도 위쪽 경로가 비어 있어야 한다. 따라서 좋은 placement는 단순히 밀도가 높은 배치가 아니라 미래 EXIT를 막지 않는 배치다.

  • 배치 점수에 future_blocker_count, exit_path_overlap, upper_layer_shadow를 넣는다.
  • 큰 블록과 due date가 이른 블록은 “묻히지 않는 위치”를 선호한다.
  • 동일층 충돌 검사는 필요조건일 뿐, 크레인 접근성은 별도의 지배 제약이다.

Insight B: geometry engine과 optimizer를 분리해야 한다

jagua-rs, Shapely, NFP 계열 자료가 공통으로 말하는 것은 기하 검증을 탐색 코드 안에 섞으면 속도와 안정성이 동시에 무너진다는 점이다. OGC에서는 “이 위치 가능한가?”를 매우 빠르게 답하는 작은 커널이 핵심 병목이다.

  • AABB/STRtree/raster bitmask로 후보를 줄인 뒤 정확 polygon 검사를 한다.
  • 방향별 layer polygon, bbox, area, footprint mask는 모두 전처리 캐시한다.
  • 탐색기는 geometry 내부를 몰라도 can_place(), insert(), remove()만 호출하게 한다.

Insight C: exact solver는 “왕”이 아니라 “외과의”다

irregular strip packing MIP 논문들은 강하지만, OGC 전체를 exact solver로 푸는 것은 시간/메모리/기하 복잡도상 위험하다. 대신 exact solver는 작고 날카롭게 써야 한다.

  • 고정된 후보 placement 집합에서 bay assignment, workload balance, preference를 MIP로 개선한다.
  • 작은 시간창의 ENTRY/EXIT interval만 CP-SAT로 재조정한다.
  • MIP start에는 항상 현재 feasible incumbent를 넣고, 실패하면 즉시 heuristic으로 돌아간다.

Insight D: leaderboard 점수는 평균 최적화보다 portfolio를 보상한다

R - nb는 절대 objective가 아니라 팀 간 상대 순위다. 한 알고리즘이 모든 hidden instance를 잘 푸는 것보다, instance regime별로 다른 접근을 달리 돌려 최소한 하나가 잘 맞는 구조가 유리하다.

  • 4코어를 seed 다양화가 아니라 전략 다양화에 쓴다.
  • Z1-dominant, Z2/Z3-dominant, dense/crane-hard, loose/solver-friendly 모드를 분리한다.
  • 마지막에는 objective가 아닌 공식 feasibility gate를 통과한 해만 비교한다.

Insight E: OGC 목적함수는 3층으로 분해된다

  1. Bay assignment layer: Z2 workload imbalance와 Z3 preference deviation의 큰 부분을 결정한다.
  2. Per-bay dynamic placement layer: 위치, 방향, crane-safe ENTRY/EXIT 가능성을 결정한다.
  3. Timing repair layer: Z1 tardiness와 exit conflict를 줄인다.

이 분해는 단순한 편의가 아니라 탐색 복잡도를 낮추는 핵심이다. move 하나가 모든 것을 뒤흔들면 delta evaluation이 불가능하다. 반대로 “bay assignment를 바꾼 두 베이만 재디코딩”하는 구조는 대회 시간 안에 수천 move를 평가할 수 있다.

6. 도출된 문제 접근법

아래는 개인 선호와 무관하게 자료들이 수렴하는 대회형 해법이다.

전처리: 블록과 베이를 “탐색 가능한 물체”로 바꾼다

각 block orientation별로 bbox, area, layer polygon, layer footprint mask, layer별 upper-shadow mask, eligible bay, preference regret, due slack을 계산한다. 모든 좌표는 integer placement에 맞춰 snap한다.

기반 자료: Shapely, STRtree, jagua-rs, NFP 논문들.

Feasible seed: 먼저 반드시 통과하는 해를 만든다

EDD, ATCS, area-desc, preference-regret 순서를 여러 개 만들고, 각 순서에 대해 crane-safe BLF 디코더를 실행한다. 실패하는 블록은 defer하고, 마지막에는 빈 시간창 force-place로 무조건 feasible incumbent를 확보한다.

대회 점수식상 이 단계가 전체 성능의 바닥이다. -1을 막는 보험이 아니라 주 전략이다.

Bay assignment MIP: Z2/Z3를 싸게 줄인다

x[i,j]를 block i가 bay j에 가는 binary로 두고, preference penalty와 workload imbalance를 선형화한다. 기하 가능성은 eligible bay 필터와 면적/높이 surrogate로만 넣는다. 결과는 placement decoder의 초기 배정 또는 ALNS repair 가이드로 사용한다.

목표는 optimum 증명이 아니라 좋은 배정 후보를 빠르게 얻는 것이다.

Per-bay decoder: 위치와 시간은 같이 결정한다

placement 후보마다 ENTRY/EXIT 가능성을 즉시 검사한다. 핵심은 현재 블록이 기존 블록을 막는지만 보는 것이 아니라, 새 블록이 들어온 뒤 기존 블록의 예정 ENTRY/EXIT 순간을 retroactively 막는지도 확인하는 것이다.

크레인 제약이 사후 repair로 밀리면 좋은 objective 해가 feasibility gate에서 무너진다.

Crane mask: suffix-OR로 위쪽 막힘을 O(1)에 가깝게 본다

bay마다 layer L 이상에 존재하는 footprint의 OR mask를 유지한다. block layer l의 크레인 접근은 footprint(block,l) & upper_mask[l]로 빠르게 필터링한다. 정확 검사는 통과 후보에만 수행한다.

이 구조는 OGC의 l2 >= l1 규칙과 정확히 맞는다.

ALNS: 문제 특화 destroy/repair를 돌린다

일반 random removal보다 OGC 특화 연산자가 중요하다. critical tardy chain removal, crane blocker chain removal, bay imbalance removal, preference regret removal, time-window cluster removal, dense-bay evacuation을 쓴다. repair는 greedy, regret-k, solver-assisted, random-biased를 섞는다.

CP-SAT/Gurobi repair: 작은 창만 정밀 수술한다

좋은 incumbent에서 일부 블록의 placement 후보를 2-5개씩 고정 후보로 만들고, 작은 시간창의 ENTRY/EXIT, bay reassignment, tardiness를 CP-SAT/MIP로 재조정한다. 시간 제한은 전체의 작은 비율로 묶고, 해가 나오지 않으면 폐기한다.

4-core portfolio: 서로 다른 실패 모드를 가진 전략을 동시에 돌린다

Core 1은 ultra-safe greedy/repair, Core 2는 Z1 tardiness aggressive, Core 3은 Z2/Z3 assignment-balanced, Core 4는 dense/crane-aware 모드를 돌린다. 모든 worker는 best feasible만 공유하고 마지막에 공식 objective로 비교한다.

구체적인 move 설계

Move 변경 대상 목적 검증/비용
ShiftBlock 블록 하나의 bay 변경 Z2/Z3 개선, 혼잡 bay 완화 기존 bay와 새 bay만 재디코딩
SwapBlocks 두 블록의 bay 교환 workload balance를 유지하면서 preference 개선 두 bay 재디코딩
ReorderWindow 한 bay의 시간창 내 순서 Z1 tardiness 감소 해당 window만 재디코딩
ReorientAndPlace 한 블록의 orientation, position crane blocker 감소, 밀도 개선 geometry delta check
EvictBlockerChain 특정 EXIT를 막는 블록 묶음 크레인 접근성 회복 관련 bay의 suffix mask 재구성
TimingShift ENTRY/EXIT 시각 같은 배치에서 tardiness/접근성 조정 이벤트 순서와 crane check

하지 말아야 할 접근

  • 전체 continuous polygon MIP: 논문적으로 흥미롭지만 OGC의 hidden instance, 시간 제한, 다층/크레인 제약을 모두 담기 어렵다.
  • bbox packing만 믿기: objective는 좋아 보여도 stage 4/5 feasibility에서 무너진다.
  • 크레인 제약 사후 repair: 나중에 고치기 어려운 blocker 구조가 이미 만들어진다.
  • 온라인 ML/RL: 평가 서버 인터넷 차단, CPU only, hidden distribution 불확실성 때문에 리스크가 크다.
  • 마지막 해 미검증 반환: 이 대회에서는 좋은 objective보다 검증된 feasible이 더 비싸다.

7. 실행 로드맵

문제 자체만 놓고 가장 효율적인 개발 순서를 제안하면 다음과 같다.

단계 목표 완료 조건 리스크
M0 공식 feasibility와 objective를 모든 실험의 단일 기준으로 고정 모든 candidate가 return 전 check_feasibility 통과 로컬 checker와 제출 checker 차이
M1 Geometry cache와 crane suffix mask 구현 entry/exit check가 기존보다 빠르고 retroactive obstruction을 잡음 mask 근사와 정확 polygon 판정 불일치
M2 항상 feasible한 constructive decoder 무작위/스트레스 instance에서 infeasible 0건 너무 보수적이면 objective 열화
M3 Bay assignment MIP 또는 greedy-regret seed Z2/Z3가 baseline 대비 안정적으로 개선 기하 불가능한 배정을 많이 만들 수 있음
M4 ALNS destroy/repair 5종 이상 동일 시간 안에 incumbent objective가 단조 개선 state copy 비용, 재디코딩 비용
M5 작은 CP-SAT/MIP repair loose 또는 tardiness-heavy instance에서 추가 개선 solver import/license 실패, time overrun
M6 4-core portfolio와 instance regime router 평균보다 최악 케이스가 개선, loss instance 감소 병렬 오버헤드와 memory peak
M7 제출 안전장치 time guard, exception guard, last feasible fallback, zip size 확인 마지막 실험 변경으로 안정성 훼손

최종 전략 문장

“후보 위치를 똑똑하게 줄인 뒤, 베이별로 crane-safe dynamic BLF를 수행하고, ALNS가 블록 묶음을 빼고 다시 넣으며, 작은 exact solver는 고정 후보의 assignment/timing만 수술한다.” 이것이 세 자료군이 함께 지지하는 OGC 2026용 균형점이다.
