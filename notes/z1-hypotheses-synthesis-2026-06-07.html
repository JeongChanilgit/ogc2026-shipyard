§A증거 베이스 (모든 추론의 근거)

A·1  핵심 사실 (다중 출처 수렴)

사실근거
z1=0은 원리상 전 인스턴스 달성 가능 — 내재(단일머신·cumulative-area) tardiness LB=0 (모든 베이 OPTIMAL, α≥0.9)z1-toggles, z1-feasibility-floor 메모, crane_headroom.py (99.9% 감소가능)
tardiness 원인 = 크레인 j≥k 직렬화 + greedy enter-ASAP 피크 + 2D 패킹 단편화. 용량 아님(tardy 블록은 베이 75~94% 빈 채 대기)packing_z1_analysis.py (area 포화 기여 0%), crane_headroom.py
진짜 벽 = 2D 비정형 packing-over-time 조정. 타이밍만/수요평탄화만으론 패킹 floor에 막힘greedy 레이아웃 최적타이밍 floor=883 ≫ 풀서치 309; 4×4 더해도 prob_14 27→25(정체)
현 파이프라인 승자 4종은 전부 "고정 배정" 위에서 재타이밍/재패킹 (cum_level·cpsat_timing·bbox_pack), cross-bay만 1블록 이동. 남은 floor는 배정 자체가 한계 (prob_20: 현배정 bbox floor 68 vs LB 0)code map + z1-toggles prob_20 분석
±20× 비결정성: cum_level CP-SAT 비결정 → 같은 인스턴스가 39s/0 또는 197s/우회. 분산이 시간·품질 둘 다 흔듦이번 세션 prob_3 솔로39s vs 경합197s

A·3  이번 세션에서 새로 확정

  • baseline 제거 불가 — A/B: 제거 시 z1 0→1만~3만 (2,800배). cum_level이 재타이밍할 토대.
  • cum_level 탐색폭(α×order)은 wall에 영향 0 — 솔로 full 3×3=222.2s vs lean 1×1=223.0s. "탐색폭 줄이기" 가설 기각. 시간은 예산 스핀에 묶임(A·2).
  • order-level break 버그픽스 완료 — 베이가 LB 도달 후 추가 재디코드 중단 (prob_3 64.7→39.3s). 단 전역 z1=0이 아닌 per-bay LB 기준이라, 병렬 부모는 여전히 느린 워커 대기(A·2).
  • greedy byte-identical 재구성은 2~4× 느려서 폐기 — greedy 비용은 "호출당 후보수"가 아니라 "포지션 호출수(O(n²))".

§3권장 실행 순서 (저위험·고확실 → 고효과·고위험)

0실험 베이스라인 정정 — T-D: CUMLEVEL_PARALLEL=1 빼고, 제출 실제 config(순차)로 20개 재측정. 지금까지 수치는 오염 가능. (싸고 필수)

1안전한 시간 절감 — T-A(cum_level stall-abort, objective-neutral) → 효과 확인 후 T-C(bbox 재정렬) A/B. 둘 다 z1 유지하며 슬로 인스턴스 대폭 단축 기대.

2정책 결정 — T-B(z1=0 조기종료): z2/z3 폴리시 vs 시간 트레이드. 대회 R−nb 동점깨기 영향 확인 후 on/off.

3z1 추가 감소(저위험 먼저) — Z-E(bbox 강화) → Z-C(작은 베이 CP-SAT exact)로 z1≤2 5개 마무리 시도.

4하드 인스턴스 돌파(고위험) — Z-A(Z1-proxy 배정/LBBD) 또는 Z-B(anticipatory 배치)로 12·14·20의 패킹 floor 공략. 비용·위험 큼 → 별도 트랙.

교차 주의점
  • ±20× 비결정성 — 단일 실행 측정은 신뢰 낮음. 모든 A/B는 다중 시드/반복으로. 분산 축소(시드 고정·multistart) 자체가 "빠른 수렴 안정화" 레버.
  • 모든 변경은 official checker 게이트 통과 — Z1↓라도 weighted-obj가 incumbent보다 나쁘면 채택 안 함(−1·회귀 방지). 새 레버는 게이트 뒤에서만.
  • 평가서버 = 인스턴스당 4코어 단독 — 측정은 솔로(또는 ≤2 동시)로. 4동시 경합 수치는 부풀려짐.
