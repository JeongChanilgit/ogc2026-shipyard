한눈에 (Executive Overview)

설계 철학

검증된 feasible 바닥(floor)을 깔고, 그 위에서 '진짜 목적함수'에 대한 assignment-level 지역탐색으로 개선하되, 모든 후보는 반환 전 check_feasibility 게이트를 통과해야 한다 — 크래시/타임아웃이 절대 −1을 못 만들도록 전 구간 try/except + 데드라인 가드.

점수 모델

score(team, instance) = -1 # infeasible / timeout / crash = R - nb # feasible (R = #teams, nb = #teams strictly better) total = Σ score over all instances
핵심 시사점
  • −1 회피가 1순위 — 한 인스턴스 실현불가 = −1, 평균 R/2 손실
  • 동점(nb 동일) OK — 엄밀히 더 좋은 팀 수만 제거
  • "모든 문제 안정적 feasible"이 "한 문제 압도"보다 유리
범례
✅ 적용됨 코드에 이미 구현 / 기본 ON
💡 추가여지 미구현이거나 default OFF인 가속 레버

크레인 j ≥ k 규칙 — 가장 어려운 제약

크레인은 수직으로만 움직인다. 블록의 layer k를 내리거나 올리면 j ≥ k인 모든 높이를 휩쓴다 → 그 경로에 수평으로 겹치는 기존 layer(j ≥ k)가 있으면 막힌다. j < k 층은 절대 방해 안 함.

시간 예산 — 데드라인 사다리

모두 time.monotonic 절대시각, T = max(1.0, timelimit).

데드라인 공식 의미 anchor
check_cost min(0.8, 2e-5·n² + 0.05) check_feasibility 1회 보수적 추정(관측 ~50×), 예약 :4160
done_by t_start + 0.88·T search+게이트 종료 목표, 12% 서버 세이프티 :4161
work_deadline max(done_by − check_cost, t_start + 0.2·T) 모든 search 작업의 소프트 데드라인 :4162
decode_deadline = work_deadline (레버용으로 당겨짐) per-decode admission/abort 경계 :4163
hard_stop t_start + hard_frac·T
(n≤120→0.970, else 0.995)		 절대 −1 가드: 이 뒤로 check를 시작 안 함 :4164

⏱ 시간단축 / 안전 방법론

  • ✅ 적용됨Monotonic 절대 데드라인 사다리 — 88% 목표 + 12% 세이프티로 타임아웃 −1 차단.
  • ✅ 적용됨_DECODE_SAFETY=1.8 (:276) — 디코드 비용을 1.8× 과대추정해 admission, 단일 per-bay crane 디코드(원자적·관측 ~1.7× 과소추정)의 오버런 방지.
  • ✅ 적용됨Per-decode deadline + 잔여 tail force-place (_decode_bay, :967-991, :1033) — 단일 디코드가 절대 벽시계 초과 못 함.
  • ✅ 적용됨Lever-reserve = min(0.40·T, max(15.0, 0.22·T)) (:4177-4192) — 후단 Z1 레버에 윈도우 확보(대형 인스턴스서 search가 예산 다 먹는 것 차단).
  • ✅ 적용됨check_feasibility 비용을 n²로 추정·예약 — check가 hard_stop을 절대 못 넘게.
  • ✅ 적용됨ALNS touch_fits 워치독 (:1704) — 2-베이 재디코드가 deadline 넘는 move 스킵.
  • 💡 추가여지적응형 _DECODE_SAFETY — 현재 고정 1.8; 관측 디코드 시간으로 동적 보정하면 보수적 마진 회수 여지.

S0

Trivial floor

Serial EDD — 동시점유 없는 최후의 −1 가드. 검증 불필요.
_trivial_solution :2097 항상 실행
입력 prob_info, bays, feasible_bays → 출력 candidates["trivial"], floor 초기화

모든 블록을 자기 베이의 시간 윈도우에 단독 배치. 동시 점유가 없으므로 crane/collision 제약이 vacuous. 검증 없이 feasible한 유일한 구성이자 최후의 −1 가드.

  • ✅ 적용됨feasible_bays 1회 precompute (:4143) 재사용.
  • 💡 추가여지baseline이 거의 항상 이기면 lazy 스킵 가능하나, 안전망이라 유지 권장.

Feasibility / −1 회피 안전망

6겹 안전망 — 모든 겹이 독립적으로 작동
  1. Trivial floor (검증 불필요 feasible) — Stage 0에서 항상 구성, 즉시 사용 가능.
  2. 검증된 floor ("never worse than baseline"가 타이밍 독립) — 모든 stage에서 단조 상승만.
  3. crane-safe 디코더 (retroactive obstruction까지, _find_slot_crane_safe :361; _force_in_bay :338 empty-window 보장).
  4. 모든 후보 게이트 검증 + objective-safe 채택규칙 — 검증 없이 "done" 선언 없음.
  5. 전 구간 시간가드 (force-place tail, _DECODE_SAFETY=1.8, hard_stop, touch_fits).
  6. 크래시 봉쇄 (전체 try/except, 모든 옵셔널 import guarded no-op).
