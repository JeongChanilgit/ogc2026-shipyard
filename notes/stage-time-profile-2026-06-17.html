한 화면 결론

레거시가 벽시계의 45%(~130s)를 먹지만 그 결과는 항상 버려진다. 모든 인스턴스에서 box·gassign(둘 다 CP-SAT)이 레거시 결과를 절반의 시간으로 짓밟는다. 그리고 obj를 실제로 줄이는 건 전부 CP-SAT 단계다 — 그리디 플로어(~65s)는 "feasible하지만 나쁜 출발점"만 만들고, CP-SAT 타이밍 오라클은 3.5s로 428M→218M을 깎는다.

  • 최대 낭비 = 레거시 예산. prob_26: 레거시 130s→200M(버려짐) vs box 74s→27.9M vs gassign 67s→21.96M(승). 레거시의 130s 정제는 box가 독립적으로 더 좋은 해를 내므로 거의 전부 헛일(피드백: 첫 산출물 아님 — 데이터로 확정).
  • 실제 일꾼 = CP-SAT 4종: cpsat_timing(레거시 내부, 초당 최대 효율) · box · gassign · perbay. 그리디는 출발점 생성만.
  • 시간 절감 레버 ① set2에서 레거시 예산을 "feasible 플로어"용으로 축소(~130s→~35s)하고 남은 시간을 box/gassign에. ② 4코어 병렬 후보 실행(현재 순차) → 같은 벽시계에 각 후보 풀예산 → gassign 굶주림 해소(prob_39서 gassign@full이 경쟁자 격파).
  • CP-SAT 방향: 그리디를 더 줄이고 CP-SAT를 더 쓰되, warm-start·증분모델·적응형 worker로 가속. §5 참조.

하이브리드 myalgorithm.algorithm()에 후보별 _stage_timer + 채택 obj _stage_obj 계측을 추가(게이트 OGC_STAGE_TIMING, 미설정 시 zero-overhead·동작불변 → 평가서버 영향 0). T=300s에서 4개 후보가 모두 활성(gassign은 T≥200, box는 reserve≥20). 3개 인스턴스로 서로 다른 레짐을 커버: prob_26(중형 150블록), prob_30(z1-갭), prob_38(z1-벽). 단계는 순차 실행(legacy→box→gassign→perbay)이라 합이 곧 벽시계.

관찰 1 (시간 낭비): 레거시는 매번 가장 큰 슬라이스(~130s, 44%)를 받지만 그 obj(200M/255M/147M)는 box·gassign에 의해 즉시 폐기된다. box는 레거시 결과를 입력으로 쓰지 않는 독립 솔버라, 레거시의 130s 정제는 "feasible 출발점 1개"를 넘는 가치가 거의 0이다.
관찰 2 (CP-SAT 효율): 모든 큰 감소가 CP-SAT에서 나온다 — box(−86~95%), gassign(−21~27%), perbay(−4.6%), 그리고 레거시 내부의 cpsat_timing이 단 3.5s로 428M→218M(−49%). 그리디 단계는 감소를 거의 못 만든다.
관찰 3 (굶주림): gassign·box가 각각 67~74s만 받는데도 승자다. 더 주거나 병렬화하면 더 낫다 — 별도 측정에서 gassign@120s는 prob_39서 경쟁자(29.74M)를 28.84M로 이김. 하이브리드에선 67s로 굶어 못 살림.

§5 CP-SAT 모델링 아이디어 ★

이미 CP-SAT인 자산: cpsat_timing(per-bay disjunctive 타이밍) · box(box-decomp 2D) · gassign(LBBD 배정+디코드+타이밍) · perbay(NoOverlap2D+크레인 joint). 실측상 obj 감소의 사실상 전부가 이들에서 나온다 → 방향은 "그리디↓ CP-SAT↑ + CP-SAT 가속".

A. 시간 절감 — CP-SAT가 대체하는 휴리스틱 제거/축소

  • 1그리디 플로어 → CP-SAT seed 축소. 플로어 65s는 폐기될 나쁜 해. set2에선 빠른 feasible 플로어(타임캡 ~20s)만 만들고 CP-SAT(box/gassign)에 위임. (cpsat_timing이 428→218 깎는 걸 보면 CP-SAT가 그리디 정제보다 압도적.)
  • 2crossbay_relocate(휴리스틱) → gassign이 이미 대체. gassign=CP-SAT 전역 재배정. 활성 시 중복 → 게이트 스킵으로 시간 절약.
  • 3z1_repair 반복 휴리스틱 → cpsat_timing 오라클 1회. gassign이 이미 이 패턴(고정 레이아웃에 disjunctive 타이밍 1-shot) 사용 → 더 빠르고 더 좋음. 레거시 z1_repair를 오라클로 교체.
  • 4cheaper_steps·cum_level alpha 멀티스타트 축소(set2). obj 기여 미미한데 시간 점유.

B. 기존 CP-SAT 가속 (같은 품질, 적은 시간)

  • 5warm-start / hint 재사용. gassign 마스터·cpsat_timing·perbay가 매번 scratch. 직전 incumbent 레이아웃을 AddHint → 수렴 가속. (gassign은 balanced_seed 힌트만 씀 → incumbent 추가.)
  • 6증분 모델 재사용 (LBBD). gassign이 LBBD iter마다 모델 rebuild. 모델 유지 + cut만 추가하면 재구성 비용 절감.
  • 7fix-and-optimize (CP-SAT LNS). perbay/timing에서 전체 재풀이 대신 윈도우 변수만 풀고 나머지 고정 → 큰 bay에서 시간↓.
  • 8적응형 worker 수. 작은 bay/instance는 1-worker+seed(4-worker 스폰 오버헤드 제거 + 결정성↑), 큰 것만 4-worker. 병렬 후보(레버9)와 결합 시 코어 배분에 필수.

C. 병렬화 (4코어) — 시간-효율 #1

  • 9후보 병렬 실행. 현재 순차(292s). legacy(축소)·box·gassign을 병렬 프로세스로 각각 ~풀 TL → best-of of full-budget. 같은 벽시계에 굶주림 해소. CP-SAT worker는 후보당 분배(예: box 2 + gassign 2). ledger상 "achievable ceiling"으로 식별됨.

D. 새 CP-SAT 정식화 (품질 레버)

  • 10z3-near-preferred 패킹. 경쟁자 승점(moderate z1, low z3)을 per-bay CP-SAT로: "선호 베이 유지 최대화 s.t. z1 ≤ budget". perbay_t3가 K² 폭발했으니 skyline/contact 후보 가지치기 + NoOverlap2D 직접 모델로 재시도. (단 prob_38류 크레인-멀티레이어 벽은 falsified.)
  • 11gassign 마스터에 z3-aware cut. 현 area-time relaxation은 z3 무관 → 과스필. 마스터가 z3-spill 비용을 보게 하면 굶주림 해소 시 더 나은 점 도달.
