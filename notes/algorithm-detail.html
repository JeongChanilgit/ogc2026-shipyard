알고리즘이 받는 것 / 돌려주는 것

OGC2026 평가서버가 algorithm(prob_info, timelimit) 을 호출. 알고리즘은 dict 형태의 solution 을 반환해야 한다. 시그니처 변경 금지.

prob_info: dict
bays베이 N개. 각각 W_j, H_j + polygon shape
blocks블록 M개. 각각 multi-layer polygon
↳ shapeorientation 별 layer polygon 리스트
↳ R_i, D_i, P_irelease / due / processing time
↳ S_ij베이 j 에 대한 선호도 (합=100)
weightsw1, w2, w3 — 목적함수 가중치
solution: dict
operations{ str_time: [op, ...] }
↳ op한 블록의 ENTRY 또는 EXIT 이벤트
↳ block_id어떤 블록인지
↳ bay_id어느 베이에 들어가는지
↳ x, y, o정수 좌표 + orientation
↳ kind"ENTRY" 또는 "EXIT"

알고리즘 안에서 우리는 별도의 내부 자료구조 (Solution, Placement) 를 만들어 개선·검증·수정을 하다가, 마지막에 위 출력 포맷으로 직렬화해서 반환한다.

검진 — 환자가 어떤 환자인지 5초 안에 판단

비유

응급실에 환자가 들어오면 의사는 5초 안에 청진기·체온·혈압 만 보고 "이 환자는 응급 / 일반 / 수술 / 중환자실" 분류한다. 정밀 검사는 그 뒤에. 처음 5초의 분류가 틀리면 다음 30분이 통째로 잘못된 자원 배분으로 흐른다.

프로파일러는 6개 지표를 측정해서 4가지 인스턴스 클래스로 분류하고, 그에 따라 Phase 1~3 의 시간 배분과 워커 선택을 결정한다.

측정하는 6가지 지표

ρ_j = Σ(A_i · P_i) / (W_j · H_j · T_h)
Capacity Tightness
베이 j 의 시공간(가로 × 세로 × 시간)이 얼마나 빡빡하게 차는가.
→ ρ_max > 0.85 = TIGHT, < 0.5 = LOOSE
H_i = S_max - S_2nd
Preference Concentration
블록 i 가 특정 베이를 *얼마나 강하게* 선호하는가.
→ H_i > 50 인 블록은 변수 고정 후보
u_j = Ā / A_j
Bay Weight
평균 베이 면적 대비 베이 j 의 면적 역수. Z2 (workload imbalance) 에 쓰임.
→ u_j 분산이 크면 Z2 가 dominant
env_i = min over orient (bbox area)
Envelope Footprint
블록 i 의 모든 orientation 중 최소 bbox 면적. 패킹 난이도 추정.
→ 큰 블록 식별 (NFP/grid 자동 스위칭)
DAG_w = max_t |active(t)|
DAG Width
시간 sampling 으로 동시 활성 블록 수의 최댓값 추정.
→ width 작으면 MIP 강력, 크면 LNS 유리
w_dom = argmax(w1·Z1*, w2·Z2*, w3·Z3*)
Weight Dominance
목적함수 Z1·Z2·Z3 중 어느 게 점수에 가장 큰 영향인가.
→ Z1 dominant 면 EDD 강화, Z2 면 balance 우선

def phase0_profile(prob_info) -> dict:
    # 약 5초 안에 완료되어야 함
    bays = prob_info["bays"]
    blocks = prob_info["blocks"]
    T_h = max_horizon(blocks)  # 모든 due_date + processing 의 최대

    # 1. 베이 가중치 u_j
    avg_area = mean(bay.area for bay in bays)
    u = [avg_area / bay.area for bay in bays]

    # 2. capacity tightness ρ_j
    rho = []
    for j, bay in enumerate(bays):
        load_j = sum(blk.envelope_area * blk.P for blk in blocks
                     if argmax(blk.S) == j)
        rho.append(load_j / (bay.W * bay.H * T_h))

    # 3. preference concentration
    H = [max(blk.S) - sorted(blk.S)[-2] for blk in blocks]

    # 4. 큰 블록 식별
    big_blocks = [i for i, blk in enumerate(blocks) if blk.envelope_area > 0.3 * min_bay_area]

    # 5. DAG width estimate
    samples = sample_times(blocks, n=20)
    dag_width = max(count_active_at(t, blocks) for t in samples)

    # 6. 가중치 dominance
    Z_estimates = estimate_objective_terms(prob_info)
    w_dom = argmax([prob_info["weights"][i] * Z_estimates[i] for i in range(3)])

    # → 인스턴스 클래스 결정
    instance_class = classify(rho, H, dag_width, w_dom)
    time_budget = allocate_time(instance_class, timelimit)

    return {"class": instance_class, "rho": rho, "H": H,
            "u": u, "budget": time_budget, "forced": [i for i in range(len(blocks)) if H[i] > 50]}

Worker A · EDD-Greedy++
베이스라인 진화 · 안전망

정렬 기반 휴리스틱. 모든 인스턴스 클래스에서 활성. 최저 안전망.

  1. 블록을 D_i 오름차순, tie-break P_i 내림차순 정렬
  2. 각 블록 i 마다:
  3. argmax_j S_ij 베이부터 시도 (선호 순)
  4. 진입시각 후보 = {기존 EXIT 시각들 ∪ R_i}
  5. 각 시각에 NFP 후보 위치 → 첫 feasible 채택
  6. 실패 시 다음 베이로 fall through
  7. 모든 베이 실패 시 시각을 늦춰서 재시도

Worker B · Aggregate LP-MIP
Theorist 의 통찰 · LOOSE 인스턴스에서 강력

공간 좌표 무시한 부분 모델을 Gurobi 가 anytime 으로 풀이.

  1. 결정변수 x_{ij} ∈ {0,1}, t_i^E, t_i^X

  6. 결과 (j, t_E, t_X) 를 NFP 배치로 좌표화

강점: 전역 최적성, Z2 single-bottleneck 정확 식별
Worker C · Anti-EDD Slack-Aware
Contrarian 의 통찰 · Z2-dominant 대비

워크로드 균형 우선. 다른 매니폴드로 직교성 확보.

  1. 블록을 (u_j · P_i) 큰 것 먼저 정렬
  2. 매 블록 배치마다 베이별 누적 부하 L_j 추적

강점: Z2 imbalance 최소화, EDD 가 약한 패턴에서 강함

시간축 진척

NFP (No-Fit Polygon) — 세 워커가 *공통으로* 쓰는 배치 도구

한 마디로

이미 배치된 블록들의 footprint 를 *Minkowski sum* 으로 확장하면, 새 블록이 들어갈 수 있는 *경계*가 나온다. 그 경계의 corner 점들이 NFP candidate.

베이스라인은 모든 가능한 corner 를 다 시도. 우리는 NFP 가 만든 경계 corner 만 시도. 완전성 (no miss) 보장, 후보 수 *수십 분의 일*.

⚡ 메모리 폭발 방지: AABB 겹침 쌍에 대해서만 lazy 계산 + LRU 캐시

def phase2_vote(workers_results: list, prob_info) -> Solution:
    # workers_results = [(solution_A, obj_A), (solution_B, obj_B), (solution_C, obj_C)]

    candidates = []
    for sol, obj in workers_results:
        if sol is None:
            continue
        ok, stage = check_feasibility(sol, prob_info)  # 5단계 검사
        if ok:
            candidates.append((sol, obj))

    if not candidates:
        # 셋 다 망함 → safety net 으로 즉시 점프
        return safety_net_force_place(prob_info)

    # 통과한 후보 중 최저 objective 선택
    best_sol, best_obj = min(candidates, key=lambda x: x[1])

    # 진 워커는 명시적으로 stop signal
    stop_other_workers()

    return best_sol  # Phase 3 시드로 전달

PHASE 3 · 10:00 ~ 25:00 / 50% time

정밀 개선 — Dual-Guided LNS 로 매니폴드 뚫기

⏱ 시간 예산: ~15분 🎯 목표: 채택된 시드에서 *strictly* 더 나은 점 찾기
비유

수술 본격 단계. 환자는 안정됐고, 이제 정밀 조작으로 결과를 개선. 외과의는 무작위로 조직을 건드리지 않는다 — 혈관조영 영상 을 보며 *어디를 건드리면 효과가 있을지* 신호를 받는다.

Theorist 의 통찰: 평균 답변은 random walk (SA / Tabu). 우리는 LP dual 의 reduced cost 를 신호로 받는다 — "이 블록을 옮기면 목적값이 △ 만큼 떨어진다" 는 1차 근사값. 매니폴드에 갇히는 걸 막기 위해 2~3 블록 simultaneous re-placement.

LNS 한 사이클 — 4단계

STEP 1
SELECT
LP dual reduced cost 큰 블록 2~3개를 destroy 후보로 선택
STEP 2
DESTROY
선택된 블록들을 현재 솔루션에서 제거. 빈 공간·시각 슬롯 노출
STEP 3
REPAIR
NFP candidate 로 동시 재배치. 베이·orientation 도 다시 결정
STEP 4
ACCEPT
check_feasibility 통과 + obj 엄밀히 더 좋으면 채택. 아니면 원복.

def phase3_dual_guided_lns(seed: Solution, lp_duals: dict,
                            time_budget: float) -> Solution:
    best = seed
    UB, LB = best.objective(), lp_duals["lower_bound"]
    deadline = time.monotonic() + time_budget
    iter_count = 0

    while time.monotonic() < deadline:
        # STEP 1: dual 신호로 destroy 후보 선택
        reduced_costs = compute_reduced_costs(best, lp_duals)
        destroy_set = top_k_by_dual_signal(reduced_costs, k=3)

        # STEP 2: 블록 제거
        partial = best.copy()
        for blk_id in destroy_set:
            partial.remove_block(blk_id)

        # STEP 3: 동시 재배치 (NFP 매니폴드 뚫기)
        repaired = simultaneous_replace(partial, destroy_set, lp_duals)
        if repaired is None:
            continue  # 재배치 실패, 다음 iteration

        # STEP 4: 검증 + 채택
        ok, _ = check_feasibility(repaired)
        if ok and repaired.objective() < best.objective():
            best = repaired
            UB = best.objective()
            iter_count += 1

            # Polyak step rule — dual update
            subgrad_norm = compute_subgradient_norm(best, lp_duals)
            step = (UB - LB) / (subgrad_norm ** 2)
            lp_duals = update_duals(lp_duals, step)

        # 안전 체크: feasibility 잃으면 즉시 best 로 롤백
        if not ok:
            best = last_known_feasible(best)

    return best

왜 *동시* 재배치인가

Contrarian 의 Round 2 공격: "NFP candidate 안에서의 최적은 그 매니폴드의 local minimum". 즉, 블록 i 를 옮기면 그 자체로는 더 좋아질 수 없지만, 블록 i 와 j 를 *동시에* 옮기면 둘 다 더 좋아질 수 있는 점이 있다. 단일 블록 swap 만으로는 그 점에 도달할 수 없다.

그래서 매 iteration 에서 2~3 블록을 함께 제거하고 함께 재배치. NFP 매니폴드를 국소적으로 뚫는다.

매 iteration 의 안전 가드

  • 모든 새 후보는 check_feasibility 통과한 경우에만 채택
  • objective 가 엄밀히 더 좋아야 함 (같으면 거부)
  • 매 iteration 직전의 best feasible 솔루션을 last_known_feasible 에 보존
  • time_budget 만료 시 즉시 best 반환, iteration 미완료 거부

        log(f"[DIAG] phase=4 result=OK obj={best.objective()}")
        return serialize_to_operations(best)  # 정상 출력

    # 2차: 실패 → safety_net 강제 작동
    log(f"[DIAG] phase=4 result=FAIL stage={stage}, falling back")
    safety_sol = safety_net_force_place(prob_info)
    ok, stage = check_feasibility(safety_sol, prob_info)
    if ok:
        return serialize_to_operations(safety_sol)

    # 3차: 그것도 실패 → utils._force_place (이론적으로 절대 실패 X)
    log(f"[DIAG] phase=4 result=CRITICAL, last resort")
    last_sol = utils._force_place_all(prob_info)
    return serialize_to_operations(last_sol)
src/myalgorithm.py :: phase4_return()

check_feasibility 5단계

  • Stage 1 — Assignment: 모든 블록이 정확히 1번 ENTRY + 1번 EXIT
  • Stage 2 — Crane entry: ENTRY 시각에 *위층 footprint* 비어있는가
  • Stage 3 — Crane exit: EXIT 시각에 *위층 footprint* 비어있는가
  • Stage 4 — Spatial: 같은 시점 같은 layer 의 블록끼리 겹침 X
  • Stage 5 — Sequential: EXIT - ENTRY ≥ P_i, ENTRY ≥ R_i

이 5단계 검사는 utils.py 에 정의되어 있고 평가서버가 동일한 함수를 사용한다. 로컬에서 통과하면 서버에서도 통과가 보장된다 (utils.py 수정 금지 이유).
