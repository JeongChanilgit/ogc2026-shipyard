§1남은 병목 2가지

B1 · 느린 수렴 (속도)

큰 인스턴스(200~300블록) 수렴이 200~296s. 단계분석: cum_level CP-SAT + 재디코드가 지배. BR캐시·기하가속으론 안 줄어듦(CP-SAT 바운드). 평가서버 4코어·no-GPU.

cum_level = bay별 cumulative-area CP-SAT(8s 예산)로 entry-target 산출 → 그 순서로 재디코드. DUAL이 2× bbox_pack 추가.

B2 · 배정 과부하 (품질)

prob_13·20·11·12: 한두 베이 footprint >100% 과부하, 나머지 19~57% 텅 빔 → tardiness 불가피. greedy 단일-블록 cross-bay가 조율된 다중-블록 재배정을 못 함(xbaymoves=80도 무효).

crane j≥k = Blocking Job-Shop + Block-Relocation. 이게 엄밀 z1<10·prob_20<10의 진짜 벽.

§2B1 개선 — CP-SAT/수렴 가속 (논문 리서치)

가설메커니즘예상위험근거(논문)
S1 고정순서 타이밍 DP ★ 순서가 정해지면 최적 타이밍은 O(n) EAS(release 존중 forward sweep) — CP-SAT를 타이밍 경로에서 제거. CP-SAT는 *순서*만 탐색. cum_level CP-SAT 대폭 단축 중
우리 제약은 2D cumulative-area라 순수 단일머신 아님 — 검증 필요		 Du&Leung 1990(1‖rⱼ‖ΣTⱼ NP-hard, but fixed-seq O(n)); Lawler 1977. cp-sat-primer
S2 CP-SAT anytime 튜닝 greedy 해를 add_hint 워밍스타트 + tight horizon(greedy makespan) + relative_gap_limit=0.05 + use_lns_only=True + num_workers=4. 같은 8s에 더 좋은 첫 해 / 더 빨리 수렴 낮음
파라미터만, 게이트가 보호		 CP-SAT Primer(Krupke); OR-Tools docs; share_objective_bounds
S3 energetic cumulative use_overload_checker_in_cumulative=True + use_dynamic_precedence — 혼잡 베이(75~94% 점유)서 강한 가지치기. congested 베이 탐색트리 축소 중
저점유 베이엔 느릴 수 있어 점유율별 토글		 Baptiste/Le Pape/Nuijten 2001; sat_parameters.proto
S4 4코어 포트폴리오 LNS num_workers=4: 1 systematic + 1 first-solution + 2 LNS, objective bound 공유. 1→3 워커서 ~90% 단축 보고. ~3~5× CP-SAT 가속 낮음 CP-SAT Primer LNS; or-tools-discuss
S5 BR캐시 완료 bounding_rect 인스턴스 메모이즈 +10~17% (적용됨) 없음 이번 세션 측정

핵심: S1(타이밍 DP)이 최대 레버 — cum_level이 사실상 *순서*만 CP-SAT로 찾고 재디코드하니, 순서를 ALNS가 주면 타이밍은 공짜. 단 2D-area 제약이 단일머신이 아니라 적용성 검증 선행. S2/S4는 저위험 즉효.

§3B2 개선 — 배정 조율 (과부하 해소) (논문 리서치)

가설메커니즘예상위험근거(논문)
Q1 배정-LNS 매트휴리스틱 ★ (1순위) MIP 배정 master(packing-aware proxy) + 빠른 패킹 oracle + ruin-and-recreate: 과부하 베이 주변 3~6블록 destroy → 그들 배정만 restricted MIP로 repair. 다중-블록 조율 이동(현 greedy의 결손). prob_13·20·12 과부하 해소 중
기존 패커 재사용, exact loop 불필요 → 구현성 최고		 Jeon&Lee 2023(조선소 block assignment, workload위반 −35%); Schaus 2014(MIP-LNS machine reassign); Ropke&Pisinger ALNS
Q2 LBBD (master=배정, sub=패킹) master(MIP)=bay 배정+tardiness proxy, sub(CP/패킹)=2D+crane feasibility 검사 → 불가능하면 minimal infeasible subset no-good cut. master가 그 부분집합을 다른 베이로 재배치. exact·유한수렴. 가장 강한 reach (하드 인스턴스 돌파) 고
polygon sub는 no_overlap_2d(사각형) 한계 → NFP 휴리스틱 oracle 필요		 Hooker 2007(planning+scheduling, ≥1000× vs MIP); Côté/Haouari/Iori 2021(2D-BPP CBD); Mao 2024(AM 스케줄+2D 패킹 CBD); Polyakovskiy&M'Hallah JITBP(2D-BPP+tardiness, 우리와 직접 유사)
Q3 더 나은 packability proxy area 대신 bbox/convex-hull area·strip 하한·shape-complexity 페널티로 배정 master capacity. + MIS 캐싱(infeasible 부분집합 재사용). 우리의 "area=나쁜 proxy" 관측 직접 대응. master가 과부하를 더 일찍 정확히 감지 낮음
Q1/Q2의 보조, 단독으로도 cross-bay 개선		 Lodi/Martello/Monaci 2002; Gardeyn 2025(pole-of-inaccessibility+hull); Côté 2021(MIS cut)
Q4 Column generation (패턴=베이 적재) 각 컬럼=한 베이에 패킹·crane-feasible한 블록 부분집합. master가 패턴 선택, pricing이 새 부분집합 생성. 과부하 베이=infeasible 컬럼(미선택). 강한 LP 하한 + 조율 배정 고
pricing(2D irregular)=NP-hard → 휴리스틱 pricing		 Pisinger&Sigurd 2005(2D-BPP B&P); Barnhart 1998; Van den Akker 1999(parallel-machine tardiness CG)

핵심: 진단(과부하 = mutually-incompatible 블록 *집합*)이 정확히 LBBD의 no-good-cut 구조와 맞음. 단 우리 polygon+crane은 표준 사각형 패킹보다 어려워 sub-oracle를 NFP 휴리스틱으로. Q1(배정-LNS)가 구현성·위험 균형 최선 1순위, Q2(LBBD)가 최대효과·고위험.

§4권장 실행 순서

1저위험 즉효 (속도) — S2(CP-SAT anytime 튜닝: hint+tight horizon+gap_limit+lns_only) + S4(num_workers=4 포트폴리오). 파라미터만, 게이트 보호. cum_level 8s 예산서 더 좋은 해.

2최대 속도 레버 (검증 선행) — S1(타이밍 DP): cum_level의 CP-SAT를 "순서 탐색"으로 한정하고 타이밍은 O(n) oracle. 단 2D-area 제약 적용성 먼저 확인.

3품질 돌파 (배정) — Q3(bbox/hull proxy + MIS 캐싱, 저위험)부터 → Q1(배정-LNS 매트휴리스틱)로 prob_13·20·12 과부하 조율 해소.

4고효과·고위험 (장기) — Q2 LBBD(master=배정, sub=NFP 패킹 oracle, no-good cut). Mao2024·Polyakovskiy JITBP가 직접 청사진.

모든 변경은 official-checker 게이트 뒤 + 다중런(±20× 비결정성) 검증. 평가서버 4코어·no-GPU·no-internet 준수.
