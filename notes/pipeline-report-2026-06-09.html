§1 파이프라인 시퀀스

objective-safe by construction — 모든 개선 단계는 consider() = full-objective 게이트를 통과해야 채택된다. 어떤 단계도 목적함수(obj)를 악화시키지 않는다. w1 지배 구조이므로 Z1을 올리는 이동은 Full-obj 게이트에서 자동 거부된다.
0
문제·예산 — 3-NP-hard 결합 + 시간 공유
베이·위치·방향·진입/퇴출 시각 동시 결정
Z1 Z2 Z3

문제 본질: 조선소 블록을 베이 배정 · 2D 위치 · 방향 · 진입/퇴출 시각 5변수를 동시에 결정. 2D 이형 폴리곤 패킹 + tardiness 스케줄링 + 베이배정이 결합된 3개 NP-hard 문제.

목적함수: obj = w1·Z1 + w2·Z2 + w3·Z3. w1(17,000~29,000) ≫ w3(125~200) ≫ w2(4~10). Z1(tardiness)가 obj를 지배하므로 파이프라인은 Z1을 먼저·강하게 줄이고 그다음 Z2/Z3를 다듬는다.

시간 예산: T = tl(로컬=100s, 평가서버 수분~30분). done_by = t_start + 0.88·T, hard_stop = t_start + min(0.988·T, T-8). 모든 후처리 단계는 단일 공유 deadline을 본다. cum_level만 잔여의 70% 캡을 먹고, 이후 단계들은 잔여 전체를 재흡수 → 앞 단계가 일찍 끝나면 절약분이 뒤로 자동 흐른다.

1
FLOOR (baseline / greedy)
최초 feasible 해 생성 — 이후 모든 단계의 출발점
Z1 Z2 Z3 모두

무엇: 모든 블록을 베이에 배치해 최초의 feasible 해를 만든다.

어떻게: baseline_greedy.greedyalgorithm. (Phase 1) EDD(Earliest Due Date) 순서로 블록을 돌며, 각 블록에 대해 선호도 내림차순 베이에서 _placement_score = w1·tardiness + w2·imbalance + w3·preference가 최소인 (베이,위치,방향)을 best-fit으로 선택, 크레인 수직접근(j≥k) 안전한 진입/퇴출 시각 부여. (Phase 2) repair로 잔여 충돌 해소.

적응형 floor: 큰 인스턴스·짧은 tl에선 fast-floor 전환. 트리거 _greedy_est = 1.2e-3·n² > 0.4·T. fast-floor는 후보위치 폭 pos_k 축소(기본 2). full floor(pos_k=0)는 ALNS 탐색(단계 8)을 동반하며 긴 tl에서만 적합.

RASTER 옵션(전처리 가속): 크레인 충돌 체크를 Shapely 대신 폴리곤을 정수셀로 보수적 래스터화한 셀집합 교집합으로. 폴리곤 정밀 유지 + 빠름 → 같은 tl에 더 넓은 floor(pos_k=3) 가능 → 더 낮은 z1. 단 dense 구조라 선호도(z3) 희생 경향.

무엇을 움직이나: z1/z2/z3 모두의 출발값을 정한다. tardy 인스턴스의 floor z1이 높으면 뒤 단계들이 끌어내린다.

2
cum_level
Z1 재디코드 — 후처리에서 시간 최다 소비
Z1 주

무엇: 베이를 재디코드해 tardiness(Z1)를 낮춘다. 후처리에서 보통 시간을 가장 많이 쓰는 단계.

어떻게: 여러 (블록순서 × alpha 가중) 시드를 best-of로 시도(OGC_CUMLEVEL_ORDERS / ALPHAS). 각 시드마다 CP-SAT 누적(cumulative) 타이밍 + 크레인-안전 재배치(_decode_bay→_find_slot_crane_safe)로 베이를 다시 푼다. 시간이 많을수록 더 많은 시드 → 더 낮은 z1 ("z1 = time + breadth").

무엇을 움직이나: Z1만(베이 배정 유지). 시간 대비 z1 수율은 중간(저효율인 인스턴스도 있음).

예산: 잔여의 70% 캡(_cl_dl).

3
cpsat_timing
Z1 타이밍 최적화 — 배치 고정, 시각만 CP-SAT
Z1만

무엇: 베이/위치/방향을 고정한 채 진입·퇴출 시각만 CP-SAT로 최적화해 tardiness를 더 깎는다.

어떻게: pairwise 크레인 충돌 boolean을 precompute한 disjunctive 타이밍 모델을 CP-SAT로 푼다(_cpsat_bay_timing_verified).

무엇을 움직이나: Z1만. 배치가 고정이라 Z2/Z3 불변(bay/x/y/orient fixed → Z2,Z3 unchanged). 보통 작은 추가 개선. 단 prob_9/prob_15/prob_16 등 대형에서는 수백~수천 단위의 큰 개선.

4
bbox_pack (+ bbox_pack2, bbox_pack_slab)
Z1 재패킹 — 베이별 위치 CP-SAT 최적화
Z1 주

무엇: 베이별로 블록 위치를 CP-SAT로 다시 패킹해 tardiness를 낮춘다.

어떻게: 각 베이에 잔여시간 비례 예산(sub_budget)을 주고 tardiness 최소화 CP-SAT(_bbox_pack_bay). 예산이 클수록 더 낮은 tardiness까지 푼다. bbox_pack2는 2차 패스. bbox_pack_slab는 슬래브 특화 패스.

무엇을 움직이나: 주로 Z1. 시간 대비 z1 수율이 매우 높은 단계. 관측 예시: prob_20 tl=100s에서 z1 171→65를 4초에, prob_1에서 z1 52→0.

5
crossbay_relocate
Z1 베이 간 이동 — tardy 블록 다른 베이로
Z1 주 Z2 부수 Z3 부수

무엇: tardy 블록을 다른 베이로 옮겨 tardiness를 낮춘다(배정 변경).

어떻게: tardy 블록을 순회하며 다른 베이로 relocate + 해당 베이 재패킹(bbox CP-SAT), consider(full-obj) 게이트로 채택. max_moves(기본 40)·deadline까지.

무엇을 움직이나: 주로 Z1. 배정이 바뀌므로 Z2/Z3도 부수적으로 변하나, 선호도를 능동적으로 노리진 않음 — z3는 약간 악화되기도.

6
cheaper_steps / reschedule
Z1 결정적 마무리 — EDD left-shift
Z1 잔여

무엇: 고정 레이아웃에서 EDD left-shift로 진입시각을 당겨 잔여 tardiness를 제거(_fixed_layout_reschedule) + 값싼 소규모 이동.

어떻게: 결정적 단일 패스(시간 비례 아님 — deadline은 중단용). 한 번에 마무리 효과.

무엇을 움직이나: Z1의 잔여분(force-place로 멀리 밀린 블록 회수). prob_17에서 z1 44→8로 대폭 감소.

7
Front B (fb_relocate / fb_swap)
Z2/Z3 유일 능동 레버 — 선호 베이 재배정
Z2 주 Z3 주

무엇: 블록을 선호 베이로 재배정해 선호도 이탈(Z3)과 부하 불균형(Z2)을 낮춘다. Z2/Z3의 유일한 능동 레버.

어떻게: 잔여 예산 동안 반복: ① relocate — 각 블록을 다른 베이로 옮길 때의 Z2/Z3를 closed-form _assignment_proxy로 평가, 개선 후보를 크레인-안전 _insert_block_fixed_others로 실현, consider(full-obj) 게이트. ② swap — relocate가 막히면 두 블록의 베이를 교환(꽉 찬 선호 베이에서 블록을 빼냄).

무엇을 움직이나: Z2/Z3. full-obj 게이트라 Z1 악화 이동은 자동 거부(w1 지배) → objective-safe. 단 "leftover budget" 단계라 앞의 Z1 단계들이 시간을 다 쓰면 거의 못 돈다. dense floor에선 단일 이동이 Z1을 깨서 채택 실패하기도(Z3가 floor에 baked-in).

8
search / cpsat_seed / seeds_decode
ALNS 탐색 — 긴 tl 전용 (짧은 tl에서는 비활성)
긴 tl 전용 전역 Z1 구조

무엇: full-floor 경로(긴 tl·작은 인스턴스)에서 도는 LNS/ALNS 기반 메타휴리스틱 탐색 + CP-SAT 시드 + 시드 디코드. 더 나은 전역 구조를 탐색.

어떻게: 파괴-재구성(destroy-repair) 반복, gated incumbent 갱신. fast-floor 경로(큰 인스턴스·짧은 tl)에선 시간이 없어 거의 0초(skip).

무엇을 움직이나: 전역적으로 obj(주로 Z1 구조). 짧은 tl=100s 대형 인스턴스에선 비활성. prob_2·prob_8 등 소형에서 cpsat_seed+seeds_decode로 Z3 대폭 개선 관측.

§2 문제별 그래프 (prob_1 ~ prob_20)

default (현행) raster (OGC_FLOOR_RASTER + pos_k=3) Z1 (tardiness) Z2 (load imbalance) Z3 (preference) obj (total)

§3 핵심 인사이트

tl=100s 조건에서 관측된 구조적 패턴

1
Z1 감소는 계단식 — floor에서 높게 출발해 cum_level → cpsat_timing → bbox_pack → crossbay_relocate → reschedule을 거치며 계단식 하강. 각 단계가 독립적으로 Z1을 깎는다. 시간 대비 효율은 bbox_pack이 최고(prob_1에서 z1 52→0을 0.56초에). cum_level은 시간을 가장 많이 먹지만 큰 인스턴스에서 필수적.
2
Z3는 거의 floor에서 결정 — 베이 배정이 floor에서 굳어지므로, Z3 궤적은 floor 이후 거의 평평하다. Front B(fb_relocate/fb_swap)가 줄이려 하나 "leftover budget" 단계이므로, 앞의 Z1 단계들이 시간을 소진하면 거의 실행되지 않는다. dense floor(raster 모드)에선 단일 이동이 Z1을 깨서 채택 실패하기도 → Z3는 floor에 baked-in.
3
대형 인스턴스에서 default의 z1 파탄 — raster가 교정 — tl=100s에서 default는 대형 인스턴스(prob_14: z1=1046, prob_18: z1=926, prob_20: z1=1549)에서 파탄적 Z1을 보인다. floor가 너무 오래 걸려 cum_level 예산을 잠식하기 때문. raster+pos_k=3은 floor를 4~40초로 단축해 후처리 예산을 보전 → prob_14: z1=9, prob_18: z1=4, prob_20: z1=6으로 전부 한 자릿수 교정. 대신 소형 인스턴스에서 raster는 z3가 높아 default가 obj 우위.
4
cum_level이 시간 최다 소비 — 거의 모든 인스턴스에서 cum_level이 전체 wall time의 40~70%를 점유한다. "z1 = time + breadth" 원칙대로, cum_level 시간이 길수록 z1이 낮아진다. 단 raster 모드에서는 floor가 빠른 덕에 cum_level이 더 많은 시드를 돌려 같은 시간에 더 낮은 z1 달성.
