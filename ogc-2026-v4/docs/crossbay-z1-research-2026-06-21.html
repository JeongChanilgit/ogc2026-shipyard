크로스베이로 z1을 핸들링할 수 있는가?

OGC 2026 · 자율 연구 · 2026-06-21 · 3-갈래 조사(이론 / 실측 진단 / 실제 A/B)
가설: 피크-타겟 크로스베이 이동 판정: FALSIFIED 유일한 z1 레버 = intra-bay crane repack (v3, 이미 프로덕션)

0한 줄 요약

크로스베이 이동으로 z1(tardiness)을 줄이는 것은 이론적으로 타당하지만(interval graph χ=ω 클리크 분해), 우리 인스턴스에서는 두 개의 독립적 장벽으로 실현 불가다. 실제 기계장치 A/B에서 21건 시도 전부 기각(채택 0). 구조적 진단(has_slack=NO)과 정확히 일치.

왜 죽었나 — 두 장벽

장벽 1 · 전역 release 몰림 (공간/구조)
블록 release가 모든 베이에 동시에 몰려, 한 베이가 피크일 때 다른 베이도 혼잡하다. 피크 시점 "가장 한가한" 도착 베이도 co-presence 6~19. 클리크를 한 베이에서 빼면 다른 베이가 동등하게 오른다 → χ=ω 하한이 per-bay가 아니라 전역이라 재배치로 못 내림.
장벽 2 · z3 페널티 ≫ 미미한 z1 한계이득 (목적함수)
CP-SAT 타이밍 오라클이 이미 베이 내 최적이라 블록 1개를 빼도 z1은 거의 안 변한다(연속·미분 작음). 반면 비선호 베이로의 이동은 z3가 w3·(S_max−S_chosen) 만큼 이산적으로 점프 → 전체 obj가 항상 증가. z3-중립 swap도 장벽 1 때문에 실패.

1가설 — v4 배정 실험과 무엇이 다른가

v4에서 falsified된 배정 레버(reassign=z3-min, reassign_balance=총부하 균형)와 다른 각도를 시험했다.

  • v4 reassign: 블록을 선호 베이로 몰기(z3-min) → z1 2~16배 폭발(선호 베이가 더 혼잡해짐).
  • v4 reassign_balance: 총 부하 균형 → z1 3~11배 폭발(작은 베이가 고밀도화).
  • 이번 가설(신규): 피크 시점 co-presence를 타겟 — 가장 혼잡한 베이의 피크 클리크 블록을 시간적으로 보완적인(그 구간에 덜 겹치는) 베이로 이동. 선호 무관, 한계 재분배. 이론은 "총부하 균형은 실패, 피크 타겟은 통한다"를 지지(§2).

2이론(문헌) — 가설은 수학적으로 옳다 VALID IN THEORY

web 리서치 결과: 피크-타겟 크로스베이 재배치는 네 갈래 문헌이 독립적으로 뒷받침한다.

Interval Graph χ=ω (Perfect Graph)
블록 [entry,exit] 구간 그래프에서 크로마틱 수 = 최대 클리크 = 피크 동시공존 수. 피크 클리크를 분해하면 크레인 직렬화 길이 k→k−1. 단 총부하 균등은 클리크 크기를 안 줄임.
Temporal Bin Packing (peak occupancy)
objective = 순간 최대 점유. 총 절약 = 잡 간 시간 겹침의 함수 → 겹치는 잡을 다른 빈으로 분리하면 peak↓.
Resource Leveling (peak-day targeting)
Burgess-Killebrew류: 피크 일자 식별 → 슬랙 있는 활동을 피크 밖으로. sum-of-squares ≠ peak.
Blocking Job Shop swap
크레인 j≥k 직렬화와 동형. cross-machine swap(부하 보존)이 blocking을 국소적으로 줄이는 neighborhood.

→ 이론은 "왜 총부하 균형(v4)이 실패하고 피크 타겟이 통할 수 있는지"를 정확히 설명한다. 단, 전제 = 시간적으로 보완적인 도착 베이가 존재해야 함. 이 전제를 §3에서 깬다.

이동마다 동일한 패턴

  1. 도착 베이 삽입 (free_ids={b}) → CP-SAT OPTIMAL, local z1 감소 (단독으로는 OK).
  2. 출발 베이 b 제거 후 재패킹 → FEASIBLE, 출발 베이 z1도 약간 감소.
  3. 전체 obj (공식 체커) → base 초과 → 항상 기각. 예 prob_26 bid=135: 도착 local z1=0(OPTIMAL)인데 global obj 14,383,920 > 14,370,841 (Δ+13,079 악화).
  4. infeasible 기각 2건(prob_38 bid=236, prob_26 bid=138): 이동이 다른 베이 crane 제약을 전역 위반.

베이스라인 z1이 1,018~4,381로 높은데도(프로덕션보다 깎을 여지 많은 출발점) 0건 채택 → 타이트한 프로덕션 해에서는 a fortiori 실패. 음의 결과가 더 강해짐.

5결론 & 다음 방향

z1 = 구조적 co-presence. 블록을 베이 간에 옮겨선 못 푼다. 세 갈래(이론·진단·A/B)가 수렴하고, 기존 falsification(v4 배정, reassign_balance, 밀도≠z1)과 정합. 재시도 가치 없음.

더 깊은 진실: z1의 하한은 전역 피크 co-presence(release/due가 결정하는 불가피한 구간 겹침의 합)이며, 어떤 공간 재배치로도 못 내린다. 줄이는 길은 둘뿐 — (a) due 슬랙 있는 블록의 entry를 피크 밖으로 미루기(= CP-SAT 타이밍 오라클이 이미 베이 내에서 수행), (b) processing footprint 축소(불가).

그래서 obj를 더 깎으려면 (크로스베이 아님)

  • 유일하게 살아있는 z1 레버 = intra-bay crane-aware repack + timing (v3, 이미 프로덕션 = best-of 타이밍 오라클).
  • z3 (obj의 7.9%): wrong→preferred 이동(bpass)은 이미 z3-타겟으로 수행 중. 추가 여지 제한적.
  • windowed relayout polish(src/relayout.py): 고-TL(≥400s)·additive에서만 살아있는 후보 — 운영 TL 길 때만 의미(별도 추적).
  • 실전 우선순위는 여전히 never−1: set2 ALL40 feasibility 최종 검증 + 운영 TL 확정이 obj 미세개선보다 점수 레버가 큼.
