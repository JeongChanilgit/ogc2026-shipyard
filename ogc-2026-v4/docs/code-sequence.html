1. 개요 / 목표

OGC 2026 (Optimization Grand Challenge 2026)은 LG CNS × 대한산업공학회 주최 최적화 경진대회다. 문제 본질: 조선소 블록들을 여러 베이(bay)에 배정하고, 각 블록의 위치(x, y), 방향(orient), 진입·퇴출 시각(entry/exit)을 동시에 결정해 아래 3-항 목적함수를 최소화한다. 

  목적함수:  min  w1·Z1  +  w2·Z2  +  w3·Z3

    Z1 = Σ max(0, exit_i − due_i)          ← tardiness (지각)
    Z2 = max_{j} workload_j − min_{j} workload_j   ← 베이 간 작업부하 불균형
    Z3 = Σ (S_max_i − S_chosen_i)          ← 선호도 페널티

  제약: 모든 블록 정확히 1개 베이 배정, 공간 충돌 없음,
        크레인 수직접근(j ≥ k 규칙), release/processing time 준수
  • set1 (prob_1..20): 경쟁자 점수 테이블 존재. 목표 = 경쟁자 total obj 이하.
  • set2 (prob_21..40): 경쟁자 데이터 없음. 크고 레이어 수 많음. −1 회피가 최우선.
  • 채점: infeasible/timeout → −1. feasible → R − nb (R=팀수, nb=더 좋은 팀 수). 동점 OK.
  • v3/v4 목표: best-of 솔버 출력에 additive never-worse 후처리(crane-repack)를 얹어 obj를 추가로 낮춘다. set1(z1=0)은 후처리 skip → 회귀 0 보장.

2. 전체 아키텍처 다이어그램

평가 서버는 algorithm(prob_info, timelimit) 한 함수만 호출한다. 이 함수는 크게 best-of 솔버(FULL 예산 사용)와 v3 후처리(남은 시간, 선택적)로 구성된다. 

┌─────────────────────────────────────────────────────────────────────┐
│  algorithm(prob_info, timelimit)  — myalgorithm.py                  │
│  SAFETY = max(8s, TL × 0.08)                                        │
│                                                                      │
│  ① v2 GLOBAL (unified_greedy)                                        │
│     └─ 예산: min(TL × 0.5, TL − SAFETY)                             │
│     └─ Linux: fork + SIGKILL 하드-킬 / Windows: in-process 폴백      │
│     └─ OGC_GLOBAL=1, OGC_ORDER=blend(R+0.5P), OGC_FFT_MASK=1       │
│                         │                                            │
│                         ▼  (v2 끝나면 남은 시간이 자연히 ②로 흘러감)   │
│  ② 원래 솔버 (solver_orig)  ← set1 강·self-limit·항상 feasible        │
│     └─ 예산: TL − SAFETY − elapsed   (FULL 예산 !)                   │
│     └─ best-of: v2 obj vs orig obj → 더 낮은 쪽 채택                  │
│                         │                                            │
│                         ▼  (둘 다 실패 시)                            │
│  ③ baseline_greedy 폴백  ← 절대 infeasible 없음                       │
│                         │                                            │
│  ─────────────────── best ──────────────────                         │
│                         │                                            │
│  ④ v3 POST-PROCESS  (조건부, additive, never-worse)                   │
│     ┌── 조건: best ≠ None                                            │
│     │         AND pp_remaining > 20s                                 │
│     │         AND OGC_NO_PP ≠ "1"                                    │
│     │         AND z1(best) > 0   ← 핵심 gate                         │
│     │                                                                │
│     │   z1 = 0 이면 → SKIP (set1 ~19/20, byte-identical 반환)        │
│     │   z1 > 0 이면 → postprocess(prob_info, best, deadline)         │
│     │                                                                │
│     └── 실패 시 → 직전 best 유지 (never-worse 보장)                   │
│                         │                                            │
│                         ▼                                            │
│  return best (solution dict)                                         │
└─────────────────────────────────────────────────────────────────────┘
set1 bypass 설계 원칙
set1의 prob_1..19 대부분은 z1=0 (tardiness 없음). 이 경우 후처리는 tardiness만 깎으므로 논리적 no-op → 완전히 건너뜀. best-of 결과가 바이트 단위로 동일하게 반환된다. 회귀 위험 = 0.
예산 설계: "best-of는 FULL 예산을 빼앗기지 않는다"
v3 후처리는 best-of가 일찍 끝나서 자연히 남는 시간에서만 동작한다. PP_RESERVE 같은 별도 예산 차감 없음. 원래 솔버가 TL 가득 쓰면 후처리는 pp_remaining < 20s → 자동 skip.

best-of 3종 솔버 비교

솔버 엔진 강점 예산 배분
unified_greedy (v2 GLOBAL) 전역 Pass B — 배정 emergent, cpsat_guideline + marginal 스코어링, FFT 마스크 set2 (+19.5% vs g0), 빠른 종료로 후처리 여지 확보 TL × 0.5 (상한)
solver_orig gassign-first PURE (C3_MULT=2.0), CP-SAT timing oracle, fastfloor set1 강 (set1 271.93M, 경쟁자 279.82M 격파), z1=0 19/20 TL − SAFETY − elapsed (잔여 전부)
baseline_greedy 공식 EDD + Best-Fit + Phase 2 repair 항상 feasible, 절대 −1 없음 폴백 전용

3. postprocess 시퀀스

postprocess(prob_info, solution, deadline_monotonic) — postproc.py

진입 시 try/except로 전체를 감싸므로 어떤 예외가 발생해도 원본 solution을 그대로 반환한다 (never-worse). 

postprocess(prob_info, solution, deadline_monotonic)
│
├─ [try/except 전체 — 예외 시 return solution 원본]
│
├─ adapter.deserialize(prob_info, solution)
│   └─ solution["operations"] 파싱 → bays_placed = {bay_id → [placed, ...]}
│   └─ 각 placed = {id, sh, x, y, orient, entry, exit, world}
│   └─ sh = gridmap.build_shape(bid, ..., orient_idx, scale=2)
│   └─ world = {layer → shapely translate(sh.layers[l].poly, x, y)}
│
├─ global_eval(prob_info, bays_placed)    ← OFFICIAL checker 호출
│   └─ 실패 / infeasible → return solution 원본
│
├─ _run_loop(data, bays_placed, base_obj, deadline, K=5)
│   │
│   └─ [ROUND LOOP — 전체 round가 accept 0이면 수렴, 또는 deadline]
│       │
│       ├─ SPATIAL 단계 (tardy 베이 우선순위 정렬, z1 내림차순)
│       │   for each tardy bay j:
│       │     for axis in "x", "y", "o":
│       │       ts = _pass_cap(len(placed_j), remaining, n_active_bays)
│       │       new_pl = crane_repack_bay(data, j, placed_j, ts,
│       │                   n_xcand/n_ycand/n_ocand by axis, K=5)
│       │       trial = {**cur, j: new_pl}
│       │       ev = global_eval(data, trial)
│       │       if ev.feasible AND ev.obj < cur_obj − 1e-6:
│       │           cur = trial; cur_obj = ev.obj; round_accepts += 1
│       │
│       └─ CROSS-BAY 단계 (tardy + 선호 베이 불일치 블록)
│           targets = 정렬(z3 기여 내림차순, lateness 내림차순)
│           for each (bid, z3c, lateness) in targets:
│             ts = _pass_cap(...)
│             trial, _ = try_move(data, cur, bid, ts, K)
│             if trial → global_eval → strictly better → 채택 continue
│             trial, _ = try_swap(data, cur, bid, ts, K)
│             if trial → global_eval → strictly better → 채택
│
│       round_accepts == 0 → break (수렴)
│
└─ if best_obj < base_obj − 1e-6:
│   final = global_eval(best_bays)
│   if feasible → return serialize(best_bays)   ← 개선된 솔루션
│
└─ else → return solution (원본)   ← 개선 없음 또는 실패

_pass_cap — 적응형 CP-SAT 시간 할당

def _pass_cap(n_bay_blocks, remaining, n_active_bays):
    # size_cap: 블록 수에 비례 (12s~40s). 큰 베이는 precompute 세금(~8-9s)이 크므로 상한 필요
    size_cap = min(40.0, max(12.0, 0.30 * n_bay_blocks))
    # budget_cap: 남은 시간을 활성 베이 수로 나눠 한 패스가 예산 독식 금지
    budget_cap = remaining / max(1.0, 2.0 * n_active_bays)
    return float(max(8.0, min(size_cap, max(budget_cap, 10.0), remaining)))

4가지 spatial axis 모드

axis(n_xcand, n_ycand, n_ocand)의미
"x"(K, 0, 0)x 후보 K개, y/orient 고정 → x축만 이동 + 타이밍 재최적화
"y"(0, K, 0)y 후보 K개, x/orient 고정 → y축만 이동 + 타이밍 재최적화
"o"(0, 0, K)orient 변형 K개 → 회전 + 타이밍 재최적화
t (timing-only)(0, 0, 0)위치 고정, 타이밍만 재최적화 (원래 timing oracle)

참고: (0,0,0) 모드는 현재 라운드 루프에서 x/y/o 세 축이 모두 타이밍을 joint하게 다루기 때문에 별도 "t" 패스는 삭제됨. 위치 자체를 건드리지 않으려면 (0,0,0)으로 호출하면 된다.

4. crane_repack_bay 4단계 — 핵심 엔진

crane_repack_bay(data, bay_id, placed, time_s, n_xcand, n_ycand, n_ocand, free_ids=None) — crane_cpsat.py

한 베이를 단위로 위치 후보(공간) + entry 시각(시간)을 CP-SAT로 동시에 재최적화한다. 크레인 충돌 boolean을 위치 이산화 덕분에 사전계산할 수 있다는 게 핵심 아이디어다.

Never-worse 보장의 수학적 근거
모든 블록의 후보 0번 = 현재 pose (current x, y, orient). CP-SAT 초기 힌트도 후보 0 + 현재 entry. 따라서 현재 솔루션이 모델 내에서 항상 표현가능 → CP-SAT 최적값 ≤ 현재 tardiness.
  • A
    위치 후보(candidates) 생성

    각 블록에 대해 선형 합집합(Linear Union) 후보 세트를 만든다 — 그리드 곱(K×K)이 아니라 합집합(K+K).

    # 후보 세트 (de-dup 포함, per block)
candidates(b) = {current_pose}             # 후보 0 — 항상 포함 (never-worse)
             ∪ {x-shifted, K개}           # x 축 후보 (current y, current orient 고정)
             ∪ {y-shifted, n_ycand개}      # y 축 후보 (current x, current orient 고정)
             ∪ {orient-variants, n_ocand개} # 다른 orient (x,y는 새 orient bbox로 clamp)

# 총 후보 수 per block = 1 + (n_xcand-1) + n_ycand + n_ocand  (중복 제거 후)
# K_x × K_y 그리드가 아니므로 combo 수 폭발 억제

    windowing (window_tardy_only=True): active 블록 = tardy 블록 + 그 주변(near_margin=8.0 이내) 블록만. 나머지는 frozen (후보 0만, 위치/시간 상수).

    LNS 모드 (free_ids ≠ None): active = free_ids ∩ 이 베이 블록들. bpass의 try_move/try_swap이 이 모드를 사용해 단일 블록만 자유롭게 움직이고 나머지를 동결.

    combo cap (_COMBO_CAP = 200,000): 후보-쌍 총 수가 초과 시 o → y → x 순서로 후보 수를 축소.

  • B
    크레인 boolean 사전계산

    모든 (블록 쌍 a,b) × (후보 조합 ci_a, ci_b)에 대해 시간과 무관한 5개 boolean을 공식 checker 함수로 계산한다. 

    # 5개 boolean per (a, b, ci_a, ci_b)
coll  = check_collisions(bay, [blk_a, blk_b])   # 공간 충돌 여부
ba_e  = check_entry(bay, [blk_b], blk_a)        # b가 존재할 때 a 진입 불가?
ab_e  = check_entry(bay, [blk_a], blk_b)        # a가 존재할 때 b 진입 불가?
ba_x  = check_exit(bay, [blk_b], blk_a)         # b가 존재할 때 a 퇴출 불가?
ab_x  = check_exit(bay, [blk_a], blk_b)         # a가 존재할 때 b 퇴출 불가?

# 공간 위치가 이산화돼 있으므로 "크레인 접근 가능 여부"를 시간 변수 없이 판정 가능
# all-False 조합은 저장 생략 → 성긴 dict

    핵심 인사이트: 위치를 이산 후보로 고정하면 크레인 boolean이 시간과 독립적으로 결정된다. 그래야 "위치 선택 → 해당 위치의 크레인 제약 → 시간 disjunction"을 CP-SAT 단일 모델로 표현할 수 있다.

    LNS 모드에서는 frozen-frozen 쌍은 현재 솔루션이 이미 feasible이므로 계산 생략.

  • C
    CP-SAT 모델 구축 + 풀기

    CP-SAT 변수:

    • sel[b][ci] BoolVar — 블록 b가 후보 ci를 선택 (ExactlyOne)
    • e[b] IntVar — 블록 b의 entry 시각 ([R_b, H])
    • frozen 블록: sel/e 변수 없음 — 현재 값이 정수 상수

    각 boolean이 True인 (a, b, ci_a, ci_b) 조합에 대해 gated disjunction을 추가:

    # 예: coll=True → 두 블록의 시간이 겹치지 않아야 함 (어느 쪽이 먼저든 OK)
if coll:
    l1, l2 = BoolVar, BoolVar
    m.Add(exit_a <= entry_b).OnlyEnforceIf([l1] + gate)   # a 먼저
    m.Add(exit_b <= entry_a).OnlyEnforceIf([l2] + gate)   # b 먼저
    m.AddBoolOr([l1, l2]).OnlyEnforceIf(gate)               # 둘 중 하나는 true

# gate = [sel[a][ci_a], sel[b][ci_b]]  (둘 다 free인 경우)
# frozen 블록은 sel var가 없으므로 gate에 포함되지 않음

# ba_e, ab_e, ba_x, ab_x 도 유사한 2-리터럴 disjunction으로 모델링

# 목적함수: Σ max(0, e[b] + P[b] - D[b])  — free 블록만
m.Minimize(sum(tard_vars))

    warm start: AddHint(sel[b][0]=1, e[b]=cur_entry[b]) → 현재 해가 힌트로 주어져 CP-SAT 시작점 = 현재 tardiness.

    4-worker 병렬, max_time_in_seconds = ts, log_search_progress = False.

  • D
    결과 추출 + 새 placed 재구성
    for p in placed:
    b = p["id"]
    if not is_free[b]:
        new_placed.append(dict(p))   # frozen: 그대로 복사
        continue
    ci = solver.Value(sel[b])에서 선택된 후보 인덱스
    new_x, new_y, new_o = cands[b][ci]
    sh = cand_shapes[b][ci]           # orient-variant면 해당 shape, 아니면 p["sh"]
    new_entry = solver.Value(e[b])
    new_exit  = new_entry + P[b]
    new_world = {l: translate(sh.layers[l].poly, new_x, new_y) ...}
    new_placed.append({...p, sh, x, y, orient, entry, exit, world 갱신})

    반환값: (new_placed_or_None, status_str, wall_s, info_dict)

    INFEASIBLE/UNKNOWN → None 반환. 호출자(postproc._run_loop)가 None이면 현재 layout 유지.

crane_repack_bay 흐름 요약:

  placed (current)
       │
  Step A: _build_candidates()
       │  ├─ active/frozen 분류 (windowing or LNS free_ids)
       │  └─ 후보 세트: {cur} ∪ x-shifts ∪ y-shifts ∪ orient-variants
       │       (combo count > 200k → shrink o→y→x 순)
       │
  Step B: _precompute_combos()
       │  └─ (a,b,ci_a,ci_b) → (coll, ba_e, ab_e, ba_x, ab_x)
       │       공식 check_collisions / check_entry / check_exit 사용
       │       frozen-frozen 쌍 skip (LNS 모드)
       │
  Step C: CP-SAT
       │  ├─ sel[b][ci] BoolVar + ExactlyOne
       │  ├─ e[b] IntVar [R_b, H]
       │  ├─ boolean → gated time-disjunction
       │  ├─ Minimize(Σ tardy, free blocks only)
       │  └─ AddHint(sel[b][0]=1, e[b]=cur_entry)  ← warm start
       │
  Step D: extract
       └─ free: solver.Value(sel/e) → 새 (x, y, orient, entry, exit, world)
          frozen: dict(p) 그대로
       → new_placed or None

6. v4 실험 결과 — 배정 레버 (전부 falsified)

v4 세션에서는 z1 근본 원인을 배정 레벨에서 제거하려는 시도를 다수 수행했다. 아래는 검증된 결론이다.

레버 설명 결과 판정
assign_floor z3-최적 배정 바닥(선호 베이 우선 배정): 낙관적 시나리오 18/20 z3=0 달성 가능성 있음 현실 적용 시 ~10.3M 총 obj 회복 가능 → 그러나 z1 폭발 (배정 바꾸면 크레인 직렬화 악화) FALSIFIED
reassign z3 집중화: 블록을 선호 베이로 몰아 z3를 낮추려 함 z1 2~16배 폭발. 5개 인스턴스 전부 obj 악화. 0/5 채택. FALSIFIED
reassign_balance z2(workload 불균형) 낮추려 부하 재분산 배정 z1 3~11배 폭발. 배정 변경이 크레인 직렬화를 악화시킴. FALSIFIED
peak co-presence 진단 z1 피크 시각에 베이 점유율이 실제로 얼마나 되는지 측정 피크 시각 베이 공간 점유율 ~50% — 공간 부족이 아님. 크레인 j≥k 직렬화가 병목. 근거 확보
핵심 결론: z1은 공간 문제가 아니다
피크 시각에도 베이 공간은 ~50% 비어있다. 지연의 원인은 크레인 수직접근 규칙(j ≥ k: 아래 레이어 블록이 있으면 위 레이어 블록이 먼저 퇴출해야 함)이 만드는 직렬화 강제다. early-release 시각에 여러 블록이 동시에 베이에 몰리면(co-presence) 크레인 순서를 맞추기 위해 일부는 대기 → tardiness 발생. 배정을 재구성해도 co-presence 자체를 줄이지 못하면 z1은 개선되지 않는다.
실제로 효과 있는 레버 (v3 후처리)
crane_repack_bay는 기존 배정을 유지하면서 각 블록의 x/y/orient 위치와 entry 시각을 CP-SAT로 동시 재최적화한다. 위치를 바꿔 크레인 직렬화 순서를 유리하게 변경하는 것이 가능하므로 배정 변경 없이도 z1을 낮출 수 있다. set2 실측: −8.71% (181.8M → 165.9M @600s), set1 prob_20 −28%.
