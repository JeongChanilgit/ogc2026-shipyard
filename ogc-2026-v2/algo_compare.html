공통 프레임 — 모든 솔버는 같은 3단계다

배정(어느 베이)  →  패킹(x,y,방향)  →  타이밍(진입/퇴출)
Z2·Z3 = 배정만의 함수
부하불균형·선호는 어느 블록이 어느 베이냐로만 결정. 패킹·타이밍과 무관(정사영).
Z1 = 타이밍의 함수
지연 = Σmax(0,퇴출−마감). 레이아웃 고정 시 CP-SAT가 1-D disjunctive로 최적해를 푼다.
패킹(x,y,o) = 거의 중립
격리+동일 CP-SAT 타이밍 검증: v2가 더 조밀(interlock↑)해도 z1 wash. 패킹은 레버 아님.
⇒ 세 솔버의 진짜 차이는 배정의 z1↔z3 trade-off와 z1 추정 정확도다. 패킹은 어느 쪽이든 비슷.

H1 (weight-adaptive 전역그리디)

global_cpsat.py
① 배정 1-pass 전역그리디: 각 블록(EDD)을 w1·tardy_est + w2·Δz2 + w3·Δz3 최소 베이에. tardy_est=area-time 혼잡 추정(weight-adaptive, CW 없음).
② 패킹 v2 폴리곤 패킹(비트맵+크레인+exact).
③ 타이밍 원래의 CP-SAT 타이밍 오라클 (동일).
강점: z3 압살(선호 베이 적극 배정). 진짜 w 반영.
약점: tardy_est가 crude proxy → 작은/저-w1 인스턴스서 z1 오추정 → 과적(z1·z2↑). 승 1/4.

H2 (toss + 실제 z1 + CP-SAT)

solve_official.py · 검증중
① 배정 everyone-preferred 시작 → toss 국소탐색: 블록을 베이 간 이동해 w1·z1 + w2·z2 + w3·z3 최소화. z1 = 실제 per-bay 패킹 지각(proxy 아님), 4코어 병렬 평가.

핵심 종합

1. 패킹은 레버가 아니다. 원래도 폴리곤-aware. v2가 더 조밀해도 같은 CP-SAT 타이밍 하에서 z1 wash. → 셋 다 패킹은 비슷.
2. CP-SAT 타이밍 = z1 레버. 셋 다 동일하게 사용. 고정 레이아웃 위 지각 최적.
3. 진짜 승부처 = 배정. 원래는 z1 위해 분산→z3 희생. H1/H2는 z3를 살리고(선호 배정) z1은 CP-SAT에 맡김. 관건 = 배정 단계의 z1 추정 정확도: H1=crude(약함), H2=실제(정확 기대).
4. weight-adaptive 필수. w1이 667~29.6K로 다양 → 배정의 z1↔z3 저울질이 인스턴스 w를 봐야. H1은 그렇게 설계(자동 적응), H2는 실제 obj로 자동 적응.
