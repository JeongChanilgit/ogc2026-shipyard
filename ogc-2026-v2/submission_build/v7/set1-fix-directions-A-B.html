A v2 뒤 per-bay 압축 후처리 (postproc, never-worse)

v2 출력을 받아 각 베이를 더 조밀하게 재배치(압축)해 빈틈을 모으고, 그렇게 생긴 공간으로 추방됐던 선호 블록을 cross-bay로 되돌린다. 전부 공식 obj never-worse 게이트 — 절대 나빠지지 않음. v2 코어는 안 건드림(추가 단계).

세부 메커니즘 — 두 변형

A1. crane_repack 확장 (기존 v3 재사용)
  • z1-게이트 제거: postproc.py:176의 if best_z1≤0: skip 삭제 → z1=0인 set1도 후처리 받음.
  • 전 베이 적용: postproc.py:85의 "tardy 베이만" → 모든 베이 순회.
  • cross-bay 타겟 확장: bpass.py:324 "tardy AND wrong" → "wrong"만(z1=0이어도 선호≠현재면 후보). set1의 추방 블록이 비로소 이동 대상이 됨.
  • crane_repack_bay가 위치 이산후보로 재배치(candidate0=현재라 never-worse) → 부수적으로 공간 정리.
주의: crane_repack 목적은 z1뿐 → set1(z1=0)엔 위치 자체는 무효. set1 레버는 A-2 cross-bay 복귀(z3). A-1은 그 공간을 만드는 역할.
A2. 진짜 압축 패스 추가 (밀도 목적)
  • crane_repack은 z1 최소지 밀도 최대가 아님. set1서 선호 베이를 실제로 비우려면 density-목적 재패킹이 필요.
  • 방법: 베이 블록을 면적 큰 순으로 bottom-left 재배치(v1식 best-of-N 순서) → 같은 블록을 더 조밀하게 → 상단/우측에 연속 자유공간.
  • 또는 left/down 컴팩션(블록을 벽쪽으로 밀어 붙임, 크레인 j≥k 유지).
  • 압축으로 생긴 연속 공간 → A-2 cross-bay move의 성공률↑.
v1이 가진 per-bay best-of/descent 압축(solver_orig S4+S6)을 v2 출력에 1패스 이식하는 것.

B v2 Pass B를 재배정 가능하게 — look-ahead / eviction

근본 원인(한 번 놓으면 영구 commit · myopic)을 구성 단계에서 고친다. 선호 베이 경쟁이 생기면 이미 놓인 낮은-우선 블록을 밀어내고(evict) 재배치하거나, 애초에 미래 수요를 내다보고(look-ahead) 좋은 자리를 아껴둔다. v2 코어(unified_greedy.py:207-246) 수정.

세부 메커니즘 — 세 변형

B1. Eviction 기반 삽입 (가장 직접적)
  • 블록 i의 선호 베이 j가 full이면 포기(→wrong) 대신: j의 블록 중 z3-우선 가장 낮은 c(여기 선호 아닌, footprint 비슷한)를 후보로.
  • 비용 계산: Δ = [i를 j에 넣는 이득(z3↓)] − [c를 빼서 재배치하는 손실(z3↑+z1)]. Δ<0이면 교체.
  • c는 다른 fit 베이에 재배치(연쇄 가능 → 깊이 1~2로 제한해 cascade 방지).
  • 구현: Pass B 루프(:221)에서 "fit 베이 없음/높은 marginal" 분기에 eviction 시도 추가. 상태는 state[j].placed 리스트에서 c 제거+i 추가+c 재삽입.
B2. Look-ahead marginal (선점 비용 부과)
  • 블록 i를 베이 j에 놓을 때, 지금 상태만 보지 말고 미래에 j를 선호하는 블록 수요를 본다.
  • 사전계산: 각 베이 j에 대해 "아직 안 놓인 블록 중 j를 강하게 선호하는 수" = demand[j].
  • marginal에 shadow price 추가: i가 j의 희소 공간을 소비하면 +λ·demand[j] 페널티 → 고선호-수요 베이의 자리를 함부로 안 씀(미래 블록 위해 아낌).
  • 구현: place_one 채점(:211-231)의 sc에 항 추가. 가벼움(상태 변경 없음).
B3. 우선순위 배치 + 예약
  • order-blend(R+0.5P) 대신/병행: 선호 강도(z3 잠재손실) 높은 블록 먼저 배치 → 고선호 블록이 선호 베이를 먼저 확보.
  • 또는 베이별 용량의 일부를 고선호 블록용으로 예약(reservation)해 뒤늦게 와도 자리 보장.
  • 위험: 순서를 바꾸면 z1(시간축 정리)이 나빠질 수 있음(order-blend는 z1용) → z3·z1 트레이드.
