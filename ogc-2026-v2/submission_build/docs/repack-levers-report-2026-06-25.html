비트마스크(P1④)는 unsafe로 반증, P4a는 보류, 나머지 레버는 대부분 중립이나 active-cap(P1①) + blprobe(P2②) 조합 = cap30bl이 변동-통제 전체 set2서 net −2.54M(−1.43%)의 재현되는 진짜 승리(never−1 안전) → 채택, 제출 zip 재빌드.

3. 측정 함정 — 페어드 풀셋 A/B는 무효였다

처음 풀셋 페어드 A/B(prod 코어 0-7 ∥ cap20 코어 8-15 동시 실행)는 cap20 = 644M (3.5× 악화)처럼 보였다. 이것은 아티팩트였다:

  • 파국이 prob_27/38/25에 집중(z1 5~8배 폭발). 그러나 그 obj가 greedy base보다도 큼.
  • global_eval = 공식 체커(seed.py:93) → postproc는 공식 obj 기준 증명상 never-worse (개선 trial만 수락). base 솔버(v2/orig/gassign)는 cap을 import조차 안 함(grep). ⟹ cap은 final을 base보다 나쁘게 만들 수 없다.
  • 변동 프로브(postproc OFF, 3회): base가 안정(prob_25 1.00×, prob_27 1.01×, prob_38 1.01×).
  • ∴ 644M = 동시-arm 실행이 base 솔버를 오염(v2/orig가 spawn한 CP-SAT 워커가 4-코어 affinity를 탈출 → 오버서브스크립션 → base 솔버 타임아웃 → 나쁜 폴백 base). cap 무죄.

교훈: postproc 레버 A/B는 반드시 인스턴스별 공유 base에서 측정해야 한다(base 오염이 arm 간 common-mode → 델타에서 상쇄). 이후 모든 측정은 공유-base 통제설계.

채택: cap30bl = OGC_PP_ACTIVE_CAP=30 + OGC_PP_BLPROBE=3

  • 왜 이김: 큰 round-starved 베이(prob_38 107블록)서 full 모델(2만 disjunction)은 패스당 40s에 under-solve. cap이 모델을 2.6K disjunction로 줄여 최적까지 풀림 + 라운드 多. blprobe는 그 작은 모델에 tardy 저-충돌 대각 후보를 줘 시너지(cap20 −1.57M → cap30bl −2.54M).
  • 왜 안전: postproc accept 기준 = 공식 obj(global_eval==check_feasibility) → 증명상 never-worse → cap/blprobe는 base를 나쁘게 만들 수 없음 → −1 추가위험 0. 전체 새 레버는 게이트 default OFF라 프로덕션 코드경로 무변경(채택분만 myalgorithm setdefault).
  • trade-off 인정: net 승리는 거대 인스턴스에 집중(prob_27/38). 작은 인스턴스 일부 소액 손해 (최대 prob_35 +160K). 베이 크기로 깔끔히 타겟 불가(적응형 cap 가설 기각). 총 obj 기준 net −2.54M.
  • 예산 의존: 운영 leftover(~20-40s@TL120)는 60s 테스트보다 짧음 → round-starvation 심함 → cap 효과 ≥ 측정치. 경쟁 긴 TL서 거대 인스턴스 승리 성장(prob_38 −1.27M@60s → −4.5M@300s).
