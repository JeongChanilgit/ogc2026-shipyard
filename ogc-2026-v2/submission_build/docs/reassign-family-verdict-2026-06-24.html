z1-피드백 재배정 계열 — 종합 판정 (M1 · M2)

2026-06-24 · 제출본 코드(_m1base = v-v3postproc-seq) · 풀 파이프라인(그리디→txyo→재그리디→txyo 끝까지) · 같은 예산 · 공식 global_eval

판정: 재배정 피드백 계열(M1 + M2) 전부 falsified. 순위가 일관되게 ORIGINAL < M1 < M2 — 재배정으로 흔들수록 더 나쁨. 어떤 재그리디도 ORIGINAL(그리디→txyo) 수렴해 아래로 못 내려감. 근본: 제출본 그리디는 이미 구조적 제약하 near-optimal 배정을 찾고, z1 은 co-presence 구조라 재배정 perturbation 은 더 나쁜 basin 으로 빠지며 txyo 가 이를 회복 못 함.

3. 왜 M2 가 M1 보다 더 나쁜가

  • M1 = tardy 블록(증상)을 다른 베이로. M2 = 그 tardy 를 막은 *선행블록*(원인, 잘-배치된 non-tardy)을 다른 베이로.
  • 선행블록은 원래 잘 놓여 있던 블록이라 옮기면 그 좋은 구조를 더 많이 깬다 → z3 폭증(prob_38 5746→7807, 선호베이 이탈) + z1 도 악화(4264 vs ORIGINAL 3970).
  • tardy 가 풀릴 만큼 크레인창이 열리지도 않음(co-presence 가 한 선행블록 제거로 안 풀림 — 크로스베이 front 가 이미 보인 결과).

4. 종합 결론 — 재배정 피드백 라인 종료

같은 구조벽에 막힌 모든 시도 (여러 세션 누적):

  • M1 (tardy블록 재배정) · M2 (선행블록 재배정) — falsified (이번)
  • v4 reassign / reassign_balance (z1 2~16배 폭발) · 크로스베이 front/cluster · moveall 강화 — 전부 falsified (이전)

공통 진실: z1 은 구조적 co-presence-bound. 제출본 그리디가 이미 그 구조하 near-optimal 배정을 찾음. 배정을 어떻게 재조정하든(tardy·선행·균형·크로스베이) perturbation → 더 나쁜 basin, txyo 복구 불가. "정확한 z1 피드백" 자체는 옳았으나, 배정은 이미 z1 을 거의 최적화한 상태라 되먹일 여지가 없었다.

5. 피벗 (남은 진짜 레버)

  1. never−1 검증 + 제출 굳히기 — 진짜 점수게임(인스턴스당 −1 회피 ≈ +R/2). 프로덕션 set2 271.93M(경쟁자 +7.89M)·feasible 40/40 을 ALL40 운영/짧은 TL 에서 never−1 확정 → 제출. obj 미세개선보다 우선. ← 추천
  2. per-bay 패킹밀도(구조 root) — 유일하게 안 막힌 레버지만 우리 패커 이미 경쟁력(27 vs 천장 33)·NFP 폴리곤 네스팅 난도 높음. 장기 연구.
  3. 재배정/피드백 계열은 재시도 금지 (M1·M2·v4·크로스베이·moveall 모두 구조벽 확인).
