x+t CP-SAT — 정밀 해부 & 개선안

엔진 crane_repack_bay() · v3pp/crane_cpsat.py · 제출본 기준 · 2026-06-24

한 줄 정의
한 베이를 대상으로, 각 블록의 위치(x, 선택적 y·방향)와 진입시각(t)을 동시에 골라 크레인 j≥k 규칙을 만족하면서 지각합 z1을 최소화하는 CP-SAT 재배치 패스. 핵심 트릭은 "기하는 미리 계산, CP-SAT는 시간만 푼다" 라는 디커플링.

1. 왜 이 구조인가 — 디커플링 철학

이 문제는 한 결정 안에 3개의 NP-hard가 묶여 있다: (a) 이형 폴리곤 패킹(위치·방향), (b) 크레인 수직접근 j≥k(누가 누구를 막나), (c) tardiness 스케줄링(시각). 셋을 한 모델에 통째로 넣으면 폭발한다(과거 box-decomp가 위치+시간 JOINT 탐색하다 폭발 → 폐기).

이 엔진의 해법은 분리다:
  • 기하·크레인(a·b) = 오프라인 사전계산. 공식 체커로 "이 포즈에서 누가 누구를 막나"를 시간-무관 불리언으로 굳힌다. → CP-SAT가 폴리곤·크레인을 직접 풀지 않는다.
  • 스케줄링(c) = CP-SAT가 푸는 유일한 부분. 깔끔한 1-D disjunctive tardiness 문제. 베이당 수십 블록도 ~1초 OPTIMAL.
이것이 _cpsat_bay_timing_verified(타이밍 오라클, 위치 고정)를 위치 선택까지 일반화한 것이다.

3. 모델 정밀 해부

3.1 변수

sel[b][ci] : Bool   블록 b가 후보 ci 선택 (FREE 블록만, ExactlyOne)
e[b]       : IntVar  진입시각 [R[b], H]   (FROZEN이면 정수 상수)
exit[b]    = e[b] + P[b]                  P=처리시간(고정, 관측 exit-entry)
tard[b]    : IntVar  >= e[b] + P[b] - D[b]   (D=due, 0과 max)
목적       : minimize  Σ tard[b]   (= z1, FREE 블록만)

3.2 후보 생성 — 합집합이지 격자가 아니다

후보[b] = {현재 포즈}                        ← ci=0, 항상 포함
        ∪ {x-이동: 현재 y·o 고정, x를 n_xcand개 균등샘플}
        ∪ {y-이동: 현재 x·o 고정, y를 n_ycand개}
        ∪ {o-변형: 다른 방향, x·y는 그 방향 유효범위로 clamp, 자기 shape}
개수 = 1 + (n_xcand−1) + n_ycand + n_ocand (덧셈). 격자 곱(K_x·K_y·K_o)이 아니라 축별 합집합이라 후보 수가 폭발하지 않는다. o-변형만 자기 재방향 BlockShape를 들고 다님(x·y변형은 현재 shape 공유).
crane_cpsat.py:203–299 (_build_candidates) · :218–223 (union 수식)

3.3 크레인 5불리언 사전계산 (Step B)

모든 (블록쌍 a<b, 후보조합 ci_a×ci_b)에 대해 공식 체커(fast=True)로 5개 시간-무관 불리언: 
coll  : 같은 층 footprint 겹침      → 시간도 겹치면 안 됨
ba_e  : b가 a의 진입경로 막음        ab_e : a가 b의 진입경로 막음
ba_x  : b가 a의 퇴출경로 막음        ab_x : a가 b의 퇴출경로 막음
5개 다 False인 조합은 저장 안 함(모델에서 제외). 포즈→Block 객체 캐시로 동일포즈 재생성 방지.
crane_cpsat.py:306–361 (_precompute_combos) · :353–357 (5 check_* 호출) · :358 (all-False skip)

3.4 gated time-disjunction (Step C)

저장된 각 (쌍, 조합)을 entry 시각의 OR 제약으로. 해당 후보를 둘 다 골랐을 때만 작동하도록 sel을 gate로 붙인다: 
coll  → ax ≤ be  ∨  bx ≤ ae           (시간 분리; 크레인 config 흡수)
ba_e  → ae ≤ be−1 ∨ ae ≥ bx           (a가 먼저 ∨ b 나간 뒤)
ab_e  → be ≤ ae−1 ∨ be ≥ ax
ba_x  → ax ≤ be  ∨  ax ≥ bx(+1 co-exit)
ab_x  → bx ≤ ae  ∨  bx ≥ ax(+1 co-exit)
   각 제약: .OnlyEnforceIf([리터럴] + gate),  gate=[sel[a][ci_a], sel[b][ci_b]]
ax = ae+P[a], bx = be+P[b]. FROZEN 블록은 sel 없음(ci=0 고정)이라 gate에서 빠지고 entry는 상수로 식에 들어간다. _CRANE_COEXIT=True면 퇴출 disjunction에 +1(strict).
crane_cpsat.py:552–593 (gated disjunctions) · :69–71 (_CRANE_COEXIT)

3.5 never-worse 보장 (구조적)

  • 후보 0 = 현재 포즈 → 현재 해가 모델 안에서 표현 가능 → CP-SAT 최적 z1 ≤ 현재 z1.
  • AddHint(sel[b][0]=1, e[b]=현재 entry) → warm start, 못 풀어도 현재 해 보장.
  • 불리언이 공식 체커에서 나오므로 채택된 어떤 이동도 크레인-feasible (bbox 모델과 달리 거짓양성 없음).
즉 베이 단위로 절대 나빠지지 않는다. 루프 레벨에서 다시 전체 obj(z1+z2+z3) & feasible 게이트로 한 번 더 거른다.

7. 개선 방안

원칙: full set 총 obj·never−1로만 판정(사용자 규칙), 답지 보고 set 분기 금지(단일 config). 반증된 레버(밀도패커·재배정·LCA·finer-raster·crossbay)는 재시도하지 않는다 — 아래는 검증된 repack 레버를 (1) 라이브 affordable 하게, (2) 더 날카롭게 만드는 방향이다.

P1 · 高확신disjunction 수 ↓ → 패스를 싸게 (72% 직격) W1

실측상 비용의 72%가 CP-SAT solve+빌드이고 그 크기는 disjunction 수(~2만)에 비례. 이걸 줄이면 같은 wall에 더 많은 라운드/베이를 돈다. (사전계산 prefilter는 AABB로 이미 −45% 채택 — 17%짜리라 추가 이득 작음.)

  • ① active-set cap (미구현, 최우선). active 블록 수에 상한을 두면 multi-candidate 블록이 줄어 combos·disjunction이 직접 감소. z1 기여 큰 tardy/blocker 우선으로 cap 내 선발 → 큰 베이에서도 패스시간 bounded. 패스시간 ∝ 블록수 병목을 정면으로 깬다.
  • ② OGC_PP_K (후보수, A/B 대기). K5→3이면 combos ~44%로 줄어 disjunction↓. 품질(reach) trade-off를 15분 full-set A/B로 — net 이득이면 단일 config 채택.
  • ③ 패스·라운드 간 precompute 메모이제이션. (bay_id, a, b, pose_a, pose_b)→5불리언 캐시. txyo 4패스 + 다라운드에서 안 움직인 쌍(대다수)은 재계산 0 → 모델빌드 30% 구간 단축. 출력 불변.
  • ④ 비트마스크 prefilter (OGC_PRECOMP_BITMASK, 미벤치). 셀단위 footprint 비트셋 AND — AABB보다 정밀(saturated interlock까지 잡음), stored 동일·출력동일 기대. 사전계산(17%) 정밀화 — 부차적이지만 AABB의 과-prune을 보정.
기대: 큰 set2 베이 패스시간 단축 → 라운드 수↑(개선이 앞 라운드 집중이므로 라운드를 더 도는 게 곧 obj↓). 리스크 낮음: ②만 품질 trade-off(A/B로 판정), ①③④는 결과 거의 불변·never-worse 유지.
P2 · 투기적(A/B 필수)conflict-aware 후보 시딩 W2W3

균등샘플 대신 크레인 불리언이 flip 하는 위치를 노린다 — repack의 목적이 "막는 놈을 비키기"이므로.

  • ① boolean-flip anchor. tardy 블록의 현재 blocker들의 x-span을 구해, 그 blocker를 flush-left/flush-right로 비켜서는 x(블록 footprint를 blocker 경계 바로 옆)를 후보로 추가. "boolean이 바뀌는 곳"을 직접 샘플.
  • ② BL-probe joint seed (W3 대각이동). 축별 합집합의 사각지대(x AND y 동시 이동)를 메우려, tardy 블록에 한해 값싼 BL/gap-probe로 찾은 최선 빈 자리 (x,y)를 후보 몇 개만 주입. 격자 폭발 없이(추가 상수개) 대각 이웃 진입.
구분: 이건 CP-SAT selection var의 이산 후보를 어디서 뽑나의 문제 — 반증된 "finer-raster"(그리디 플로어 래스터)나 "LCA/contact-area 배치"(constructive 스코어러)와 다른 메커니즘. 리스크 중: 후보 수↑면 P1로 상쇄해야 하고, full-set A/B에서 falsify될 수 있음(정직히 베팅).
P3 · 中확신active = 실제 현재 blocker (정확 인과집합) W4

기본 active 선택은 x-bbox 근접 휴리스틱(:191). 대신 현재 포즈의 사전계산 불리언에서 tardy 블록을 실제로 막는 쌍만 active로. 인과적으로 정확하고 더 작은 모델. xt 모드(이미 구현됨)를 기본으로 올리는 것도 한 단계 — 크레인 co-presence는 본질적으로 시간 문제라 x-bbox보다 정확.

리스크 낮음: 더 작은 모델·더 정확한 타겟. 단 active가 너무 좁아 연쇄 blocker(blocker의 blocker)를 놓치면 1-hop으론 부족 → k-hop 확장 옵션.
P4 · 보조weight-aware 목적 + tighter bounds W5
  • 베이 repack에서 z3는 상수(베이 고정), z2만 entry 분포에 따라 약간 변함. low-w1 인스턴스(w1=667)에선 z1-only가 싼 항을 과최적화해 z2 악화 → 게이트 거부. z2 프록시(베이 내 동시작업 peak 페널티)를 작은 가중으로 더하면 게이트 통과율↑. (단 z1 지배 set2에선 영향 미미 — 단일 config로 weight-adaptive하게.)
  • entry 상한 타이트화: H=makespan+maxP는 느슨. 블록별 e[b] ≤ due[b] + slack 류 상한으로 도메인 축소 → CP-SAT 가속(미세).
리스크 낮음·이득 작음. P1·P2 이후 마무리 튜닝.

8. 우선순위 & 검증 프로토콜

순서: P1(비용절감) 먼저 — 이게 되어야 P2·P3의 후보·active 확장을 예산 안에서 감당하고, 무엇보다 검증된 레버를 라이브로 배선(PENDING 해소)한다. 그 다음 P3(작고 안전) → P2(reach, 베팅) → P4(마무리).

검증(사용자 규칙 준수):
  • 판정 기준 = full set(ALL40) 총 obj, 개별 z 아님.
  • never −1 최우선 — feasible 40/40, wall 예산 내. P1은 출력 byte-identical이라 회귀 0 보장; P2/P3은 gated additive로 never-worse 유지.
  • 답지 보고 튜닝 금지 — set1/set2 config 분기 X, 단일 config가 솔브시점 적응(혼잡 프록시·베이크기 게이트).
  • 코드 변경은 실행중 런 멈추고. 게이트 env는 기본 보존(프로덕션 무영향).
