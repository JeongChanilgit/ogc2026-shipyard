한 줄 요약
둘 다 한 베이에서 "블록을 언제(entry) — x축이면 어디(x)까지 — 두면 크레인 규칙을 지키며 지각(z1)이 최소가 되나"를 CP-SAT로 푼다.

· timing = 위치 고정, 시각만 결정
· x축 = 거기에 x 위치 후보 몇 개를 더해 위치+시각 동시 결정

핵심 트릭: 기하(누가 누구를 막나)는 미리 계산, CP-SAT는 시간 순서만 푼다 → 작고 빠름(~1초 OPTIMAL).

0. 어디서 도나 — txyo 루프

postproc는 z1>0인 베이마다 축을 하나씩 돌린다:

매 라운드 (시간 끝까지):
  z1 큰 tardy 베이부터:
    for 축 in x, y, o:
      crane_repack_bay(베이, 축후보)  ← 여기
      개선&feasible 이면 채택 (never-worse)
    cross-bay move/swap
  개선 0 → 수렴 종료

x→(K,0,0), y→(0,K,0), o→(0,0,K). 한 패스 = 한 축. 단 entry(시각)는 어느 패스든 항상 자유 → 모든 패스가 timing도 같이 함. "순수 timing"은 (0,0,0).

1. CP-SAT timing

무엇 — 모든 블록의 위치·방향을 그대로 두고, 각 블록 entry 시각만 정해 지각 합 최소화. exit = entry + P(고정)라 사실상 "각 블록 언제 넣을까"만 푼다.

모델

변수:  entry[b] ∈ [release, H]
유도:  exit[b]  = entry[b] + P[b]
      tardy[b] = max(0, exit[b] − due[b])
목적:  최소화  Σ tardy[b]   (= z1)

크레인 j≥k 제약 (핵심)

크레인은 위에서 수직으로 넣고 뺀다 → 넣/뺄 때 그 위쪽 경로가 비어야 함. 2단계로:

1오프라인 사전계산
모든 블록 쌍에 대해 공식 체커로 시간-무관 불리언: 
coll : 같은 층 겹침 (시간 겹치면 안 됨)
b막a_진입 / a막b_진입
b막a_퇴출 / a막b_퇴출
"누가 누구를 막나"는 기하 문제 → 여기서 다 풀어둠.
2CP-SAT 시간 분리
위 불리언을 entry 시각의 OR 제약으로: 
겹침금지 : a가 b 전에 끝 ∨ b가 a 전에 끝
b막a진입: a가 b보다 먼저 들어가 ∨ b 나간 뒤 들어가
막는 쌍은 시간상 안 겹치게 강제. CP-SAT가 이걸 지키는 시각 중 지각 최소를 찾음.
왜 강력한가
어려운 부분(폴리곤 기하·크레인 접근)은 사전계산 = 비용 0 불리언이 되고, CP-SAT는 깔끔한 1-D tardiness 스케줄링만 푼다 → 베이당 수십 블록도 ~1초 최적. 채택된 시각은 공식 기준 크레인 가능 보장.

파이프라인의 timing — 두 구현

① parallel_timing (그리디 직후, txyo의 첫 t)
타이밍은 베이 독립 → 베이별 CP-SAT를 4코어 병렬 후 공식 검증.

② crane_repack_bay(0,0,0) (루프 안 순수 t)
후보=현재 위치 1개뿐 → entry 시각만 자유. 위 모델의 특수경우.

2. x축 CP-SAT

무엇 — timing에 x 위치 자유도를 더함. 각 블록에 x를 좌우로 옮긴 후보 몇 개(y·방향 고정)를 주고, CP-SAT가 블록마다 (어느 x, 언제 entry)를 동시에 골라 지각 최소화.

왜 x를 움직이나? 블록을 좌우로 밀면 누가 누구를 크레인으로 막는지가 바뀐다 → 막던 블록을 비켜 tardy 블록이 빈 크레인창으로 일찍 진입. timing만으론(위치 고정) 못 하는 일.

x 후보

유효범위 [x_lb, x_ub] 에 정수 x 를 n개 균등 배치
후보[b] = {현재} ∪ {x-이동들}   (합집합, 격자 아님)
        = 1 + (n_xcand − 1) 개

★ 합집합이라 후보 수가 덧셈으로 작게 유지(격자면 곱셈→폭발). 그래서 축을 따로 돈다.

모델 (timing에 추가되는 것)

변수:  sel[b] = 후보 중 하나 선택 (정확히 1개)
      entry[b] ∈ [release, H]
크레인: 사전계산을 (쌍, 후보조합)별로 →
       제약에 sel 변수를 gate 로 붙임
       = 두 블록이 그 후보를 골랐을 때만 제약 작동
목적:  최소화 Σ tardy[b]

timing은 막는 쌍이 고정이지만 x축은 고른 x에 따라 막는 관계가 달라짐. 그래서 사전계산을 후보조합마다 해두고 CP-SAT가 위치 선택과 시각을 함께 푼다.

y · o 패스

같은 엔진. (0,K,0)=y 이동 후보, (0,0,K)=방향(회전) 변형. 좌표하강이라 x→y→o 따로, 각각 작은 1-축 CP-SAT.

3. never-worse 보장

  • 후보 0 = 현재 위치 + 현재 시각 hint → 현재 해가 모델 안에 표현 가능 → CP-SAT 최적 ≤ 현재. 베이 단위로 절대 안 나빠짐.
  • 루프의 global_eval 게이트: 전체 obj(z1+z2+z3)가 개선 & feasible일 때만 채택.
  • 비용 가드: 후보조합이 너무 많으면 o→y→x 순으로 줄여 폭발 방지.

4. timing vs x축 — 비교

결정
t: entry 시각만
x: x 후보 + entry 시각
바꾸는 것
t: 언제 넣나
x: 어디(x)+언제 넣나
못 하는 것
t: 위치 못 바꿈 → co-presence 고정
x: y·방향·베이는 못 바꿈
여는 레버
t: 크레인 줄을 시간으로 정렬
x: 옆으로 비켜 막힘 자체 해소
크기/속도
t: 가장 작음, ~1초
x: 후보배수만큼 크나 여전히 빠름
호출
t: (0,0,0) 또는 parallel_timing
x: (K,0,0)
핵심 직관
한 베이의 지각은 좁은 시간창에 블록이 몰려 크레인이 한 줄로 서야 해서 생긴다.

· timing = 그 줄을 가장 효율적 순서로(언제)
· x축 = 블록을 옆으로 비켜 줄 자체를 짧게(어디)

둘 다 못 푸는 잔여 = 베이가 진짜 꽉 참(밀도 한계) — 우리가 부딪힌 구조벽이고, 배정 재조정(M1·M2)으로도 못 푼 그 z1 floor.
