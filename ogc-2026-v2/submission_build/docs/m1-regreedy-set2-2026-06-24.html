2. 정직한 주의점 (반드시)

  1. best-of-over-lam 노이즈 편향(winner's curse) — lam 4개 중 best를 인스턴스별로 고르고 단일 R0와 비교하면 CP-SAT 노이즈(±130K)만큼 gain이 부풀려진다. 작은 gain(<100K: prob_27·31·36)은 노이즈일 가능성. 큰 4개 (30·38·23·29)는 여러 lam 일치 + 매그니튜드≫노이즈라 진짜.
  2. postproc 미포함 = 가장 큰 미검증 — 이건 greedy+timing 단계 비교다. 프로덕션은 뒤에 postproc(공간+크로스베이)가 붙는다. postproc이 같은 z1을 독립적으로 잡으면 M1 우위가 사라질 수 있다. ← 다음 결정적 검증.
  3. 비용 5× — lam-race는 R0 + 4 피드백 라운드 = greedy+timing 5회. 서버 TL(가변·비공개)에서 비싸다. 단일 lam=0.2 + best-of(R0)는 2×로 race gain의 ~76%(추정 3.24M) 회수 → 비용대비 훨씬 낫다.
  4. v2-vs-프로덕션 비교는 muddy — src/ gassign 트랙과 ogc-2026-v2 트랙이 별개. "v2가 프로덕션 이긴다" 주장 금지. 유효 주장은 within-v2 A/B(−2.13%)뿐.
  5. 답지 튜닝 아님 확인 — lam-race는 solve-time에 각 lam 돌려 실측 obj로 best 선택(scale-bestof와 동형) = 정당 적응. 인스턴스별 lam 하드코딩은 금지(그건 답지 튜닝).
