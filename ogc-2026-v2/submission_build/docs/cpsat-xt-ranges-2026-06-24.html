한 줄 답
· t(시각) = 전 범위, 모든 정수를 다 본다 (timing과 똑같이 촘촘).
· x(위치) = 전 범위지만 몇 개만 샘플한다 (듬성듬성, n_xcand개 후보).

즉 t는 연속처럼 촘촘, x는 듬성한 이산 후보 — 이 비대칭이 핵심.

t (entry 시각) 범위

entry[b] = IntVar( R[b] , H )
  • 하한 R[b] = 그 블록의 release_time(출시 시각). 그 전엔 못 넣음.
  • 상한 H = 현재 makespan + maxP
    = (현 해에서 가장 늦은 exit) + (최대 처리시간).
→ release 부터 H 까지 모든 정수 시각을 CP-SAT가 자유롭게 고름. 빠진 시각 없음(풀 IntVar).

x (위치) 범위

후보 = _x_anchors(범위 [x_lb, x_ub] 를 n_xcand개 균등 샘플)
x_lb = 좌벽 한계 (world x ≥ 0)
x_ub = 우벽 한계 (x + 블록폭 ≤ 바이폭 W)
  • 범위 자체는 전체 — 블록이 바이 안에서 좌벽~우벽 어디든 갈 수 있는 전 구간 [x_lb, x_ub].
  • 그러나 다 보지 않음 — 그 구간을 n_xcand개(예: 5개)로 균등 분할한 점만 후보로 줌. 현재 위치는 항상 포함.
→ 전 범위에서 몇 개만 골라본다 (이산 샘플, 사이 위치는 안 봄).

그림으로

t (시각): 전부 다 봄 — 촘촘
R ┝━━━━━━━━━━━━━━━━━━┥ H
   ↑ 모든 정수 시각 후보

x (위치): 전 범위지만 5개만 — 듬성
x_lb ●──●──●──●──● x_ub
     ↑ n_xcand개 후보(사이는 건너뜀)

왜 이렇게 비대칭?

  • t 는 싸다 — 1-D 시각이라 풀 IntVar로 둬도 CP-SAT가 잘 푼다. 그래서 전 범위 다 봄.
  • x 는 비싸다 — x를 풀 범위로 두면, 두 블록의 크레인 막힘 관계가 정확한 x마다 달라져 미리 계산해 둘 수가 없다(조합 폭발).
    그래서 x를 소수 후보로 고정해야 각 (쌍, 후보)별 크레인 불리언을 미리 계산할 수 있다 → 모델이 작아짐.
실무적 함의
· x 후보가 적으면(예: 5) 빠르지만, 진짜 좋은 x가 후보 사이에 있으면 놓칠 수 있다.
· 늘리면(예: 9) 더 촘촘하나 사전계산·모델이 커져 느려짐.
· 그래서 좌표하강(x→y→o 따로) + 합집합 후보(곱셈 아님)로 후보 수를 덧셈으로 억제.
· 또 tardy 근처 블록만(window) 후보를 받고, 나머지는 현재 위치 고정 → 모델 더 작게.
