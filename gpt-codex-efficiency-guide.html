0. 먼저 — 무엇이 같고 무엇이 다른가

가장 중요한 사실: Claude Code에는 한 세션이 여러 서브에이전트를 네이티브로 병렬 spawn하는 Agent/Task 도구가 있다. Codex CLI에는 이에 1:1 대응하는 내장 fan-out 기능이 없다. 그래서 "병렬 위임"은 GPT에서 다른 방식으로 직접 구현해야 한다(§3). 반면 토큰 절약 규칙은 하니스와 무관하게 그대로 이식된다(§2).

1. GPT에서도 동일한 최대 누수원

이 워크스페이스의 토큰 누수는 하니스와 무관하다 — 거대 파일을 통째로 모델에 넣는 것이다.

파일크기GPT에서 할 일
instances/**/*.json1~3 MB (prob_14 ≈ 80만 토큰)python tools/peek.py로 요약만
results/**/*.html0.3~1.7 MB옆의 report.md(2KB)만 첨부
docs/*.pdf2.4 MB필요한 쪽만 추출해 첨부
우리가 만든 tools/peek.py는 모델/하니스 무관 순수 파이썬이라 Codex·ChatGPT·API 모두에서 그대로 쓴다. 첨부·붙여넣기 전에 항상 peek로 줄여라.

2. Codex CLI 셋업 (GPT의 Claude Code 대응물)

2.1 AGENTS.md — 이미 있음, 절약 규칙만 추가

워크스페이스 루트의 AGENTS.md를 Codex가 자동으로 읽는다. 여기에 토큰 절약 절을 추가하면 끝 (우리 Claude쪽 cheap-context 스킬의 GPT 버전).

# AGENTS.md 에 추가할 절 ↓

## 토큰 절약 규칙 (반드시 준수)
- 거대 파일을 통째로 읽거나 첨부하지 마라:
  - instances/**/*.json (1~3MB), results/**/*.html, docs/*.pdf
- 대신 `python tools/peek.py <파일|폴더>` 로 수치 요약만 본다.
- 결과는 results/<dir>/report.md · score_*.json (작은 요약) 만 읽는다.
- 큰 소스는 해당 함수 구간만, 심볼 탐색은 ripgrep(`rg`) 사용.
- 방금 수정한 파일을 검증용으로 다시 통째로 읽지 마라.

2.2 config.toml — 모델 티어를 profile로 분담

Claude의 opus/sonnet/haiku 분담을 Codex에선 profile로 구현한다. 무거운 판단은 강모델, 일상 작업은 빠른 모델, 잡일은 mini/nano.

# ~/.codex/config.toml  (또는 프로젝트 .codex/config.toml)
model = "<강모델>"            # 기본: 어려운 추론·아키텍처
approval_policy = "on-request"  # 위험 동작만 승인

[profiles.fast]
model = "<mini 계열>"        # 일상 코딩·탐색·요약

[profiles.cheap]
model = "<nano 계열>"        # 잡일·포맷·단순 변환

# 사용: codex --profile fast "..."  /  codex --profile cheap "..."
모델명은 시기마다 다르다(예: GPT-5 계열 강모델 / mini / nano). 위 <...>를 codex --list-models 또는 OpenAI 문서의 현재 가용 모델로 직접 매핑하라.

2.3 MCP·승인 모드

  • MCP: config.toml의 [mcp_servers.*]에 우리가 쓰는 서버 등록(Claude와 동일 개념).
  • 승인 모드: 읽기 위주 작업은 on-request/never로 권한 프롬프트를 줄여 왕복 토큰 절약. 평가서버는 인터넷 차단이므로 네트워크 요청 도구는 끈다.

3. 병렬 위임 — GPT에서 구현하는 3가지 방법

Codex엔 네이티브 fan-out이 없으므로, 목적에 따라 셋 중 하나를 쓴다.

방법 A · 멀티 세션 (가장 쉬움)

독립 작업을 여러 Codex 프로세스로 동시에 — 터미널 분할 + git worktree.

# 작업별 격리 worktree
git worktree add ../w-A featA
git worktree add ../w-B featB
# 각 창에서 (병렬)
cd ../w-A && codex --profile fast "이슈 A 구현"
cd ../w-B && codex --profile fast "이슈 B 구현"
  • 장점: 진짜 병렬, 파일 충돌 없음(worktree 격리)
  • 용도: 독립 코드 변경, 인스턴스별 솔버 실험
  • 출처 패턴: agent_farm의 worktree/lock 격리

방법 B · API 오케스트레이터 (진짜 fan-out)

GPT API로 오케스트레이터 스크립트를 짜서 N개 서브태스크를 동시 호출. Claude의 Agent 도구를 코드로 재현.

# asyncio 로 N개 모델 호출 병렬
async def worker(task):
    return await client.responses.create(
        model="<mini>",        # 워커=경량
        input=task.prompt)

results = await asyncio.gather(
    *[worker(t) for t in subtasks])
# 오케스트레이터(강모델)가 results 합성
  • 장점: 모델 티어·구조화 출력·캐싱 완전 제어
  • 용도: 3-에이전트 토론, 인스턴스 일괄 분석
  • 참고: OpenAI Agents SDK도 동일 패턴 제공

방법 C · 파일 기반 오케스트레이션 (wshobson 패턴 · 단일 세션)

한 Codex 세션 안에서 단계별 산출물을 파일로 기록하고 다음 단계는 그 파일을 읽는다. 컨텍스트 윈도우에 의존하지 않아 긴 워크플로·재개에 강함 (TOP1 레포 wshobson/agents의 핵심 기법).

# AGENTS.md 에 오케스트레이션 절차로 기술
1. 분석 결과를 .task/01-analysis.md 로 저장
2. 다음 단계는 .task/01-analysis.md 를 읽고 .task/02-plan.md 작성   # 메모리 아닌 파일 참조
3. state.json(current_step, files) 으로 중단 후 재개
# → 컨텍스트가 비대해지지 않음 = 토큰 절약 + resume
병렬 상한: 평가서버가 4 CPU 코어이므로 방법 A/B의 동시 실행은 2~4개로 제한하라 (vijaythecoder가 병렬 ≤2로 제한한 것과 같은 이유). 무제한 fan-out은 비용·rate limit만 키운다.

4. 작업별 에이전트 정의 이식

우리가 Claude에 만든 code-writer · code-analyzer · doc-writer를 GPT로 옮긴다. 정의 표준(트리거형 description + 최소권한 tools + model 티어)은 5개 레포 전부의 공통 합의라 그대로 쓴다.

Codex CLI

역할별 profile + 역할 프롬프트를 AGENTS.md나 별도 프롬프트 파일로. "이 역할일 때 이렇게 행동/이 도구만 사용"을 명시.

OpenAI API / Agents SDK

역할별 system 메시지 + tools 화이트리스트 + model을 객체로 선언해 오케스트레이터가 골라 호출. Claude 에이전트 .md의 frontmatter를 그대로 dict로 변환.

# 역할 정의를 코드로 (API/SDK)
CODE_ANALYZER = {
  "model": "<mini>",                              # 읽기 분석=경량
  "tools": ["read_file", "grep"],                  # 최소권한: 쓰기 도구 없음
  "system": "코드를 읽고 결론+file:line 근거만 반환. 파일 덤프 금지. 코드 수정 금지.",
}
CODE_WRITER = {
  "model": "<강모델>",                            # 구현=강모델
  "tools": ["read_file", "edit_file", "run"],
  "system": "명확한 스펙 1개를 구현하고 변경요약(file:line)+검증결과만 반환.",
}
역할모델 티어도구(최소권한)반환
code-analyzerminiread, grep (쓰기X)결론 + file:line
code-writer강모델read, edit, run변경요약 + 검증
doc-writerminiread, write(.md)작성 경로 + 요지
critic / 전략토론강모델read만입장 + 근거 + 반박

5. GPT API 직접 구축 시 토큰 절약 핵심

  • 프롬프트 캐싱 — 긴 system/컨텍스트를 요청 앞쪽에 고정하면 동일 접두가 자동 캐시되어 입력 토큰 대폭 절감. 변하는 부분은 뒤에 둔다.
  • parallel_tool_calls — 한 응답에서 독립 함수 여러 개를 동시에 호출(왕복 횟수↓).
  • Structured Outputs(json_schema) — 스키마 강제로 파싱·재시도 토큰 제거. 서브태스크 반환을 구조화.
  • 모델 티어 라우팅 — 정찰·분류·요약은 mini/nano, 어려운 한 단계만 강모델로 에스컬레이션.
  • max_output_tokens 상한 — 워커 출력을 의도적으로 짧게 묶어 "결론만" 반환 강제.
  • 대용량은 모델 밖에서 — 인스턴스 JSON 파싱·집계는 파이썬(peek.py)으로 하고 모델엔 요약만.

6. ChatGPT 앱(코딩 아닌 일반 사용)

  • Projects로 작업공간을 분리하고, 프로젝트 지침에 §1·§2의 토큰 절약 규칙을 넣어 매 대화에 적용.
  • Custom Instructions에 "큰 파일은 요약만, 결론 먼저, 불필요한 재출력 금지" 류 상시 규칙.
  • 병렬 fan-out은 ChatGPT 단독으론 불가 — 진짜 병렬이 필요하면 §3-B(API)로 내려간다.
