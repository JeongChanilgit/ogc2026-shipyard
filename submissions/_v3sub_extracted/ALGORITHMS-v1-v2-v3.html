왜 set1 강 (z1=0, 19/20)

set1은 작고 저압력 → S4 greedy BL이 모든 블록을 entry=R에 crane-safe 배치(공간 충분, delayed/forced 거의 없음). 레이아웃이 충분히 좋으니 S5 타이밍오라클이 그 위 tardiness를 최적=0으로 마감. z3는 S2가 선호를 직접 목적에 넣고 spill이 적어 유지.

왜 set2 약 (z1 지배)

병목 = S2 배정 + S4 BL(S5 아님). S2가 z1-blind라 선호-magnet 베이가 블록의 57~59% 흡수 → 단일 크레인이 115+ 블록 직렬화. S4도 고압력·멀티레이어서 밀려 레이아웃에 z1 내장. S5는 위치 고정이라 구조적 z1을 못 고침.

엔진: crane_repack_bay (crane_cpsat.py:333) — never-worse가 구성적으로 보장되는 이유

  • 위치 후보(_build_candidates): 블록마다 candidate 0 = 현재 pose + active 블록에만 선형합집합 {현재}∪{x시프트}∪{y시프트}∪{방향변형} (격자곱 아님 → 폭발 방지, _COMBO_CAP=200k).
  • 크레인 5불리언(_precompute_combos): 모든 쌍×후보조합에 공식 check 함수로 (coll, entry차단×2, exit차단×2) 사전계산. 시간-독립이라 가능. = bbox 근사 아닌 진짜 크레인 feasibility.
  • CP-SAT: sel[b][ci](위치선택 ExactlyOne) + e[b](entry) 동시 결정, 5불리언을 sel로 게이트한 disjunction, min Σtardy.
  • never-worse: cand0=현재 pose + AddHint 워밍 → 현재해가 모델 내 feasible → CP-SAT 최적 tardy ≤ 현재. 채택 위치는 공식 check라 항상 crane-safe.

왜 축 분리(x/y/o)가 monolithic보다 2배

한 축만 열면 후보가 선형(블록당 ~K개) → 조합 폭발 없음 → CP-SAT가 1-D 부분문제를 OPTIMAL까지. monolithic(동시)은 combo-cap에 막혀 suboptimal. 게이트가 매 패스 never-worse라 t→x→y→o 누적이 안전. (t=(0,0,0)=순수 타이밍; 단 제출 루프는 x/y/o만 돌고 t는 각 패스 entry IntVar에 내장.)

cross-bay의 z3 레버

이미 tardy인 블록은 z1이 이미 발생 → 선호 베이로 옮겨도 z1 wash, z3(선호편차)만 down. free_ids로 도착 베이 기존 블록을 동결해 다른 z1 안 건드림.

❓ set1을 v2로 "완벽하게" 풀 수 있나 — 분석

핵심 진단: v2가 set1에서 지는 건 타이밍이 아니다(v1과 동일 오라클). 원인은 v2 Pass B의 ① 단일패스 commit(재배정·재패킹 없음)과 ② per-bay 압축 단계 부재 둘뿐. 즉 v2는 빡빡한 선호 베이를 v1만큼 조밀하게 못 채워, 블록이 선호 베이 밖으로 밀리고(z3↑) 늦게 들어간다(z1↑).

그래서 v2로 set1을 잡으려면 — 후보 방향

  • A. v2 + per-bay 압축 후처리: Pass B 뒤에 v1식 per-bay best-of/descent(또는 v3 crane_repack을 z1=0에도 full-obj로) 1패스. 밀도를 끌어올려 선호 베이 수용↑ → z3·z1 회수. (현 v3 postproc는 z1-gate라 set1 스킵 — 이걸 풀면 됨.)
  • B. v2 commit을 재배정 가능하게: 단일패스 영구 commit 대신, 선호 베이 경쟁이 생기면 이미 놓인 블록을 밀어내고 재배치(local repacking). myopic marginal을 look-ahead로.
  • C. v2 + 명시적 z3 floor: 가이드라인을 nudge가 아니라 제약으로 — 선호 베이 용량을 예약해 뒤 블록이 들어갈 자리 보장.
  • D. 현실 인정: set1은 v1이 이미 z1=0·강함. "v2로 set1 완벽"이 목표라면 결국 v2에 v1의 2단계(정밀배정+압축)를 이식하는 것 = v1에 수렴. 오히려 best-of로 set1=v1·set2=v2를 라우팅하는 게 실용적.

다음 실험 후보: A(v3 postproc의 z1-gate 제거 + full-obj를 set1에 적용)가 가장 싸고 직접적 — set1 z2/z3를 never-worse로 깎을 수 있는지 측정. 현재 돌고 있는 fix 런이 정확히 그 방향(z1-gate 제거).
